# 知识库：员工使用页与管理治理页

状态：可交互视觉原型，待产品确认。原始 `space-2.html` 保留。原型不替换正式路由，不连接真实数据、审批、文件提取或任务服务。

## 1. 设计结论

员工端回答“哪份知识可以帮助我完成当前工作”；管理端回答“哪些知识可信、可用，谁负责维护”。每端只有一个知识页面，详情、分类选择、修订和确认均在同页完成。

两端共享知识标识、分类与版本模型，展示不同职责所需的信息。实际接入应共享后端数据，不能建立两套独立知识库。本原型两端数据为各自内存示例，刷新恢复初始值。

## 2. 页面层级

| 层级 | 员工端 | 管理端 |
|---|---|---|
| 平台导航 | 原有 12 项菜单全部保留，包括 3 项明确禁用入口 | 原有 10 项菜单全部保留 |
| 页面顶栏 | 知识库；可见知识说明 | 知识管理；分类目录、新建知识 |
| 检索区 | 标题/主题/负责人搜索，领域/主题选择，知识类型，重置 | 同样检索方式；后续可增加负责人、范围高级筛选 |
| 快捷视图 | 全部、收藏、最近查看 | 全部、待审核、已发布、草稿、已停用 |
| 列表 | 名称、分类路径、类型、更新日期、版本、收藏标记 | 名称、分类路径、类型、状态、责任人 |
| 同页详情 | 内容；来源与版本 | 内容；属性与范围；版本记录 |
| 主动作 | 用于当前任务：确认知识版本和目标任务 | 待审核内容主动作是审核；草稿是提交审核；其他状态主动作是新建知识 |
| 辅助动作 | 收藏/取消收藏 | 修订；更多中的范围调整、停用、版本记录 |

导航文案与顺序依据当前 `src/layout/Workbench.tsx`、`src/layout/adminNav.ts`。原型中其余平台菜单显示完整，点击说明其沿用平台入口，不创建假业务页面。

## 3. 分类与知识心智

浏览路径：主题域族 → 领域（主题域）→ 主题 → 知识条目。界面以具体工作语境组织内容；内容模型和载体放到管理端属性中，避免员工先理解技术分类才能查资料。

| 主题域族 | 领域 | 主题示例 |
|---|---|---|
| 增长与合作 | 红人合作、内容营销、品牌运营 | 红人发现、建联邀约、合作执行、效果复盘；选题策划、内容审核等 |
| 交易与履约 | 供应链、商品运营、客户服务 | 供应商开发、采购询价、质量管理；安装售后、退换货等 |
| 经营与管理 | 销售运营、财务管理、法务合规 | 线索培育、报价方案；结算付款；合同管理、广告合规等 |
| 组织与平台 | 人力行政、数据分析、平台使用 | 入职指引；指标口径、数据质量；任务协作、知识管理等 |

原型包含 4 个主题域族、12 个领域、48 个主题、48 条示例知识。员工初始可见 24 条已发布示例；管理员初始可见全部 48 条。所有计数从示例数据计算，无虚构总量或效果指标。分类弹窗支持搜索与层级展开；不把几十个选项铺成标签墙。

六种面向员工的类型：操作指南、邮件模板、检查清单、复盘方法、制度规范、工作模板。管理属性保留原稿的“结构化/非结构化”与“在线编辑/文件上传”两个独立维度。

这些分类是设计样本，正式编码需对照后端当前分类契约映射；不直接写入生产字典，也不把示例正文作为业务制度。

## 4. 原稿六个入口如何归位

| 原稿入口 | 新版位置与处理 |
|---|---|
| 工作台 | 收敛到当前列表及状态视图；取消重复 KPI 大卡 |
| 知识生产 | 新建/修订弹窗：在线内容、来源文件、分类、模型；提取作业未来在条目详情呈现真实状态 |
| 知识设计 | 内容模型保留在属性与编辑中；Schema 的字段设计后续作为同页配置面板，当前未实现字段设计器 |
| 知识资产 | 页面主体：检索列表 + 同页内容详情 |
| 效果分析 | 后续在单条知识详情呈现真实引用/反馈记录；没有数据时不展示虚构趋势。全局分析不是本次原型能力 |
| 系统配置 | 分类目录在顶栏；范围在属性/更多。系统级权限沿用平台治理，不在知识页另建权限系统 |

## 5. 视觉与空间

- 按现行 `docs/DESIGN.md`，浅色密集数据工作台；从 `src/styles.css` 提取现行根 token 到 `space-3-tokens.css`，不引入旧稿独立青绿色主题。
- 桌面侧栏 260px；详情目标占内容区 54%，最小 360px、最大 820px；列表填充剩余空间。
- 页面标题 16px，内容 14px，列表次要信息 12px；控件 32px，控件圆角 6px，面板圆角 8px。使用 CSS token，不加载外部字体/CDN。
- 选中项用辅助色背景与边线，状态有文字和符号。主色只强调当前关键动作，同一视口至多一个实底主 CTA；打开确认弹窗时降低背景动作强调。
- 列表采用两行信息，不铺卡片墙；长标题省略，选中后详情完整展示。不重复堆放统计、描述和大标题。
- 宽度 ≤1100px 列表与详情上下堆叠，默认显示 6 条结果并可展开全部；≤860px 导航进入可关闭抽屉。窄屏字段单列。
- 高度 ≤640px 收紧顶部留白；粗指针控件扩大至至少 44px。外层不滚动，桌面仅导航/列表/详情滚动，窄屏由工作区滚动。

## 6. 状态与安全边界

- 员工初始展示已发布示例。真实权限必须在后端检索、预览、引用时校验，不能依赖原型的前端过滤。
- 收藏、最近查看与筛选在原型内工作。使用知识仅演示选择版本及目标任务，不自动发信、推进阶段或执行工具。
- 新建与修订保存示例草稿。修订已发布知识时复制出新草稿，保留当前发布版本；真实实现须用一个知识 ID 下的版本关系承载，原型仅用独立示例行展示两种状态。
- 审核需要填写意见。发布、退回、停用与范围调整仅修改当前页面内存；不冒充真实审批回执。
- 文件选择只展示入口，不上传、提取或生成模拟提取结果。正式流程应有上传、排队、提取中、失败及重试状态。
- 无结果、空详情、必填校验、禁用操作、确认弹窗均有明确反馈。完整生产加载、网络失败、权限拒绝和并发版本冲突还需后端接入后实现。
