# Home 页面覆盖规则

> 这是 Home 重做时的目标行为简报，不是当前页面设计说明。除已落地 token 外，不继承现有页面的布局和组件造型。业务事实与验收以对应 FS/UX 为准。

## 职责

Home 回答“我现在要做什么”，默认进入“今日任务”。平台模式：今日任务、我的待办。KOL 试点另挂：AI 发现、已关注创作者（不是平台一等清单）。模式切换保留用户当前上下文，不伪装成 Pipeline 阶段。

## 布局

- 首屏优先显示当前模式、任务状态和一个主动作。
- 今日任务以真实状态分组，等待项说明等待对象和恢复入口。
- 我的待办强调责任人、截止时间和完成条件。
- AI 发现由 Composer/搜索条件、紧凑筛选和 CreatorCandidate 结果组成；结果区是主要视觉重量。
- 已关注创作者沿用同一创作者信息层级，避免另一套卡片语言。

## AI 发现筛选

- 平台：YouTube / Instagram / Facebook。
- 地区为单选；方向为多选，最多 8 项。
- 显式 Chip 选择覆盖自然语言中冲突的同类条件，并显示可见的覆盖结果。
- 重置筛选不清空用户的自然语言目标。
- 低频条件折叠在“更多条件”，展开后不改变主结果区的位置语义。

## 创作者结果与关注

- CreatorCandidate 显示真实来源、匹配理由和当前可用身份信息。
- 缺少真实主体 ID 时不得创建 Collaboration；界面应说明仍需验证什么。
- “关注”是 L3 确认动作。成功后进入已关注集合，但不暗示已发送、已暂存或已进入 Pipeline。
- 同一创作者在发现与已关注模式中使用一致的信息层级和操作位置。

## 状态与响应式

- 空状态区分“尚未搜索”“筛选无结果”“服务不可用”。
- 检索失败保留输入与筛选，并提供重试；不得只显示底层 HTTP 文案。
- 窄屏将筛选放入抽屉，模式导航可横向滚动，但页面主体不得横向溢出。

## 交互状态矩阵

| 元素 | Default / Hover | Focus / Selected | Loading / Disabled / Error |
|---|---|---|---|
| 模式 Tab | 文字按钮；hover 只改变背景或文字强调 | 焦点环完整可见；选中同时提供底色、文字和 `aria-selected` | 加载不锁死模式切换；不可用时说明原因 |
| 筛选 Chip | 原生按钮；hover 不改变尺寸 | `aria-pressed` 与视觉选中同步 | 请求中仍可检查条件；禁用项说明约束 |
| 搜索/生成 | 主动作清晰 | Enter 可提交，焦点不被结果更新抢走 | 使用稳定占位和忙碌状态；错误保留输入、筛选和重试 |
| 关注 | 显示真实对象与当前状态 | L3 Dialog 内焦点受控，关闭后返回触发按钮 | 执行中防重复提交；成功留下持久回执；部分成功逐项说明 |

模式与筛选应进入 URL，以支持刷新、分享和浏览器返回。横向模式导航支持方向键和键盘滚动，并提供可见的溢出提示。
