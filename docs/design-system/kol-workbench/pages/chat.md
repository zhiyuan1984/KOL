# Chat 页面覆盖规则

> 这是 Chat 重做时的目标行为简报，不认可或继承当前页面设计。Chat 是完成一项具体任务的连续工作区。

## 结构

- 顶部：任务标题、真实状态、必要的范围或参与者信息。
- 主区：单一时间线，依次容纳用户目标、系统理解、计划、能力调用、等待和结果。
- 底部：Composer 固定于可用工作区底部，但不能遮挡最后一条内容。
- 可选详情在侧栏或抽屉展示，不拆分任务线程。

## 消息与结果

- 计划应可检查但不过度展开内部推理；显示步骤、依赖、状态和用户可干预点。
- 工具调用用紧凑状态行表示；只有错误、确认或重要结果才展开为面板。
- 结果卡必须说明对象、来源、生成时间和下一项合法动作。
- 长结果先给摘要和关键证据，再按需展开原文或明细。

## 副作用

- L1 查询可直接运行。
- L2 草稿明确显示未外发、可编辑和可撤销。
- L3 卡片展示动作对象、范围、后果和确认按钮；发送、暂存、导入、解密、删除分别确认。
- 执行后在同一线程显示真实回执；失败保留输入和可恢复路径。

## Composer

- 自然语言输入是主入口；附件、技能和连接器是辅助入口。
- 高频能力直接可见，低频设置渐进披露。
- 发送期间若允许继续输入，必须区分“排队”与“已执行”；否则明确锁定原因。
- placeholder 只给输入示例，不承担操作说明。

## 响应式

- 桌面端对话正文保持可读行长，结构化结果可扩宽。
- 窄屏详情栏转抽屉；确认卡的对象和后果始终先于动作按钮显示。

## 交互状态矩阵

| 元素 | Default / Hover | Focus / Active | Loading / Disabled / Error |
|---|---|---|---|
| Composer | 输入、附件和能力入口边界清楚 | 焦点使用 `--focus-ring`；多行输入不改变工具栏位置 | 排队、上传和发送分别显示；失败保留文字与附件 |
| 发送/停止 | 图标与文字语义稳定，hover 不位移 | Enter 发送规则可预期；停止动作键盘可达 | 发送中防重复；停用必须说明是无内容、无权限或任务状态限制 |
| 工具调用行 | 默认紧凑 | 可展开项提供 `aria-expanded` | `queued/running/retrying` 使用业务文案和 `aria-busy`；失败提供恢复动作 |
| L3 确认卡 | 对象、范围、后果先于按钮 | Dialog 聚焦标题或首个安全动作，关闭后返回来源 | 执行中锁定重复确认；成功、部分成功、失败均在线程留下持久回执 |

固定 Composer 必须为滚动内容预留底部空间，键盘焦点和最后一条结果不能被遮挡。重要结果更新使用适当的 live region，但普通流式文本不得逐字打断读屏。
