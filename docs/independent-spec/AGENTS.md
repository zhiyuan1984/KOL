## 2. 审宪程序

任何需求、规则或实现变更都必须先执行 CONST-08：

```text
需求 → 主责角色 → 宪法条款 → 基本法条款 → 结论与证据 → 下一步
```

结论只能是：

- `符合`：在授权范围内继续。
- `违宪`：指出具体宪法条款和冲突行为，调整方案。
- `违反基本法`：引用具体文件、条款和证据，由责任角色修正。
- `规则空白或冲突`：交所属角色补充，只暂停依赖该决定的部分。

不得在没有条款依据时使用“可能违宪”阻止工作。代码现状、历史决定和测试断言都不能自动成为规则。

## 3. 层级与责任

- `CONSTITUTION.md` 高于三部基本法。
- `PRODUCT.md`、`BUSINESS.md`、`TECHNOLOGY.md` 按领域分工，互不凌驾。
- 其余文件是实施细则，不得覆盖上位规则。
- 跨领域变更分别由对应责任角色确认；项目经理只协调，不替其他角色决定规则。
- 本目录不依赖同级目录外的规范正文。代码、配置、schema 和测试只作为实施资产或证据。

## 4. 禁止事项

- 禁止在页面重新发明业务权限、审批链或阶段规则。
- 禁止把发送、暂存、导入、解密、删除或阶段推进合并为同一个副作用。
- 禁止将 L2 草稿冒充正式结果，或跳过 L3 确认、审批、幂等和回执。
- 禁止用模拟结果、占位页面、测试通过或文档完成冒充生产能力。
- 禁止用远端 API 的物理限制改写业务规则。
- 禁止把历史决定、缺失证据或过时快照描述为当前事实。
- 禁止在本目录新增指向外部现行规范或历史归档的依赖；需要的规则应复制、审查并收敛到本目录。
- 禁止在基本法正文维护易过期的具体代码完成状态；实施状态使用独立登记表。

## 5. 跨领域不变量

- 发送不推进正式阶段。
- 快捷读取、Codex 思考、受控业务动作和后台事件使用不同入口契约。
- L1 只读可直接执行；L2 草稿必须标明；L3 外发、导入、删除、解密和正式写入执行前必须确认并保留回执。
- 权限在取数、模型调用、缓存、索引、导出、分享和后台执行前校验，不能先取全量再过滤。
- 等待必须展示原因、状态和恢复入口；不得伪造联系人、结果、完成或进度。
- 状态不能只靠颜色表达；同一视口最多一个实底主 CTA。
- 设备适配按宽度、高度、输入模态三轴分别处理，禁止 UA 嗅探。
- MediaCrawler 是单任务异步作业，必须支持进度、取消、重试和真实终态。

## 6. 验证要求

- 每项变更关联适用条款、实施资产、责任人和验收证据。
- 阶段机器配置必须与阶段正文等价，并进入契约校验和发布门禁。
- 外部写入只使用明确授权的对象和范围；只读或记忆功能不需要通过发信证明可用。
- 文档变更至少检查内部链接、条款引用、层级声明和失效历史引用。
- 发布验证区分模拟测试、真实 Codex harness 测试与授权外部集成验证；一种通过不代表其余通过。
