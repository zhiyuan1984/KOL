# 管理侧员工目录：UI/UX 视觉与交互方案

> **2026-10-03 取代注记：** 本历史方案的员工技能/工具授权入口由 Agent 绑定新法取代；员工管理页应显示和变更 Agent 绑定及直接/负责人继承来源。视觉密度建议仍可参考，现行方案见 [agent-skill-governance-design.md](superpowers/specs/2026-10-03-agent-skill-governance-design.md)。

**版本：** v1.0 · 2026-09-27
**状态：** 视觉与交互方案，尚未实施
**范围：** 管理端员工目录、员工编辑弹窗、工具授权弹窗、停用确认

---

## 1. 设计结论

> 员工管理页是一个**高密度、可筛选、可批量理解的列表页**；编辑和授权在两种职责明确的弹窗中完成。

不做卡片墙，不复制员工工作台，也不把 KOL Pipeline 搬进管理端。目录回答“谁能使用平台、归属哪里、绑定什么业务资产、已获哪些工具权限”；弹窗只承担“编辑资料”和“修改授权”两件事。

本方案是对现有 Admin 的 **Extension（增量扩展）**，不是整体改版。视觉语言直接复用技能治理页的表单节奏：白底分区、轻描边、紧凑字段、分段标题、小圆角、单一主按钮和克制的状态标签。

## 2. 设计读与约束

### 2.1 设计读

```yaml
artifact: 管理端员工目录 + 两个治理弹窗
primary_audience: 组织管理员、业务负责人、权限管理员
mode: Extension（保留既有 Admin 信息架构和路由）
visual-language: data-dense-dashboard；技能治理页同源表单
visual-variance: 2/10
motion-intensity: 2/10
information-density: 8/10
asset-dependence: 0/10
brand-fidelity: 10/10
```

### 2.2 保留、改进与明确移除

| 类别 | 决策 |
|---|---|
| 保留 | Admin 的紧凑密度、现有 `.admin-table` 行分隔、技能页的白底表单分区、`btn / btn work / danger` 语义、确认弹窗、状态标签与现有路由 |
| 改进 | 当前“员工目录 + 新增员工”双卡布局替换为主列表；把员工详情、绑定资产、授权操作从列表行中抽离；所有高影响变更均给出影响说明和确认 |
| 移除 | 目录中的大卡片、每一行的长段落信息、用“删除”掩盖实际“停用”的文案、即时切换权限而没有保存与确认 |
| 不改变 | 平台账号仍是员工目录主实体；Starry 只作为外部身份 / 邮箱事实；不显示 Token，不在此页面直接管理 Starry 邮箱 ACL |

### 2.3 视觉系统

| 维度 | 方案 |
|---|---|
| 容器 | 页面背景沿用 Admin；目录是一个完整的线性列表容器，不再将每个员工做成卡片。编辑/授权仅在弹窗内使用白底分区卡。 |
| 颜色 | 只使用现有 `--primary`（本页唯一实底 CTA）、`--accent`/`--accent-text`（选中、链接和筛选）、`--success`/`--warning`/`--danger`（状态）。不新增渐变或新色相。 |
| 字体 | 标题、行内容、辅助信息分别沿用 `--ds-font-section`、`--ds-font-body`/`--ds-font-sm`、`--ds-font-helper`/`--ds-font-tag`。不在页面散落硬编码字号。 |
| 间距与圆角 | 仅用现有 `--space-*`、`--radius-control`、`--radius-card`、`--ds-radius-input`。列表靠细分隔线，不靠投影分组。 |
| 控件 | 搜索、筛选、按钮统一紧凑高度；表单弹窗复用 `--control-h-form` 与连接器表单的字段比例。输入默认无描边，以填充区分；获得焦点后显示现有 focus ring。 |
| 图标与动效 | 采用已有细描边图标。弹窗为短距离淡入；行 hover 只改变背景和链接颜色；遵从 `prefers-reduced-motion`，不做装饰性动画。 |

## 3. 员工目录页

### 3.1 页面骨架

```text

管理平台账号、组织归属、业务绑定与工具权限

[ 搜索姓名、邮箱、岗位或工号                         ] [ 组织 ▾ ] [ 品牌 ▾ ] [ 状态 ▾ ] [ 重置 ]

────────────────────────────────────────────────────────────────────────────────────
员工                    组织 / 品牌             业务绑定              工具权限        最近变更      操作
────────────────────────────────────────────────────────────────────────────────────
[ZY] 赵良玉              推广部 / LT 组           邮箱 2 · KOL 38       已启用 7项      今天 14:20   查看 编辑 授权 ⋯
     larry.zhao@…        LT · RO                  larry.zhao@…
────────────────────────────────────────────────────────────────────────────────────
[WX] 魏银平              推广部 / LT 组           邮箱 1 · KOL 12       已启用 4项      昨天 09:12   查看 编辑 授权 ⋯
     henry.wei@…         LT

```

### 3.2 页面层级与工具栏

| 区域 | 视觉与交互 |
|---|---|
| 标题区 | 左侧仅保留“员工”与一行辅助说明；不做 hero。右侧唯一实底主 CTA 为“+ 新增员工”。 |
| 搜索 | 宽搜索框放在筛选行最左，placeholder：`搜索姓名、邮箱、岗位或工号`。输入后 250–300ms 防抖查询；按 Esc 清空而不离开焦点。 |
| 筛选 | “组织”“品牌”“状态”三个紧凑下拉。已选择的筛选项以文字和值展示，`重置`为无底色文字按钮。组织可显示完整路径，如“品牌与用户增长中心 / 推广部”。 |
| 结果摘要 | 紧贴工具栏下方，使用辅助字号：`已显示 24 / 38 名员工 · 已启用 35 · 待核验 3`。没有造假的 KPI 卡。 |
| 列表头 | 弱化文字、细底边；列名可排序的列保留箭头和 `aria-sort`。默认按“账号状态、最近变更”排序。 |
| 列表行 | 68–76px 的双行信息密度，整行只有轻 hover 底；行之间 1px 分隔；无独立投影、无大面积色块。 |

### 3.3 列定义

| 列 | 内容 | 规则 |
|---|---|---|
| 员工 | 名称、首字母头像砖、登录邮箱；停用时追加“已停用”文字标签 | 名称是“查看”入口，不以头像作为唯一点击区。头像没有真实照片时使用名称首字，不伪造头像。 |
| 组织 / 品牌 | 主组织 / 团队路径；第二行显示品牌标签 | 无组织或品牌时明确写“待设置”，不留空白。 |
| 业务绑定 | `邮箱 n · KOL n`，第二行显示一个真实邮箱样例或“未绑定” | 所有详细邮箱与 KOL 仅在编辑 / 查看弹窗展示；不可通过计数推断权限。 |
| 工具权限 | `已启用 n 项`；若存在阻塞，显示“待绑定”“待考试”等文字状态 | 工具数量是摘要，不代表绕过连接器、考试或 Host Gateway。 |
| 最近变更 | 日期时间、操作者可在详情审计中查看 | 辅助信息列，在中等宽度可隐藏。 |
| 操作 | `查看`、`编辑`、`授权`三个文本按钮；`⋯` 收纳停用等低频动作 | `授权`始终可见；危险操作不与主按钮并列。 |

### 3.4 行级操作

| 操作 | 结果 | 强调级别 |
|---|---|---|
| 查看 | 打开同一员工资料弹窗的只读模式；可从此进入“编辑” | 文本 / accent |
| 编辑 | 打开“编辑员工”弹窗，默认可编辑 | 描边次按钮 |
| 授权 | 打开“工具授权”弹窗 | 描边次按钮；不使用实底主色 |
| ⋯ → 停用 | 打开停用确认；确认后失效会话并保留审计 | danger 文本 |
| ⋯ → 重新启用 | 对已停用员工出现；确认后恢复平台使用资格 | 次按钮 |

**删除文案的约束：** 当前后端 `DELETE /api/admin/users/:uid` 的真实行为是“停用账号 + 清除会话”，不是不可恢复的物理删除。因此 UI 必须写 **“停用”**，不能标为“删除”。将来若实现不可恢复删除，必须单独设计“永久删除”入口、依赖检查、保留策略和二次确认，不能复用停用按钮。

## 4. 弹窗 A：编辑员工

### 4.1 尺寸与结构

使用浏览型弹窗宽度（桌面约 `--dialog-w-browse`），而非窄表单弹窗；原因是该弹窗必须同时承载基本资料、全部绑定邮箱和 KOL 列表。窄屏收为 `100vw - 32px`，保持外层遮罩、焦点锁定、Escape 关闭和关闭后焦点回到触发“编辑”的按钮。

```text
╭──────────────────────────────── 编辑员工  [已启用]                         × ─╮
│ 赵良玉 · larry.zhao@amperetime.com · 平台 ID usr_…                            │
│                                                                                │
│ 基本资料                                                                       │
│ 姓名                     [赵良玉                         ]  账号状态 [已启用 ▾] │
│ 登录邮箱                 [larry.zhao@…                   ]  岗位     [KOL经理  ] │
│ 所属组织                 [推广部 / LT 组                 ]  直属负责人[魏银平 ▾] │
│ 品牌范围                 [ LT ] [ RO ]                                      │
│                                                                                │
│ 业务绑定（只读，来源：Starry KOL · 上次同步 2026-09-27 19:40）                 │
│ ┌ 绑定邮箱（2）────────────────────┐ ┌ 负责 KOL（38）──────────────────────┐ │
│ │ 搜索邮箱…                        │ │ 搜索姓名 / KOL ID…                   │ │
│ │ larry.zhao@…  RO 负责人  已核验   │ │ [K] Alice Green · KOL… · 合作中       │ │
│ │ brandmarketing@… LT 有权限 待核验 │ │ [K] Robert Chen · KOL… · 待联系       │ │
│ │ …可滚动显示全部绑定邮箱            │ │ …分页 / 虚拟列表显示全部 KOL            │ │
│ └──────────────────────────────────┘ └─────────────────────────────────────┘ │
│                                                                                │
│ [取消]                                                    [保存修改]           │
╰───────────────────────────────────────────────────────────────────────────────╯
```

### 4.2 弹窗分区

| 分区 | 内容 | 编辑权限与状态 |
|---|---|---|
| 标题块 | `编辑员工`、姓名、邮箱、平台 ID、账号状态标签、关闭 X | 平台 ID 只读；标题不堆叠无关标签。 |
| 基本资料 | 姓名、登录邮箱、岗位、所属组织、直属负责人、品牌范围、账号状态 | 本地平台字段可编辑。组织、品牌采用受控选择，不允许自由文本制造不存在的组织。 |
| 业务绑定 | 绑定邮箱列表、负责 KOL 列表、来源、最后同步时间、对账状态 | **只读。** 外部记录显示“已核验 / 待核验 / 冲突 / 未绑定”文字与形状信号；不显示 JWT、Token、密码。 |
| 操作回执 | 保存中、保存成功、保存失败或外部数据暂不可用 | 使用 `role=status` / `role=alert`，错误不得只靠红色。 |
| 固定页脚 | `取消` + 唯一实底 `保存修改` | 保存时禁用重复提交，保持弹窗打开直至获得真实 API 回执。 |

### 4.3 “所有绑定邮箱和 KOL 列表”的具体处理

- **绑定邮箱：** 完整加载并可在本分区内滚动；每条显示邮箱、品牌、绑定角色（负责人 / 被授权人）、Starry 对账状态。小规模数据不分页。
- **KOL：** 不只展示前三条。列表按“名称 / KOL ID、阶段、所属邮箱”提供本地搜索和分页或虚拟滚动；标题计数显示完整总数，例如“负责 KOL（38）”。
- **KOL 事实边界：** 列表仅展示负责归属、阶段等已授权管理事实；点击 KOL 不自动跳到员工端 Pipeline，也不在弹窗内编辑 KOL。
- **无数据：** `尚未关联 Starry 邮箱，因此没有可核验的 KOL 归属。` 与 `Starry 数据暂不可读，请重试。` 分开呈现，绝不以空列表掩盖接口失败。

## 5. 弹窗 B：工具授权

### 5.1 目的

该弹窗只回答：**这位员工可使用哪些已审阅的工具，以及本次要授予或停用哪些直接权限。**

它不将“工具已授权”误写为“外部操作将直接成功”。工具权限仍要受连接器授权、个人绑定、考试、数据范围、Host Gateway、确认和审批约束。

### 5.2 布局与交互

```text
╭──────────────────────────────── 工具授权                                      × ─╮
│ 赵良玉 · larry.zhao@amperetime.com                                               │
│ 已启用 7 项 · 待绑定 1 项 · 本次尚未保存变更                                    │
│                                                                                  │
│ [ 搜索工具名称、能力或连接器                                      ] [全部 ▾]  │
│                                                                                  │
│ 工具                         来源连接器       前置条件              当前状态  本次 │
│ ────────────────────────────────────────────────────────────────────────────── │
│ 邮件会话读取                  Starry KOL       已绑定 · read          已启用   [✓] │
│ 根据负责人读取邮箱会话        已审阅 · L1                                       │
│ ────────────────────────────────────────────────────────────────────────────── │
│ 合作邮件草拟                  Starry KOL       已绑定 · 考试通过      未授权   [ ] │
│ 生成草稿，发送仍需确认        已审阅 · L2                                       │
│ ────────────────────────────────────────────────────────────────────────────── │
│ 邮箱权限保存                  Starry KOL       管理员范围 · L3        不可授予 [—] │
│ 高风险远端写操作，仅由连接器治理页配置                                          │
│                                                                                  │
│ 本次变更：新增 2 项 · 停用 1 项                         [取消] [保存 3 项变更] │
╰──────────────────────────────────────────────────────────────────────────────────╯
```

### 5.3 工具列表行

| 字段 | 视觉表达 | 说明 |
|---|---|---|
| 工具名称和说明 | 首行名称，次行一句业务说明 | 优先业务名；原始 MCP tool name 只在管理员“详情”折叠区显示。 |
| 来源连接器 | 简洁来源标签，如“Starry KOL” | 用于定位依赖，不挤占主要阅读。 |
| 审阅与风险 | `已审阅` + `L1 / L2 / L3` 文字标签 | L3 不是可被个人授权直接打开的旁路。 |
| 前置条件 | `已绑定`、`未绑定`、`需考试`、`连接器仅 read` 等 | 阻塞原因必须可读、可定位；没有条件时显示“无额外前置”。 |
| 当前状态 | `已启用`、`未授权`、`因前置条件阻塞`、`不可授予` | 状态标签必须同时使用文字与非颜色信号。 |
| 本次变更 | checkbox 作为草稿选择，或“不可授予”占位 | 不在行内立即提交；管理员可同时选择多个项目。 |

### 5.4 授权 / 停用流程

1. 打开弹窗时读取**已审阅且可在组织范围内分配**的工具目录，同时读取该员工的当前有效状态。
2. 管理员勾选或取消勾选工具，仅形成“本次变更草稿”。页脚实时汇总：`新增 2 项 · 停用 1 项`。
3. 点击唯一实底按钮 `保存 3 项变更` 后，弹出确认层，明确展示：员工、每项工具、授予 / 停用、立即生效范围、不会绕过的风险闸门。
4. 确认后才写入；完成时显示真实回执并刷新目录“工具权限”摘要。
5. 若工具没有被审批、连接器停用或员工已停用，行进入 `不可授予`，checkbox 禁用，并解释原因而不是静默消失。

### 5.5 筛选

- 搜索：工具名称、业务说明、连接器名称。
- 状态：全部 / 已启用 / 未授权 / 有阻塞 / 不可授予。
- 连接器：全部 / Starry KOL / 其他已接入连接器。
- 默认排序：本员工当前已启用 → 本次变更 → 可授予未授权 → 有阻塞 → 不可授予。

这样管理员首先看到现状与风险，而不是一长串无序工具。

## 6. 停用确认

停用是高影响的账号访问变更，不能由溢出菜单一键完成。

```text
停用员工
赵良玉（larry.zhao@amperetime.com）

范围：组织账号 · 登录与工作台授权
影响：该员工将立即无法登录或使用工作台；已发出的邮件、业务记录与审计保留。
可恢复：可在员工目录中再次启用。

[取消，不执行]                                      [确认停用]
```

- 确认按钮使用 danger 语义，但仍是本对话框唯一强行动。
- 列出工具权限会变为不可用，但**不删除**授权历史。
- 不在确认框中虚构“已回收 Starry 邮箱权限”；Starry ACL 是否存在由其外部事实单独显示。

## 7. 状态、错误与空态

| 场景 | 视觉与文案 |
|---|---|
| 首次加载 | 表头保留，使用 6 条与真实行高一致的骨架行；不使用大面积加载卡。 |
| 搜索无结果 | `没有与“赵”匹配的员工。` + `清除筛选` 文本操作。 |
| 无员工 | `尚未创建平台员工。` + 行内 `新增员工`；不使用营销式空态。 |
| Starry 数据未连接 | 编辑弹窗中显示：`尚未配置或无法读取 Starry KOL；外部邮箱和 KOL 绑定暂不可核验。` |
| Starry 返回为空 | 显示：`该员工当前没有已同步的邮箱 / KOL 记录。` 与接口不可用严格区分。 |
| 保存失败 | 保留原字段与选中授权，错误行紧贴页脚，并给出 `重试保存`。 |
| 保存成功 | 弹窗内短暂 `已保存 · 20:03` 回执，刷新目录对应行；不显示伪造进度。 |

## 8. 响应式与无障碍

| 视口 / 模态 | 行为 |
|---|---|
| ≥1280px 指针 | 展示完整 6 列目录；操作列固定最右；编辑和授权弹窗居中。 |
| 1024–1279px 指针 / 键盘 | 隐藏“最近变更”独立列，将其放到员工次行；保留搜索、组织、品牌筛选和三项主操作。 |
| ≤860px 触摸 | 筛选折成两行；目录保持线性列表而非卡片墙，行内只显示员工、组织/品牌、绑定与权限摘要；操作改为显式 `查看` + `更多`。弹窗使用 `100vw - 32px`，工具列表列改为上下信息块，固定页脚不遮挡最后一行。 |
| 键盘 | 弹窗 focus trap；Escape 关闭未保存弹窗（已有草稿时先提示）；Enter 不直接提交危险操作；筛选、每个行操作与页脚可见 focus ring。 |
| 读屏 | `table` 使用列标题，筛选使用 label；授权变更摘要使用 `aria-live=polite`；保存失败用 `role=alert`；图标按钮均有 `aria-label`。 |

## 9. 为落地该设计需要的数据契约

| 视图 | 必需数据 | 说明 |
|---|---|---|
| 员工目录 | 分页员工、搜索命中、组织、品牌、账号状态、绑定邮箱 / KOL 计数、有效工具数、最近变更 | 服务端按 `q`、`organization_id`、`brand_id`、`status` 过滤；前端不拉全量后筛选。 |
| 编辑弹窗 | 本地员工资料、组织选项、品牌选项、直属负责人选项、所有绑定邮箱、所有归属 KOL、Starry 来源 / 同步状态 | 邮箱与 KOL 使用分页 / 虚拟列表接口；“所有”代表可完整浏览，不是只返回前三项。 |
| 工具授权 | 已审阅工具目录、来源连接器、风险级别、当前直接授权、有效授权来源、前置条件和不可授予理由 | 需要单一后端 PEP 解释；不能由前端自行叠加“技能 / 连接器 / Starry”状态。 |
| 停用 | 账号当前状态、影响摘要、确认后真实回执 | API 语义应与 UI 一致：停用，不是物理删除。 |

建议 API 形态：

```text
GET  /api/admin/users?q=&organization_id=&brand_id=&status=&page=
GET  /api/admin/users/:id
GET  /api/admin/users/:id/bindings?kind=mailbox|kol&page=
GET  /api/admin/users/:id/tools
PUT  /api/admin/users/:id/tools              # 提交完整、可审计的授权变更草稿
PATCH /api/admin/users/:id
DELETE /api/admin/users/:id                  # 仅“停用”语义，保持现有事实契约
```

## 10. 实施验收要点

- 目录为**列表行**，不是员工卡片网格；1280px 宽度下不出现页面级横向滚动。
- 搜索、组织、品牌三项过滤可组合、可清除，并反馈真实结果数量。
- 每行可查看、编辑、授权和停用；停用操作可恢复且有明确确认。
- 编辑弹窗能完整浏览该员工的绑定邮箱和 KOL，不只显示计数或三条预览。
- 授权弹窗展示工具、来源、风险、前置条件和当前状态；授予 / 停用均先形成草稿，再确认提交。
- 一个页面 / 弹窗在同一视口最多一个实底主 CTA。
- 授权不会被表述或实现为绕过 Starry 邮箱 ACL、连接器权限、考试、Host Gateway、确认或审批。
- 状态、错误、空态和加载态均具备文字说明；无需依赖颜色才能理解。

## 11. 建议的实施顺序

1. 先完成目录 API 的搜索、组织 / 品牌过滤和绑定资产计数。
2. 实现列表页与“查看 / 编辑”弹窗，先把外部邮箱、KOL 作为只读事实展示。
3. 建立单一的工具授权 PEP 与“为什么可用 / 不可授予”数据，再实现工具授权弹窗。
4. 最后接入停用确认、审计回执、窄屏适配和端到端测试。

在进入代码阶段前，唯一需要锁定的产品命名是：目录危害操作采用 **“停用”**（与真实 API 一致），而不是“删除”。
