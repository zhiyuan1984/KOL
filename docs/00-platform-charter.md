# 数字员工中台产品总纲

## 愿景

让企业像配置岗位一样创建数字员工，像组合能力一样编排 Skill，像发布业务流程一样发布 Agent。新增 Agent 主要由业务配置、Skill、MCP 工具声明和审批策略完成；Codex app-server 负责业务语义编排，平台内核负责权限、状态、一致性和副作用。

## 产品边界

平台服务多个公司、组织单元、品牌和业务 Agent。当前安培时代试点的第一个范围是 `org:brand_user_growth_center → org:promotion_department` 下的 `org:lt_team` 与 `org:pq_ro_tb_team`；`org:brand_project_group` 和 `org:market_department` 是该中心的并列组织单元。张慧玲负责品牌与用户增长中心，刘敏负责推广部；部门负责人按公司政策自动拥有公司全部品牌、区域和普通业务数据读写范围，高风险动作仍受 Host 闸门控制。

安培时代试点 PEP 的正式授权证据由组织截图、100%真实的邮箱负责人绑定清单、远程 Starry MCP 只读负责人/邮箱授权结果和 `config/org-registry.yaml` 共同构成。未补齐的外部 user_id、工号或任职元数据是非阻断待办，不得再次被描述为“组织主数据未完成”。

## 五层架构

```text
平台内核：租户、权限、任务、状态、审批、事务、审计
声明式业务层：Digital Employee、Agent、Workflow、Skill、Policy
Codex harness：thread、turn、Skill、MCP、事件和模型输出
物理连接层：Starry、MediaCrawler、邮件、CRM、ERP、OA 等真实接口
体验层：员工端业务工作台、管理端资产/Trace 工作台
```

## 不变量

- 模型不能越过租户、品牌、用户和工具权限边界。
- 高风险外部副作用必须经过运行时审批。
- 发送、阶段变更、导入、解密和删除是不同动作，不能隐式合并。
- 每个结果必须可追溯到任务、Thread、Turn、Skill、工具调用和审批。
- 业务语义由 Skill 和 Workflow 描述；安全和一致性由平台内核强制执行。
- Stub 只用于测试；生产验收必须使用真实 Codex app-server 和授权 MCP。

## 成功标准

新增普通 Agent 时，平台代码不随 Agent 数量线性增长；新增能力通常只需配置 Agent、Workflow、Skill、MCP 白名单、数据范围和审批策略。

## 共创产物与退出条件

业务负责人带来目标、真实样例、风险边界和验收权；运营员工带来工作步骤、例外和失败样本；产品经理把它们整理成概念卡、PRD、用户故事和功能规格；工程确认数据、接口、权限、状态和实现边界；前端确认双端流程与所有运行态；测试把规则转成测试/评价集；运维确认环境、监控、容量、密钥和回滚。

每个阶段都有退出条件：没有目标和非目标不进入概念；没有参与者、状态、权限和验收不进入功能规格；没有失败测试和评价样例不进入编码；没有真实 app-server/MCP 证据不进入灰度；没有监控、密钥和回滚不进入生产。业务价值由业务负责人决定，产品范围由产品经理决定，平台安全和一致性由工程否决，质量证据由测试否决，运行就绪由运维否决。

## 角色任务、责任与权利

| 角色 | 主要任务 | 对什么负责 | 可行使的权利 |
|---|---|---|---|
| 业务负责人 | 定义目标、边界、风险、指标、真实数据和决策人 | 业务结果、规则正确性、采用和业务风险 | 决定业务优先级/范围/验收，否决不符合目标的方案 |
| 业务/运营员工 | 提供真实步骤、样例和失败案例；试用、确认、接管和反馈 | 日常事实核验、人工确认、异常处理 | 查看自己的任务，编辑草稿，确认/拒绝/停止/接管，报告错误 |
| 产品经理 | 把目标转成场景、Agent、Workflow、Skill、Policy、UX、指标和规格 | 需求完整、取舍、版本、可验收性和跨角色对齐 | 组织共创和评审，要求影响分析；不能降低安全/隔离门禁 |
| 后端/平台工程师 | 实现租户、组织、权限、Task、状态、审批、幂等、审计、Codex/MCP adapter | 安全、一致性、可靠性、性能和可恢复性 | 否决越权、不可审计、不可恢复的方案；要求接口和所有权明确 |
| 前端工程师 | 实现员工端/管理端、任务状态、业务卡、审批、错误恢复和无障碍 | 状态可见、可理解、一致、可操作和无障碍 | 要求稳定 schema/事件/错误契约；否决无状态等待和隐藏风险 |
| 测试与评价 | 设计单元、契约、harness、集成、E2E、UX、红线和 Agent 评价集 | 质量证据、风险覆盖、越权拒绝和行为质量 | 退回不可测试需求；阻止未通过红线/真实集成/评价的发布 |
| 运维/SRE | 维护 app-server、MCP、密钥、队列、监控、告警、容量、灰度和回滚 | 可用性、恢复、运行安全、版本一致和事故响应 | 阻止无监控/回滚/容量/密钥方案的发布 |

任何角色都不能把专业判断转嫁给 Codex。Codex 可以探索、解释、实现和提出备选方案，但业务价值、产品取舍、平台安全、质量证据和生产就绪必须由对应角色签署。
