# 远程真实 MCP、15 阶段 SOP 与智能体实施计划

日期：2026-09-07。范围：当前 TypeScript 工作区。本文件是实现计划，不表示功能已上线，也不执行真实发信、审批、采集或部署。

## 1. 目标、依据与边界

运营围绕一位 KOL 的合作持续工作：系统读取真实业务数据，选择符合当前事实的 SOP，准备产物，在需要决策时交给授权人员，通过远程真实 MCP 执行动作，并记录回执。批量处理采用相同执行引擎。

研发 KOL、审批、爬虫三个智能体入口；每个智能体使用 Codex app-server 线程。本计划「15 个 SOP」映射为 `backend/src/stages.ts` 的 15 个主阶段，对应 15 份 skill。

约束：

- 生产业务读取和外部动作全部通过授权的远程真实 MCP；入站事件通过真实服务签名 Webhook 接收。Webhook 是事件入口，不等同于 MCP 调用。
- Codex 使用真实 app-server（**Codex harness = Codex app-server**）；本地 stdio 是 Host 与 app-server 的通信方式，与远程 MCP 的要求不冲突。Host 不代替 harness。
- UI 可有 KOL、审批、爬虫三个智能体入口；内部复用一套任务引擎与现有 Profile，不建立互相聊天的多套运行时。
- 发送、来信分析、SOP 完成、正式阶段写入是独立动作。来信只生成建议，不自动改正式阶段。
- 沿用已确认的报价、寄样、发货和阶段规则；方案覆盖其连接器及执行机制，不擅自修改商业规则。
- 单元测试可使用隔离 fixture；真实集成验收、候选部署和生产必须禁用所有 mock/stub 与本地假回执。

## 2. 本轮落地（相对完整计划的切片）

已实现、须在 **Codex app-server + 授权远程 MCP** 上验收（Host 内 stub 不算生产验收）：

1. 15 份版本化 SOP skill（`sop_*`）与 `SOP_PACKS`；Codex turn 展示资料包，不发信、不改正式阶段。
2. 发送回执按供应商明确成功字段判定，不再使用 `sent !== false`。
3. `expected_version` 只接受非负整数；空值不再变成 `0`。
4. 来信列表游标分页、暂缓后恢复；搜索/绑定按租户品牌范围收敛。
5. Webhook Message ID 与 `kol_mail_seen` 指纹共用同一套身份键。
6. 生产启动不再自动清理历史 seed / 旧类型审批；正式迁移与启动分离。
7. UI 增加 KOL / 审批 / 爬虫三个智能体入口，复用同一套 Codex 任务引擎与 Profile，不另起运行时。

本轮明确不做：远程企微/OA MCP、持久执行队列、真实发信/审批/采集/部署、修改报价寄样发货规则。
