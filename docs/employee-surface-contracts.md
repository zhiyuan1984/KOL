# 员工表面详细契约

> 跨页面硬规则以 `CONSTITUTION.md` 为入口；本文件保留 Home、`/kb`、`/agents`、员工侧栏等详细能力面契约，仅由 `CONTEXT-MANIFEST.md` 按需加载。未被摘要的细节仍有效，但不得与宪法冲突。

员工端与会话工作台的产品级体验法律。日期：2026-09-13；2026-09-14 修订：`/agents` 专家中心（数字员工入口）只回答「找谁协作 / 召唤岗位专家」。同日再修订：Home **内**四模式（今日任务 / 我的待办 / AI发现 / 我跟进的红人），见 ADR-018。同日轻备注：AI发现条件区（NL 主输入、芯片纠正），见 ADR-019。同日再修订：员工知识库 `/kb` 是并列能力面（查找 / 理解适用场景 / 预览 / 收藏 / 用于当前任务），**不是**邮件模板管理台，见 ADR-021。同日再修订：AI发现「加入跟进」与写入主档是同一张确认卡（三模式；成功才跟进），见 ADR-022。同日再修订：产品是智能体中台；十六项一等能力（含技能、数字团队预留）；KOL 只是首个试点，见 ADR-023 / `CONSTITUTION.md` §4.1–4.2。同日和解：Pipeline / 生命周期默认侧栏是 KOL 试点 UX 密度，不是平台硬入口；缺导航不是 P0 / 违约。来源：产品负责人反馈，固化为后续界面取舍的默认立场。

本文件管各能力面的**注意力、信息架构和主路径感觉**。闸门、风险分级和无障碍仍以 `04-ux-ui-system.md` 与 `specs/UX-KOL.md` 为准。视觉与 token 默认见 `design-system/kol-workbench/MASTER.md`。

## 核心闭环语义

```text
Express goal → Agent understands task → Make execution plan → Call system capabilities → Return results.
```

表达目标 → Agent 理解任务 → 做出执行计划 → 调用系统能力 → 返回结果。

会话 / KOL 工作台的任务应能追溯到这条链；具体可见步骤按 `CONSTITUTION.md` 的 L1–L3 风险表压缩展示。界面的工作是让人表达目标、看懂必要的执行状态、确认高影响结果，而不是展开无价值的过程说明。

评审问题时只问：

1. 人是在表达目标，还是在填写后台表单？
2. Agent 是否理解了任务，还是把选择推回给人？
3. 执行计划是否由系统推进，还是要人在卡片之间点「下一步」？
4. 能力调用是否发生在后台，还是被展开成引擎说明书？
5. 回到线程里的是不是可确认的结果 / 草稿，而不是教材？

任一问失败，该改动违约。

## 产品规则

以下规则由 2026-09-13 产品负责人反馈导出，与核心闭环同级。

### 1. Agent 表面，不是管理后台

Session / KOL 工作台必须像在跟一个会干活的 Agent 说话，而不是 SOP 卡片、状态面板、手工模式页签互相抢注意力。

连接器**治理**、Trace、调试开关属于管理端或显式调试视图。员工端可以开始一项工作，但不能把会话变成能力图鉴（技能/连接器使用面仍是一等能力，见 ADR-023）。

### 2. 一条主线程

对话 / 结果是脊柱。阶段漏斗、KOL 身份等上下文是次要辅助条（chrome）：紧凑、可扫视，不是第二本小说。

主窗格里只保留一条阅读路径。身份、阶段、邮箱、等待原因可以常驻，但必须短到不打断结果。

### 3. 禁止教练式「下一步」卡片

删除「下一步：写合作邮件 →」这类教人去点哪个菜单的卡片。Agent 应直接做，或给出可改的草稿 / 结果。

Journey 条可以留作**紧凑定向**，不能再当教练剧本。`04` / `UX-STATE-VISIBLE` 里的「下一步」是等待态操作（停止 / 重试 / 接管）和缺口补全，不是「建议你去打开某某技能」。

### 4. 发送 ≠ 推进阶段

硬产品不变量。只保留一句安静的说明即可，禁止在每张卡上重复横幅。

发送卡不得带阶段选择；阶段写入必须是独立确认，且选择具体 `stage_code`。见 `UX-SEND-NE-STAGE` 与平台不变量。

召唤岗位专家比发送更早：只建立绑定会话 / 协作绑定，**不**发信、**不**写阶段。见「`/agents` 专家中心」下的召唤副作用法律。

### 5. 禁止嵌套滚动地狱

主窗格优先一条纵向滚动。任务卡 / KOL 卡禁止横向滚动。次要面板默认折叠。

横向滚动只允许真正的宽表或显式调试条，不能出现在员工主路径的卡片上。

### 6. 结果优于说明书

优先 `task_result`、草稿和确认动作，而不是 SOP 教科书和「建议下一步」墙。

资料型 Skill 可以回答「这阶段要什么证据」，但默认交付仍是结果卡，不是把课本铺进线程。

### 7. 与已在航运的 P0 对齐

后续改动不得回退这些已经落地的方向：

| P0 | 含义 |
|---|---|
| Home 无横向滚动 | 首页任务 / KOL 卡沿纵向阅读，卡片内禁止 H-scroll |
| 邮件摘要 | 往来用短摘要，不把历史信全文当作主阅读物 |
| 等待态诚实 | 排队、执行中、待确认、失败用词必须与真实状态一致，禁止无状态 spinner |
| Agents 是工作入口（专家中心 / 数字员工） | `/agents` 只回答「找谁协作 / 召唤岗位专家」。不是技能图鉴、不是第二套 Home 待办页、不是连接器目录。Home 独占**平台**任务模式：今日任务 + 我的待办。AI发现 / 我跟进的红人是 **KOL 试点特化**，不是平台一等清单。专家中心 ≠ Home |

## 表面分工（详细契约）

Home、Chat 是员工核心工作表面（任务/会话脊柱）；Pipeline 是 **KOL 试点**工作表面，不是中台壳。Admin 是独立治理域。§4.1 十六项（数字员工、技能、知识库、审批、考试、连接器使用、定时、设置等）是一等能力面——「支撑」只禁止复制 Home / Chat / Pipeline / Admin 的 IA，**不是**二等。每个表面只回答自己的问题；跨表面复制信息架构视为违约。后续 PR 不得把 Home 的四模式、待办语义或任务计数再贴进 Pipeline 或 `/agents` 专家中心。

| 页面 | 角色 | 只回答 | 禁止 |
|---|---|---|---|
| **Home** | 现在做什么 / 等待诚实 | **四个模式**：**今日任务** \| **我的待办** \| **AI发现** \| **我跟进的红人**。对象与改名见下节 | 正式 15 阶段资产板、管理端权限树、平行任务首页 |
| **Pipeline** | **KOL 试点**合作资产页：正式生命周期坐落（页仍存在；**不是**默认侧栏硬入口） | 正式阶段、品牌/负责人、停留、近期事件、同步来源/时间、阶段风险、允许提出的阶段变更 | 首页四模式（今日任务 / 我的待办 / AI发现·线索 / 我跟进的红人）、首页待办桶（需要我处理/等待中）、审批任务、首页任务计数、「帮我处理今天工作」、邮件任务入口、与 Home 相同的等待语义；把本页写成平台默认导航义务 |
| **Chat** | 如何完成一件具体任务 | 表达目标 → 计划 → 能力调用 → 可确认结果；邮件草稿、回复分析、阶段确认卡 | 把 Pipeline 当成第二会话启动器；在资产页批量开新会话 |
| **Admin** | 谁 / 权限 / 审计 | 组织、授权、连接器、Trace、审计 | 员工主路径的待办或生命周期扫视 |

### Home 内四模式

Home 仍是**一页**。平台模式是今日任务 / 我的待办；后两项是 **KOL 试点特化**，不是中台一等清单，也不是第五套脊柱。KOL 试点员工文案顺序：

```text
今日任务 | 我的待办 | AI发现 | 我跟进的红人
```

未指定 `tab` 时默认落在 **今日任务**。员工 Home 禁止 MCP / Codex / Thread / Skill 等引擎行话（`UX-COPY-ENGINE`）。

| 模式 | 只回答 | 主对象 |
|---|---|---|
| **今日任务** | 今天的优先事项（邮件 / 阶段建议、今天推荐预填——即**旧「AI发现」**的任务推荐语义）。只推荐 / 预填，**不**自动执行；待确认需人确认才进「我的待办」 | 今日优先工作项——**不是**红人发现 |
| **我的待办** | 已入队的 Task / WorkItem 队列 | Task·WorkItem（逾期 / 今天到期 / 结果待确认 / 等审批 / 已入队 / 执行中；**仍不含**「后续」历史桶） |
| **AI发现** | 端到端**红人线索发现** | CreatorCandidate（红人线索）——**不是**任务推荐 |
| **我跟进的红人** | 我跟进的合作 | Collaboration。**加入跟进才建 Collaboration**；未跟进的发现线索不是合作 |

**改名（硬约束）：** 旧「AI发现」不得再表示任务推荐 / 今天推荐预填。新「AI发现」不得再表示邮件或阶段建议。Pipeline 与 `/agents` 专家中心不得复制这四模式的语义或对象。Home 拥有任务（今日任务 + 我的待办）；「AI发现」「我跟进的红人」是 **KOL 试点特化**，不是中台壳（ADR-023）。专家中心 ≠ Home（ADR-016）；并列能力面仍解耦（ADR-015）。

#### AI发现条件区

自然语言是**主输入**；平台 / 地区 / 方向芯片只做纠正。生成计划时**以芯片为准**（覆盖 NL 里冲突的平台、地区或方向）。重置条件芯片**不**清空 NL。对象仍是 CreatorCandidate，不是任务推荐；加入跟进才建 Collaboration（ADR-018）。

| 控件 | 规则 |
|---|---|
| **平台** | **单选芯片**。只展示已支持海外平台：YouTube / Instagram / Facebook。**禁止 TikTok**，**禁止「全部平台」**。 |
| **地区** | **单选芯片**。 |
| **方向** | **多选标签，最多 8 个**。 |

海外平台检索用员工能读懂的**实际检索用词**（中文方向会扩成英文，如「户外电源」→ portable power station）。计划卡仍用员工原词。检索完成且 0 条线索时写：「按「portable power station」没有找到线索，可换词再试。」禁止 MCP / MediaCrawler / Job 等引擎行话或参数堆。

不把条件区做成今日任务推荐芯片。不 LIVE。不写引擎行话。细则见 ADR-019。

#### 加入跟进（与主档）

加入跟进支持三种方式：单个加入、勾选后批量加入、按条件批量加入。按条件本期必须同时能筛：粉丝数不少于 N、近 10 条均播放不少于 M、评分不少于 S；平台 / 地区沿用发现计划已有条件，不另做一套。列表里先按条件看，写入前再核一遍。

加入跟进与写入主档是**同一张确认卡**，不是两步。采集完成只产生线索，不自动写入主档、不自动建合作。只有主档回传真实红人编号后，才算已跟进并建立合作；不得用本地假编号当成功。本路径不发信、不改阶段、不编造邮箱、不查看隐藏联系方式。粉丝数门槛在列表预览和写入前复核。细则见 ADR-022。不实施 FE/BE。不 LIVE。

治理域的配套套件（`/admin/connectors` 枢纽与详情、`/admin/agents` 治理、连接器/授权/绑定审计切片）与员工表面的硬边界见 `21-admin-employee-page-roles.md`。员工连接器使用面与知识库、审批、考试、技能等同属一等能力面（ADR-015 / ADR-023），并与 `/agents` 专家中心、今日任务队列解耦。`/agents` 只回答“找谁协作”，不得复制 Home 四模式、待办桶或任务计数。管理端不得复制 Home、Pipeline、Chat、Agents 的开工 IA；`/admin/agents` 只治理发布、授权和考试闸门。

Pipeline 的筛选只允许 `brand|owner|stage|region|kol|sync` 与生命周期旁路/异常侧状态。阶段动作只允许「提出阶段变更」→ 人确认 → 既有 `confirm_stage` 审批/写入；不得在本页发明 LIVE 发送或新权限模型。缺字段用诚实空态，不得伪造近期事件、同步时间或审计。

可执行细则见 `specs/FS-KOL-010-pipeline.md`。与本表冲突时，以本表为准。

## 员工侧栏信息架构

员工工作台左侧栏用于到达核心工作表面与一等能力面，不是目录说明书，也不是第二套操作系统。入口密度是 UX，不得改写宪法位阶（技能可见 ≠ 必须挂侧栏；Pipeline / 生命周期可见 ≠ 必须挂默认侧栏；数字团队未实现 ≠ 永久禁词）。缺 Pipeline 导航不是 P0 / 违约。侧栏改动不得削弱“发送 ≠ 推进阶段”或其他硬产品不变量。

### 逻辑簇，不是可见组标题

侧栏主栈逻辑上仍分簇（今日工作 / 数字员工 / 资产），但**禁止**画出可见的组标题（`.nav-label` 文案，含「今日 / 智能体 / 资产 / 数字员工」）。簇与簇之间只用水平分割线。`<nav>` 保留 `aria-label` 供读屏（中簇读屏名与 `/agents` 的「数字员工」入口对齐，指岗位专家，不是专家团）；不要发明新的可见组标题词。项目 / 最近若仍存在，同样走分割线、不写可见组标题。

### 定时任务属于今日工作簇

`/cron`（定时任务）与「新工作任务 / 进行中」同属今日工作簇，**不是**资产。它回答「今天或按点要跑什么」，不回答「这是哪份可回看对象」。

| 簇 | 员工入口（现行） | 禁止 |
|---|---|---|
| 今日工作 | 新工作任务、进行中、定时任务；确认入口若仍挂在本簇，必须与「审批」同路由，不得再发明第三套确认表面 | 把定时任务画进资产清单；用侧栏复制 Home 待办桶 |
| 数字员工 | `/agents` 专家中心。侧栏入口文案写「数字员工」（岗位专家）。「数字团队」是**独立一等能力、尚未实现**：预留法律地位，本簇不挂假入口，也**不得**把该产品名词永久写成禁词。技能是独立一等能力；是否进侧栏是 UX 密度，不是「员工永远不许看见」 | **专家团**（任何入口、占位或假导航）；把未实现的「数字团队」做成专家团冒名；把技能图鉴塞进本簇压过任务脊柱；Profile / Harness / MCP / Codex chrome；连接器**治理**挤进本簇（见 `21`） |
| 资产 | **一等能力面**：知识库、审批、考试、可选连接器使用面（`/connectors`，Settings 邻接亦可）；明示非本期占位（云盘、遥控、项目等）。Pipeline / 「生命周期」是 **KOL 试点 UX 密度**，不是本簇硬入口；默认侧栏**可以不挂**，缺 Pipeline 导航不是 P0 / 违约 | 把能力面隶属 KOL Agent 或「有进行中任务才出现」；把 Pipeline 写成平台默认侧栏义务或「缺则违约」；把 Pipeline 变成今日待办；把定时任务当资产；把使用面做成治理目录或深链 `/admin/connectors` |

「等我确认」若从今日簇移除，定时任务仍留在剩余的今日块里；确认表面以资产簇的「审批」页为准。本条不授权重做 Admin 导航，也不授权改 Chat 主线程。

### 并列能力面（与 Agent / 任务解耦）

员工工作台的一等能力面包括技能、知识库、审批、考试、连接器使用面、定时/自动化、通知/收件箱、个人设置，以及明示可占位的项目、云盘、手机遥控电脑，以及**预留未实现**的数字团队。它们与数字员工开工入口、今日任务队列相互独立：不隶属 KOL Agent，也不因“有没有进行中任务”才存在。专家中心（`/agents`）不拥有这些面；KOL / 合作对象只可作为其中的数据或示例。Agent 会话可以调用这些能力，但能力面不得复制 Chat 主线程或 Home 待办桶。

这些一等能力面不得升级为平行任务首页，也不得被读成二等「支撑」。员工 `/kb` 的定位、IA、动作分家、CTA 与卡片元数据底线见下一节与 ADR-021。技能与数字团队的页级「只回答」见本节后「预留 / 占位能力（只回答）」。

| 硬规则 | 含义 |
|---|---|
| **能力面主权** | 技能、知识库、审批、考试、连接器使用面、数字团队（预留）、云盘 / 遥控 / 项目等是独立产品面；禁止降级为 Agent 设置或任务详情 Tab。 |
| **数据可进、壳子不出** | KOL / 合作 / 邮件可作为记录类型或示例数据；页面 IA、导航、空态不得改成「先选 Agent / 先开任务」。 |
| **调用单向** | Chat / Agent 可调用已授权连接器、检索知识、提交审批；反向禁止能力面变成第二会话台或第二套今日待办。 |
| **禁止能力图鉴压过任务脊柱** | 技能是一等能力（ADR-023）。侧栏是否露出 = UX 密度，**不是**硬「员工永远不许看见技能」，也**不是**「技能目录不是员工默认入口」的永久禁令。禁止把技能目录做成连接器 / 知识的上级目录，或做成压过任务/会话脊柱的图鉴。`/agents` 是岗位专家召唤入口，不是技能图鉴，也不拥有并列能力面（见 P0、ADR-015）。 |
| **Pipeline 侧栏 ≠ 平台义务** | Pipeline 仍是 KOL 试点页（`FS-KOL-010` 仍有效，本文件不删该页）。是否进默认侧栏 = UX 密度。**禁止**把「缺 Pipeline 导航」写成 P0 / 违约。 |
| **不是平行 Home** | 一等能力面不得复制 Home 的任务模式、待办桶或开工信息架构。「支撑」≠ 二等。 |
| **知识库不是邮件台** | 员工 `/kb` 不得做成邮件模板管理台或启用器；邮件模板只是一类资料。见下节。 |

### 预留 / 占位能力（只回答）

下列与知识库、审批、考试同属宪法 §4.1 一等能力。本表只立法「只回答」，**不实施 UI**，也不因占位而降等。

| 能力 | 只回答 | 禁止 |
|---|---|---|
| **数字团队** | 哪些数字员工组成协作单元、如何编排。法律地位已预留，**尚未实现** | 「专家团」假导航或占位；把本名词永久写成禁词；挂在 `/agents` 冒充已上线 |
| **技能** | 我有哪些可调用技能、如何用于当前任务。一等能力；侧栏露出 = UX | 能力图鉴压过任务脊柱；做成 `/agents` 或连接器/知识的上级目录；把英文 Skill / MCP 摊给员工（`UX-COPY-ENGINE`） |
| **项目** | 这项工作属于哪个项目容器 | 做成第二套 Home 或 Pipeline |
| **云盘** | 文件在哪、如何取用 | 做成治理目录或第二会话台 |
| **手机遥控电脑** | 如何从手机驱动桌面会话 | 做成连接器治理或调试 chrome |
| **定时/自动化** | 今天或按点要跑什么（`/cron`，属今日工作簇） | 画进资产清单；复制 Home 待办桶 |
| **通知/收件箱** | 有哪些要我看的通知 | 做成第二套审批页或第二套 Home |

## 知识库 `/kb`（并列能力面）

员工 `/kb` 属于 ADR-015 并列能力面，**不是**第五套 Home，也**不是**邮件模板管理控制台。产品已裁定：现行员工 `/kb`（「我的知识库 / 知识市场」主 Tab、邮件模板启用/停用、「走 Codex harness」、页头宣讲「发送不等于推进阶段」）**不适合**作为员工知识库。本条立法员工面；发布 / 停用 / 版本 / 范围仍是管理端治理。细则见 ADR-021。

本条只定义详细契约，不直接修改 JSX / API；表面职责以 `CONSTITUTION.md` 为准。

### 只回答

```text
查找 / 理解适用场景 / 预览 / 收藏 / 用于当前任务
```

不是「启停邮件模板」，不是「对本账号隐藏」治理台，也不是从本页发信或改阶段。

### 员工 `/kb` 禁止

| 禁止 | 原因 |
|---|---|
| Codex / Harness / MCP / Thread / Skill 等引擎行话 | `UX-COPY-ENGINE`。现行「启用后走 Codex harness」违约 |
| 在 KB 首页 / 页头 / chrome 宣讲「发送 ≠ 改阶段」 | 该不变量仍有效（本文件 §4、`UX-SEND-NE-STAGE`），但不在知识库说教；KB 不是布道页 |
| 把整库做成邮件模板管理台 | 邮件模板只是一类资料，不是整库 IA |
| 主 CTA 做成启用 / 停用 / 发布 / 隐藏 | 治理在管理端；隐藏若残留只许次要偏好 |
| 从 KB 应用动作发信或写阶段 | 应用只产未发送草稿 |
| 升格为平行任务首页 | 保持为职责明确的一等能力面（不是二等「支撑」） |

### 员工 IA（Tab / 筛选，顺序锁定）

```text
全部资料 | KOL合作SOP | 邮件模板 | 品牌与产品 | 报价与谈判 | 最近使用
```

「邮件模板」是其中一类，不得再当整库的信息架构（现行「邮件模板 / 口径与其它」+「我的知识库 / 知识市场」主 Tab 违约）。不要用「我的知识库 / 知识市场」定义员工主 IA。KOL / 合作对象只作资料里的数据或示例，不得改写本面 IA（ADR-015）。「最近使用」是最近打开/应用过的资料筛选，不是 Home 待办桶。

### 动作分家

| 端 | 主动作 | 禁止当成该端主路径 |
|---|---|---|
| **员工** | **查看** / **收藏** / **用于当前任务** | 停用、发布、版本管理、范围编辑 |
| **管理** | **停用** / **发布** / **版本** / **范围**（治理） | 把治理按钮抄进员工卡主 CTA |

若员工面仍保留「隐藏」：只许降为**次要偏好**（本账号少看见），不得当主治理动作，也不得与管理端停用 / 下线混读。

「收藏」是员工个人偏好，不是发布，也不是「启用到本账号才会带进 Codex」。

### CTA 改名与副作用

员工主 CTA：**「用于当前任务」**（取代「用这份写信」）。

副作用只能是：把该条资料作为**未发送草稿**填入**当前任务 / composer**。邮件类对齐已合并的 #75「正文进框」：填入组信正文，可改后再发。禁止：从 KB 应用动作发送邮件；从 KB 应用动作写入或推进阶段。

「发送 ≠ 推进阶段」仍然有效；KB 应用比发送更早，必须两都不做——只是不要把这句话写在 KB 首页。

### 卡片元数据底线（有数据才展示）

每张卡在数据存在时必须能展示：

```text
适用品牌 / 区域 / 阶段 / 场景
版本
生效
来源
已发布
```

缺字段用诚实省略，不得伪造。用词对齐 `14` 知识库契约的 `brand_scope`、`region_scope`、版本、来源、`effective_from/to`（生效窗口）。**本条不要求本 PR 做 schema 迁移**——先立法 UX 底线，后端可后补字段。

## `/agents` 专家中心（数字员工入口）

`/agents` 是员工一等能力面「数字员工」，员工称呼为“数字员工”或专家中心。它只回答“找谁协作 / 召唤哪位岗位专家”。它不是技能目录、平行 Home、连接器目录，也不是「数字团队」页。

内部对象可以叫 Expert 或 Agent；员工可见文案只用「数字员工」或「岗位专家」。本条只立法，不实施 ExpertManifest API，也不改数字员工对象模型 schema。

### 与 Home、并列能力面的边界

| 表面 | 只回答 | 专家中心禁止复制 |
|---|---|---|
| **Home** | 现在做什么 / 等待诚实。平台模式：今日任务 + 我的待办。KOL 试点另挂 AI发现（CreatorCandidate 线索）+ 我跟进的红人 | 待办桶、任务计数、今日任务预填、「今天推荐」启动器、红人线索漏斗、跟进列表 |
| **专家中心 `/agents`** | 找谁协作 / 召唤已发布岗位专家 | 技能图鉴、连接器状态、Home 四模式（含待办与线索） |
| **并列能力面** | 技能 / 知识库 / 审批 / 考试 / 连接器使用面 / 数字团队（预留）等（ADR-015 / ADR-023） | 把这些面收进专家中心或做成专家下级目录 |
| **Chat** | 如何完成一件已绑定的具体任务 | 把专家中心做成第二会话台 |

召唤之后的具体干活仍走 Chat（核心闭环）。Home 仍独占平台任务（今日任务 + 我的待办）；AI发现（线索）与「我跟进的红人」是 KOL 试点特化，也只在 Home，不在专家中心。

### 员工默认表面（硬禁止）

默认员工 `/agents`（以及侧栏等与数字员工相关的员工 chrome）：

| 必须显示 | 禁止显示 |
|---|---|
| 已发布、可供召唤 / 协作的**岗位专家** | Profile 内部、Harness、MCP、Codex |
| | 把技能图鉴 / Skill picker 做成专家中心主 IA |
| | 连接器状态 / connector pills 作为主 IA |
| | **专家团**（无入口、无占位、无假导航） |
| | 把未实现的「数字团队」做成专家团冒名或挂在本页 |
| | Home 待办桶、任务计数或四模式（今日任务 / 线索 / 跟进） |

引擎行话仍按 `UX-COPY-ENGINE` 禁止（MCP / Codex / Thread / 英文 Skill / 原始堆栈）。产品名词「技能」是一等能力，与引擎词 Skill 分家：员工可以有独立技能面；禁止把图鉴塞进 `/agents` 或压过任务脊柱。侧栏是否露出技能入口是 UX 密度，不是本页硬隐藏令。本条不强制本轮加侧栏入口，也不实施技能面 UI。

### 召唤副作用法律

召唤一位岗位专家**只**建立绑定会话 / 协作绑定。禁止：

- 发送邮件（无 send-mail 副作用）
- 写入或推进阶段（无 stage-change 副作用）

「发送 ≠ 推进阶段」仍然有效。召唤更早：它既不是发送，也不是阶段写入。后续若要发信或改阶段，必须走既有独立确认卡（`UX-SEND-NE-STAGE`）。

### 对象命名与页面位阶

| 层 | 用词 |
|---|---|
| 内部 / 规范 / API（后续实现） | Expert 或 Agent 均可 |
| 员工可见文案 | 「数字员工」或「岗位专家」 |
| 侧栏入口 | 「数字员工」。禁止「专家团」。「数字团队」是另一等能力的预留名词，不是本入口的别名，也不是永久禁词 |
| 页面位阶 | `/agents` 是一等能力面「数字员工」，只负责寻找和召唤岗位专家，不复制 Home，不冒充数字团队 |

不要把“数字员工”做成平行任务首页，也不要复制 Home、Pipeline、Chat 或 Admin 的职责。

## 非目标

- 本宪法本身不实施 `Chat.tsx` 重设计；没有单独的「宪法合规」UI PR。
- 不废止 `04-ux-ui-system.md` 的 L1–L3、双端边界、无障碍和 UX ID。
- 不把 SOP Skill、阶段机或管理端 Trace 删掉；只禁止它们占领员工主表面。
- 不把「建议 / 预填」升级成自动执行。首页「今日任务」推荐、芯片和快捷入口仍只锁定 / 预填，不绕过权限、审批和状态机。新「AI发现」是线索发现，不是把推荐自动写成 Task。
- Home 四模式仍在 Home 内；其中「AI发现」「我跟进的红人」是 KOL 试点特化，不是中台壳。一等能力面不得复制 Home。不把旧“AI发现”任务推荐语义留在新“AI发现”上，不在发现阶段自动建 Collaboration。
- 不为体验层再写一套调度器、状态机或 Host 旁路。
- Pipeline 不得再复制 Home 四模式、待办桶、任务芯片或 Chat 技能快捷入口；会话页重构仍须先符合本宪法。
- 一等能力面不是第五套 Home；不削弱核心闭环、发送 ≠ 推进阶段、无可见侧栏组标题；不改连接器使用面 vs 治理面。
- 本修订不实施 ExpertManifest / 数字员工 API，不改前端或后端；只定义后续实现契约。不削弱宪法表面职责、能力主权（ADR-015）或连接器使用面 vs 治理面。Home 四模式和 AI 发现条件同样只定义契约，不代表 FE/BE 已实施或 LIVE。
- ADR-023 不实施数字团队 UI，不强制把技能加进员工侧栏，不改 `kol-workbench` 设计系统路径名。禁止专家团假导航；预留「数字团队」名词与一等位阶。本和解不删除 Pipeline 页或 `FS-KOL-010`，也不把 Pipeline 默认侧栏写成平台义务。
- 员工 `/kb`（ADR-021）只立法：不实施 FE/BE/CSS，不 LIVE，不新增 UX ID，不迁知识 schema，不扩张组织权限或审批系统。不把 KB 做成第五套 Home 或邮件模板管理台。不在 KB 首页宣讲「发送 ≠ 改阶段」（不变量仍有效，只是不在本页说教）。不削弱 ADR-015 / 016 / 018 / 019 / 020。
- AI发现加入跟进（ADR-022）只立法：不实施 FE/BE，不 LIVE，不在跟进时改阶段或发信。不把采集完成写成自动入主档。条件批量本期全开（粉丝 / 近10均播 / 评分 / 平台 / 地区）；平台 / 地区不另造控件。不削弱 ADR-018 / 019、发送 ≠ 推进阶段、Collaboration-on-follow-only。

| 允许 | 禁止 |

| 线程里出现草稿、`task_result`、确认 / 拒绝 | 「建议下一步」墙、菜单教练卡、说明书式 SOP 长文 |

## 落地顺序

1. 新员工端 PR 先用“核心闭环”五问自检，再读取 `CONSTITUTION.md` §4.1–4.2 与 `design-system/kol-workbench/MASTER.md`（路径是试点皮肤名，不是产品身份）。`/agents` 先过本文件专家中心条款（只召唤岗位专家；无专家团；不把「数字团队」做成假导航；召唤不发信、不写阶段）。技能面先过「一等能力；入口密度=UX；禁止图鉴压过任务脊柱」。员工 `/kb` 先过本文件知识库条款（查找/预览/收藏/用于当前任务；非邮件台；无引擎行话；应用不发信不写阶段）。管理端导航/连接器/Agent 治理先过 `21-admin-employee-page-roles.md`，再谈视觉。
2. 可执行验收仍走 `specs/UX-KOL.md` 与 `specs/ux-traceability.json`；本文件不新增 UX ID。
3. 会话页若重设计，先压缩辅助条、去掉教练卡、让结果回到脊柱，再考虑新组件。
4. 冲突写入 `DECISIONS.md`，不要在前端分支里另立一套体验规则。
