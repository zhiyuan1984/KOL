# UX：豆包工作台的推荐任务

**角色**：产品 / UX  
**依据**（冲突时从上到下）：`docs/灵工-Agent中台开发规范.md` → `docs/codex-KOL-编码规范.md` → `docs/remote-mcp-sop-agents-plan.md`。  
**对齐**：豆包 B 端「工作」首页——先问今天做什么，再给可点的下一步；不把人丢进空聊天。  
**原则**：推荐是建议，不是执行。点推荐 = 预填对话。AI 发现不会自动变成待办。发送 ≠ 改阶段。推荐文案与缺口是 **已发布 Skill 的契约**，由 Codex app-server 按 Skill 产出，不是后端 Host 目录。员工端不出现 MCP / Codex / 线程字样。
**配套**：邮件往来见 `docs/UX-邮件闭环.md`。本文只写「系统把下一步递到眼前」。

---

## 0. 运营打开首页时发生什么（一句话）

运营看到「今天有什么工作要处理？」和今天的待办数字。默认主视图不再铺卡片，而是一份和会话过程同款的 **图标 Markdown 清单**：**今天推荐** 用 1、2、3… 标任务 id（最多 8 条）。真正要做的下一步还有三条旁路：**任务模板**（目录里的技能）、**AI发现**（系统注意到的信号，仍在自己的 Tab）、**会话芯片 / 结果卡建议下一步**。全部只预填，不自己跑、不自己发信、不自己改阶段。

---

## 1. 「推荐任务」是什么、不是什么

灵工工作台对标豆包工作：弱化纯聊天，强化「点一条推荐就开始干」。产品里有五类容易混叫「推荐」的东西，界面语言必须分开。

| 名称 | 出现在哪 | 运营看见什么 | 点了之后 | 不是 |
| --- | --- | --- | --- | --- |
| **今天推荐** | 首页默认「我的待办」主视图 | 图标 Markdown 清单，数字 id 1–8 | 预填首页输入框，**不立刻开跑** | 不是卡片，不是已确认的待办 |
| **任务模板** | 首页 Hero 旁「任务模板」→ 侧栏「全部工作」 | 按线索 / 商机 / 谈判 / 履约 / 增长 / 管理 / 异常分组的技能卡 | 预填首页输入框，**不立刻开跑** | 不是待办，也不是 AI 自己找出来的事 |
| **AI发现** | 首页 Tab「AI发现」 | 系统先放在这里的信号卡，带「AI发现」标签 | 「转为我的待办」才进待办；「查看沟通记录」进会话；「忽略」消失 | 不是已经承诺要做的工作 |
| **下一步芯片** | KOL 常驻会话的 composer 上方 | 最多 **3** 颗胶囊按钮 | 预填本会话输入框并锁技能 | 不是目录，不是「下一阶段」口令 |
| **建议下一步** | 右侧结果卡底部 | 「建议下一步」列表 | 预填本会话输入框，或跳到站内链接 | 不是确认发送、不是确认阶段 |
| **缺口提示** | 输入框 placeholder + 未发送结果的第一颗芯片 | 与结果页缺字段同一句话（报价「金额 [USD]」） | 预填补缺口口令，**不锁**新技能 | 不是确认发送；契约在写合作邮件 Skill |

另外两处容易被当成推荐、但**不是任务**：

- 红人卡第五栏 **「建议进入阶段」**：只展示具体正式阶段名（如「已回复-有兴趣」），禁止写「下一阶段」。点卡进会话或预填画像，不因这一栏改库。
- 技能页 **「特别推荐」**：技能目录里的磁贴，点「使用」走技能，不是首页工作流。

## 2. 入口的界面与点击

### 2.0 首页 · 今天推荐（图标 Markdown，不是卡片）

**位置**：Hero 问句和 Tab 行下方，默认「我的待办」主视图的第一块。始终露出，数据空时用任务模板补齐，禁止整块卸载。

旧的推荐边框卡、待办卡（`.todo-card` / `.recommended-task`）从默认主视图消失。已确认的待办改成同一套 Markdown 清单，放在推荐下面，标题 **我的待办**。AI发现 Tab、生命周期五栏卡、任务模板抽屉仍保留各自形态（确认 / 忽略需要按钮）。

**形态**（与会话 `process_trace` 同款：加粗标题 + 图标行，不用卡片描边）：

```
**今天推荐**

1. ✉️ 给停留 12 天的 @小美妆日记 写跟进
   停留 12 天未回 · AI发现
2. ○ 先给 @户外充电君 补画像
   尚未进入生命周期 · 按阶段
3. 💬 回复分析
   先粘贴达人回复 · 任务模板
```

| 区块 | 规则 |
| --- | --- |
| 任务 id | 展示序号 **1, 2, 3…**，不是 `tsk_…` / `rec-mail-…`。点「推荐 1」= 第 1 条 |
| 图标 | 写邮件 ✉️ / 回复 💬 / 画像 👤 / 记状态 📍 / 风险 ⚠ / 纪要 📝 / 发现 🔎 / 今日任务 📋；对不上则 ○ |
| 标题 | 情境句，带 `@红人`；目录补齐项用技能中文名 |
| 原因行 | `{人话原因} · {按阶段 / AI发现 / 任务模板}` |
| 条数 | 情境排完后用任务模板补到 **最多 8 条**。3 条不够扫完今天的工作 |
| 点击 | 与任务模板相同：预填 + 锁技能芯片 + 500ms 挡住误触发送。**不跑箱、不改阶段** |
| 空数据 | 星空未绑定、看板没有红人时，仍然露出 1–8 条目录项（写合作邮件、回复分析、达人画像…） |

不做：把推荐画成边框卡、默认主视图只露 3 条、推荐为空就整块 `return null`、点序号即执行。

会话芯片仍最多 3 颗，不受这条清单条数影响。

### 2.1 首页 · 任务模板（对标豆包首页技能卡）

**位置**：Hero 问句下方，Tab 行最右一颗文字链「任务模板」。不占默认主视图。默认主视图是「今天推荐」Markdown。

点开后出现右侧抽屉「全部工作」，两个 Tab：

1. **今日任务**：当前用户全部 `work_items`，可筛全部 / 待处理 / 高优先级 / ✦ AI发现，可按优先级、截止、进度排序。
2. **任务模板**：`GET /api/home` 的 `recs`，与技能目录一一对应，全部 `act=ask`。

每张模板卡：

```
┌─────────────────────────────┐
│ 写合作邮件                 → │
│ 在会话中分析并生成结果        │
└─────────────────────────────┘
```

- 标题 = Skill 中文名；副文 = 描述，没有描述时用 Profile 名或「在会话中分析并生成结果」。
- 未授权：卡半透明、不可点，右下「未授权」。点了会在首页出一句：「“××”尚未授权，请联系管理员在技能授权中开通。」
- 悬停：边框变星蓝，背景浅灰。

**点击路径（必须预填，禁止直接跑箱）**

1. 输入框填入该技能的 starter（写类技能带 `[占位符]`，读类技能就是目录标题）。
2. 输入框上方锁一颗技能芯片（技能名，可叉掉）。
3. 抽屉关闭，输入框聚焦，选中第一处占位符，方便直接改。
4. 500ms 内挡住误触发送，避免「点模板 = 立刻开跑」。
5. 运营改完（或不改）按发送，才开 `/s/:id`。

**例外**：已建联红人会话里 `/` 点「写合作邮件」会先把这一封英文草稿填进输入框（报价写成 USD n per hour，不要套餐总价）。芯片、首页模板、今天推荐仍只预填。见 `docs/UX-邮件闭环.md`。

空态不适用于模板目录：目录始终按分类铺开。今日任务空态：「今天还没有任务 / 试试描述你想完成的工作。」

### 2.2 首页 · AI发现（对标豆包「系统替你盯着」）

**位置**：Hero 下第二个 Tab「AI发现 N」。有高价值发现时，Tab 上出现红点（高优先、紧急、有风险、失败）。

卡片结构：

```
失联跟进                              AI发现  高价值
@小美妆日记 · 初步接触
AI发现 · 停留 12 天未回，建议跟进

[转为我的待办]  [查看沟通记录]  [忽略]
```

| 区块 | 规则 |
| --- | --- |
| 标题 | 任务标题 |
| 标签 | 一律「AI发现」；高优先 / 紧急 / 有风险 / 失败再加红色「高价值」 |
| 对象行 | `@红人 · 所处阶段`，没有则省略 |
| 原因行 | `AI发现 · {风险 / 描述 / 上下文 / 历史 / 截止}` |
| 主按钮 | **转为我的待办** → 写入 `promoted_at`，切回「我的待办」，计数 +1 |
| 次按钮 | **查看沟通记录** → 已有会话则进该会话；有合作则打开该红人常驻会话；否则才 `run` |
| 忽略 | 写入 `dismissed_at`，卡消失，不进待办 |

**硬规则**：`source=ai` 且未确认、未忽略、未关闭的任务，**只出现在 AI发现**。待办空态必须写清：「AI 发现不会自动变成待办。确认后才会出现在这里。」

AI发现空态：「暂时没有新的发现 / 系统注意到的信号会先停在这里，确认后才进入我的待办。」

高价值卡底边略偏红，方便扫一眼，不做警报弹窗。

### 2.3 会话 · 下一步芯片（对标豆包输入框上方建议）

**出现条件**：这是一条 KOL 常驻会话，且顶部已经展开本阶段 SOP。芯片画在 SOP「怎么问」那一格的 composer **上方**。普通空会话（没有 SOP）不画芯片，避免把目录塞进每一条闲聊。

最多 **3** 颗。文案是技能短名，不是整句 prompt。

按当前正式阶段取优先级（异常优先风险扫描）。**第一颗邮件芯片是这一阶段的信**，不是永远「写合作邮件」：

| 当前阶段 | 三颗芯片（顺序） |
| --- | --- |
| 初步接触 | 写合作邮件 · 回复分析 · 记状态 |
| 已回复-有兴趣 | 回复分析 · 写跟进 · 记状态 |
| 合作评估 | 要媒体包 · 记状态 · 回复分析 |
| 报价待确认 | 写报价邮件 · 记状态 · 回复分析 |
| 商务谈判 | 写谈判邮件 · 记状态 · 回复分析（可插入谈判纪要） |
| 待寄样 | 核对地址 · 记状态 · 回复分析 |
| 已发货 | 发货通知 · 记状态 · 回复分析 |
| 已签收-测试中 / 内容策划 | 催大纲或发brief · 记状态 · 回复分析 |
| 异常旁路 | 风险扫描 · 记状态 · 回复分析 |
| 其他主流程 | 该阶段那封信 · 记状态 · 回复分析 |

点芯片：

1. 输入框换成带 `@红人` 的完整口令，例如 `写合作邮件 @Wendell Fishing`。
2. 锁对应技能芯片。
3. **不提交**。运营还可以改、补知识、换附件，再发送。

视觉：浅紫底、紫边圆角胶囊，字色星蓝。禁用态（会话正在跑）半透明。

### 2.4 右侧结果卡 · 建议下一步

结果卡（`task_result_card`）底部固定一节 **「建议下一步」**。条目来自 Skill 产出的 `recommended_actions`。

- 有 `href`：站内链接（例如去生命周期）。
- 没有：按钮，把文案预填回中间输入框。只预填，不执行。
- 邮件草稿 / 已发送卡会洗掉「补全发件 / 记状态 / 费用审批 / 提出阶段变更」这类会把人带偏的项。草稿默认留下「核对预览后回复「确认发送」」；已发送默认「再写一封」。

回复分析等只读技能把可点口令写进 `recommended_actions`（「写合作邮件 …」「提出阶段变更 …」），明确禁止在这一步 send / 写阶段 / 企微。

采集结果卡上的「推荐」按钮是另一条旁路：预填 `基于创作者 {id} 创建合作推荐任务`，仍只进输入框。

## 3. 和待办、生命周期怎么分工

豆包工作把「今天该干的」和「系统觉得你可以干的」拆开。灵工同样拆三栏 Tab：

```
我的待办 N     AI发现 N●     生命周期     任务模板
     │              │            │
     │              │            └─ 看谁卡在哪（五栏卡，含建议进入阶段）
     │              └─ 系统信号，等人认领
     └─ 人已经认领或人手建的工作
```

**待办**按逾期 / 今天到期 / 等待中 / 后续分组，但默认主视图用 Markdown 行而不是卡片。每行：状态标、标题、`@红人 · 紧急度 · 原因`。点击整行等同原来的 **立即处理**。

立即处理：有会话进会话；有合作打开该红人会话；否则才创建并跑任务。缺字段时停在首页澄清，不起箱。

**生命周期**不是推荐任务列表。17 个阶段 Tab 只显示短名 + 人数。每张红人卡固定五栏：KOL 名称 / 合作摘要 / 最近跟进 / 所处阶段 / **建议进入阶段**。已建联点进该红人会话；未建联预填 `达人画像 {handle}`，不进生命周期页。

Hero 统计只报待办数字：`N项待处理 · N逾期 · N今天到期 · N等待中`。AI发现人数只在自己的 Tab 上，不写进这行，避免「待办被 AI 灌满」。

## 4. 推荐怎么来（产品定义，不是算法黑盒）

| 入口 | 数据从哪来 | 人能不能改规则 |
| --- | --- | --- |
| 今天推荐 | 未读来信 → 未确认 AI 信号 → 未建联 / 异常 / 停留≥7 天 → 其余红人；不足 8 条用任务模板补齐；条目标 `n` + `icon` | 不能在员工端改排序 |
| 任务模板 | 已发布 Skill 目录；管理员授权决定能不能点 | 授权在管理端；员工端不能改目录 |
| AI发现 | `work_items.source=ai`，且没有 `promoted_at` / `dismissed_at` / 完成 | 人只能确认或忽略，不能在员工端改生成规则 |
| 下一步芯片 | 当前合作的正式 `stage_code`：第一颗是 **这一阶段要写的那封信**（写合作邮件 / 写跟进 / 写报价邮件 / 核对地址…），仍锁 `email_compose`；最多 3 条。未发送结果缺金额/运单/地址时，第一颗改成补缺口且不锁技能 | 不能用聊天口令换一套芯片 |
| 建议下一步 | 当前这条 Skill 结果的 `recommended_actions`；邮件卡与写合作邮件 Skill 的缺口同一份 | Skill 契约规定；不得另写一套 Host 推荐表 |

所有推荐的 **act 都是 `ask`**。禁止 `go`（点一下就跳走执行）。自由文本识别任务时，低置信度只出澄清选项，不假装成推荐任务。

## 5. 已落地与仍缺

首页 Hero 下会露出 **今天推荐** 图标 Markdown 清单（1–8 条，带任务序号）。点行只预填，不跑箱。旧推荐卡 / 待办卡从默认主视图消失。AI 发现仍不会自动变成待办。

| 场景 | 现状 |
| --- | --- |
| 刚打开首页 | Hero 下方露出 **今天推荐** Markdown（例如 `1. ✉️ 给停留 12 天的 @小美妆日记 写跟进`），来源打标「按阶段」「AI发现」或「任务模板」；点法与模板相同：预填，不跑 |
| 看板没有红人 | 清单不会消失，用任务模板补到最多 8 条 |
| 待办为空 | 推荐下方只留一句「AI 发现不会自动变成待办」 |
| 新邮件进来 | 未读来信会出现在推荐清单（「@红人 回复 · 待判断」）。**尚未**自动写入 AI发现 Tab 的 work_item |
| 会话芯片 | KOL 常驻会话 SOP 输入框上方最多 3 颗；无 SOP 时钉在底部输入框上方；跑箱时禁用但不消失 |
| 为什么推荐 | 每条有一行人话原因（停留天数、来信摘要、风险） |
| 点完模板 / 推荐 | 人还要按发送。**不要**点行即跑箱 |

不做：独立「推荐中心」页面、超过 3 条的会话芯片墙、把建议进入阶段做成可点的「下一阶段」按钮、把首页推荐再画回卡片。

## 6. 交互状态与文案

| 状态 | 界面 |
| --- | --- |
| 模板未授权 | 卡 disabled + 「未授权」；错误句带技能中文名 |
| 模板已点、输入框已填 | 技能芯片可叉；叉掉后变回自由文本 |
| AI发现未确认 | 只在 AI发现 Tab |
| AI发现已确认 | 出现在我的待办，带「AI发现 · …」原因；AI发现列表里消失 |
| AI发现已忽略 | 两边都不出现 |
| 会话正在跑 | 芯片 disabled |
| 结果卡没有建议 | 不画「建议下一步」空标题 |
| 缺字段 | 首页出澄清，任务停在 `needs_clarification`，推荐行不当成已开始 |

禁止文案：

- 「下一阶段」（必须是具体 `stage_code` 中文名）
- 「已自动加入待办」
- 员工端出现 MCP / Codex / 线程 / Host 等引擎词（模板 hint 里的 `ask · Skill · Codex` 只走 API，不渲染）

## 7. 反模式（评审必拦）

1. 点任务模板 / 芯片 / 建议下一步直接 `run` 或发信。
2. AI发现未点「转为我的待办」就出现在我的待办。
3. 会话芯片超过 3 颗，或把整份技能目录铺在输入框上。
4. 推荐文案写成「下一阶段」或「自动进入 XX」。
5. 未授权技能仍可点、失败只在点发送后才说。
6. 把「建议进入阶段」做成会写库的按钮。
7. 员工端推荐卡上画 Skill 时序、MCP 名、原始堆栈。
8. 用 Toast 代替清单：推荐必须落在编号 Markdown 或芯片上，能回看。不要把首页推荐再做成边框卡。
9. 把采集卡「推荐」理解成改阶段或建正式合作（它只预填一句话）。
10. 为推荐再造一套跳过 Skill 的旁路 API。

## 8. 验收句式

1. 打开首页，默认 Tab 是我的待办；主视图是 **今天推荐** Markdown，能看到 `1.` `2.` `3.` 和技能图标；没有 `.todo-card` / `.recommended-task` 边框卡。AI 来源且未确认的任务不在待办里出现。
2. 点「任务模板」能看到与目录一致的分组卡；点一张后输入框有 starter 和技能芯片，**地址栏仍是首页**，没有新会话。
3. 未授权模板不可点，并出现带书名号的授权说明。
4. AI发现高价值时 Tab 有红点；点「转为我的待办」后待办计数 +1，该卡从 AI发现消失。
5. 打开已建联红人会话，SOP 下最多 3 颗芯片；初步接触点「写合作邮件」后输入框为 `写合作邮件 @{handle}`；报价待确认默认提示是 `写报价邮件 @{handle} 金额 [USD]`，点「写报价邮件」后为 `写报价邮件 @{handle}`。不写金额出结果后，第一颗芯片变成「补上金额」。会话未新开、未发信。同一会话 `/` 点「写合作邮件」后输入框是英文草稿。
6. 回复分析结果卡「建议下一步」可点进预填；点完阶段仍不变。
7. 红人卡「建议进入阶段」是具体阶段名；未建联为「初步接触」，异常为「需人选回到主流程」或「无需推进」。
8. 员工端任何推荐面上都不出现 MCP / Codex / 线程字样。

**怎么验**：与生产同一条链路——已发布 Skill、真实 Codex app-server、授权远程 MCP。`CODEX_MODE=stub`、import 后端 Host 函数 **不算** 本需求验收。

推荐文案以各 Skill 的 `recommended_actions` 与缺口表为准，不要再维护一套 Host `STAGE_REC_INTENT`。
