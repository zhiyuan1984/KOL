# 任务中心视觉评审与整改建议

**评审日期**：2026-10-07  
**评审对象**：任务中心的 Agent／系统任务运营报表、业务工单空态、任务明细表与新建业务任务抽屉  
**评审依据**：`docs/DESIGN.md` v3、当前实现、已提供的四张生产截图  
**改造模式**：**Redesign · Preserve** —— 保持路由、数据口径、任务／工单功能与现有品牌 token，不重写信息架构；将页面统一回 `data-grid` 密度档。

> 结论：当前页面功能已可用，但视觉密度、表格列预算与空态策略没有满足 `DESIGN.md`。应做一次定向的结构性收敛，而不是继续叠加局部 CSS。

---

## 1. 设计读法与边界

```yaml
Design Read:
  artifact: 任务运营数据面（报表 + 任务表 + 业务工单）
  audience: 需要快速判断任务负载、失败与待处理事项的员工
  visual-language: 克制的中台 data-grid；汇总条 + 明细表，不是营销页或卡片墙
  mode: redesign-preserve
  visual-variance: 2/10
  motion-intensity: 1/10
  information-density: 9/10
  asset-dependence: 0/10
  brand-fidelity: 10/10
```

### 必须保留

- Agent／系统任务与业务工单的数据边界及各自接口。
- 周期切换、搜索、状态筛选、KPI 下钻、详情展开、CSV 导出、新建业务任务流程。
- 当前颜色职责：品牌粉只做本视口唯一 L1；蓝色只做选中态和 L3 文字操作；红/黄/绿只做状态。
- 当前数据真实性：零业务工单必须诚实显示为零，不能用假数据填充。

### 必须改进

- 统一为 `data-grid` 密度档：表头 36px、默认表格行 44px、仅含双行对象时 52px。
- 让空数据**收起**，而不是用大面积虚线容器或保留无内容的表格骨架。
- 使列预算、文本截断和动作位满足 `DESIGN.md §9.1`。
- 将抽屉表单改回 `dialog-compact` 的紧凑字段节奏。

## 2. 设计评审

### 总分：**4.3 / 10 · 需要整改**

| 维度 | 评分 | 评审结论 |
|---|---:|---|
| 规范一致性 | 3/10 | 页面同时出现 data-grid、放大标题、营销式空态和宽松表单四种密度，违背 `DESIGN.md §2` 的单视口密度一致性。 |
| 视觉层级 | 4/10 | 表格、业务工单空态和报表子表都获得相近视觉权重；用户难以优先判断“现在该处理什么”。 |
| 工艺质量 | 4/10 | 结果摘要列被压至逐字换行；长标题撑高多行；抽屉表单控件明显大于规范；空白区域没有承担阅读节奏。 |
| 功能表达 | 6/10 | 搜索、周期、筛选、状态和详情仍可理解；但零数据区域、重复入口和低效列占用了任务列表的工作空间。 |
| 原创性 | 4/10 | 视觉上新增了渐变、英文大写眉题和大面积空态，但这些元素没有服务于中台数据面，反而稀释了既有系统语言。 |

### 应保留的优点

- Agent／系统任务与业务工单已在数据和文案层面区分，避免混淆口径。
- 状态仍有文字标签，不仅依赖颜色；符合无障碍的基本方向。
- 周期与 KPI／状态筛选的下钻关系是正确的，应保留并做得更紧凑。
- 详情继续使用右侧抽屉，而不是重新引入大弹窗。

## 3. 问题与整改方案（按严重度）

### 1. 页面没有按 `data-grid` 收敛 —— ⚠️ 关键

**现状**

- 任务类型分布在没有可展示内容时仍留下标题、表头和大片无内容区域。
- “尚无业务任务或标准工单”被渲染为大面积虚线空态卡，正文与操作之间留白过多。
- 页面把报表、业务工单、任务明细都包装为同等权重的完整 Panel，使真实任务表被挤到视口下方。

**为什么不符合规范**

- `DESIGN.md §2` 指定该场景为 `data-grid`，强调“一屏内行数优先于留白”。
- `§8.3` 要求零数据不渲染；`§9.3` 要求空态紧凑、左对齐、动作内联，禁止 hero 空态。

**整改**

1. 运营区保留一个紧凑汇总面：状态分布条 + KPI 行；任务类型表仅在存在类型数据时出现。
2. 若任务类型为 0，隐藏整张表，仅在汇总面末行显示：`当前周期暂无可归类的任务。`，不保留表头和表格高度。
3. 若业务工单为 0，业务区收缩为一条 44px 的辅助行：
   - `业务工单 0 · 暂无标准工单`；
   - 同行 L3：`新建业务任务`；
   - 导出入口在无数据时隐藏。
4. 业务工单有数据时才展开为：一行 4 项汇总 + 模板表；不再另造大面积虚线卡。

---

### 2. 明细表的列预算失控，导致“结果摘要”逐字换行 —— ⚠️ 关键

**现状**

- 生产截图中“结果摘要”只有约一个汉字宽度，标题被逐字纵向折行。
- 长任务标题直接撑到三至四行，单条记录占用约两到三倍的标准行高。
- 现有表格既保留了宽的“类型”“操作”列，也保留了结果摘要列和展开按钮列；固定列占用过多，挤压内容列。

**为什么不符合规范**

- `DESIGN.md §9.1`：默认行高 44px，长文本应单行截断；需要阅读的信息进入展开行。
- 同节规定：操作列固定为单操作 72px、双操作 124px、更多操作收纳；固定列总和不得挤压主要内容列。

**整改**

采用以下桌面列模型（1440px 基准）：

| 列 | 宽度策略 | 处理方式 |
|---|---|---|
| 选择 | 32px | 仅可批量操作状态显示 |
| 类型 | 80px | `Agent` / `业务` 文字徽章，不扩展 |
| 任务名 | `minmax(280px, 1fr)` | 单行省略；完整标题保留 `title`；点击展开后显示完整内容 |
| 状态 | 88px | 文案 + 状态形状，禁止只靠颜色 |
| 更新时间 | 112px | 等宽数字、单行 |
| 操作 | 124px | 最多两个 L3 文字操作；其余进入“更多” |
| 展开 | 32px | 仅图标、焦点态清晰 |

- **移除主表“结果摘要”列**：摘要进入展开行（与技能、创建时间同层），避免无内容的列消耗宽度。
- 长任务名不再使主行变高；只有用户点击展开才显示完整标题、摘要、技能和时间。
- 表头固定，表体独立滚动；默认 44px，实际有二级信息的展开行才用 52px。

---

### 3. 信息层级重复，且主行动不明确 —— ⚡ 重要

**现状**

- 顶部“新建任务”和“新建业务任务”并列，业务工单空态内又出现“创建业务任务”。
- “BUSINESS WORK ORDERS”英文眉题、中文标题和一整段解释同时占用同一块，数据为零时仍有三层标题。
- 多个面板都使用完整边框/留白，视觉权重相当，用户看不到“运营概览 → 当前任务表”的主路径。

**为什么不符合规范**

- `DESIGN.md §1.1`：同一视口最多一个 L1 实底主 CTA。
- `§1.6`：同一粒度避免重复；`§4.2`：工具栏和行内操作默认 L3 文字按钮。

**整改**

- 页面唯一 L1：**`新建任务`**（品牌粉实底）。
- “新建业务任务”移入业务工单辅助行，降级为 L3；仅当用户明确选择业务目标时打开现有抽屉。
- 去除英文大写眉题和解释性长文案；业务工单标题区只保留 `业务工单` + 口径/更新时间元信息。
- 报表使用同一个稀疏边框容器；业务工单与明细表通过 1px 分隔和区块标题区分，而不是连续堆叠大 Panel。

---

### 4. 新建业务任务抽屉是“表单放大版”，未采用 `dialog-compact` —— ⚡ 重要

**现状**

- 截图中的标题、字段标签、输入框和纵向间距均明显偏大；四个字段形成接近整屏的稀疏表单。
- 抽屉顶部“新建业务任务”眉题与标题语义重复。

**为什么不符合规范**

- `DESIGN.md §7.1`：字段 ≤5 的弹窗/抽屉使用紧凑内边距；控件统一为 `--control-h-form` 32px。
- `§5`：标题、正文、控件统一 `--ds-font-sm`，不另起放大字阶。
- `§19`：字段间距 `--space-3`，相关字段成组，提交区清晰。

**整改**

- 沿用现有 480px 右侧抽屉宽度；header 只保留标题 `新建业务任务` + 关闭。
- 采用 4 个 32px 紧凑控件：标题、业务目标（唯一多行，约两行高度）、优先级、截止日期。
- Label、输入和错误说明回归 13px token；字段间距使用 `--space-3`。
- 抽屉底部使用 sticky 提交区：左侧唯一 L1 `创建业务任务`，旁边 L3 `取消`。不让提交按钮漂浮在正文末端。

---

### 5. 自造视觉语言破坏系统一致性 —— ⚡ 重要

**现状**

- 新增的渐变运营报表底色、16px 标题、英文蓝色字距眉题、58px 状态条与 92px KPI 卡同时存在。
- 当前代码里混用了硬编码尺寸、fallback 尺寸、`rem` 和 token；部分样式晚于既有规则覆盖，造成同一组件的行为不可预测。

**为什么不符合规范**

- `DESIGN.md §0、§3、§4、§5` 要求使用既有 token、克制的四职责颜色和 13px 工作台字阶。
- `§9.2` 允许 KPI 数字 20px，但不允许整套卡片扩大为展示型 dashboard。

**整改**

- 删除渐变、英文眉题和非 token 字阶；底色仅使用 `--surface` / `--bg` / `--bg-subtle`。
- KPI 改为 6 等分紧凑统计单元：label 12px、value 20px/600、内边距 12px 16px；只有可下钻项目可点击。
- 状态分布条保持同一容器，按计数比例分段；只保留一个选中态和一个清除筛选入口。
- 合并任务中心后置 CSS 覆盖，删除与前序规则冲突的尺寸和列宽，形成单一规则源。

## 4. 推荐的目标页面结构

```text
任务中心                                                     [新建任务 L1]
────────────────────────────────────────────────────────────────────
任务运营  · 实时/今日/本周/本月/全年                         [周期切换 L3]
[状态分布条：待启动 | 执行中 | 等待处理 | 已完成 | 失败 | 已取消]
[任务总量] [执行中] [等待处理] [完成率] [逾期] [中位处理时长]
（有类型数据才显示）任务类型分布紧凑表
────────────────────────────────────────────────────────────────────
业务工单  0 · 暂无标准工单                                    [新建业务任务 L3]
（有数据才展开业务汇总与模板表）
────────────────────────────────────────────────────────────────────
任务明细
[搜索________________] [时间范围]                         [更多筛选 L3]
[全部] [排队中] [执行中] [待确认] [失败] [已完成] [已取消]
┌─ 类型 ─ 任务名 ─ 状态 ─ 更新时间 ─ 操作 ─┐
│  Agent  统一工作计划  执行中  10/7 07:09  详情 查看进度 › │
└─────────────────────────────────────────────┘
```

### 行为说明

- 点击状态分布或可下钻 KPI：表格进入相同状态筛选，并在筛选栏显示一个可清除的已选条件。
- 点击任务行尾展开：在展开行展示完整摘要、技能、创建时间和开始时间；主表不换行撑高。
- 业务工单为零：不显示模板表、导出入口或大空态；只保留辅助行及创建入口。
- 小于 860px：隐藏可选列，任务表横向滚动或转为标签式行；不压缩主列到逐字换行。

## 5. 实施范围与验收标准

### 会改动

- `frontend/src/pages/Tasks.tsx`：精简主表列、调整区块顺序与行动层级；不更改 API 与业务数据。
- `frontend/src/tasks/TaskOperationsReport.tsx`：收敛运营汇总和零数据处理。
- `frontend/src/tasks/TaskReportHeader.tsx`：将业务工单零态改为紧凑辅助行。
- `frontend/src/tasks/TaskDetailDrawer.tsx` 及任务中心相关 CSS：表单、抽屉、表格、状态条和响应式规则回归 token。
- 相关渲染/行为测试：覆盖零业务工单、长标题截断、单一 L1、状态下钻、紧凑抽屉。

### 不会改动

- Agent／系统任务和业务工单的后端口径、权限、周期、导出文件与路由。
- 业务任务创建的字段名、字段顺序、提交行为与原有详情抽屉入口。
- 现有任务详情、取消、会话跳转和筛选 URL 参数的业务语义。

### 验收标准（对应 `DESIGN.md`）

1. 1440×900 下，运营汇总 + 任务表首行可见，表格至少可完整显示 12 条标准 44px 行（在任务量充足时）。
2. 主表中不再出现逐字折行；任务名单行截断，摘要进入展开行。
3. 业务工单为 0 时不出现大型空态、空表头或导出入口；只保留一条紧凑辅助行。
4. 同一视口仅一个 L1：`新建任务`；其他新建、导出、详情、查看、展开均为 L3/L4。
5. 所有标题、label、控件走 `--ds-font-sm`，KPI 数字仅使用 `--stat-value-font` 例外。
6. 表头 36px、默认行 44px、表头 sticky；选中/状态有文字与形状等非颜色信号。
7. 新建业务任务抽屉在 480px 内保持紧凑，字段控件 32px，底部提交区可见且不遮挡正文。

## 6. 待确认的决策

**推荐整包确认：**采用本方案的 `Redesign · Preserve` 路线。

| 决策 | 推荐值 | 需要确认的原因 |
|---|---|---|
| D1 页面主行动 | `新建任务` 为唯一 L1；`新建业务任务` 降为业务区 L3 | 会改变两个创建入口的视觉优先级，但不改变功能。 |
| D2 业务零态 | 收缩为 44px 辅助行，隐藏空模板表和导出 | 会移除当前大虚线空态。 |
| D3 主表结构 | 移除“结果摘要”主列，摘要移入展开行 | 会改变主表列，但能根治逐字换行和行高膨胀。 |
| D4 类型分布零态 | 无数据时隐藏整张类型表，仅保留一行提示 | 会消除当前空表头和大量留白。 |
| D5 抽屉密度 | 480px 紧凑抽屉、32px 控件、sticky 提交区 | 会明显缩小当前表单视觉比例，字段和提交行为保持不变。 |

**推荐确认语句：**`确认 D1–D5，按 data-grid 方案重做任务中心视觉并进行截图验收。`
