## 实施资产

- 共用浏览：`KnowledgeBrowse`、`KnowledgeFilterControls`、`CompactButton`、`useBrowseRows`、`browseMemory`、`asset-browse.css`；技能页复用实际知识组件，不单独重建外观相似的布局。
- 草稿交接：`AssetTaskAction`、`composer/taskDraft`、`ComposerDock`、`Chat`。`/skills`、`/kb`、`/s/:id` 和发现恢复地址保留；目录动作不提交消息、不创建任务或会话、不调用模型与外部工具。
- 个人技能记录：`employee-skill-preferences` 与 `/skills/personal`、`/skills/:id/favorite`、`/skills/:id/view`。身份取自服务端 scopedUser，资源集合来自已发布且当前可见技能。偏好使用 PostgreSQL 参数化查询，不创建技能/Agent授权。
- 使用口径：收藏与查看分别保存。常用按本人已实际启动的正式任务数量排序，最近使用按启动时间；目录填入不增加执行次数。知识近期查看按员工隔离，本机记录只组织已授权返回条目。
- 发布迁移：`037_employee_skill_preferences.sql` 已登记到既有 PostgreSQL schema 迁移脚本，未在生产执行。
- 视觉规范：`DESIGN.md` §32；刷新已有 Token 登记表以反映实际 CSS，不修改 Token 值。23 个已有待落地项继续明确标注。

浏览器使用 HTTP 夹具，证明呈现、草稿恢复与请求边界；后端记录测试使用 PostgreSQL 查询 mock，未声称真实数据库或 Codex/MCP执行闭环已验收。未发送邮件、导入或变更合作阶段；未修改生产配置或部署。正式发布前需在隔离 PostgreSQL 执行已登记迁移并验收身份/可见范围/收藏持久化与正式任务统计；真实授权集成与发布门禁另行记录。

基线纯 PostgreSQL HTTP 模式目前明确返回身份提供者未接入，且首页转到任务中心；这是原有运行时限制。本改动提供明确失败和恢复，不绕过身份边界或通过重写路由隐藏限制。后台旧 SQLite 依赖未纳入新功能，新增偏好只使用 PostgreSQL。
