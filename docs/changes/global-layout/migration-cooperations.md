## 最小迁移

| 页面区域 | 采用的共享模式 | 展示变化 | 保持不变的业务契约 |
|---|---|---|---|
| 合作项目列表 | `RecordRow`、`TruncatableText` | 标题和阶段状态进入同一主行；达人、预算、未完成工单进入显式第二层详情；长标题可通过“展开”访问完整文本。 | `role=listbox/option`、选中状态、鼠标/键盘打开详情、筛选和请求不变。 |
| 合作详情基础事实 | `PropertyList`（`short` 标签宽度） | 阶段、品牌、预算、更新时间改为标签左、内容右的单列属性组，使用共享 24px 标签—内容留白。 | 字段、阶段全称、空值语义与时间格式不变。 |
| 阶段推进 | `HorizontalForm`、`ActionGroup` | 短字段横向对齐；确认推进、归档、取消收敛为内容列起点对齐的动作组。 | 原有阶段可选项、跨阶段/回退/进出异常原因校验、提交请求、归档确认、取消原因提示与错误反馈均未改动。 |
| 项目事件 | `HorizontalForm`、`ActionGroup` | 事件类型和事实摘要采用横向短表单，提交动作与内容列对齐。 | 事实摘要必填校验、事件类型、随机幂等键、请求和失败信息不变。 |
| 工单记录 | `RecordRow`、`TruncatableText` | 工单标题和状态在主行，模板、主受理人和更新时间在第二层详情。 | 工单字段、状态映射、顺序及只读性质不变。 |
| 新建合作抽屉 | `HorizontalForm` | 短字段改为标签左、控件右；长“结算条款”明确使用堆叠编辑例外。 | 线索搜索/选择、必填校验、预算转换、结算条款、幂等键、创建请求、抽屉关闭和提交行为不变。 |

页面局部 CSS 全部以 `.cooperations-page` 为作用域，复用现有颜色、字号、间距、圆角、控件高度和标签列 token；未新增全局样式或硬编码全局覆盖。

## 已合规保留

- 页面不存在数据表；因此**没有将任何既有表格改成 `div` 列表**，也没有需要登记的既有合规表格列结构。
- 查询输入、阶段筛选、`只看我负责`、项目总数、详情选择、加载/空态、商务条款只读提示和项目动态信息结构均保留。
- 所有既有请求、错误、确认、阶段、审批相关提示、风险后果和实际异常信息均保留；没有重算权限、阶段或审批结果。
- 路由和深链恢复逻辑未修改。

## 多行例外

以下内容不强压进单行，以避免隐藏真实信息或破坏编辑可用性：

1. 列表中的达人/平台、预算、未完成工单放在 `RecordRow.detail` 第二层；标题与阶段仍稳定同一行。
2. 工单的模板、主受理人与更新时间放在记录详情层。
3. 事实摘要输入保留完整内容宽度；结算条款使用 `ui-field-stacked` 的长文本编辑区。
4. 页面级和表单级失败提示继续原位显示，不为压缩高度而移除或截断。
5. 实际容器小于 720px 时，列表与详情受页面容器查询收为单列；共享表单在小于 480px 的实际容器中按其既有规则收为标签上置。
