# 全局信息布局实施记录

## 需求与职责

需求：已批准的全局布局目标——短字段左右排列并留24px列间距；普通记录的标题、状态和动作同行；长内容保留完整可达详情；降低重复占位而不修改业务。

主责：UI/UX规范、前端共享组件及测试；发布由本任务唯一收尾。

依据：CONST-04/05/08/09/10、TECH-FE-01/02/03、TECH-TEST-01/02/03/04、DESIGN §19/列表密度、IA §1.1。结论：符合；不改后端权限、组织事实、阶段规则、审批权或路由。

## 实施资产

- 共享 `PropertyList`、`HorizontalForm`、`RecordRow`、`ActionGroup`、`TruncatableText`。
- 语义尺寸token：96/112/128px标签列、24px间距、360/480px内容宽度；按实际容器<480px切换短编辑字段，正文/复杂字段堆叠例外。
- 只读事实用dl/dt/dd，不伪装Input；标准记录最小40px，原任务表保持原44px，触摸操作至少44px。
- 六类设置、员工端高频领域、人员编辑/绑定详情、Agent/工单/本体治理；详情复用共享模式，既有合规表格和专业工作区不重造。
- 原生form保留字段名、FormData、required、minLength/maxLength和提交回调；无form的受控编辑保留原行为。
- 长线索名称由hover-only改为聚焦可达展开；展开按钮阻止父级记录点击/键盘误触。
- DESIGN原位替换“所有label上置”默认规则；旧设置专属行样式删除。
- 部署共享Git目录flock互斥；提交+PID专属构建目录；产物index与Git版本检查；release.json记录完整提交；保留PG本体发布门禁。

## 行为边界

本批API调用AST比对保持一致；没有新增权限、提交端点或schema变更。没有保存生产偏好、发送邮件、创建业务工单或批准本体变更。

员工与管理端不因共用组件而混淆职责。个人默认值不是授权；连接状态不是发信许可；运行状态不是业务阶段；审批发起不是批准。

## 验证及状态

初始静态代理检查的缺依赖说明不作为最终类型证据：已在服务器独立worktree复用既有依赖执行真实前端类型、构建和浏览器回归。

设置18项浏览器门禁、共享9项单元、全局新增样板先行通过；最终结果以交付报告日志为准，不用初步通过冒充全部完成。

原管理用例存在过期默认筛选、旧DOM和批量API夹具，已依据现行源代码对账，未改页面规则。最终门禁对编译产物执行，避免多个开发服务共享缓存造成lazy模块长时间未完成。

## 真实回归修正记录

人员卡的强制RecordRow迁移在真实几何门禁中造成646px拉伸，且破坏既有紧凑身份布局。本轮撤回该卡结构迁移，保留原32px头像、<=54px宽屏双行、原操作/Agent折叠和原几何断言。只迁移编辑/绑定详情。这是保留达标专业模式，不以放宽高度门禁掩盖退化。

管理Agent计数徽章属于真实可访问名称的一部分；测试匹配改为标签+计数，同时继续验证人数、筛选唯一项和取消零写。预览由连续句子变为dl属性，改为分别验证组织版本dd和覆盖人数dd，而非删除断言。
