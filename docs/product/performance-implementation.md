## 当前功能边界

用户端：个人列表、待办列表、目标编辑与确认、自评、上级评价、部门校准与系数调整、HR复核、核算复核、部门汇总、结果知悉、异议处理、面谈记录、受控 CSV 核算交接。

管理端：从已登记Excel建立模板/规则草稿、两级配置审批、退回/撤回/独立发布、周期快照、显式考核关系、启动、发布已复核结果、归档及操作元数据审计。配置管理员不自动获得个人评分、评语或导出资格。

状态链：目标草稿 → 目标待确认 → 自评 → 上级评价 → 部门审核 → HRBP复核 → 核算复核 → 待发布 → 已发布 → 已知悉。退回只去指定的前一责任环节，修改员工自评会使旧上级评分失效。异议另有处理中状态及处理说明。

计算口径：月度指标权重须合计100%；正式分数采用上级分项评分加权，自评分单独汇总；额外系数按百分点相加；等级校准与系数调整独立记录。未填写评分不得按0补齐。模板、规则均需配置并发布，不预置附件样例分数。

尚未实施：通用Excel文件上传及原格式导出、附件上传预览、自动通知与催办、可视化流程配置、自动强制分布及取整、自动否决项认定、运行中考核关系转交、发布后更正重审、奖金金额核算、AI辅助、细粒度字段权限配置页。没有为这些能力提供假导航或假完成状态。

### 审批与发布

配置流程为：草稿 → 指定部门负责人审核 → 指定HRBP复核 → 审批通过 → 申请人独立发布。指定两位审批人的动作由配置管理员确认并留痕，不从Excel姓名推断授权。审批人使用员工端“绩效 / 配置审批”办理；管理端用于配置、发起及查看记录。

- 配置内容哈希与审批实例绑定；审批中和审批通过后禁止编辑。实质修改须退回/撤回后重新申请，已发布配置以新草稿修订。
- 两位审批人须为当前公司有效成员、互不相同且不同于申请人；决定时重新校验组织资格，管理员角色没有替人审批旁路。
- 审批意见、退回理由、待审批节点、决定时间和回执持久化；退回不伪装为已发布。
- 建周期必须选择已审批发布、与模板审批时规则相符的配置；启动时再次核验配置资格。旧未审批配置不能用于新建或启动草稿周期。
- 个人办理链继续按被考核人 → 直属上级 → 部门负责人 → HRBP → 核算人推进；部门/HR/核算通过及退回均填写意见。HR等级调整与基准系数、加减点分别记录。

### 源表异常与边界

源表月度权重130%、10项超过说明7项上限、固定总分88、年份命名冲突、G/I列评分口径差异、汇总缓存均值差异均在来源预览中提示。原始指标和权重保留为草稿；权重不是100%时服务端阻止提交审批。指标数量超过所选评分规则上限也阻止提交；可合并指标或先审批规则修订。没有悄悄平均分配或归一化。

尚未实现通用文件上传导入、真实邮件通知、工作日历与迟交自动扣减、出勤折算或奖金金额核算。这些原表说明可查阅，不能据此声称自动执行。
