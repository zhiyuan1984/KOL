## 实施边界

现有工单模板的 `fill_policy.collaboration_dependencies` 是版本化技术关联契约，唯一支持动作是 `work_order.advance_stage`；只通过现有模板发布路径生效。前置模板及版本、审批所属公司及类型/版本、审批字段映射由已发布配置指定。发布时核对前置模板已经发布、映射字段属于该公司的已发布审批定义。没有声明的关系显示“未发布依赖规则”，不从同任务、同 KOL 或时间先后推断依赖。此首波未把该契约扩展到邮件外发或付款。

审批覆盖同一合作、同一工单、同一动作、同一产物 ID/版本/内容指纹。产物从原有 `task_artifacts` 权威记录重读，旧内容指纹不能自行冒充当前内容。查询要求当前有效主体、工单权限、明确品牌范围、当前公司组织成员关系及审批参与关系；不以管理员角色绕过。缺失或错误绑定拒绝，返回受控原因而非另一合作的私有内容。

已有 Jev 决策仍为建议/影子记录，审批事件不直接启动模型、建单、派单、外发或完成任务。A3 队列执行时重新检查依赖及决策快照版本，变化记为 skipped 回执；不增加第二套审批引擎、队列或调度器。

人工采纳复用原 `executeWorkOrderDecision`：首波限当前正式任务负责人、已有发布且启用的 A1/A2 模板，保留原执行门槛及确定分派规则。只接受该 Task 下已存储的 verified event；自由文本影子事件不能冒充正式依据。预检快照绑定员工、父任务版本、模板/发布规则、事件和可合并工单版本；L3 确认提交时重读并持锁到提交。同模板版本已有开放工单时只提供明确目标的合并，不再创建副本；合并追加真实事件依据和 Outbox，增加目标版本及最新决策引用，不改变状态、负责人、截止时间或验收条件。人工与 Worker 共享父任务事务锁及同事件/模板版本去重范围，成功回执用 human_adoption / created 或 merged 标注；相同请求重放仍复核当前归属和品牌权限，核对原确认对象及参数后返回原回执。只读建议查询可补读当前员工的持久回执。

任务详情新增建议列表和确认区，未采纳建议与正式待办分开；依据变化取消旧确认，提交后刷新原任务和统计。首波人工写入权限仅支持当前任务负责人及显式品牌范围，不声称覆盖全部组织负责人继承或协作成员采纳权。
