## 实施边界

现有工单模板的 `fill_policy.collaboration_dependencies` 是版本化技术关联契约，唯一支持动作是 `work_order.advance_stage`；只通过现有模板发布路径生效。前置模板及版本、审批所属公司及类型/版本、审批字段映射由已发布配置指定。发布时核对前置模板已经发布、映射字段属于该公司的已发布审批定义。没有声明的关系显示“未发布依赖规则”，不从同任务、同 KOL 或时间先后推断依赖。此首波未把该契约扩展到邮件外发或付款。

审批覆盖同一合作、同一工单、同一动作、同一产物 ID/版本/内容指纹。产物从原有 `task_artifacts` 权威记录重读，旧内容指纹不能自行冒充当前内容。查询要求当前有效主体、工单权限、明确品牌范围、当前公司组织成员关系及审批参与关系；不以管理员角色绕过。缺失或错误绑定拒绝，返回受控原因而非另一合作的私有内容。

已有 Jev 决策仍为建议/影子记录，审批事件不直接启动模型、建单、派单、外发或完成任务。A3 队列执行时重新检查依赖及决策快照版本，变化记为 skipped 回执；不增加第二套审批引擎、队列或调度器。
