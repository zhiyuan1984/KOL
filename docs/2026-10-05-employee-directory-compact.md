# 管理侧人员页面紧凑化

## CONST-08 审查

需求 → 中栏搜索与三级部门/人员联动、右栏精简列表、编辑弹窗统一字阶与控件、品牌全选。

主责角色 → UI/UX 专家（呈现与无障碍）、前端专家（交互与实现）。

宪法条款 → CONST-04（不改业务规则）、CONST-05（沿用服务端授权与确认）、CONST-08（先审查）、CONST-10（验证范围如实记录）。

基本法条款 → BUSINESS BIZ-02/03/04（权威组织、品牌及邮箱事实）、TECHNOLOGY TECH-FE-01/03（服务端授权结果、真实状态与恢复）。视觉依照 DESIGN §4–9、§11。

结论与证据 → **符合**。部门筛选只影响列表，不授予权限；人员仍是组织成员而非组织节点。Agent 覆盖与撤销确认沿用服务端接口；品牌“全部”提交当前可配置品牌的显式集合，不引入未来品牌的隐式授权。绑定详情请求失败显示重试，不以零计数冒充成功。

下一步 → 依据前端构建与接口夹具浏览器回归检查呈现。该验证不代表真实外部集成或发布完成。

## 实施资产

- `frontend/src/admin/employees/EmployeeDirectoryV2.tsx`：搜索图标、状态命名、三级部门/人员筛选与上级变更清空下级、数量单点展示、精简列表与文字操作。
- `frontend/src/admin/employees/EmployeeDirectory.tsx`：品牌全选/半选、绑定信息合并、失败重试与真实计数。
- `frontend/src/admin/employees/employee-directory.css`：统一小字号、控件等高、居中标题、单列窄容器与文字按钮。
- `frontend/e2e/admin-employees.spec.ts`：联动、Agent 绑定与撤销、品牌选择与保存、错误恢复回归。

## 验证范围

前端 `npm run build` 包含 TypeScript 检查和生产构建。浏览器回归使用 Vite 与按真实接口结构构造的夹具，不连接真实业务服务，不执行真实外部写入。

结果：前端类型检查与生产构建通过；三个员工页回归用例通过；增加宽度适配断言后，联动与编辑两个相关用例再次通过，覆盖 1280/1024/860 宽度无横向溢出。编辑弹窗截图已核对居中标题、等高控件、品牌全选和业务绑定摘要。临时 Vite 夹具配置已清理，保留正式回归用例。
