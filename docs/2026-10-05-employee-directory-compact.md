# 管理侧人员页面紧凑化

## CONST-08 审查

需求 → 中栏搜索与三级部门/人员联动、右栏精简列表、编辑弹窗统一字阶与控件、品牌全选。

主责角色 → UI/UX 专家（呈现与无障碍）、前端专家（交互与实现）。

宪法条款 → CONST-04（不改业务规则）、CONST-05（沿用服务端授权与确认）、CONST-08（先审查）、CONST-10（验证范围如实记录）。

基本法条款 → BUSINESS BIZ-02/03/04（权威组织、品牌及邮箱事实）、TECHNOLOGY TECH-FE-01/03（服务端授权结果、真实状态与恢复）。视觉依照 DESIGN §4–9、§11。

结论与证据 → **符合**。部门筛选只影响列表，不授予权限；人员仍是组织成员而非组织节点。Agent 覆盖与撤销确认沿用服务端接口；品牌“全部”提交当前可配置品牌的显式集合，不引入未来品牌的隐式授权。绑定详情请求失败显示重试，不以零计数冒充成功。

下一步 → 依据前端构建与接口夹具浏览器回归检查呈现。该验证不代表真实外部集成或发布完成。

## 跟进（同日）：员工卡片双行对齐

需求 → 右栏员工卡改为双行：首行＝头像＋姓名·工号＋Agent 文案＋账号启停入口（固定靠右）；次行＝邮箱＋操作组（编辑 | 管理绑定 | 停用/启用，固定靠右）；左侧自适应省略，右侧不随文字长度漂移；另加 1200/960 两档响应式（收紧内边距、分隔与操作组间距，限制 Agent/邮箱宽度）。验收对照图1右栏的三种情况：无 Agent＋短邮箱、长 Agent 文案＋长邮箱、未登记邮箱。

主责角色 → UI/UX 专家（呈现与无障碍）、前端专家（实现）；不涉及业务权限、审批与阶段。

宪法条款 → CONST-04（不改业务规则）、CONST-05（沿用服务端确认与回执）、CONST-08（先审查）、CONST-10（验证范围如实记录）。

基本法条款 → TECHNOLOGY TECH-FE-01/03（真实状态与恢复入口）；视觉依照 DESIGN §1 不变量 1（全部为文字动作，不新增实底 CTA）、不变量 4（停用/启用以文案区分，颜色只作加强）、§4 控件尺寸与 §5 字号阶梯（全部引用既有 token）。

结论与证据 → **符合**。`EmployeeDirectoryV2.tsx` 行结构改为 `.employee-card` 双行卡片；样式在 `employee-directory.css` 页面域内落地（颜色、字号、间距、圆角全部引用既有 token，无新增 hex 与字号档）。顶行右侧账号启停与底行第三按钮共用 `changeActive` 与既有停用确认；停用账号两处均显示“启用”，保留恢复入口。无照片头像以首字回退（`text-transform: uppercase`；头像层 aria-hidden，姓名文本仍可读）。右缘基线由 flex 保证：左侧 `min-width: 0` + ellipsis，右侧 `flex: 0 0 auto` 固定。
