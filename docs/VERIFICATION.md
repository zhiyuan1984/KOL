# 独立规范集对比验证

验证日期：2026-09-21  
验证对象：历史归档规范集与本独立规范集  
性质：迁移证据，不是新的产品、业务或技术规则

## 1. “更好”的可验证定义

本报告不把篇幅更短、文件更新或措辞更统一直接当作“更好”。只有满足下列可复核标准，才能声称相应维度得到改善：

| 维度 | 可观察标准 |
|---|---|
| 独立性 | 规范性 Markdown 链接全部留在本目录，且目标存在 |
| 层级清晰 | 只有一部宪法、三部基本法；每份细则声明所属基本法和责任角色 |
| 单一事实源 | 同一规则只有一个规范正文；机器配置必须验证等价，不能与正文竞争权威 |
| 引用有效 | 不引用不存在的章节、废止编号、历史决定或外部同名规范作为现行依据 |
| 证据诚实 | 有日期的事实快照与长期规则分开；证据缺失时降低结论强度 |
| 可执行性 | 规则能够指出责任、适用条件、可观察结果和验证方式 |
| 实现诚实 | 文档完成不等于代码完成；实现状态、测试和真实集成证据分别记录 |

## 2. 自动扫描结果

扫描口径：递归统计 Markdown；解析本地 Markdown 链接；判断目标是否存在、是否越出各自文档集；搜索权威、法律层级与旧引用信号。

| 指标 | 历史归档集 | 独立规范集 | 结论 |
|---|---:|---:|---|
| Markdown 文件 | 52 | 13 | 新集减少 75%，降低检索和同步面；文件少本身不证明规则更正确 |
| Markdown 行数 | 6,655 | 1,889 | 新集减少 71.6%；需要通过覆盖审查防止误删规则 |
| 本地 Markdown 链接 | 160 | 62 | 新集减少间接依赖 |
| 目标不存在 | 31 | 0 | 新集通过 |
| 链接越出文档集 | 46 | 0 | 新集通过独立性要求 |
| 包含“权威/宪法/基本法/Class”等权威声明的文件 | 29 | 9 | 新集显著收敛；仍需按层级逐份审查，而不能只看数量 |
| 旧章节、旧 Class、ADR 或历史路径作为现行依据 | 多处 | 0 | 新集通过当前静态扫描 |

这些数字证明的是：**新集当前更闭合、断链更少、权威声明更集中。** 它们不证明业务口径一定正确，也不证明软件已经实现这些规则。

## 3. 关键问题的逐项对照

### 3.1 入口与层级

历史集采用 A–K、编号别名、产品宪法、技术宪法、IA 类别、设计类别和 ADR 的组合导航。规则本身可能合理，但读者必须先理解多套层级和别名。

新集固定为：

```text
AGENTS.md
→ CONSTITUTION.md
→ PRODUCT.md / BUSINESS.md / TECHNOLOGY.md
→ 相关实施细则
```

证据：本目录 [AGENTS.md](AGENTS.md) 和 [README.md](README.md) 给出同一加载顺序；实施细则不能创造第四种基本法位阶。

**结论：通过。** 新集降低了决定“先听谁”的成本。

### 3.2 视觉 Token

历史集把视觉规则分散在设计入口、MASTER、页面覆盖、默认观感参考和遗留设计摘要中，需要额外冲突优先级。

新集仅以 [ui-ux-rules.md](ui-ux-rules.md) 作为视觉数值来源，同时容纳颜色、字体、控件、间距、布局、三轴适配和验收矩阵。它还修正了两个内部矛盾：间距改称 2px 基础网格；命中区不再由宽度档直接决定。

**结论：通过静态一致性检查。** 尚需通过 CSS token 对照和各视口 E2E 证明运行实现已同步。

### 3.3 阶段规则

历史规则同时提及 Markdown、JSON、ADR 和运行代码，且机器配置未必进入发布门禁。新 [阶段转移细则](business-rules/stage-transitions.md) 明确规范正文，要求运行时配置完整表达节点、边、原因和审批，并在不等价时阻断发布。

**结论：设计改进，运行验证待完成。** 在契约校验器真正检查等价性之前，不能标记为生产通过。

### 3.4 事实与授权证据

历史评估曾把一个当前不可访问的邮箱负责人清单描述为“100%真实”，并据此扩大到“正式授权已确认”。新 [主数据评估](18-mcp-master-data-assessment.md) 将它改为有日期的证据快照：远端只读结果只证明当时可读；缺失绑定证据时，正式写操作须重新核验。

**结论：通过证据诚实性检查。** 代价是部分写操作会保持阻断，直到业务专家补齐证据。

### 3.5 基本法与实现快照

历史技术正文混入具体代码文件、已修复事项和 Cron handler 当前状态，代码变化会使基本法过期。新 [TECHNOLOGY.md](TECHNOLOGY.md) 改为规定实施登记所需字段和自动任务最低契约，不再把某次代码扫描写成长期法律。

**结论：通过生命周期分离检查。** 仍需另建项目级实施登记，才能持续跟踪实际完成度。

## 4. 尚不能证明的事项

以下结论目前**不能**从文档扫描推出：

- 业务专家已经接受所有 KOL 对象、阶段、排他范围和 14 天口径。
- 当前代码符合新规范。
- 阶段机器配置已经受到发布门禁保护。
- 所有 Skill、Policy、Workflow 和 schema 已完成迁移。
- DESIGN 的 token 已全部写入 CSS，并通过键盘、读屏、缩放、深色和三轴设备测试。
- 远端 MCP、邮箱绑定和组织授权证据当前有效。

因此，“新集更好”的准确表述是：

> 新集已经证明在文档独立性、链接完整性、层级清晰度、单一来源设计和证据措辞上优于历史归档；业务正确性、代码一致性和生产可用性仍需专项验收。

## 5. 升级为现行规范前的门禁

| 门禁 | 验收责任 | 通过标准 | 当前状态 |
|---|---|---|---|
| G1 文档闭合 | 项目经理、测试经理 | 内部链接、层级、条款引用扫描为 0 问题 | **已通过** |
| G2 规则覆盖 | 平台产品经理、KOL 业务专家、架构师 | 历史有效规则逐项映射为保留、替代或废止，无未解释删除 | 待审查 |
| G3 业务空白 | KOL 业务专家 | BIZ 末表所列建联、归属、14 天、审批、合规和报表口径有版本化结论 | 未通过 |
| G4 机器等价 | 后端专家、测试经理 | 阶段、权限、动作风险配置与正文自动校验，漂移阻断发布 | 未通过 |
| G5 代码符合 | 前后端专家、测试经理 | 受影响代码、接口、E2E 和 Agent 评价均有条款追踪 | 未验证 |
| G6 真实集成 | 业务专家、测试经理 | 授权范围内完成只读及必要写入验证，保留真实回执 | 未验证 |
| G7 视觉实现 | UI/UX 专家、前端专家、测试经理 | CSS token 与 DESIGN 一致，验收矩阵全部有证据 | 未验证 |
| G8 用户批准 | 用户 | 明确接受替换范围、生效版本和回退方案 | 未批准 |

只有 G1–G8 全部通过，才能把“结构更好”升级成“可替代旧规范并指导生产”。

## 6. 复跑方法

对任意两个候选文档集重复以下检查，结果应可比较：

1. 统计 `*.md` 文件和行数。
2. 提取所有本地 Markdown 链接，检查目标存在性和是否越出各自根目录。
3. 搜索失效章节、历史编号、ADR、Class、重复“唯一来源”和外部同名规范引用。
4. 列出所有宪法、基本法和权威声明，人工确认是否符合一宪法、三基本法层级。
5. 对规则空白、事实快照和实现完成声明做人工证据审查。
6. 对机器规则执行配置—正文—代码—测试四方等价检查。

复跑结果必须记录日期、扫描范围和未覆盖事项，不能只保存一个“通过”结论。
