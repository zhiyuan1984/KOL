## 0. 口径与判据

### 0.1 什么是事件（六构件 §4）

- 事件 = **已经发生的事实**：不可变、带时间戳、按时间有序。
- 事件是对象状态变化的**唯一合法来源**——属性不被随手改掉，由事件触发规则重新计算（事件溯源）。
- 铁律（六构件 §6）：所有修改都必须走动作；**动作产生事件**。链条：`事件 → 规则 → 动作 → 新事件`，每一步的「为什么」可回放。

### 0.2 事件与任务（任务篇 §1、§2）

- 事件向后看（事实，不可改）；任务向前看（工作，有生命周期）。
- 任务流转本身也是事件流（已创建、已分配、已完成、已逾期……）；四种关系：事件触发任务、任务生命周期产生事件、任务执行产生业务事件、事件—任务闭环。

### 0.3 记录形状与处理要求

- 载体：事件表（记忆三件套 = 事件表 + 工单表 + 摘要；一表三用：触发器、账本、记忆源）——概念落地对照表。
- 最少字段（TECH-BE-04、org-permissions §审批和审计记录）：稳定 ID、主体对象、**发生时间**与接收时间（外部来源）、来源与版本、关联动作与执行者、证据指针、外部回执、幂等键、前后 diff；审批事件另含申请人、审批人、决定与理由；敏感字段脱敏，原始秘密不入日志。
- 处理要求：能去重、重试、恢复，正确处理迟到和乱序事件（TECH-BE-04）；前端断线重连从事件位置恢复，重复事件不重复展示或提交（TECH-FE-03）。
- 命名口径：事件一律写成**过去时事实句**（「XX已YYY」），不写成待办、建议或指令。

### 0.4 事件必须遵守的跨领域不变量

| 不变量 | 出处 |
|---|---|
| 发送 ≠ 推进阶段；阶段唯一官方写入口是 `confirm_stage`（带 `expected_version`） | BIZ-11、BIZ-12、stage-transitions §3 |
| L1 只读直接执行；L2 草稿必须标明；L3 外发、导入、删除、解密、正式写入执行前确认并保留回执 | CONST-05、BIZ-14、docs/AGENTS.md §5 |
| 回执不确定时不得宣布成功、不得盲目重复发送，如实返回「不确定」 | BIZ-11、TECH-BE-03 |
| 重复确认、重试、事件重放不得造成重复副作用 | TECH-BE-03 |
| 权威事实源之外不造事实：摘要、评分、推断、建议、测试夹具都不是正式业务事实 | CONST-06、BIZ-02 |
| 到期执行读取事件的**发生时间**，不用晚到的接收时间 | TECH-BE-05 |
| 有效业务事件提交后更新索引；摘要失败保留旧摘要并标过期，不伪造 | PROD-AGENT-07 |
| 后台事件是独立入口，按已授权流程运行，不依赖员工打开页面 | CONST-07、BIZ-06、PROD-PLAT-06 |
| 不得伪造完成、进度、联系人、结果 | CONST-10、docs/AGENTS.md §5 |
| 取消后仍展示已发生的外部动作；不通过隐藏消息抹去执行历史 | PROD-AGENT-09 |

### 0.5 产生方式分类（清单用）

- **人确认动作**：L3 受控动作执行后落事件（可叠加组织审批）。
- **授权自动事实**：后台作业按已发布规则运行（如 14 天到期复核、定时扫描）。
- **外部事实**：webhook、物流、平台发布等外部来源，验源、去重后落事件。
- **系统作业状态**：异步作业的创建、进度、终态（真实、可恢复）。

## 2. 线索与发现（对象：线索、采集候选）

导入成功前，候选不能冒充正式 KOL 档案（BIZ-10）；采集是异步作业，同一时间只跑一个 MediaCrawler 采集任务，必须有进度、取消、重试和真实终态（docs/AGENTS.md §5）。

| 事件（事实句） | 产生方式 | 关键载荷与证据 | 依据 |
|---|---|---|---|
| 采集作业已创建 | 人确认动作（`creator_discovery` 提交后入队） | 平台、筛选参数、提交人、来源批次 | BIZ-10、ADR-2026-09-28（公海/「分析已选」） |
| 采集进度已更新 | 系统作业状态 | 当前平台、已获数量（可查、可取消） | BIZ-10 |
| 采集作业已完成 | 系统作业状态 | 真实终态；产出候选，不是正式档案 | BIZ-10 |
| 采集作业已取消 | 系统作业状态 | 取消人、时间 | BIZ-10 |
| 采集作业已失败 | 系统作业状态 | 失败原因、可重试入口 | BIZ-10、PROD-AGENT-09 |
| 候选线索已生成 | 授权自动事实 | 平台数据、原平台链接、来源批次、画像依据 | BIZ-10 |
| 导入已提交 | 人确认动作（独立确认） | 批次、对象清单、提交人 | BIZ-10、BIZ-14 |
| 导入项已成功（逐项） | 人确认动作结果 | 真实 ID、去重键（外部 ID + 来源批次） | BIZ-10 |
| 导入项已失败（逐项） | 人确认动作结果 | 失败原因；部分成功不整批重做 | BIZ-10 |
| 导入项已跳过（重复） | 规则结果（去重） | 命中的外部 ID／来源批次 | BIZ-10 |
| 档案同步已完成／已失败 | 系统作业状态 | 同步结果与差异 | BUSINESS 技能表（`creator_library_sync`） |

边界：

- 工具返回的名单不能自行生成组织权限（BIZ-02）。
- 缺邮箱不能通过编造邮箱解决（BIZ-10）。

## 5. 合作关系

### 5.1 关系本体与阶段变更

| 事件（事实句） | 产生方式 | 关键载荷与证据 | 依据 |

补充口径：

- 进入 `PLAN_PENDING`、`CONTRACTING`、`CONTENT_REVIEW`、`PUBLISH_PENDING`、`SETTLING` 时，在人确认之外叠加审批要求；审批结果是独立事件（见 §8）。
- 展示层 8 段只是折叠，不能压缩 16 个写入节点（stage-transitions §1）；`COMPLETED` 是结算后的结果，不是主阶段（BIZ-08）。
- 远端「只能相邻写」是物理适配，不得改写产品边（stage-transitions §6）。

| 回复已分析 | Agent 产出（标记为建议） | 证据优先级（正文明确动作＞附件链接＞履约字段＞邮件主题）、建议阶段、不确定性、风险、下一步 | BIZ-13 |
| 草稿已生成（L2） | Agent／工具 | 英文主题正文 + 中文内部译文；标注 L2 | BIZ-11 |
| 草稿已修改／已暂存（L2） | 人编辑 | 最后编辑版本 | BIZ-11 |
| 邮箱已授权／已移交／已停用 | 治理动作 | `responsibleStatus`（在职／已移交／停用）；发件箱必须在授权品牌范围 | BIZ-04、domain-objects §2.5 |

边界：

- 生成、改写、预览邮件不发送；内部译文不得意外发送（BIZ-11）。
- 确认发送不等于组织审批，也不能跳过发送闸门（org-permissions §审批审计）。
- 回复理解建议不直接改正式状态（BIZ-13）。

## 7. 任务与工作项

| 事件（事实句） | 产生方式 | 关键载荷与证据 | 依据 |
|---|---|---|---|
| 任务已创建 | 人／规则／事件触发 | 负责人、对象、依据、期限、摘要与下一步 | BIZ-16、任务篇 §2.1 |
| 任务候选已生成 | Agent 建议（未授权保持候选） | 采纳为待办时留审计 | BIZ-16、PROD-AGENT-08、ADR-2026-09-28（候选推荐） |
| 任务已分配 | 人／规则 | 执行责任 | BIZ-16 |
| 任务已转办 | 人确认 | 保留历史与责任变化 | BIZ-16 |
| 任务已排队 | 系统 | 忙时入队（轮到时自动开始） | ADR-2026-09-30、PROD-AGENT-09 |
| 任务已开始执行 | 系统（开始即执行） | `run.started`；开始即执行，不预写 running | ADR-2026-09-30 |
| 任务已成功 | 系统终态 | 结果已生成；终态必达且可读 | ADR-2026-09-30 |
| 任务已失败 | 系统终态 | 失败原因；给出恢复入口 | ADR-2026-09-30、PROD-AGENT-09 |
| 任务已停止 | 人停止 | 已保留已产生内容；可重新执行 | ADR-2026-09-30 |
| 任务已取消 | 人／系统 | 终态 | ADR-2026-09-30 |
| 任务已完成 | 验收 | 依据任务验收条件；发信／关会话／解归属不自动完成 | BIZ-16 |
| 任务已逾期 → 任务已升级 | 后台规则 | 设计口径（任务篇 §3、总表 §调度） | 任务篇 |

边界：

- 未授权的 AI 建议保持候选状态（BIZ-16）。
- 重启对账：Host 启动时把仍为 running 的运行按「执行被中断；未产生结果，可重新执行」收尾（ADR-2026-09-30）。

## 8. 审批

| 事件（事实句） | 产生方式 | 关键载荷与证据 | 依据 |
|---|---|---|---|
| 审批已提交 | 人确认动作（`business_approval`） | 申请人、对象、金额、币种、用途、制度版本、必要汇率及日期与来源 | BIZ-14 |
| 审批已通过 | 审批人决定 | 决定、审批人、时间、幂等键 | BIZ-14、org-permissions |
| 审批已拒绝 | 审批人决定 | 理由（记录） | BIZ-14、BIZ-15 |

边界：

- 报价确认与费用审批是不同事项；Agent 不得代人批准（BIZ-14）。
- 公开搜索到的通用制度不能替代公司制度；固定代码金额或模型记忆不能补缺（BIZ-14）。
- 实质内容、金额或授权条件改变后，旧审批不能自动覆盖新版本（BIZ-15）。
- 审批链：工具权限 → 业务 Policy → 人工确认 → 组织审批（如需）→ 外部提交 → 回执（org-permissions §审批链）。

## 9. 风险

| 事件（事实句） | 产生方式 | 关键载荷与证据 | 依据 |
|---|---|---|---|
| 风险已识别 | 授权自动事实／Agent 分析（按发布规则） | 类型（延期／内容／失联）、证据、不确定性 | BIZ-13 |
| 风险已解除 | 人确认／规则 | 解除依据 | BIZ-13 |
| 风险扫描已完成 | 系统作业 | 定时规则走后台，可重试 | BUSINESS 技能表（`risk_scan`）、PROD-PLAT-06 |

边界：

- 业务风险状态与归属到期分别判断（BIZ-13）。
- 「以后有空」不等于永久拒绝；个人突发事件不直接判违约（BIZ-13）。

## 10. 项目、活动与报表

| 事件（事实句） | 产生方式 | 关键载荷与证据 | 依据 |
|---|---|---|---|
| 项目已创建 | 人确认 | 名称、公司／品牌范围、负责人、目标与状态 | BIZ-19 |
| 活动已创建 | 人确认 | 同上；活动隶属项目 | BIZ-19 |
| 用量已记录（成本） | 系统（每次模型运行） | 标明来源与是否为估计值；按月按公司／Agent／员工个人／项目活动汇总 | PROD-PLAT-08、ADR-2026-09-29 |
| 预算阈值已触发 | 程序执行 | 80% 警示／100% 硬停；硬停只阻止新运行并显示原因与恢复入口 | PROD-PLAT-08 |
| 预算已变更 | 人确认 | 操作者、对象范围、前后版本与时间；进入审计 | PROD-PLAT-08 |
| 报表已生成（按项目／活动汇总） | Agent／受控作业 | 范围、统计期、币种、来源、计算口径及更新时间；已发生、预测和模型解释分开 | BIZ-17、BIZ-19 |

边界：

- 项目／活动不得替代任务、阶段或合作关系本身（BIZ-19）。
- 项目／活动的字段、状态机、可见范围、分配／领取规则＝规则空白；口径未发布前，界面与接口不得自行补全（BIZ-19）。
- 预算报告不执行付款或预算调整；源数据不足时报告缺口，不用模型填造金额、订单、效果或员工绩效（BIZ-17）。

## 11. 记忆与索引（派生事件层）

| 事件（事实句） | 产生方式 | 关键载荷与证据 | 依据 |
|---|---|---|---|
| 索引已更新 | 事件驱动（新邮件、任务变更、归属变更、审批结果） | 同一来源版本不重复提炼摘要 | PROD-AGENT-07 |
| 摘要已更新 | 后台 Codex 作业 | 参与方、时间范围、关键约定、未决问题、下一步及原引用 | BIZ-18、PROD-AGENT-07 |
| 摘要已失败并标记过期 | 后台作业 | 保留旧摘要，不伪造新摘要 | PROD-AGENT-07 |
| 记忆已记录／已修改／已删除 | 员工快捷指令（直接访问记忆服务） | 不创建 thread／turn；≠ 业务事实写入 | CONST-07、PROD-AGENT-01/04 |

边界：

- 摘要和模型推断不能覆盖原始事实；正式状态、权限和金额必须能回到权威记录核验（CONST-06、BIZ-18）。
- 记忆生成失败不得回滚已成功的事实（如发信）；通过可重试作业修复索引（PROD-AGENT-07）。

## 12. 事件 → 规则 → 动作 → 新事件（KOL 版链条）

1. **逾期未互动回公海**：「有效往来中断计满 14 天」→ 规则复核最新互动与当前归属版本 → 自动释放动作 → 「归属已自动释放」事件 → 公海可见性更新 → 记忆索引更新。
2. **回复驱动的阶段推进**：「邮件已到达」事件 → 回复理解规则（证据优先级）→ 建议（Artifact，不直接改状态）→ 人确认 `confirm_stage`（必要审批叠加）→ 「阶段已变更」事件 → 对应 SOP／后续任务。
3. **发布与结算**：「发布证据已核实」→ 建议 → 人确认 → 「已发布」阶段事件 → 结算流程（发票／付款事件）与效果复盘任务。
4. **任务回环**：「风险已识别」事件 → 规则 → 「任务已创建」事件 → 人执行 → 新的业务事件（任务篇 §2.4 闭环）。

## 13. 禁止的事件模式（对照宪法与基本法）

| 反模式 | 为什么不允许 | 依据 |
|---|---|---|
| 发送成功 → 自动写阶段事件 | 发送≠推进阶段；唯一写入口是 `confirm_stage` | BIZ-11/12、stage-transitions §3/§4 |
| 模型建议／摘要／评分直接写正式状态 | 建议不直接改正式状态；推断不能覆盖事实 | BIZ-13、CONST-06、PROD-AGENT-04 |
| 回执不确定 → 宣布发送成功 | 不得宣布成功或盲目重复发送 | BIZ-11、TECH-BE-03 |
| 重试／重放 → 重复副作用事件 | 幂等要求 | TECH-BE-03 |
| 旧审批覆盖新版本 | 版本变化后旧审批不能自动覆盖 | BIZ-15 |
| 旧定时任务释放已续期／已重分配的归属 | 执行前复核最新版本；旧任务作废或重排 | BIZ-06、TECH-BE-05 |
| 未授权 AI 建议直接成为任务 | 未授权建议保持候选 | BIZ-16 |
| 摘要失败 → 伪造新摘要 | 保留旧摘要并标过期 | PROD-AGENT-07 |
| 用接收时间替代发生时间 | 到期执行读发生时间 | TECH-BE-05 |
| 用远端「只能相邻写」作为产品禁止跨段 | 物理适配不得改写产品边 | stage-transitions §6 |
| 后台事件依赖员工打开页面 | 后台独立入口、按已授权流程运行 | CONST-07、BIZ-06 |
| 导入前把候选冒充正式档案 | 导入成功前不能冒充正式 KOL 档案 | BIZ-10 |
| 把工具返回名单当组织权限事实 | 名单不能自行生成组织权限 | BIZ-02 |

| 空白 | 影响的事件 | 责任角色 | 依据 |
