## 一、口径：什么算一个「对象」

本体口径（[本体六构件](本体六构件-定义与实例.md) §1）：对象是业务世界里的「名词」——一类有唯一标识的事物；区分**类型**（schema，如「合作关系」）与**实例**（如某条 `公司 + 品牌 + 活动 + KOL` 的合作记录）。Palantir 官方四件套（对象类型/属性/链接类型/动作类型）与讲解用六件套口径一致，本文只处理「对象」这一构件。

落到本项目，收录标准三条（每条都能被法条核验）：

1. **有稳定标识**：KOL 使用平台及稳定外部 ID 识别；同名、昵称相似或邮箱前缀相同不能认定为同一对象（BIZ-01）。记忆条目至少能识别「对象类型与 ID」（PROD-AGENT-05）。
2. **有条款依据**：业务对象由 KOL 业务专家定义（CONST-04）；平台不把 KOL 名称、阶段、期限、审批金额或事实写死在内核（CONST-02）。
3. **有权威来源，或已登记来源空白**：业务专家为每类业务事实指定来源、有效期和冲突处理口径（BIZ-02）；来源未定的登记为空白（本页 §八），不自行补全。

分层（依据 CONST-02「平台与业务分离」）：本清单分三层——**平台对象**（平台内核，跨试点复用）、**KOL 业务对象**（业务包）、**组织与治理对象**。同时单列「不是对象的项」（§六），防止把配置值、界面和动作混进对象层。

## 二、与宪法法规的对照要点

| # | 本体口径（研究笔记） | 本项目法条 | 对照结论 |
|---|---|---|---|
| 1 | 对象 = 一类有唯一标识的事物 | BIZ-01（稳定外部 ID；同名/邮箱前缀不能认定同一）、PROD-AGENT-05（对象类型与 ID） | 一致；本项目额外给出识别与去重口径 |
| 2 | 平台承载对象与业务定义对象 | CONST-02（业务对象、关系、动作、规则、流程及事实来源由业务专家定义，不写死内核）、PROD-PLAT-03（平台提供承载机制，不替业务先定规则） | 一致；本清单据此分三层 |
| 3 | 事件是已发生的事实；属性由事件触发规则重新计算（事件溯源） | CONST-06、BIZ-02（摘要和推断不能覆盖原始事实；权威事实源由业务专家指定）、PROD-AGENT-07（有效业务事件提交后更新对应索引） | 部分一致：本项目把业务事件用作记忆与审计的触发源；正式状态、权限和金额必须能回到权威记录核验（BIZ-18），事实自动写入是未来路径（BIZ-12） |
| 4 | 所有修改都必须走「动作」 | CONST-05（读数据、写草稿、执行正式动作分清）、BIZ-14（L1/L2/L3、确认、审批、回执）、07-mcp（工具风险目录与物理闸门） | 一致；动作 = 受控动作 + 确认/审批/回执 |
| 5 | 规则是「始终有效的法律」（派生逻辑 + 约束校验） | CONST-03（确定的权限、审批和状态规则必须被程序执行）、CONST-10（规则要说清责任、条件和可观察结果）、stage-transitions | 一致；规则归属有明确责任角色（CONST-04） |
| 6 | 六件套与四件套为同一含义的两种讲解口径 | CONSTITUTION 引言（条款已写明不代表已实现）、ia §2（未实现不降等） | 讲解口径无冲突；落地状态另行登记 |

补充：项目的「发送 ≠ 推进阶段」「使用 ≠ 治理」「L1–L3 分档」等治理不变量，是本体通用模型之外的附加约束；它们不属于「对象」构件，故只在 §六 作为「不是对象的项」登记，不混入对象清单。

| B14 | 项目 | KOL 业务包的承载对象；成本按项目/活动汇总 | BIZ-19、PROD-PLAT-02、PROD-PLAT-08 | 待业务专家发布字段（见 §八） | 不得替代任务、阶段或合作关系本身；界面与接口不得自行补全口径 |
| B15 | 活动（Campaign） | 活动隶属项目；合作关系引用活动 | BIZ-19、BIZ-01、org-permissions | 待业务专家发布字段（见 §八） | 同上；分配/领取规则待发布 |
| B16 | 邮箱 / 发件箱 | 品牌邮箱与邮箱授权；负责人状态（在职/已移交/停用） | BIZ-04、BIZ-02、domain-objects（邮箱字典） | Starry 邮箱授权 + 个人绑定（设置端） | 不得默认第一只邮箱；不能用名字或邮箱前缀匹配代替授权 |
| B17 | 采集批次（source_batch）/ 发现计划 | 异步采集的批次载体；同一时间只跑一个采集任务 | BIZ-10、BIZ-02、07-mcp | Host 侧入库（`upload_creators`） | 每个 source_batch 独立确认；禁止采集任务结束时直接写 Starry；缺邮箱不能靠编造解决 |
| B18 | 报表 | 预算、预计支出、合作进度、转化、履约、ROI、人员工作量 | BIZ-17 | 业务专家指定的现行制度和可信数据源 | 必须定义范围、统计期、币种、来源、计算口径及更新时间；已发生、预测和模型解释分开 |

示例串（虚构，仅示意对象之间如何连接）：采集批次 → 线索（CreatorCandidate）→ 导入 → KOL 画像 → 建联 → 员工跟进关系 → 合作关系（公司 + 品牌 + 活动 + KOL）→ 报价 / 合同 / 样品 / 内容 / 结算 → 任务 / 审批 / 风险 / 邮件；任一环节的写入仍按各自动作的确认与审批要求执行。

## 五、清单 C：组织与治理对象

依据：[org-permissions.md](../org-permissions.md)（组织、范围、PEP、确认/审批/审计）与 BIZ-03。

| 对象 | 含义 | 条款依据 | 来源 / 备注 |
|---|---|---|---|
| 公司 / 租户（Company / Tenant） | 公司级范围与租户边界 | org-permissions、PROD-PLAT-02、BIZ-02（组织 registry 提供组织授权事实） | 机器可读：`config/org-registry.yaml`（实施证据） |
| 组织单元（OrganizationUnit） | 人员与职责归属树；人员不是组织树节点 | org-permissions、BIZ-03 | 中心/部门/项目组/团队 |
| 用户 / 员工（User） | 真人账号；跨部门通过成员关系表达，不复制用户记录 | org-permissions、BIZ-03 | 账号停用等走 PROD-PLAT-07 |
| 成员关系（CompanyMembership / OrganizationMembership） | 用户 ↔ 公司 / 主组织与协作组织 | org-permissions（关系模型） | 各关系不能合并成 `owner_id` |
| 品牌（Brand）/ 区域（Region） | 业务经营维度与区域 | org-permissions、BIZ-03 | 机器可读：`config/brand-registry.yaml` |
| 品牌 / 区域范围（BrandScope / RegionScope） | 可服务的品牌和区域；部门负责人按已确认政策自动为全部范围 | org-permissions、BIZ-03 | 普通员工不继承该范围；高风险动作仍需确认与审批 |
| 职责分配（ResponsibilityAssignment） | 对目标与规则负责（业务负责人/品牌负责人/审批人） | org-permissions（关系模型） | 与 `task_assignment`、`approval_assignment` 分立 |
| 角色 | platform_admin / company_admin / department_admin / agent_operator / employee / auditor | org-permissions | 角色不是数据范围 |
| 技能授权 | 人员授权只对技能 | CONST-02、PROD-PLAT-05、org-permissions | 连接器与工具不按人授权 |
| 技能 × 工具绑定 | 每个技能可调用哪些工具 | org-permissions（`/admin/agents`） | 治理页只读展示 + 治理入口 |
| 凭据引用（credential_ref） | 连接器凭据的「位置」而非原值 | org-permissions（`/admin/connectors/:id`） | 永不回显原值、JWT、Key、Bearer |
| 审批分配（approval_assignment） | 某次高风险动作的审批权 | org-permissions（关系模型） | 与 B12 审批记录、A4 审批流程配置分立 |

## 六、不是对象的项（防混用）

| 项 | 为什么不列为对象 | 依据 |
|---|---|---|
| 阶段码（15 个正式阶段 + exception） | 是合作关系上的「值/节点」，由阶段图与配置管理，不是独立对象 | BIZ-08、stage-transitions |
| 风险标签、主平台、语言、邮箱品牌、负责人状态、爬虫状态 | 字典 / 枚举，是对象的属性取值 | domain-objects §2/§3 |
| 公海 | 归属与可见性状态 / 视图（只答“有哪些当前可见、可分析或可领取的对象”） | BIZ-06、BIZ-07、ia §5 |
| 看板 / Pipeline / 首页模式 | 界面 / 业务包表面 | PROD-PLAT-02、ia §1/§5 |
| 评分 | 派生属性，须注明依据、版本和不确定性；不是正式业务事实 | BIZ-10、BIZ-02 |
| 摘要、推断、测试夹具 | 非正式业务事实；不能覆盖原始事实或授权规则 | CONST-06、BIZ-02 |
| 发送 / 暂存 / 导入 / 解密 / 删除 / 分享 / 导出 / 归档 / 转办 | 动作与生命周期处置，不是对象；发送 ≠ 推进阶段 | BIZ-11、BIZ-14、PROD-PLAT-07、[AGENTS.md](../AGENTS.md) §5 |
| 人工接管 | 处置能力 / 状态入口，依附 Task / WorkItem | PROD-PLAT-02「人工接管」 |
