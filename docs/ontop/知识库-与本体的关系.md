# 知识库：与本体的关系

> 整理时间：2026-10-01
> 本篇是《企业智能体与本体论研究笔记》的拆分文件之一，聚焦"知识库"及其与本体的关系。

---

## 1. 对比表

| 维度 | 知识库 | 本体 |
|---|---|---|
| 回答的问题 | 书上是怎么写的 | 世界是什么样 |
| 内容形态 | 文档集合（手册、政策、会议纪要、FAQ） | 结构化业务语义（对象/属性/关系/事件/规则/动作） |
| 组织方式 | 按文档，向量切块、语义相似度检索 | 按业务语义，精确的对象与关系 |
| 口径 | 三份文档可能三个定义，RAG 和稀泥 | 有且只有一个定义、一个计算规则 |
| 能不能算/干 | 只能回答，不能计算也不能行动 | 能推理、能计算、能通过动作执行 |
| 时效 | 文档更新向量库没重建就答过期答案 | 属性实时同步，规则走版本管理 |

## 2. 典型问题分流

- "退货政策怎么写？" → 知识库。
- "客户 A 上月退货金额是多少？" → 本体/结构化业务数据。
- "客户 A 的退货是否应该批准？" → 本体提供事实，知识库提供政策依据，规则和动作完成判断与执行。

## 3. 三条连接线（互补而非替代）

### 3.1 知识库挂载到本体上

拜访纪要属于客户A、合同关联订单B。先通过本体定位，再在范围内检索——这就是"把所有档案柜扔给天才"问题的解法：碎片有了对齐的地图。

### 3.2 知识库是本体的原材料和注释

建本体时从文档提取对象与规则；本体术语可链回政策原文（每个术语有出处）。

### 3.3 Agent 双手并用

查本体拿精确事实（逾期金额到底是多少），查知识库拿背景和做法（话术怎么写、政策原文怎么说）。

## 4. 一句话总结

- **只有知识库没有本体**：AI 是"背了很多书但分不清东南西北的书呆子"。
- **只有本体没有知识库**：AI 是"精明但没文化的人"。
- 两者连起来，AI 才真正懂这家公司。

**知识库是必要条件，本体是充分条件。**
