## 0. 属性口径与引用

### 0.1 整理方法

需求（整理 KOL 业务对象属性清单）→ 主责角色：KOL 业务专家（业务对象、关系与权威数据源，CONST-04）→ 按 BIZ-01 / BIZ-18 / BIZ-19 列出对象 → 按条款提取属性（值域、来源、口径）→ 标注规则空白 → 输出对照发现与审宪记录（§7、§8）。平台侧只做整理，不改写业务口径。

### 0.2 列定义

| 列 | 含义 |
|---|---|
| 属性 | 业务属性名；括号内的英文 code 取自现行实施资产（`domain-objects.md`、`07-mcp-data-contract.md` 等），仅作对照线索，不是平台契约 |
| 基础／派生 | 基础＝存进去的；派生＝算出来的（本体六构件口径） |
| 业务类型 | 整理建议：文本、枚举、日期时间、金额（币种）、引用（对象 ID）、布尔、结构化文本；最终以对象注册表与业务专家确认为准 |
| 权威来源与血缘 | 来源系统；口径与新鲜度要求（BIZ-02） |
| 口径与规则 | 该属性的业务口径、值域或计算规则；未定义写「未细化」 |
| 依据 | 条款编号或细则章节 |
| 缺口备注 | 规则空白、待补证据或对照发现 |

### 0.4 三条与属性直接相关的硬规则

1. **属性归属**：价格、阶段、邮箱、合同、负责人和 ROI 挂**合作关系**（公司 + 品牌 + 活动 + KOL），不挂全局 KOL（org-permissions §KOL 归属；BIZ-18）。
2. **身份识别**：KOL 使用平台及稳定外部 ID 识别；同名、昵称相似或邮箱前缀相同不能认定为同一对象（BIZ-01）。
3. **副作用分离**：发送 ≠ 推进阶段（BIZ-11／BIZ-12）；确认发送 ≠ 组织审批（org-permissions §三类执行）。
