# 员工审批通知与发起入口修复

用户要求：将站内通知展开三角改为铃铛和数字角标，修复新建审批入口；沿用此前合并 main、push、deploy 和仅验证相关功能的授权。

## 实施与验证

保留旧通知数组接口兼容；新增只读 inbox 投影同时返回列表和未读总数。没有数据迁移、预置或自动发布生产流程。通知只在审批详情成功打开后调用现有本人已读接口。

限定验证通过：2 个 PostgreSQL API 用例（全部未读计数、列表上限、本人已读、公司隔离及现有提交确认后重验），8 个 Chromium 用例（铃铛与计数、已读、键盘关闭、窄屏、加载/详情失败、配置缺口恢复、角色和 intake、提交确认、草稿与触控）。前后端类型检查及前端生产构建通过。界面用例使用 HTTP 夹具，接口用例使用独立测试数据库；未写入正式生产审批或发布公司流程。

发布按服务器现有独立目录方式执行：以合入 main 的固定 SHA 创建审批发布目录，保留前一线上目录中的 5 项既有补丁（发现导入、Starry、相关测试和候选状态）。复制受限环境配置，共用原数据目录；构建成功后切换 API、Outbox 和两个执行 Worker。原开发工作区与前一发布目录不修改，失败恢复原服务路径；不执行数据库迁移。最终版本与健康回执保存于本次工作区的 artifacts。
