# 阶段5：通用对象选择与业务化技能创建

基线：GitHub main `3c9a5d2b`。范围：复用已有技能草稿、测试、发布、Agent装配和Codex执行链，统一新建、上传、编辑入口。

## 实现

- 对象选择器从真实公司可用目录读取业务族、域、主题、对象及动作，不硬编码六主题或KOL对象。搜索与筛选保留已选对象；正式版本变化须明确采用，未发布对象允许暂存但不能通过测试/发布依赖检查。
- 共用业务表单保存用途、适用条件、业务对象或通用范围、必要/推荐上下文、能力、输入引导、工作方法、成果和失败恢复。保存仅产生技能草稿或候选，不授予人员资格、不发布、不装配到Agent。
- 上传先解析到同一表单，不执行文档指令、不启用运行资产声明；保存时保留第三方来源。内置技能可查看或复用为新草稿，原资产受保护。
- 新元数据和实时context沿现有SKILL.md及注册解析链传递。邮件线程、会话等仍由既有实时上下文解析器读取；邮件内容不构成审批或合作事实。
- 编辑候选保留原运行包，使用版本摘要及数据库条件写入拒绝陈旧/并发覆盖；依赖检查不调用模型或业务工具。原发布前检查、测试证据、工具挂载、审批和Agent资格链继续适用。

## 验证边界

只验收本次表单、对象/版本选择、上传解析、草稿并发/权限和既有能力契约；桌面与一个窄视口。没有验收32个技能、全部设备矩阵，也没有批量迁移已有技能。阶段6的多个业务技能不属于本次交付。保存/检查不等于完成技能的真实模型试算、依赖实施或正式发布；新副作用和新异步协议仍需按原执行闸门接入。

实际交付验收：16项定向用例通过（9项原生PG创建/版本/权限/候选测试及7项既有能力契约），后端类型检查与前端生产构建通过；真实Host页面完成保存重开、刷新、上传解析、离开保护和两个限定视口。源码及证据哈希已通过 development-verify 校验；AI页面复核不冒充真人签字。
