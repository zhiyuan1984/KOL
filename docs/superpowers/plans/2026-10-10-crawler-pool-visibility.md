# 爬虫公海来源独立可见性修复

## 需求与审查

- 用户 2026-10-10 19:23:03 +08:00：修改阻断规则，让保留的爬虫档案在公海可见。
- 主责：KOL 业务规则由本次用户决定；后端专家实施查询；测试经理验证归属隔离与真实页面。
- 宪法：CONST-04（业务规则决定权）、CONST-05（不扩大授权）、CONST-06（来源与姓名不是归属证据）、CONST-08（先审查）、CONST-10（真实交付）。
- 基本法：BIZ-01、BIZ-03、BIZ-05、BIZ-07（本次新增来源独立规则）、BIZ-18；TECH-BE-01/03/06/08 与 TECH-TEST-01/02/03。
- 结论：符合。公开查询仅为 `crawler` 来源解除“旧合作负责人姓名存在但 Starry 快照不存在”阻断；已验证归属、本地跟进、品牌锁、公司范围和公开字段白名单保持不变。

## 根因证据

- 清理后本地开放档案仅剩 14 条 `crawler`。
- 14 条均有旧合作 `owner_name`，但没有相应 `starry_profile_ownership` 快照。
- 当前 Starry 归属同步状态为 failed，故障记录更新时间在本次删除之前；源列表编号不一致。
- 原 SQL 将这些爬虫档案全部排除；后置校验把零匹配当成公海归属故障，接口返回 503。
- 历史合作负责人姓名不能独立证明爬虫档案的当前员工排他归属。

## 实现

1. `p.ingest_source='crawler'` 仅豁免旧合作姓名+缺快照的排除条件。
2. 保留已核实并绑定有效员工的 Starry 归属过滤。
3. 保留本地 active follow（同 UID 或同平台稳定账号）过滤。
4. 保留查看者品牌锁、公司范围、发现候选排除和公开字段白名单。
5. 来源依赖档案计数与页面计数在同一个 SQL 查询内完成。后置 failed 判断仅在“整体可见集为空且仍存在依赖 Starry 核验的非爬虫开放档案”时触发。
6. 搜索无匹配、阶段筛选无匹配、分页超界及纯爬虫确实空集不因无关 Starry 故障报 503。
