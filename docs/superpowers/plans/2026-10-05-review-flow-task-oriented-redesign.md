# 管理侧评审流程四步改造计划

日期：2026-10-05。状态：代码改造完成，影响范围验证通过；未发布。范围：流程列表及四步编辑页；本计划基于现有代码与用户文字评审，未直接查看原截图，不表示生产验收完成。

目标：管理员能够知道每步需要完成什么、系统如何判断、为什么可以继续。统一路径为「基本信息 → 表单设计 → 评审步骤 → 检查与发布」。

## 3. 四步任务与完成契约

步骤状态统一为「待完善 / 已完成 / 有问题」，正在保存、检查及检查过期属于独立操作状态。数量只作为次级信息。所有通过状态绑定当前定义修订；未检查时不得显示已完成。

| 步骤 | 要完成的任务 | 完成依据 | 主操作与继续条件 |
|---|---|---|---|
| 基本信息 | 明确名称、发起说明及创建归属 | 名称合法且创建默认名称已确认或修改；说明可选，符合长度限制；归属由服务端接受 | 「下一步：表单设计」；满足本步最小有效条件，保存成功才切换 |
| 表单设计 | 设置员工填写字段并查看实际效果 | 字段名、类型、选项、数值规则等通过同源检查；无字段的通用流程显示「无需填写字段」；知识系统字段保持契约 | 「下一步：评审步骤」；字段配置无阻断问题且保存成功 |
| 评审步骤 | 配置路径、处理规则及人员来源 | 结构、连接、条件及静态人员规则通过服务端检查；动态人员规则标「需按发起人验证」，不宣称对所有人解析成功 | 「保存并检查」；允许带问题进入最后一步，由检查区集中说明和定位 |
| 检查与发布 | 解决配置问题，按需验证样例，确认生效版本 | 最新已保存修订的配置检查通过；试运行作为单独证据；服务端发布时再次核验权限与版本 | 「发布流程」；不存在阻断项、未保存修改或过期检查，且当前版本尚未发布；点击后进入现有确认 |

创建时通用名称改为空并使用占位提示；预置知识名称可以保留但要求管理员确认基本信息。名称确认属于编辑会话状态，不写入业务定义。重开已有有效草稿不要求重复确认默认文案。

步骤条可返回所有已到达步骤，保留输入；向前跨步走同一继续契约，不能绕过必需信息。返回不要求用户为修改先保存。脏修改返回最后一步时统一保存并检查；保存失败停留原编辑内容并展示「重试保存」，不丢输入、不继续检查。

草稿允许不完整：顶部工具区保留低强调「保存草稿」、撤销和重做；它们不代表本步已完成。底部仅保存状态、上一步和唯一主操作。离开时继续提供保存并离开、放弃修改、留在此页。

## 4. 保存、检查、试运行与发布状态

1. 单一导航函数管理下一步、向前步骤点击及「去修改」回访。save 返回实际保存对象，后续检查使用返回的模板 ID、版本和定义快照；无脏修改不重复写入新版本。
2. 引入独立 `saveState`、`checkState`、`trialState`；保存显示未保存、保存中、已保存版本、保存失败；检查显示未检查、检查中、通过、有问题、已过期、服务失败。
3. 检查结果绑定 tenant、templateId、savedVersion、definitionRevision；请求序号或 AbortController 防止乱序。修改、撤销、重做、归属变化使旧结果过期；撤销回原内容也重新检查，不复活旧确认。
4. 试运行结果还绑定测试发起人、测试数据修订及可获得的组织上下文版本。只改测试数据使试运行过期，不使结构检查过期；改流程使两者都过期。服务端执行时仍按最新组织事实解析。
5. 最后一步进入即保存（如需要）并自动检查。检查不需要测试人员及测试表单；失败按问题类型显示具体原因和恢复入口。
6. 发布继续 `useReviewCommand` 的 prepare → 确认 → commands。确认摘要包含当前版本、归属、变更与影响；确认期间锁定编辑，服务端再次检查防止其他管理员或组织变更后提交旧确认；成功显示回执与生效版本。
7. 发布禁用原因给出一个明确的优先原因：保存中 / 保存失败 / 尚未检查 / 正在检查 / 配置已修改 / 还有 N 项配置问题 / 当前版本已发布。网络错误不能呈现为「配置不合法」。
8. 试运行中或确认中限制冲突操作；重试保存前处理「响应丢失但可能已写入」：已有草稿重新读取并比对内容，409 不覆盖远端；新建保存需要幂等创建键或可恢复请求记录，不能盲目重复 POST 生成多个草稿。

## 5. 页面结构

### 5.1 列表及外围

- 列表改紧凑表格：流程名称、草稿版本、已发布版本、版本关系、操作；名称打开编辑，启停移至列表次级操作，保留正式动作确认。
- 版本关系区分未发布、与发布版一致、有未发布修改、正在加载、差异加载失败。先使用相同版本快速判一致；不同版本依内容 diff 判定，不逐行无节制请求，可按需或由列表接口批量返回关系。
- 编辑顶部一行真实组织路径及切换入口，下一行页面标题、流程名称与草稿标记；名称、状态避免重复出现。完整层级从组织树推导，不固定三级或四级。
- 修改归属放入显式面板，说明只变更创建归属；跨公司切换不得静默迁移草稿，说明会离开当前公司编辑上下文，脏修改执行保存/放弃保护。
- 顶部工具区与底部操作区固定可见，主体一个纵向滚动容器；画布/表单长内容避免再叠纵向滚动。窄内容区按实际可用宽度堆叠，不强行维持比例。

### 5.2 表单设计

- 宽内容区编辑/预览并排，以约六四的内容分配为目标，服从右侧可读宽度与 DESIGN 容器规则；窄区切换编辑/预览，输入与选中项保留。
- 列表头「表单字段 · 数量」与辅助「添加字段」同排；行内固定角色列：排序、名称、类型、必填、操作，名称可伸缩，操作不挤压名称。
- 选中字段才展开其专属配置；新增立即选中并聚焦名称，保留现有聚焦能力；拖动与上下移结果一致。
- 删除图标有可见或可读名称、提示和键盘入口；利用现有历史提供「已删除，可撤销」。删除被条件或补充材料引用的字段明确列出影响，检查定位引用错误，不静默删除相关业务规则。
- 系统字段继续锁定名称、类型、必填和删除；排序是否保留现有限制按原契约核对，不因新拖动绕过锁定。
- 预览复用 `ReviewForm` 并新增无上传副作用的预览模式；显示当前标签、顺序、必填与类型，预览值单独保存，不写入定义；删除/改类型后清理不兼容预览值。

### 5.3 评审步骤

- 画布按 next/otherwise 的真实有向图渲染，起点/终点为固定小标记；评审、征询、办理和抄送卡显示名称、方式、人员来源摘要及待修复问题。
- 连接处「＋」菜单显示名称与说明：评审—指定人员作出决定；条件分支—按表单进入不同路径；抄送—通知相关人员；征询—征求意见；办理—执行事项。菜单和试运行均为辅助样式。
- 右侧三组：步骤信息、人员与方式、处理规则。转交、加签、补充材料与超时折叠；按服务端能力展示，不给征询/办理新增不支持的操作。
- 人员摘要区分指定人员未选、角色未选、已配置指定人员、动态「发起人所在组织负责人」。权限和实际解析人来自后端；前端只描述规则。
- 明确继续条件：抄送无需决定，成功解析并生成抄送后继续；征询/办理按单人、全部、任一或依次完成继续；评审保留同意及拒绝规则。试运行略过真实处理动作，不展示已实际完成。
- 顺序流程插入/移动/删除原子更新入边与出边，移除普通「下一节点」。默认新步骤可以保留现有人员来源，但用摘要明确其动态含义。
- 分支在「条件满足 / 条件不满足」路径上分别插入；展示汇合及嵌套分支，不能复制共享节点制造两份执行步骤。新增条件初始可两路到同一后续步骤，但明确「两条路径当前相同」。
- 分支流程不保留仅改变数组顺序的排序按钮。移动只允许到明确连接位置并修复原路径；无法安全解释的复杂图保留忠实图展示和路径目标选择，禁止自动改为线性流程。
- 删除普通步骤可接回后续步骤；有多入边、分支或汇合时先列出影响，要求选择保留路径或拒绝歧义操作。起止不可删除、拖动或移动。
- 「待配置」显示缺项；点击问题直接选中步骤、展开对应组并聚焦字段。后端 issue 同时兼容现有数组索引与节点 ID 路径，优先增加稳定 target 标识。

### 5.4 检查与发布

- 左侧配置检查：基本信息/归属、表单规则、步骤连接/条件、人员与处理规则；每项通过、有问题或需要样例验证，缺项不渲染假通过。
- 右侧路径试运行：「测试发起人」、测试表单、辅助「开始试运行」。说明：选择一位员工，查看其发起时匹配的分支和处理人；不会创建正式申请。
- 路径结果呈现有序步骤、条件命中/不命中及依据、各步骤真实解析人、阻断位置和原因。保持多个同一步骤处理人的分组，不把 tasks 逐人拼接成多个执行步骤。
- 后端返回完整路径 trace，不在前端另实现条件求值或人员解析。可保留旧 path/tasks/status 兼容调用者，但 UI 映射为「路径可解析 / 路径阻断 / 测试数据有问题」，不把 approved 显示为审批通过。
- 动态人员和条件分支显示建议验证项及未验证路径；本轮不声称自动枚举全部条件组合或全人群覆盖，也不强制增加试运行发布门槛。
- 「填入示例数据」本轮不新增，按钮使用「开始试运行」；必填知识系统资料引用与附件采用隔离的测试输入契约，缺少合法测试值时如实提示，禁止编造正式资料或上传凭证。
- 发布差异作为检查侧可展开区；功能说明收起。启停移出向导底部。底部保留保存状态、上一步、发布流程及不可用原因。
