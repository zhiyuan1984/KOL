# 公海评分可解释性与长文本换行修复

## 审查记录

需求 → 主责角色 → 宪法条款 → 基本法条款 → 结论与证据 → 下一步：

- 需求：修复公海卡片长文本不换行，并说明参考评分的真实来源，不能用目标筛选条件冒充评分理由。
- 主责角色：UI/UX 专家（信息分层与换行）、前端专家（契约投影与渲染）、测试经理（概率边界、不同宽度、可访问性与副作用回归）。
- 宪法：CONST-04（不修改业务评分、权限或阶段规则）、CONST-06（事实、推断与来源区分）、CONST-10（交付证据）。
- 基本法：BIZ-02、BIZ-10（评分不是正式业务事实，必须注明依据、版本、不确定性）；TECH-FE-02、TECH-TEST-01/02/03；DESIGN §1.7、§6.2、§9.3（窄栏与可读性）。
- 结论：**符合**。只解释已保存的公开评分数据，保留原始分数；不调用模型、不重新评分、不发信、不导入、不修改归属或阶段。缺失的逐项理由不由前端补造。
- 下一步：按服务器当前代码基线测试；以独立提交发布，避免回退或覆盖其他已部署修复。

## 只读根因核查

已通过服务器 PostgreSQL 只读查询核对用户截图对应对象。公开记录的潜力分为 1、置信度为 0.98，分类概率为 `high_potential=0, watch=0.01, insufficient=0.99`，模型 `jev-1.13`，版本 `jev-kol-v1`。代码中的概率权重分别为 100、50、0；加权结果 0.5，四舍五入为 1。

当前公开记录的粉丝、均播、互动、方向、地区和平台字段为空。存储的 `assessment_criteria` 是评分目标筛选条件，**不是红人已验证指标，更不是逐项评分理由**。当前字段不能冒充历史输入快照；模型置信度也不是红人质量或合作成功率。

前端原 `toPoolKol` 丢失概率和版本；评分依据只渲染目标条件。依据 `<details>` 位于身份 flex 行，使用 `width:auto` / `flex:0 0 auto`，长条件无法合理收缩。普通元数据 span 的匿名 inline-flex 文本也会溢出。

## 已知边界

本次不重评历史对象、不补采平台指标、不修改评分权重。历史逐项理由与评分时输入快照未在公海卡片契约中提供，因此只能展示可核对的概率与计算，以及明确的证据缺口，不能还原或编造逐项因果解释。
