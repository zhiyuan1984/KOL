# 阶段4：六主题与25对象契约对齐

目标：沿用用户确认的六主题与 `main@65b2b027` 已保留的25个对象身份，补齐可校验的属性、来源、关系及规则引用。实施基于 GitHub main `499e7f66`，不改业务族、业务域，不重复建设分类或治理页面。

## 实施

- 在通用 `ontology-definition-supplements.json` 中维护25对象的148项属性定义/校正、90项关系定义、32项规则引用。通过原目录加载器合并，保留原属性/动作/事件与稳定code；未涉及的企业规划对象继续为空，不伪造执行器。
- 达人资源：档案、平台账号、线索、来源批次分别保留身份；线索与正式档案的关联需要平台稳定标识及核实证据，批次、计划、异步作业分开引用。
- 达人评估：评估记录关联达人/账号及模型版本；报告引用评估与成果；标签定义与打标关联证据分开，当前评分不覆盖历史评估。
- 达人关系与沟通：建联、跟进任务复用统一任务身份；通信引用共享邮件/原渠道记录，区别于Agent会话；互动保留原证据。档案负责人、跟进负责人、合作负责人分别表达，线索状态、任务状态、合作阶段不混用。
- 达人合作与交付：合作计划引用项目、活动及单次合作；报价有版本与明细；协议/佣金协议复用统一合同身份与适用版本；交付任务引用统一任务及内容对象。
- 达人样品履约：寄样申请、履约单、样品事项与反馈分别关联，共享产品、SKU与物流运单；申请不代表发运，物流签收不代表本人反馈。
- 达人费用与结算：佣金结算复用统一结算身份、协议和期间，费用明细保留依据；付款事实引用共享财务付款单，不用结算或审批完成代替付款成功。
- 校验补充定义的对象身份、重复项、关系目标、基数及反向关系一致性，沿用原动作风险下限。该配置机制也验证了非KOL领域属性扩展，内核不增加达人分支。
- 目录导入与发布确认使用全部五份语义输入的同一来源指纹；属性或关系补充变化不会被旧导入回执误判为已同步。

## 版本边界

本轮交付的是对象类型及引用契约，不是新增真实业务实例、通用关系查询引擎或寄样/支付执行器。没有改写邮件实时上下文捕获、通讯正文、任务或审批模块，没有迁移历史 `collaborations` 数据。

目录导入保留公司已有正式快照、未发布草稿和历史。新定义需经原 `OntologyService` 的保存草稿、核对、确认、发布流程成为公司正式版本。两个已上线技能继续使用原 `kol_profile@revision2`，目录同步不会静默升级运行依赖或 Agent 发布版本。其它技能迁移、对象选择与技能创建页面按后续阶段实施。
