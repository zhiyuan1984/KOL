# 通用评审流程实现记录

日期：2026-10-04。状态：核心人工评审链路已实现，尚未发布；详细设计 D01–D17 没有全部完成。此记录只登记实现与证据，不修改现行法。

## 可操作入口

- 员工端 `/approvals`：已发布流程选择、动态表单、个人草稿、提交确认、本人参与的列表、评审进度、同意/拒绝/撤回、阻塞原因与重试、操作记录及回执。
- 管理端 `/admin/approval-types`：基本信息、表单、流程、校验与发布四个面板；侧栏入口为“评审流程”。
- 旧单据列表 `/approvals/legacy`，旧详情 `/approvals/:id`，旧类型管理 `/admin/approval-types/legacy`。新实例直达链接 `/reviews/:id`。没有重写历史单据或从旧链自动推算新图。

当前发布能力：短文本、长文本、普通数值、精确十进制、货币金额、日期、单选、多选、附件；开始、人工评审、字段条件、抄送、征询、办理、结束节点；单人、会签、或签、依次评审；指定组织人员、有效评审角色、发起人所在组织负责人。费用不是引擎前置条件；货币字段独立保存金额字符串与配置币种，不自动换汇。

无分支流程拖动处理节点会同步修改实际执行连线；有分支时拖动只调整画布顺序，连线在节点属性中明确编辑。上移/下移提供键盘与触摸替代。画布和节点属性共用同一份定义与撤销历史。

命令确认有效期 5 分钟，绑定当前操作者、组织、命令内容和人员/角色证据。重放先查当前授权范围内的旧回执，再判断确认有效期；命令内容变化不允许复用幂等键。实例与任务快照、参与人、确认消费、事件、回执在一个事务内提交。PostgreSQL 序列化冲突、死锁、唯一键竞争及 SQLite 写锁冲突有有界重试，最终返回明确冲突。

人员不会回落到默认员工；未知角色不会回落到主管；缺失条件值不会按零或 false 自动通过。发起人出现在评审人集合时阻塞。已撤销资格的原评审人不能继续决定；界面提示恢复资格或撤回重发。

## 本次续作：受控操作与持久超时

- 转交只接受发布策略候选人，原任务留痕；新任务在决定时重新检查当前组织资格。会签和依次评审支持受限加签，依次评审插入当前处理人之后。
- 补充材料只允许修改发布时列明的字段；提交后从起点完整重审。`review_revisions` 保留每轮材料，旧轮次意见不计入新轮次结果。
- 抄送产生真实站内通知并继续流程；征询和办理只能提交意见/完成，不能提交同意或拒绝。每条可达终点路径仍必须经过真正的评审节点。
- 超时作业通过现有 `execution_jobs`、`execution_outbox` 与 dispatcher 执行。工作进程校验租约、当前组织资格、实例轮次、任务状态及期限；同一事务写入结果与作业回执。撤回或任务替换后，旧作业到期只返回跳过。
- 自动升级要求发布策略解析出唯一合格目标，且最多升级一次。无法解析则保留待处理状态，展示接管原因并通知发起人，不自动批准。
- 站内通知只向收件人返回。尚未接入企业微信、邮件等外部投递；旧超时任务未提前物理删除，到期校验后失效。
- 运行自动超时需要部署现有 execution worker 及其 PostgreSQL/Redis 队列依赖；仅启动 Web/API 不代表定时执行已启动。本机验证使用 SQLite 真实存储、outbox、dispatcher 和回执，不冒充 PostgreSQL/Redis 集成验收。

## 本次续作：复合条件与模板启停

- 条件支持嵌套的全部满足（all）、任一满足（any）、取反（not）与原有字段比较；原有已发布单条件无需迁移。后端限制最多 6 层、100 项，每组 1–20 项，校验字段、类型、选项及未知属性；不执行脚本、不自动转换字符串与数值。
- 所有参与表达式的缺失字段都明确阻塞，不能借布尔短路隐藏缺失字段而选中另一条路线。设计器可编辑、增删条件与分组，共享原有撤销和保存状态。
- 管理端启停经过真实管理员资格、独立状态版本、确认、事务及幂等回执校验。停用在后端阻止新提交并从员工发起列表移除，已经发起的流程继续按快照处理。停用期间仍可编辑和发布，发布不会暗中启用模板。
- 确认证据增加模板与启停状态版本，停用后再启用不会复活此前的提交确认。模板原发布版本、已有申请与历史记录不因启停被改写。
- 新表 `review_template_lifecycle` 通过 SQLite 初始化与 PostgreSQL 增量迁移接入；迁移未在生产或 PostgreSQL 服务上执行。

## 本次续作：材料、恢复、检索与上线控制

- 发布差异由后端对照已发布版本生成，按字段/节点稳定 ID 匹配并单独列出顺序变化；管理端展示变更前后。
- 旧个人草稿提供升级预览和复制操作，检查原草稿 revision、目标发布版本及本人范围；仅复制同类型且通过新结构校验的字段，未兼容原材料保留在旧草稿。个人草稿停笔后自动保存，保存冲突/网络失败保留当前输入并暂停自动重试；正式确认期间不自动保存。
- 实例列表改为服务端参与范围过滤、标题/流程名检索和待办筛选，按不可变提交事件时间与 ID 游标分页，默认每页 30、最多 100。每次最多扫描 2000 条已授权记录，若尚未遍历完则返回继续游标，空结果页仍可继续。状态更新不改变排序锚点；暂不提供总数。
- 多组织选择只列出有效权威组织成员关系。客户端携带明确组织选择，后端每次重新核验；附件下载链接也携带组织范围并重新校验。
- 附件通过独立受权上传入口生成不可变 ID、大小及 SHA-256。当前采用数据库保存小文件原始字节的 base64 表达，单文件 2 MiB、单字段 10 个、每人每组织 100 MiB；不复用会向客户端暴露本机路径的个人工作区附件接口。提交和补充材料校验上传所有者，随后把文件引用绑定到实例与轮次；下载复核当前参与范围，核对摘要，使用 attachment/nosniff/no-store 响应，不内联执行文件。
- 上传中禁止提交；失败保留错误与重新选择入口。草稿移除附件引用不物理删除文件；原评审轮次仍可下载原文件。大文件对象存储、留存清理和对象引用字段未实现。
- `REVIEW_V2_NEW_REQUESTS=drain`（任何非 enabled 值均关闭新发起）在后端停止新提交，已有申请、超时 worker、历史查询与旧回执重放继续工作；默认 enabled。可用 `REVIEW_V2_COMPANIES` 逗号分隔组织 ID 控制定向开放，未设置时不额外限制，显式空值不开放任何组织。回退仍须保留识别 v2 数据的服务，不能直接换成完全旧版二进制。

## 本次续作：精确十进制与货币字段

- 新增 `decimal` 与 `money` 字段。十进制使用字符串；货币使用 `{amount, currency}`，金额必须为字符串。普通 `number` 字段兼容保留，旧数据不静默改型。发布快照、草稿复制校验、提交、补充材料与试运行共用后端验证。
- 流程管理端配置总精度、小数位及可选上下限；货币须显式配置币种代码字典及业务来源/版本。技术上限为 38 位精度、18 位小数；无默认币种、汇率或业务阈值。来源文本是发布者声明，尚未连接权威币种目录做来源真实性核验。
- 条件比较用有界字符串解析与 BigInt 对齐精度，支持精确相等及大小比较。不接受浮点金额、科学计数法、千分位符号、超精度数据或隐式舍入。货币比较要求同币种，缺值或币种不一致时流程阻断；嵌套条件及取反不掩盖该阻断。不提供汇率转换、货币合计或跨币种比较。
- 员工端显示精度/范围提示，金额与币种分别填写；当前及历史材料显示原金额文本与币种。管理端可编辑同币种条件阈值；发布差异对精度、范围、币种与来源提供中文标签。
- 新增精确数值边界测试、真实 HTTP 确认提交及轮次材料存储测试，以及管理配置到员工提交的浏览器夹具测试。未增加数据库表，也未执行生产操作。
