## 实现与切换

- 删除 Starry 环境变量读取、凭据文件自动扫描和 Codex 箱内远端请求头注入。
- 画像、邮件同步及业务 Gateway 复用通用 managed client，从已保存的连接配置解析保险柜引用。模型工具仍经 Skill Runtime 校验 Agent、装配、工具策略及版本。
- 删除画像查找、会话创建失败后的 Host 身份重试。
- 个人邮箱绑定的历史 `bearer_token` 列仅存保险柜 ID；已有明文值拒绝使用，返回迁移错误。探测令牌先写临时保险柜凭据，探测后删除；解绑和替换清理不再引用的个人凭据。
- Starry 模板拒绝环境变量及匿名配置；MediaCrawler、KOL Claw 本次不迁移。
- L1 只读提示来自已审核本地策略，同时尊重远端明确声明的写入或破坏性提示；L2/L3 不获得只读豁免。

发布顺序：停止旧服务的 Starry 使用入口，使用相同数据库及保险柜主密钥运行 `backend/scripts/migrate-starry-binding-vault.ts --apply`，再启动新版本并复测。脚本默认仅预检，支持重复执行，只输出数量。新版本拒绝未迁移的个人令牌。切换后可清理部署环境中已不被读取的旧 Starry MCP 参数；保险柜主密钥仍属于部署基础设施。

回滚注意：旧代码不能把保险柜 ID 当 JWT 使用。回滚须保持此连接层，或在受控维护窗口恢复切换前的数据库备份及原密钥；不要直接回退代码后继续运行。
