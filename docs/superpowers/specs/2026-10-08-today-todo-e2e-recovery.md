# 今日任务与我的待办：远端回归修复

需求 → 完成界面密度与标准 Tab 改造，远端验证，推送、合并、部署。

主责角色 → UI/UX 专家、前端专家、测试经理。

宪法条款 → CONST-04（前端呈现已定义规则）、CONST-06（事实与运行记录可追溯）、CONST-08（先审宪再审法）、CONST-10（交付证据真实）。

基本法与细则 → TECH-FE-01/03、TECH-TEST-01/02/03/04、PROD-AGENT-08/09、DESIGN §1/3.1/4.2；工具风险另遵守 07-mcp-data-contract，不由任务风险 chip 推导执行资格。

结论 → 符合。只恢复真实执行事件的可读性与既有服务端投影，不修改业务权限、审批、阶段或工具风险闸门。

证据与修复：

- `/api/workbench/tasks?view=todo` 返回所有未结责任；`view=today` 是其子集（backend/src/routers/tasks.ts）。E2E 改用 canonical 工作台接口，不再 mock 旧接口或把待办排除今日任务。
- 计划终态曾使真实事件步骤不可见，且没有展开入口。完成态默认折叠、失败态默认展开，均可查看和收起执行详情；失败原因与恢复入口保留。
- DESIGN §3.1 的任务风险低/中/高对应 R1/R2/R3；旧代码高低映射颠倒，现予修复。这是任务风险，不代表同编码的工具副作用档。
- 分析区使用“本次判断与依据”，移除重复完成时间；重试与详情入口使用 L3 文字按钮。
- “打开”任务只读最新详情，不应触发 acknowledge 或运行。E2E 验证零写入；明确审批动作仍走已定义 acknowledge 与审批入口。
- 摘要与异常筛选共用同一展示谓词，包含未结任务的上次执行失败与 last_error，避免摘要少计。执行失败且仍 pending 的任务在缺省文案中显示“待处理”，不显示“未开始”。新增回归覆盖独立刷新、清除筛选及摘要与过滤计数一致。
- 首轮修复后远端 28 项回归中 27 项通过，剩余鼠标操作失败暴露了侧栏折叠按钮覆盖任务明细关闭按钮。明细头部现预留与任务板相同的控件空间；“开始执行”降为 L3 文字动作，避免与中栏提问框形成两个实底 CTA。
