# 公海右栏头部收敛：范围定义迁入中栏

- **日期**：2026-09-27
- **模式**：Redesign · Preserve
- **范围**：Home「公海」模式。仅重分配中栏与右栏的交互职责；不更改公开 DTO、领取权限、阶段、后端命令或分析任务契约。

## 审宪记录（CONST-08）

| 需求 | 主责角色 | 宪法 / 基本法依据 | 结论与证据 | 下一步 |
|---|---|---|---|---|
| 将右栏头部的筛选、排序、批量分析和资料维护挪至中栏，引导人先定义问题再与 Agent 协作 | 智能体产品经理、UI/UX 专家、前端专家、KOL 业务专家 | CONST-03/04/05/08/10；PROD-AGENT-01/03/09；BIZ-07/14；TECH-FE-01/02/03；IA §5；统一工作台规格 §4、§9.4 | **符合**：中栏恢复为范围定义与提问的主轴；右栏仍只展示服务端授权的公开字段和独立 L3 领取动作。筛选或评分不推断权限；填写提问框不等于执行或发送。 | 用目标域 E2E 验证布局、范围和 L3 回归。 |

## 现状审查

右栏原头部同时承担五种不同性质的工作：

1. **定位结果**：搜索、筛选、排序；
2. **定义本轮范围**：全选、已选数量；
3. **开始思考**：`分析已选`；
4. **维护公开索引**：补头像、Jev 评分、清理无主页；
5. **展示对象结果**：公海行、公开字段与领取动作。

这使右栏既像“结果列表”又像“工作台”，压缩了中栏的对话空间。用户必须先理解一串工具，再回到下方 Composer；“我现在要让 Agent 判断什么”没有清晰入口。

## 职责重分配

| 信息 / 操作 | 新位置 | 原因与约束 |
|---|---|---|
| 搜索、筛选、排序 | **中栏：范围定义区** | 它们定义本轮分析的语境，而不是对象行的永久属性。结果仍在右栏实时收敛。 |
| 当前范围、全选、清除选择 | **中栏：范围定义区** | 让“我将和 Agent 讨论谁”在提问前可见；保持最多 8 位的既有选择上限。 |
| `填入提问框` 与两个问题起点 | **中栏：Agent 协作起点** | 只预填 Composer 并聚焦，绝不自动发送、领取、发信或修改阶段。提交后继续走既有 `kol_analyze` 入队契约。 |
| 补头像、Jev 评分、清理无主页及其确认 / 回执 | **中栏：资料维护区** | 三者是对公开索引的有意操作，不应与“领取此对象”争夺右栏头部。清理继续保持预览、数量锁和明确确认。 |
| 公海名称、数量、公开对象行、对象勾选 | **右栏：结果列表** | 结果集合和对象选择留在对象附近，便于扫描；不显示旧邮件、合同、价格、联系方式或私有笔记。 |
| `领取跟进`、确认、撤销领取 | **右栏：受控对象动作** | 领取仍是独立 L3 行内动作，继续要求确认；不与 Agent 提问共用提交路径。 |

## 人机协作路径

```text
中栏：搜索 / 筛选 / 排序
  → 右栏：勾选公开对象
  → 中栏：看到“已定义 N 位分析对象”
  → 中栏：选择问题起点或“填入提问框”
  → Composer：用户补充问题并决定是否发送
  → 既有 kol_analyze 流程：真实排队 / 结果 / 恢复状态

右栏：任何时刻都可发起独立的“领取跟进”
  → L3 确认
  → 真实回执 / 撤销入口
```

> **边界**：资料维护只处理公开索引；Jev 评分只是辅助信号；“填写提问框”不是执行；领取不发送邮件、不改正式阶段。

## 保留与回滚

- 保留 `?tab=pool`、公开 DTO 白名单、当前筛选结果批量选择、最多 8 位、`data-*` 测试锚点、分析入队、L3 领取确认与撤销领取。
- 没有修改后端 API 或业务规则。若需回退，只需恢复呈现组合；已发生的领取、清理或索引维护仍按后端真实回执展示。
- 右栏只调整布局职责，不成为新的 Agent 对话或独立任务脊柱。
