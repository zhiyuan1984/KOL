## 已发现的实现差距

- 路由懒加载与会话任务异步读取串联，首帧无法识别发现专项布局。
- 发现专项条件外叠加通用任务标题、状态、技能交互模板与手动完成。
- L3 卡默认展开原始参数；普通内部检查结论占据主回答。
- 文本清理将连续空白（包含段落换行）压为一个空格，破坏 Markdown 结构。
- 中栏 flex 子项允许收缩；新内容尺寸变化缺少完整的滚动状态更新。

这些是代码差距，不作为新业务规则。

## 验证入口

- `frontend/playwright.presentation.config.ts`：独立前端展示回归，所有 API 被测试夹具拦截，不接外部系统。
- `frontend/e2e/discovery-presentation.spec.ts`：延迟任务加载、发现首帧、条件与确认摘要、内部审查折叠、冲突可见、内容增长不抢历史视口、上下跳转、底部确认可达、统一字号与无横向溢出。
- 视口：1440×900、1024×589、390×700；减少动效启用。
- 前端构建包含类型检查；后端契约校验不启动真实工具。
- 验证结果：前端展示 E2E 五项通过，包含 Home 单一箭头与输入区可达；前端类型检查和构建通过；后端契约校验 valid（无错误、无告警）。

上述前端夹具验证不代表真实 Codex 输出或授权外部采集已验收。生产集成沿用原发布门禁。
