实施资产：用户审批页、旧单据页、ReviewDetail、ReviewActions、ReviewForm、useReviewCommand、知识材料、审批样式；发布名称校验及审批 E2E。

范围边界：知识发布仍由知识资料入口绑定真实文件后发起；员工不能在通用表单手填系统资料引用。旧费用仍使用原接口，并保留次级入口，不伪造迁移或归并身份。外部付款等结果仅展示服务端真实回执。

验证区分：浏览器夹具只验证交互；不宣称已完成生产部署或真实审批外部执行。

## 验证结果（2026-10-05）

- 前端 `npm run build` 通过（含 TypeScript 检查）；最终控件尺寸调整后再次构建通过。
- 后端 `npm run typecheck` 与 `npm run validate:contracts` 通过，契约无错误、无警告。
- `review-engine.test.ts`、`review-service.test.ts`：49 项通过，包含发布边界拒绝默认节点名、草稿保留。
- `approvals-workbench.spec.ts` 与 `review-workflow.spec.ts`：19 项浏览器夹具回归通过。个人草稿折叠后，既有恢复测试同步改为先打开草稿入口。
- 最终样式调整后，工作台 5 项及 PDF 审批材料 1 项重新通过；覆盖列表身份/搜索保留、当前步骤/记录排序、小高度/窄宽度动作可达、确认与失败意见保留、费用审批/业务结果分离、冻结原件/资料试算/发布时间。保存了工作台截图，并核对控件 token。
- `review-api.test.ts`：1 项通过、19 项失败；本机无 `DATABASE_URL`，权威组织/存储接口返回 500，不能据夹具测试宣称真实集成通过。
- 扩展知识发布管理侧浏览器套件原有 5 项均在访问旧管理入口后找不到 `[data-knowledge-publication]`。其中本次受影响的 PDF 审批材料测试已拆除对管理入口的依赖并通过；其余 4 项管理侧夹具问题留为既有回归缺口，未修改无关管理页实现。

状态：代码与适用规则/交互检查已验证；真实 PostgreSQL 集成与生产发布未验证。不会用本记录或夹具结果代替生产能力验收。
