## 已实现的路径

- 全局导航保持原位。中栏只筛选；右工作区互斥承载列表、详情、创建、修订、发布检查及人员绑定。
- 默认全部 Agent，不自动选中列表外对象。筛选、页码、选中项、滚动和焦点按账号与公司上下文保存；详情可用 URL 定位。
- 详情先呈现身份、职责和有效能力，随后呈现人员资格、考试、依赖条件、版本与审计。知识范围在查询技能下按需展开，技能和共享依赖有治理链接。
- 名称、职责和技能装配统一写入 R2 草稿。失败及版本冲突保留输入；冲突后可重新读取版本依据并明确核对。
- R3 发布先预检，列出增删及版本变化、覆盖范围、阻断和提示，再确认。确认依据绑定操作者、草稿、技能、资源配置、绑定及组织事实，十分钟过期；提交时重新核验。
- 发布原子切换有效装配、归档内容快照、删除本次草稿，并生成发布回执和审计。同一请求标识的重试返回原回执；已接入版本治理的 Agent 不能从旧装配 API 绕过。
- 历史 Agent 在首次修订时归档现有装配。界面明确区分最后管理更新时间与发布时间，说明原始发布人、发布时间和回执未记录。
- 停用、恢复已有版本、新增绑定及撤销独立于草稿。绑定预览变化后重新核对；撤销确认可无原因取消，实际撤销仍须原因。

本地隔离 PostgreSQL 端口 55472；独立测试库以随机名称创建和清理。原有组织内核和运行时测试使用本地模板库。测试夹具不调用业务外发接口。

- 前后端类型检查、前端生产构建：通过。
- 契约、注册表、脱敏扫描：通过。
- KOL 评价：16 个案例通过，附属红线及契约行为测试 11 个通过。
- 原生 PostgreSQL 发布边界：15 个案例通过，覆盖草稿隔离、冲突、原子发布、幂等、四种依据变化、过期与操作者绑定、启停、旧接口防绕过、运行时版本、撤绑与新建。
- 组织树与人员资格：17 个既有案例通过。
- Agent、员工、知识页浏览器回归：26 个通过，其中 Agent 12 个、员工 5 个、知识基准 9 个。含四种视口、发布确认、绑定/撤销、取消和原有审批路径。
- 既有 Agent/技能运行时回归：68 项通过，其中管理 API 12 项、技能治理 7 项、技能执行 49 项。合并轮次共 82 项通过、1 项因隔离模板库缺少 `starrykol` 参考登记失败；使用仓库既有 `db:seed:reference` 补齐模板库后，仅重验该失败项并通过。连同新增发布边界 15 项及组织资格 17 项，相关后台测试共 100 项通过。

复验入口：前端 `npm run test:e2e:agents` 会先构建再运行上述浏览器夹具；可用 `PW_EXECUTABLE_PATH` 指定本机 Chromium。后端需要具有建库权限的隔离 PostgreSQL 和完成迁移及 `npm run db:seed:reference` 初始化的 `lingong_template`，通过 `TEST_POSTGRES_URL`、`TEST_DATABASE_URL`、`DATABASE_URL` 配置测试实例，然后运行：

```text
npm run typecheck
npm test -- tests/agent-workspace.postgres.integration.test.ts tests/admin-agents.test.ts tests/skill-runtime-governance.test.ts tests/skill-runtime-execution.test.ts --hookTimeout=90000 --testTimeout=90000
```

本轮后台合并结果及单项重验分别保存在本地生成文件 `backend/artifacts/agent-workspace-regression.json`、`backend/artifacts/agent-workspace-runtime-recheck.json`，须结合读取；该目录按仓库约定不纳入版本控制。

初轮浏览器出现本机网络暂停和休眠引起的超时；改用本机已有 Chromium 和构建产物重跑。另修正了已有值的职责 textarea 精确标签定位，并避免构建清空输出目录时同时读取预览产物。会话恢复后，测试数据库停止以及沙箱中的 Vite/Vitest 模块加载受限导致回归未启动；恢复隔离集群并在获准的沙箱外重跑。环境中断及启动失败不作为通过依据。

## 上线与恢复边界

上线前在目标 PostgreSQL 执行 `backend` 的 `npm run db:apply:postgres-schema`，包含登记的 `20261012_agent_workspace` / `029_agent_workspace.sql`；再部署后端与前端。保留版本、回执和审计，不通过删表撤销已生效动作。

遇到发布依据变化时重新预检；保存冲突时保留输入并重新核对。若能力不适用，可独立停用 Agent、撤销绑定，或保存新的修订草稿并重新发布。未新增未经定义的组织审批制度。

目前依赖展示是配置投影，实际调用仍需资源探测、权限、考试与业务闸门。本轮未验证真实外部资源调用，未完成生产上线。发布前还需处理现有 TB 品牌门禁：当前远端字典和邮箱数据不含 TB；不在本页面任务中改写品牌事实或绕过门禁。
