# MCP 连接器管理员配置与授权审查

## CONST-08 审宪记录

| 项 | 结论与证据 |
|---|---|
| 需求 | 管理端统一配置受管 MCP 的端点、协议、凭据引用；验证连接并查看工具；逐工具设置风险、访问级别与范围；可保存或移除范围授权；移除 Starry 专属接入页和 Host 身份分支。 |
| 主责角色 | 平台管理员负责连接器目录、配置、凭据与工具治理；平台后端负责每次调用的身份和范围校验；UI/UX 专家负责管理端信息架构与可读性。 |
| 宪法条款 | `CONST-04`：管理界面实现既定平台治理边界；`CONST-05`：管理员不得绕过授权、确认或审批；`CONST-08`：本记录留存审查依据；`CONST-10`：以可观察构建和部署版本验证交付，不以页面或测试结果冒充生产能力。 |
| 基本法条款 | `PROD-PLAT-02/04/05`：平台连接器能力、治理与授权配置；`TECH-BE-01`：每次访问按当前身份和对象范围校验；`TECH-BE-07`：登记端点、协议、Schema、风险、授权方式与凭据引用；`docs/07-mcp-data-contract.md`：L1/L2/L3 与 Gateway 物理闸门；`docs/org-permissions.md`：连接器治理属于管理端。 |
| 结论与证据 | **符合**。管理员保留治理入口，但连接器执行改为必须具备显式连接器授权；工具范围治理启用后，每个工具都要通过当前用户范围校验。范围“所有员工”仍要求当前有效账号和连接器授权。L3 执行仍受 Host Gateway 控制。凭据保险库只回显引用元数据，不回显秘密。实现资产见下表；部署完成后补充 commit、服务状态与 `/api/version`。 |
| 下一步 | 完成前后端类型检查和生产构建；按仓库部署流程提交、推送并刷新 `lingong`；核对服务 commit。按任务要求不运行测试套件。 |

## 范围与实现资产

| 能力 | 实现 |
|---|---|
| 通用接入 | `/admin/connectors/:id` 使用同一运行时配置器；凭据保险库折叠在详情中；端点、MCP 协议、凭据引用、测试记录与逐工具审批集中管理。 |
| 逐工具范围 | 支持沿用未配置状态、无人、所有已获连接器授权的有效员工、部门树节点、岗位和绑定到指定有效账号的个人节点；选择无人会持久化范围治理状态，后续不会回退到旧授权。 |
| 执行校验 | `backend/src/runtime/execution.ts` 不再对管理员跳过连接器授权或工具范围校验；范围治理启用后，未明确授权的工具默认不可调用。 |
| Host 边界 | L3 仍由既有 Host Gateway 控制；管理员治理权限不会产生连接器使用授权。 |
| 通用化 | 移除 Starry 专属接入组件、专属凭据绑定接口、专属目录排序和专属启用分支；保留领域 Host Gateway 与已有业务适配器。 |

## 已知范围语义

本地用户账户没有部门字段。一级/二级部门授权覆盖其下已配置的岗位和个人节点；个人节点直接绑定一个有效本地账号。岗位按 `users.position` 匹配，因此需要精确限制某部门成员时，应在相应部门下配置个人节点。页面对该限制作出说明。
