# 四栏邮件谈判工作台 — 设计规格

## 目标

把「邮箱通讯」页从“传统邮箱 + 会话详情”收敛为**四栏邮件谈判工作台**：

```
会话列表  →  当前邮件原文  →  AI 辅助（会话摘要 + 当前邮件翻译）
```

用户围绕 **同一合作主题 → 邮件时间线 → 当前邮件 → AI 理解** 工作，不引入额外的文件夹页 / 会话详情页。

## 现状勘测（改前）

| 设计要求 | 现状 | 结论 |
|---------|------|------|
| 四栏（左导航 + 列表 + 正文 + AI） | 全局左导航已存在；`mail-split` 已是 `300px / 1fr / 340px` 三栏栅格 | ✅ 结构已在，按新宽度微调 |
| 一级筛选为 收件箱/发件箱/未读/已读 | `MAIL_TABS` 已是这四个，无 CRM 阶段 | ✅ 已满足 |
| 会话摘要数据 | `kol_mail_threads.digest_text`，经 `GET /api/mail/conversations/:id` 返回 | ✅ 已满足 |
| 当前邮件翻译数据 | `kol_mail_items.translation_zh`，`messages[]` 中**每封各自带** | ✅ 已满足 |
| 第二栏：会话内邮件时间线 | 未实现（点击只切会话，不展开邮件） | ❌ 待改 |
| 第三栏：只显示当前一封 | 把整个 thread 的所有邮件纵向铺开 | ❌ 待改 |
| 第四栏标题“中文摘要” | 文案误导（实为会话级摘要） | ❌ 待改 |
| 顶部邮箱切换 | 所有邮箱横向平铺 chips | ❌ 待改（改下拉） |
| 选中态视觉 | 无明确“当前这封”指示 | ❌ 待改 |
| 视觉：卡片套卡片 | 多层卡片容器 | ❌ 待改（去嵌套卡片） |

**后端无需新增接口**：`GET /api/mail/conversations/:id` 已同时返回会话级 `digest_text` 与 message 级 `messages[]`（含各自 `translation_zh`）。

## 信息架构

```
Mail_Page (1440×960 基准)
├── Sidebar（全局左导航，不改）
├── Mail_List_Panel      330px
├── Mail_Content_Panel   540px
└── AI_Assistant_Panel   350px
```

窄屏自适应：
- ≥1280：330 / 540 / 350
- 1024–1280：300 / 1fr / 320
- <1024：单栏 + 顶部三段切换（会话列表 / 原文 / 翻译），沿用现有 `mail-mobiletabs`

## 数据绑定规则（本页最重要的约束）

| 区域 | 绑定到 | 切换时机 |
|------|--------|---------|
| 会话摘要（第四栏上半） | **Conversation ID** | 仅切换会话时刷新；在会话内切邮件**不刷新** |
| 当前邮件原文（第三栏） | **Message ID** | 每次选中邮件刷新 |
| 当前邮件中文翻译（第四栏下半） | **Message ID** | 与第三栏严格一一对应 |

URL 状态：`?c=<conversation_id>&m=<message_id>`，可分享、可刷新保持；`m` 缺省时选中该会话最新一封。

## 交互设计

### 第二栏：会话 + 会话内邮件时间线（手风琴）

默认展示会话列表项：

```
[头像缩写] 对方名                        时间
           Re: 主题
           预览片段                        ●未读
```

点击会话项 → 在原位置**内联展开**该会话的邮件时间线（不跳页、不替换列表）：

```
▼ Ellis Benus
    05/22 10:24   Re: Potential outdoor power collaboration   ← 选中
    05/21 15:36   Re: Potential outdoor power collaboration
    05/20 10:24   Potential outdoor power collaboration
```

点时间线中任一封 → 第三、四栏（下半）切换到该封。

### 选中态

- 时间线选中项：背景 `#FFF0F6`，左侧 `3px` 品牌粉指示条
- 会话项在展开时高亮其标题行

### 顶部

- 只保留：`邮箱通讯` + 副标题 `管理多邮箱协同沟通，推动合作进展`
- 邮箱切换改为下拉（`MailboxSwitcher`）：默认只显示当前邮箱 `● 邮箱名 地址 ▾  未读数`；展开菜单列出所有邮箱 + `＋ 添加邮箱` / `⚙ 邮箱设置`
- 不重复展示全局的搜索 / 通知 / 头像

### 第三栏（当前邮件）

只渲染选中的那一封：主题 + 星标/更多 + 发件人（名 + 地址）+ `To:` + 时间 + 正文。

- 发件邮件（outbound）与收件（inbound）用不同头部样式（`MailContent` 变体）
- 底部操作：`回复` / `快速分析` / `AI 生成回复` / `…`（沿用现有能力，不新增）

### 第四栏（AI 辅助）

```
┌ ✨ 会话摘要            AI生成 ┐   ← 标题改（原“中文摘要”）
│ 会话级摘要正文 …             │
│ 更新于 <时间>                │
└──────────────────────────────┘
┌ 中文翻译           [复制翻译] ┐   ← 随当前邮件切换
│ 当前邮件译文 …               │
└──────────────────────────────┘
```

## 组件拆分（前端）

| 组件 | 职责 |
|------|------|
| `MailboxSwitcher` | 当前邮箱 + 下拉切换 |
| `MailFilter` | 收件箱/发件箱/未读/已读 |
| `ConversationItem` | 会话行（读/未读/展开中/选中） |
| `MailTimelineItem` | 会话内邮件行（默认/选中/收发） |
| `MailContent` | 当前邮件原文（收/发变体） |
| `ConversationSummary` | 会话摘要（加载/完成/刷新中） |
| `TranslationPanel` | 当前邮件译文（加载/完成） |

`Mail.tsx` 只负责编排状态（选中会话、选中邮件、筛选、搜索），渲染下沉到上述组件，控制在可读规模内。

## 测试计划

- `frontend/src/mail/` 纯函数单测：
  - 选中态解析：`?c=&m=` → 选中会话/邮件（含 `m` 非法或缺省时回退到最新一封）
  - 会话切换不重置已选邮件、邮件切换不重置会话摘要
  - 时间线排序（旧 → 新在上或在下，按规格：新在上）
- 组件/集成（现有 vitest 环境）：
  - 展开会话后点第 2 封 → 第三栏与翻译区都切到第 2 封，摘要区文本不变
- 回归：现有 `mail/client.test.ts`、`mail/fallback.test.ts`、`mail/digestView.test.ts` 全绿

## 不在范围内（YAGNI）

- 不新增“谈判阶段/待寄样/已成交”等 CRM 字段或筛选
- 不新增文件夹页 / 独立会话详情页
- 不改远端同步、拉取与摘要生成逻辑（`digest_text`、`translation_zh` 均复用现有数据）
- 不新增邮箱接入方式（Amazon Message 等仅要求组件可复用）

## 风险

- `Mail.tsx` 现有 800+ 行且混有 fallback / 移动端分支，重构需保持这些分支行为不变
- 列表接口 `digest_text` 较大（上一轮已 gzip）；本改造不下发新字段，不受影响
