## 审宪记录

需求 → 修复新任务 AI发现提交后 `runtime_tool_arguments_invalid`，以及错误的接口缺口、候选快照描述。

主责角色 → 后端专家负责参数契约与模型运行上下文；智能体产品经理负责错误恢复说明；测试经理负责回归证据。

宪法条款 → CONST-03 程序执行契约、CONST-05 确认与授权、CONST-08 审查、CONST-10 可验证交付。

基本法条款 → TECH-ARCH-04 共享契约、TECH-BE-02/07 提交闸门与真实连接、TECH-TEST-01/03 验证与证据；PROD-AGENT-03/09 真实回答与恢复。工具风险与异步契约继续遵循 [MCP 数据契约](../../07-mcp-data-contract.md)。

结论与证据 → **符合**。仅明确已接受的参数类型和失败诊断，不增加远端字段、不删除必要范围、不绕过 L3 确认、单任务锁与持久异步作业。用户调试文本中的拟用 `keywords` 为数组；只读查询线上 `tools/list` 确认 `platforms` 为数组、`keywords` 为字符串。字符串形式 `boat life,marine power,sailboat living` 通过远端和本地呈现 schema 两层校验。因此模型关于“schema 不接受平台、关键词”的结论缺少证据，不能用其修改远端契约。尚未从原始失败调用中取得完整实参，不把拟用参数当作完整调用回执。

下一步 → 修复技能说明、字段说明与校验诊断；补充空快照和运行箱上下文说明；验证 Runtime 提案和确认边界。生产发布与真实 harness 验收另记，不以单元测试代替。
