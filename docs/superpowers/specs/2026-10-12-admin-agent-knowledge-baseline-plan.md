# 管理侧 Agent：以知识管理页为基准的对比、目标与计划

日期：2026-10-12。基线：本工作区 `01100039`。

状态：用户已于本任务中批准“开工”，M0–M3 的本地实现与相关验证已完成。以下现状对比描述改造前的仓库静态核查；实施结果及验证证据见 [交付记录](2026-10-12-admin-agent-workspace-delivery.md)。未登录生产页面，不把夹具和本地测试当作生产完成证据。

定位：产品与交互实施方案，不是法条正文。范围是管理侧 `/admin/agents` 对照管理侧 `/admin/knowledge`，不是员工 `/agents` 对照员工 `/kb`。

## 1. 核心判断

两页共享的用户心智是：**管理一项资产，找到它，理解当前有效状态，形成修改，核对影响，使修改正式生效，并能追溯。**

因此，知识页可以作为 Agent 页的浏览、详情、编辑、返回、反馈和操作布局基准。Agent 特有的能力装配、人员授权和执行闸门，应作为这一流程里的业务内容。

Agent 页的核心问题应明确为：**这个 Agent 给谁用、能做什么、当前生效的是哪一版、能否使用，以及下一步需要处理什么？**

从实现看，知识页已经围绕资产与操作流程组织；Agent 页仍围绕配置项组织。改善重点是把管理员的治理任务组织成闭环，而不仅是调整卡片、按钮和间距。

## 3. 相同点：直接复用的使用心智

| 管理员的任务 | 知识页基准 | Agent 页目标 |
|---|---|---|
| 找到资产 | 搜索、状态和分类筛选、同源计数、分页列表 | 搜索、发布状态和绑定范围筛选、同源计数、分页列表 |
| 理解当前对象 | 身份、类型、状态、版本、适用范围、来源 | 名称、职责、状态、有效版本、装配能力、使用范围 |
| 查看与修订 | 同一工作区在详情与编辑之间切换 | 查看有效配置，进入独立编辑态；浏览时不混入大量勾选框 |
| 形成修改 | 保存草稿，显示未保存状态 | 保存装配及职责修改草稿，明确其尚未影响员工 |
| 正式生效 | 允许动作、确认、发布及真实回执 | 预检、差异与影响、确认应用发布版本及回执 |
| 返回继续管理 | 保留筛选、页码、选中项、滚动与焦点；URL 可定位对象 | 同样恢复列表上下文；新建后定位新对象，返回原筛选 |
| 处理失败 | 错误、空结果和等待分开；保留输入，可恢复 | 同样分开加载、无结果、失败、冲突；操作失败不丢表单 |
| 追溯 | 来源、版本、审批与操作记录 | 版本、人员覆盖依据、装配变更、发布与授权审计 |

这些是共同任务，并不表示两页当前都已完整实现。

## 4. 不同点：必须保留的 Agent 治理内容

| 维度 | 知识管理 | Agent 管理 | 设计后果 |
|---|---|---|---|
| 资产内容 | 资料、方法、制度、在线条目与文件 | 职责和已装配能力的组合 | 详情主体从知识正文换成职责与能力清单 |
| 组织方式 | 主题域族 → 主题域 → 知识库 | 发布状态、组织/人员绑定及能力特征 | 共用筛选交互，使用各自语义；不为 Agent 强造知识三级目录 |
| 授权作用 | 知识库不是独立人员权限入口 | Agent 是唯一人员使用权限锚点 | 单独解释绑定点、直接覆盖、负责人继承与组织版本 |
| 依赖关系 | 资料被查询技能使用 | Agent → 技能 → MCP/API/知识库 | 装配显示技能版本与资源依赖；知识不能成为执行旁路 |
| 变更影响 | 当前资料版本、引用与检索 | 当前 Agent 的能力、员工使用资格；共享技能可能影响其他 Agent | 变更前提供影响范围，不只给一个“保存成功”提示 |
| 有效与可用 | 草稿版、已发布资料及其适用范围 | 发布版、启停、当前授权、考试、资源健康和动作闸门共同影响可用性 | “已发布”与“当前可用”分别展示；不得把覆盖人数当作实际可用人数 |
| 版本变化 | 新草稿不能覆盖已生效知识 | 新装配草稿不能覆盖有效能力；撤权与停用仍须及时生效 | 内容版本与授权/启停分别处理，发布快照不能冻结旧组织权限 |
| 审批 | 已有知识审批与独立发布机制 | 现有发布确认和执行闸门；不等于有同一套知识审批 | 共用预检、确认、反馈方式，按真实规则显示审批 |
| 验证 | 内容、原件、查询引用和加工结果 | 能力依赖、技能版本、风险、人员覆盖和实际调用 | 只读试算及资格预检；不靠真实发信证明页面可用 |

风险表达统一采用现行 R1/R2/R3：只读、草稿、正式或敏感动作。技能的风险与执行方式来自工具目录及服务端契约；MediaCrawler 仍是单任务异步作业，不能在装配列表中被描述成同步执行能力。

## 6. 页面目标与建议结构

目标：管理员使用与知识页一致的流程，完成 Agent 资产的查找、理解、修订、影响预览、正式生效和追溯，并能辨别能力配置、人员资格与实际可用性。

推荐布局保留现有全局导航。中栏只负责 Agent 搜索与筛选；右侧工作区在列表、详情、新建/编辑、发布检查之间互斥切换，不新增常驻第四栏。

| 工作区状态 | 展示内容 | 当前主动作 |
|---|---|---|
| 列表 | 名称、职责摘要、发布状态、有效版本、绑定范围摘要、更新时间；分页 | 新建 Agent |
| 详情 | 身份与版本 → 职责 → 技能与有效知识范围 → 人员范围 → 发布与考试/依赖状态 → 版本与审计 | 已发布对象“创建修订草稿”；草稿按服务端允许动作进入下一步 |
| 新建/编辑 | 名称与职责、装配能力选择、版本与共享依赖说明、变更摘要 | 保存草稿 |
| 发布检查 | 当前版与候选版差异、依赖和风险、绑定与当前覆盖、受影响对象、阻止发布原因 | 确认发布/应用版本 |

人员新增绑定和撤销保留独立任务入口与影响预览，不与技能装配保存合并。停用与撤权明确即时效果；组织变化后的使用资格始终由当前服务端事实计算。

知识范围在 Agent 页以有效依赖投影为主。修改共享查询技能时，进入该技能的草稿治理流程并列出关联 Agent；需要不同知识范围时创建独立查询技能。返回后显式应用已发布的技能版本，避免同时维护新旧两套知识绑定入口。

页面关键内容使用平面分区、细线和现行密度 token；复杂记录按需展开。复用知识页的交互，不复制旧设计稿的字号例外或知识专属颜色授权；所有视觉取值以现行 DESIGN 为准。

## 7. 实施计划

| 批次 | 主责 | 工作与交付 | 验收与依赖 |
|---|---|---|---|
| M0：收口方案与契约 | 平台产品经理、UI/UX、架构与后端 | 收口工作区状态、允许动作、内容版本与授权状态；更新 Agent IA 实施细则；盘点现有接口与迁移范围 | 确定哪些可复用、哪些缺后端；不新增未经定义的审批规则 |
| M1：对齐浏览与详情体验 | 前端、UI/UX | 拆分 AgentFilters、AgentList、AgentDetail、工作区宿主及上下文状态；默认全部；列表元信息；身份优先；平面详情；URL、返回恢复、错误/空态与 dirty 保护；接现有审计 | 列表与详情互斥；筛选/页码/焦点可恢复；可见结果与选中对象一致。现有正式写入仍按真实语义显示，不把旧接口包装成“保存草稿” |
| M2：完成草稿与发布闭环 | 后端、架构、前端 | PostgreSQL 版本化迁移；Agent 内容/装配草稿与发布快照；有效技能版本；差异、影响与预检；允许动作投影；预期版本、幂等、发布回执；接新建/编辑/发布检查 | 保存不影响有效版；发布后消费正确快照；依赖变化使旧预检失效；并发冲突保留输入；人员绑定与停用仍独立执行。此批是目标完整实现的必要条件 |
| M3：补齐治理解释与验证 | 后端、前端、测试经理 | 直接/继承覆盖依据；当前资格与可用性分开；依赖健康、R1/R2/R3、考试阻断；共享技能影响、版本记录；适用时补安全的修复/恢复入口 | 真实依据可追溯；无字段明确标示不可用；不伪造完成。完成相关契约、PostgreSQL、前端 E2E 与发布检查 |

M1 可先交付体验改善；M2/M3 完成后才能把“Agent 治理闭环”标为完成。审计、人员绑定、撤销、现有发布确认、知识技能范围和推荐排序能力在迁移中保留；推荐是管理员主动打开的辅助能力，不占默认详情首屏，不自动装配。

## 8. 验收标准

1. 首次进入列出当前权限范围内全部 Agent；搜索、状态、绑定范围和计数同源，空结果不会继续展示一个未经说明的无关对象。
2. 列表 → 详情 → 编辑/发布检查 → 返回，恢复筛选、页码、滚动、选中项与焦点；详情可深链访问。
3. 详情首屏先识别名称、职责、有效版本与状态，并看到当前关键治理动作；共享知识内容不先于 Agent 身份。
4. 浏览态与编辑态分开；离开未保存内容可取消；失败和版本冲突保留输入。
5. 已发布 Agent 创建新草稿时，有效能力保持原版；保存草稿不正式生效；发布才应用候选版并留下真实回执。
6. 停用、撤销和组织变更仍及时影响新的调用及再次执行；发布快照不能保存旧人员名单作为永久授权。
7. 新增或撤销绑定先显示服务端计算的直接/继承影响及组织版本；版本变化后重新预览；覆盖人数与当前实际可用人数不混用。
8. 知识始终通过查询技能调用；共享技能依赖变更列出受影响 Agent，草稿与有效依赖分开；不存在 Agent 直连资源的执行旁路。
9. 风险与异步方式来自真实契约；缺失依赖、未发布技能、考试或授权阻断显示原因与适用恢复入口；不通过发信验证只读治理功能。
10. 版本历史与审计可访问，区分版本号、变更记录和有效快照；没有真实证据的状态不显示“已通过”。
11. 视觉遵循 DESIGN 的同屏最多一个实底主 CTA、状态非颜色表达、字段容器适配和三轴验收矩阵；关键操作可见可点。
12. 运行与改动相适应的后端契约/类型检查/真实 PostgreSQL 测试、前端构建及 Agent、知识、员工授权相关 E2E；发布按 release-gate。夹具、真实服务和生产证据分开记录。
