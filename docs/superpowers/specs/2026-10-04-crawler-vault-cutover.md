需求 → 用户要求迁移 MediaCrawler 连接器，并将本次邮件和采集改动合并 main、推送、部署。

主责角色 → 架构师确定连接边界，后端专家实施迁移与执行，测试经理验证受影响场景。

宪法条款 → CONST-04、CONST-05、CONST-08、CONST-10。

基本法条款 → TECH-ARCH-02/03、TECH-BE-01/02/03/04/07/09、TECH-TEST-01/02/03/04；工具与异步约束见 [MCP 契约](../../07-mcp-data-contract.md)。

结论与证据 → **符合**：凭据来源统一到服务端保险柜，保留作业单任务锁、进度、停止、重试和导入闸门。停用连接器或组织凭据后不再通过环境令牌继续采集。没有修改业务权限或风险分档。既有管理配置和保险柜仍使用 PostgreSQL 同步兼容层，这是已有 TECH-ARCH-01 迁移缺口，本次不声称完成全库原生化；邮件持久作业使用原生 PostgreSQL。

下一步 → 完成针对性测试，备份生产配置与未提交文件，迁移并验证后部署，记录真实结果。

## 实施资产

- `backend/src/crawl/managed-connection.ts`：采集与连接检查使用已启用的 `claw` 管理配置，凭据限定为活动组织保险柜引用。
- `backend/src/config.ts`、`backend/src/mcp/remote.ts`：删除采集环境凭据和 Markdown 自动扫描回退，通用 MCP 客户端要求显式端点。
- `backend/mcp/codex-config.ts`：生产 Codex 配置不注入采集地址或令牌；采集继续经异步作业入口。
- 连接器 Host-only 识别改为内置 ID/已保存 URL；配置修改后仍须新版本验证再启用。
- `backend/scripts/migrate-crawler-vault.ts`：默认只预检，`--apply` 迁移旧环境地址与令牌，使用版本竞争检查，失败清理新凭据，重复执行不重复迁移；新版本置为停用/待验证。
- 入库回调改用独立保险柜引用，保留显式 ingress token 兼容，不再读取 MCP 环境令牌。

## 发布与恢复

迁移前备份数据库、环境文件和前端产物。停止应用与受影响 Worker 后应用迁移；同版本启动/停止探测成功后启用，再启动新版本。旧入库回调的令牌可保留为独立组织保险柜引用，避免静默中断自动回传。旧环境地址与出站令牌在新版本不再读取。

生产预检：服务器代码为 `49de285`；应用、outbox、execution Worker 活跃；本地无活动采集作业。实际环境端点的只读 `get_crawl_status` 返回 `idle`。管理端旧配置 v13 与该端点不同且验证失败/停用。服务器有两处知识库页面未提交改动，部署须备份并保留。

回滚使用本次部署前代码、前端产物和环境备份；组织保险柜新增记录可保留，旧配置恢复须使用备份并保留审计。不要回滚既已完成的 Starry 个人凭据迁移，也不要将 `cred_` 引用当作旧明文令牌。
