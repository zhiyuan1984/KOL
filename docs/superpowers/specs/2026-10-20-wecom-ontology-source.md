# 企业微信组织人员本体来源接入

## 用户授权与目标

用户于 2026-10-20 要求补充管理侧组织、人员本体，并在核对 wecom-mcp 7 个只读工具后确认「开始」。本轮补充组织单元、用户／员工、成员关系、组织、部门、组织层级关系、员工、员工档案、员工任职记录和岗位的业务定义、来源属性及关系。企业微信通讯录作为组织人员数据来源；岗位只接入职位文本证据，不生成正式岗位主档。

## 实施决策

现有本体目录、稳定对象编码、三级分类、五维工作区、组织主档与用户权限维持原样。定义通过既有 `ontology-definition-supplements.json` 和语义覆盖追加，保留原属性及公司已发布覆盖。数据通过已启用的 `wecom-mcp` 和平台同步 Agent 装配的只读技能，使用相同的工具挂载、风险和连接器凭据闸门读取；不新增 Host 直连或明文凭据回退。

组织、人员及成员关系使用独立的公司级来源快照表。外部引用以公司／租户、来源和外部稳定 ID 识别，不按姓名、邮箱前缀或职位合并。平台登录账号、组织归属、负责人政策、权限、Agent 绑定及技能装配均不由快照导入改变。

管理侧通过所选组织人员对象的「企业微信来源」入口查看来源状态、字段映射和已导入快照。读取预览取得同一成功发布版本的完整可见分页数据，显示数量、来源采集时间、版本、历史快照告警和候选值。明确确认、填写原因后，由服务端以预览标识、内容指纹、连接器装配版本、当前公司／操作者和幂等键核验，事务保存快照及回执。过期、版本变化、分页异常、环路、超限或撤权均不能将部分数据误报为完整导入。

## 来源事实与限制

已核对的部门返回字段包含 `id`、`parentId`、`name`、`nameEn`、`sortOrder`、`leaderUserIds`、`syncedAt`、`path`、`parentUnavailable`。人员返回字段包含 `userId`、`name`、`position`、`mainDepartmentId`、`activationStatus`、`directLeaderUserIds`、`syncedAt` 和 `departments[{departmentId,sortOrder,isLeader,syncedAt}]`。

`activationStatus` 仅表示企业微信激活状态，不作为 HR 在职／离职状态。`position` 仅表示来源职位文本，不提供正式岗位 ID、编制、职责、资格或任职起止时间。来源未找到仅说明当前可见同步范围未找到，不自动删除、停用或推断离职。来源时间与本地预览／导入时间分别保留；成功批次不是实时读取的承诺。

## 工程边界

- `config/ontology-*.json`：版本化本体定义及来源语义。
- `shared/wecom-ontology.ts`：字段映射、状态、预览、确认和分页快照契约。
- `backend/src/ontology/`：来源解析、完整性校验、版本检查与持久快照。
- `backend/src/routers/ontology-workspace.ts`：管理权限及公司作用域入口。
- `frontend/src/ontology/`：来源查看、候选核对、确认和回执；不在页面生成权限规则。
- PostgreSQL 迁移：新增独立本体来源数据表，不更改组织／人员权限表。
