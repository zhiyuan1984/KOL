# Skill Runtime：绑定、发现、统一授权

## 审查

需求 → Agent 的当前 Skill 绑定决定能力，Skill 的当前 Connector 绑定决定执行资源；工具从远程 MCP 发现，工具提交前统一校验。

主责 → 架构师（模块边界）、后端专家（执行与一致性）、测试经理（验证）。

条款 → CONST-02/03/05/08/10；PROD-PLAT-04/05/07；TECH-ARCH-02/03/04、TECH-BE-01/02/07/08、TECH-TEST-02/03。

结论 → 符合。使用现有 SQLite、Hono、MCP SDK 和唯一 Codex harness；代理只负责协议转发和确定性授权，不另建业务工具或模型推理循环。L3 仍走原 Host Gateway，不能由授权一个工具策略绕过确认。

## 接口与执行

1. 版本化 Agent→Skill、Skill→Connector 绑定，停用保存墓碑；写入要求 `expected_version`。没有绑定就拒绝，不从旧 Skill `mcp` 字段隐式补权。
2. Connector 的端点与凭据**引用**由治理配置提供。工具动态发现每次重新读取，遍历分页；元数据及 schema 不由 Host 预写。新工具默认不可执行，由治理登记风险和描述/schema 指纹后授权。
3. 每个 Codex run 启动一个绑定 localhost、一次性令牌保护的透明 MCP 代理。代理把真实远端工具描述/schema交给 Codex；调用由 Codex 决定。每次调用前/结果返回前重新校验当前用户、Agent/Skill绑定、资源绑定、连接器状态、工具策略及指纹。
4. L1/L2 可在当前权限内执行；L3 从代理拒绝，保持原确认/审批/幂等 Gateway。远端自报 readOnlyHint 不作为授权来源。
5. 不缓存身份和权限，也不在撤销后返回旧结果。撤销前已提交的远端动作不能宣称回滚。取消代理后不再启动调用；已发出调用仍保留真实审计状态。
6. 审计记录 run/agent/skill、绑定/配置/策略版本、工具/元数据指纹及输入输出摘要；原始凭据和敏感内容不入日志。
7. 没有动态修改旧 thread 的能力声明保证，因此受管 run 使用新 thread，避免恢复旧端点/令牌。业务上下文仍由 Host 的授权数据包传入。

## 迁移边界

本次提供治理 API 和 Worker 接入，不自动授予生产权限、不自动修改线上数据库。部署前必须显式登记 Agent-Skill 绑定、资源配置及工具策略；未迁移的真实运行会明确拒绝，不能静默回退到旧直连 MCP。stub 仅保留测试功能，不作为生产验收。

本次不改写全部既有 Skill SOP，不重做管理界面，不重构已有异步采集/正式写入工作流。代码交付不等于完成生产发布或所有八项业务验收。旧工具白名单接口只为遗留测试/专用链保留，不能作为新 Worker 授权依据。

## 验证

A：同一 Skill 绑定多个动态资源；B：解绑/停用/撤权后新调用拒绝；C：换服务 ID 和工具名不改 Worker/Skill；D：新工具动态出现但治理授权前不可执行。额外覆盖身份隔离、管理员停用边界、schema 漂移、分页、错误、恶意 schema、令牌隔离与代理关闭。

验证类别必须分别记录：本地单元/协议集成、真实 Codex harness、授权生产外部验证。后两类未执行时如实列为未执行。
