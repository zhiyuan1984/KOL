# 公海对象信息密度、头像补全与 Jev 评分审查

- **日期**：2026-09-25
- **模式**：Redesign · Preserve
- **范围**：Home「公海」对象行的动作控件、头像、主页外链、邮箱边界、重复“公海原因”以及公开资料的 Jev 评估。

## 审查结论

截图中的大按钮、较大的汉字/首字母方块并非来自宪法或无障碍法规要求。它们是公海组件曾有的局部 CSS 取值；项目的 `data-dense-dashboard` 规则要求工作台使用 24 / 28 / 32px 控件阶梯、13 / 14px 文字按钮，并只在粗指针设备提高触摸命中区。[1]

领取仍属于 L3 动作，因为它会创建排他跟进关系；后端在缺少 `confirm=true` 时必须拒绝。然而，L3 的要求是**明确确认**，不是视觉放大。最终桌面设计保持行内的 `96×32px` 领取按钮与 `56px` 头像尺寸，避免因进一步压缩而降低扫描和领取效率；确认区使用两枚 28px 控件，说明收敛为“建立我的跟进；不发信，不改阶段”。[2]

| 观察项 | 实现原因 | 当前处理 |
|---|---|---|
| 首字母/汉字方块 | 没有 `avatar_url` 或图片加载失败时，`name.slice(0, 1)` 是诚实降级，不伪造头像 | 保留 56px 降级识别砖；对有公开主页的公海对象提供显式“补头像”作业。 |
| 主页链接 | DTO 允许 `homepage_url`，但部分同步档案缺失 | 有 URL 时展示“主页 ↗”；无 URL 时不制造假链接。 |
| 邮箱未展示 | `email`、`contact_email` 与掩码邮箱均在公海 DTO 禁止字段中 | 继续不展示地址；领取后的授权跟进详情才可使用已核实联系方式。 |
| “公海原因”重复 | 状态标签已经完整表达当前可执行状态 | 移除“公海原因”及其重复值，保留“未首次建联 / 14天无回复”。 |
| 无主页本地记录 | 既不能抓取公开头像，也不适合作为可比较候选 | 提供预览、数量锁和确认后删除；只处理未领取的公海记录。 |

> **边界**：`无主`、旧会话和邮箱等事实不得通过列表文案重新推断或泄露。公海只读取白名单公开画像；领取后才建立排他跟进关系。[3]

## 信息布局

公海行是可横向比较的“线索表行”，而不是详情卡。桌面结构固定为 **选择框（16px）→ 头像/降级识别砖（56px）→ 弹性信息主列 → 领取动作（96×32px）**。主列顺序为 **名称 + 状态 + 有置信度的 Jev 标签**、**平台 / 在库 / 主页**、**公开指标 + 入库时间**、**方向/风格/地区**。缺失公开指标只显示“公开指标待补充”，不空出整列、不伪造数据。

状态紧贴名称，因为它是领取前最需要立即判断的业务事实。主页只在 URL 存在时显示；邮箱不进入该行。领取是唯一的行内业务写动作。右栏工具条下方提供紧凑的“资料维护”行：`补头像`、`Jev 评分`、`清理无主页`。这三项不挤压领取按钮，也不会在页面加载时自动运行。

## 公开头像补全与安全边界

“补头像”仅处理已存 `homepage_url` 且缺少 `avatar_url` 的未领取公海对象。每次最多处理 12 条；服务端只访问公开 `http(s)` 主页，拒绝环回、私网、带凭据 URL 和超过一次的重定向。作业只提取 `og:image` / `twitter:image` 元数据；不保存页面正文、不使用登录 Cookie、不绕过访问控制，也不定时循环。成功时回写公开头像 URL；失败时仅记录短错误与检查时间。

“清理无主页”先返回只读预览。确认界面显示候选数及受保护的 active follow 数量；员工再次点击确认时，服务端在同一立即事务内重新核对预览数量。只有数目一致才删除，范围固定为**未领取、仍处于公海、且没有主页链接**的本地 `kol_profile_index` 记录。存在 active follow 的档案始终保留。

## Jev 的正确使用方式

Jev 不能领取对象、发送邮件、修改阶段或替代人工判断。本实现通过既有 `OpenRouter / jev-1.13` 配置，且只提交公开索引状态：平台、账号名、主页/头像存在性、公开粉丝/播放/互动指标、方向、地区和风格。不会发送邮箱、联系方式、所有者、邮件摘要、报价、合同、私有备注或线程内容。[4]

每次“Jev 评分”最多评估 12 条对象，并从固定 choice 中产出两个**辅助信号**：合作潜力（`high_potential / watch / insufficient`）和资料/匹配风险（`high_risk / watch / normal / insufficient`）。仅当模型置信度 `≥0.70` 时才写入本地评估缓存；评分 `≥80` 的对象才在名称旁显示“高潜”或“高风险”，并可使用筛选和“潜力”排序帮助人工复核。评分不会改变公海状态、领取关系或正式阶段。

| 命令 | 入口 | 会话 / 模型 | 数据与副作用边界 |
|---|---|---:|---|
| 补头像 | `POST /api/home/pool/avatar-enrich` | 否 / 否 | 公开主页元数据，最多 12 条。 |
| Jev 评分 | `POST /api/home/pool/jev-assess` | 否 / 是 | 模型型 think 入口但不创建用户会话；仅公开索引字段，最多 12 条，结果是建议。 |
| 清理预览 | `GET /api/home/pool/cleanup-preview` | 否 / 否 | 只读，显示被保护的 active follows。 |
| 确认清理 | `POST /api/home/pool/cleanup-missing-homepage` | 否 / 否 | 明确确认 + 预览数量锁 + 公海未领取范围。 |

## 实施与验收护栏

本次实现保留 `?tab=pool`、公开 DTO 白名单、最多选择 8 人、分析入队、L3 领取确认、领取后撤销和现有 `data-*` 测试锚点。回归覆盖无邮箱/`mailto:` 链接、存在主页时显示“主页 ↗”、存在公开头像时直接展示、头像补全只取公开元数据、无主页清理的保护与数量锁、Jev 高潜/高风险标签、1280px 以上桌面行的 56px 头像与 32px 领取动作。
