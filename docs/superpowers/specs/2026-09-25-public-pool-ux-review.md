## 保留、改进与回滚

**保留**既有路由、`GET /api/home/pool` 的零写入读取契约、公开字段边界、L3 领取确认、领取后撤销入口，以及最多选择 8 人的限制。**改进**信息顺序为身份/当前公开状态、平台与在库信息、公开指标与入库时间、公开简介，以及右侧明确标注的「公海原因」；该原因复用后端已返回的公开状态，不读取或推断私有归属和往来字段。局部硬编码色值和不一致控件尺寸收敛到全局设计 token；搜索、更多操作和外链使用语义 SVG；批量操作明确作用于当前可见结果。空态的「立即同步红人库」现在显式调用 `POST /api/home/pool/sync`，只通过白名单的 Starry 只读档案接口更新本地公开档案索引，随后轮询同一路径的本地回执；远程 MCP 调用不再占住浏览器 HTTP 请求。该流程不创建会话、不调用模型、不读取联系方式，也不改远端档案。**移除**全选时覆盖隐藏选择、分析按钮对隐藏选择仍可提交的误操作风险，以及点击“同步”实际仅重试读取而不刷新索引的断链。最高风险是筛选前后的选择集合、同步失败的可见反馈和远端超时，因此增加了端到端与接口回归用例。回滚方式为还原本次提交；正式领取、阶段与远端业务数据均未变更。

## 2026-09-25 聚焦工作区补充

**模式**：Redesign · Preserve。**保留**左侧全局导航、`?tab=pool` 路由、搜索/筛选/排序字段、`data-*` 测试锚点、分析入队语义与领取的 L3 确认。**改进**公海从窄右栏提升为中栏的主工作面，删除不产生决策价值的空白引导区域；标题、筛选工具与行内容共享一个宽度轴，按“状态与身份 → 公开指标 → 公开简介 → 领取与原因”组织，便于在一屏内比较更多对象。领取仍是逐行显式动作，分析反馈则回到列表标题下方，避免在页面其他区域丢失。前端基于公开主页 URL（无 URL 时基于平台与显示名）折叠同一公开档案的遗留/远程重复 UID，优先保留公开字段更完整的记录；不合并、不读取也不推断私有业务数据。
