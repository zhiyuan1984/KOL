# 管理侧 Agent、技能与员工绑定设计

状态：目标设计，未实施 · 2026-10-03  
依据：[CONSTITUTION.md](../../CONSTITUTION.md) CONST-02/05、[PRODUCT.md](../../PRODUCT.md) PROD-PLAT-04/05、[BUSINESS.md](../../BUSINESS.md) BIZ-03、[TECHNOLOGY.md](../../TECHNOLOGY.md) TECH-FE-01/BE-01/BE-07、[DESIGN.md](../../DESIGN.md)。

## 设计哲学

总纲：**权限单点收敛，能力分层开放。** Agent 决定谁能使用，技能决定能做什么，MCP / API / 知识库提供技能调用的基础设施。人员不直接获得技能或资源授权。

1. **能力与权限解耦。** MCP、API、知识库只回答能力与依赖，不回答谁能用；Agent 是唯一的人员使用权限锚点。下游资源仍保留凭据、可用状态、数据范围及风险控制。
2. **组织即权限载体。** 管理员把 Agent 绑定到权威组织树中的任意组织单元（含三级组）或人员，服务端按权威组织树计算使用资格。配置对象从逐人逐资源的矩阵收敛为 Agent 绑定清单；调岗、入离职和负责人变化按组织版本重新计算。
3. **管理穿透是内建监督关系。** 绑定任一组织单元时，该单元负责人、下级成员与其各级上级负责人均可使用；绑定人员时，本人与其各级上级负责人均可使用。穿透只沿该绑定对象的上级链，不给旁支负责人或跨公司人员放行；拥有 Agent 使用资格也不自动扩大业务数据读取范围。
4. **一切调用经过技能。** 知识库查询本身是技能；管理员在 Agent 页选择知识库，只是为该 Agent 装配查询技能及其知识库依赖。不存在知识库、MCP、API 的特权直连执行路径。运行链统一记录「人 → Agent → 技能 → 下游能力」。

收益：管理员主要维护 Agent 绑定清单；新资源接入不增加按人授权配置；技能可跨 Agent 复用，SOP 可先沉淀为技能再装配给 Agent；员工只需理解自己的 Agent 能做什么，管理者只需核对自己范围内的 Agent。Agent 装配过多技能会扩大可用能力，因此发布前必须预览技能列表、风险档、覆盖人员和变更影响。Agent 使用资格、业务数据范围与高风险动作确认是独立闸门，任何一项都不能代替另一项。

## 权限真值与边界

| 绑定目标 | 有效使用者 | 不自动包含 |
|---|---|---|
| 任意组织单元（一级/二级/三级） | 该单元负责人、该单元及其全部下级成员、沿上级链逐级可追溯的各级上级负责人 | 同级兄弟单元、其他分支及其负责人 |
| 人员 | 本人、所属各级上级负责人 | 同事、旁支负责人 |

权威组织记录必须给出公司、组织层级、成员关系、负责人及版本。层级不存在的上级节点不虚构负责人；缺失事实、跨公司和旁支关系均不推断权限。服务端在列表、详情、启动和工具执行处使用同一判定；前端只展示服务端给出的覆盖预览。撤绑或组织变动后新请求立即复核，已发生外部动作保留回执。

## 管理侧三页

| 页面 | 主问题 | 列表与详情 | 主要操作 |
|---|---|---|---|
| 员工 | 此人能用哪些 Agent，来源是什么？ | 员工表保留账号/组织；详情列出 Agent、直接或负责人继承来源、状态和组织版本 | 绑定或撤销 Agent；查看影响和审计 |
| Agent | 谁能用这个 Agent，它装了哪些能力？ | 左侧 Agent 搜索/状态/绑定类型；右侧详情按「技能与知识库」「人员范围」「发布与考试」「运行与审计」「版本」组织 | 绑定任意组织单元（含三级组）或人员；装配/移除技能；选择知识库查询技能；发布/停用 |
| 技能 | 此技能做什么、依赖什么、风险如何？ | 左侧技能搜索/类型/阶段；右侧详情按「契约」「MCP/API/知识库依赖」「引用 Agent」「测试」「版本与记录」组织 | 编辑草稿、核对依赖、测试、发布/回滚/停用 |

Agent 页中的「人员范围」展示绑定点、直接成员、负责人继承成员及依据，修改前后给出差异。技能页不显示按人授权表；「引用 Agent」是反向索引，不是授权入口。MCP、API、知识库的连接健康、凭据状态与风险由技能依赖或连接器治理面展示，不在员工页呈现底层工具。

## 视觉与交互

- 管理侧左栏直接沿用项目 `b8cfe46` 的 `Workbench` 侧栏结构、菜单、图标和样式，不另造导航。页面内容不重复显示「员工 / Agent / 技能」标题、说明或页头新增按钮；侧栏已提供当前位置。员工、Agent、技能三页各有中栏与右栏，两栏分别使用贯穿工作区高度的独立竖向滚动条。
- 新增员工、Agent、技能按钮固定在各页中栏底部，始终可见；中栏筛选项以低强调选择态呈现，不与行动按钮同形同色。同一视口只保留这一个实底主 CTA。
- 中栏每组筛选为单选：每组同一时刻只有一项选中，「全部」也是组内一项；点已选中项不取消，不存在零选中。选中项用辅助色底、辅助色描边与文字标识，不加阴影、不用实底强调（2026-10-03 确认）。
- 员工右栏列表每人一行，不设单独状态列，也不因 Agent 绑定信息换成双行。姓名、邮箱、岗位、品牌、绑定 Agent 与行内操作优先于最近变更；行内编辑、绑定、停用/启用及三个新增入口都必须有可点击的完整交互界面。原型中的内存反馈仅用于评审，生产实现需要真实服务端契约和回执。
- 筛选组、对象列表、详情面板各有明确边界；组间用细分隔线及 `--space-*` 留白，列表以行分隔而非卡片墙。标题最高使用 `--ds-font-section`；统计数不另用大字阶。
- 状态同时有文案和形状/字重，不能只靠颜色；长说明折叠到详情。筛选无结果、尚未配置、服务不可用分开表达。
- 绑定、发布、停用、移除、回滚分别显示目标、影响范围和生效版本。正式改变权限前由服务端重算覆盖名单并给出确认所需信息，成功后保留回执；L3 正式副作用继续走既有确认与审批闸门。

## 实施差距

当前 `frontend/src/admin/employees/EmployeeDirectory.tsx` 展示 `skill_grants`，`frontend/src/pages/AdminAgents.tsx` 主要为只读治理，`backend/src/auth.ts` 与 `backend/src/runtime/execution.ts` 仍校验 `user_skill_grants`。本文件和法条不代表这些链路已经完成迁移。实施需先定义 Agent 绑定及组织版本契约、数据迁移/回滚和权限集成用例，再改页面；旧技能授权不能静默继续作为生产放行依据。
