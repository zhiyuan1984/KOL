# 技能写工具挂载与执行门禁

需求 → MediaCrawler 与其他 MCP 一样由技能挂载，写工具可见；执行仍受控。

主责角色 → 架构师负责平台与业务边界；后端专家负责确认、并发、持久执行；测试经理负责受影响链路验证。

宪法条款 → CONST-02、03、05、08、10。

基本法条款 → TECH-ARCH-02/03、TECH-BE-01/02/03/04/07/08、TECH-TEST-02/04、PROD-AGENT-03/09、BIZ-14。

结论与证据 → **符合**。用户明确要求写工具可以挂载、执行时门禁。挂载只产生提议能力，不赋予确认、审批或远端写入权限。既有按工具名隐藏和按 URL 识别 Host 专用连接属于实现限制，不是上位法要求。

下一步 → 分离工具目录与提交权限；默认连接测试只读取目录；将待确认动作、确认快照、真实回执持久化。远端提交前复核身份、绑定、配置、schema 与业务范围。模型不能通过参数伪造确认；不确定结果禁止自动重放。采集与导入独立确认。

发布条件：未确认零远端写入；参数或授权变化使旧确认失效；重复确认只有一次提交；采集实例互斥；撤权与进程恢复保留真实状态。新链路完整验证前保留旧链路，不将挂载成功视为生产迁移完成。

实施资产：`runtime/action-*` 为平台待确认动作及原生 PostgreSQL 作业；`crawl/runtime-gates.ts` 为采集业务校验与监控；`crawler_collect` 为线索智能体入口；`RuntimeActions.tsx` 为核对、确认、进度与回执。首页发现提交转入该智能体，旧采集记录仍保留，迁移标记写入后旧启动接口返回迁移提示。

边界：目录允许 L3 挂载；本批注册 MediaCrawler 启动与停止的专用门禁。**2026-10-06 修订**（见 [DECISIONS.md](../../DECISIONS.md) ADR-2026-10-06「写入型工具通用放行」）：没有专用门禁的写入工具改走通用门禁——仍须员工确认、提交前重新核对授权、只提交一次并留回执；发信（`sendEmailNow`）与正式阶段写入（`changeLifecycleStage`）没有专用门禁时连待确认动作都不提出，继续走发送确认与 `confirm_stage`。采集结果不会自动导入正式档案、发信或推进阶段。监控后台持久运行；用户下一轮对话获得当前会话的持久任务编号以继续读取与分析，不声明自动分析或自动入库已实现。
