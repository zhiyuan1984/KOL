## 1. 背景与评审结论

### 1.1 space-2.html 评审摘要（借骨架、换血肉）

原型方向成立（单页多视图、三步新建、抽屉治理、反馈闭环），但含四类不可原样采纳的问题：假数据/假指标（CONST-10）、一键审批与前端直改状态（CONST-05/04）、自定 token 与 CDN 资源（DESIGN 唯一来源）、占位弹窗（CONST-10）。

**借鉴（已纳入本设计）**：单页 + tab 骨架；三步新建弹窗与标题锁定规则；内容模型 × 载体双标签；待处置指标条与队列行；生产路径说明与入库记录；Schema 模板只读展示；资产全量表列与筛选；效果分块结构；配置行式块；顶栏「用户端视图」入口；员工端 hero 搜索、领域浏览、反馈闭环；断点式响应式与诚实空态。

**舍弃/修正**：全部假数据与指标（改真实查询或空态）；自定 token/字体/CDN（改本仓 token）；「变更中」独立状态（改派生标签）；一键审批（改确认 + 理由 + 回执 + 版本保护）；前端直改状态（全部走 API）；库=团队库（保持库=容器+策略）；假导出报表（移除）；占位弹窗（真实现或标注未接入）；硬编码身份；无入口的「缺口」话术（落地前不宣称）。

## 3. 总纲

### 3.1 一页一问与唯一归属

`/admin/knowledge` 一个路由承载六个顶层 tab；每 tab 只回答一个问题；管理动作（新建/编辑/审批/配置）一律走弹窗/抽屉/确认框，不另开页面。信息与动作的唯一归属：

| 对象/动作 | 唯一归属 | 说明 |
|---|---|---|
| 待办（待审/草稿/到期/反馈/待审资料） | 待处置 | 每行只把你带到条目（或资料）详情执行 |
| 上传/提取/管线状态/入库记录 | 生产·入库 | 素材进入管道 |
| 知识缺口与建设计划 | 生产·规划 | 底层 tickets；不重复员工反馈列表 |
| 族/域/库的结构管理 | 设计·领域与主题 | 新建/编辑/归档只在此处 |
| 内容类型与字段标准（kinds） | 设计·Schema 模板 | v1 只读；真相源 `config/knowledge-kinds.yaml` |
| 写作规范（pattern / 写法样例） | 设计·写作规范 | 列出 pattern 类条目 + 说明 |
| 条目总览与库的资产视图 | 资产 | 只读 + 进入详情；库结构不在此编辑 |
| 使用统计与复审线索 | 效果 | 只读聚合 |
| 引用绑定（技能 × 选择器 + 试算） | 配置·引用绑定 | 沿用「保存≠生效」 |
| 审批/授权语义说明、审计切片 | 配置 | v1 只读；编辑能力未开放处明确标注 |

### 3.2 路由与深链（零破坏 + 新增）

既有路由全部保留（e2e 与外部链接依赖）：
`/admin/knowledge`（待处置）、`/admin/knowledge/catalog`（设计·领域与主题）、`/admin/knowledge/bases/:id`（资产·库详情）、`/admin/knowledge/entries/:id`（条目详情）、`/admin/knowledge/ingest`（生产·入库）、`/admin/knowledge/bindings`（配置·引用绑定）。

新增/语义升级：
- `/admin/knowledge/entries`（无 id）＝资产·条目全量表（原为「先去目录选一个」提示）；
- `/admin/knowledge/bases`（无 id）＝资产·库列表（同上，升级）；
- `/admin/knowledge/planning`＝生产·规划；
- `/admin/knowledge/standards`＝设计·Schema 模板；
- `/admin/knowledge/guides`＝设计·写作规范；
- `/admin/knowledge/effects`＝效果；
- `/admin/knowledge/policies`、`/admin/knowledge/audit`＝配置·审批与权限、审计与通知。

顶层 tab 由路由前缀推导高亮；子 tab 为链接式（深链可达）。

### 3.3 内容模型 × 载体（正交口径）

| 维度 | 取值 | v1 实现口径 |
|---|---|---|
| 内容模型 | 结构化 / 非结构化 | 结构化＝`knowledge` 条目（有 kind 字段定义，可编辑/校验/绑定）；非结构化＝文档资料（`knowledge_documents`，PageIndex 管线） |
| 载体 | 在线编辑 / 文件上传 | v1 按来源派生展示（有源文件/原稿＝文件上传；否则＝在线编辑）；后端补列（content_model/carrier）列入后续批次 |
| 标题规则 | 结构化＝自定义条目名；非结构化 + 文件＝上传文件名（锁定不可改）；非结构化 + 在线＝自定义 | 与已决口径一致；文件替换：结构化不动标题、非结构化同步新文件名 |

## 4. 管理端六 tab 详细设计

### 4.1 待处置（`/admin/knowledge`）——「有什么在等我决定？」

- 指标条（真实计数）：待我审批｜我的草稿｜本周到期｜待处理反馈。
- 分块（现有数据源）：待审条目（pending_review）｜我的草稿（draft）｜隔离提案（proposals）｜到期提醒（`expires_at` 临近）｜员工反馈处置（三原因）｜待审资料（非结构化 pending_review documents，含管理端试算入口）。
- 0 实底 CTA；行内动作链接式；审批/驳回走 ConfirmDialog + 理由 + 回执（现状保持）。

### 4.2 生产（`/ingest`、`/planning`）——「内容从哪来、怎么进管道？」

- **入库**：沿用并升级现有 Ingest 视图——上传（L2）、提取作业真实状态与失败重试、入库记录；非结构化管线状态按 2026-10-02 规格（uploaded→normalizing→indexing→pending_review→published→archived，含 failed/cancelled 与取消/重试）。
- **规划（接 tickets，不做假池）**：
  - 对象：知识缺口（Gap）＝「应该有但没有/需要补齐的知识」；建设计划＝围绕缺口的处理流。
  - 底层：`tickets` 表；新增票种（暂名 `knowledge_gap`「知识缺口工单」，命名与渠道待业务确认）增补进 `config/ticket-types.yaml`。
  - 缺口字段（承载方式实施计划细化）：来源引用（反馈/试算跳过/零引用/手工）、目标族·域、期望产出、关联产出条目 id。
  - 入口：手工新建；从「效果·零引用/复审」与「试算跳过原因」一键转缺口；员工端「没找到」反馈（P4 开通）。
  - 出账：缺口完成时关联产出条目（发布后回填），形成「缺口→建设→产出」闭环。
- 顶栏主 CTA「新建知识」（三步弹窗，见 §5）。

### 4.3 设计（`/catalog`、`/standards`、`/guides`）——「分类与标准怎么定？」

- **领域与主题**：复用现有目录视图（族→域→库 CRUD；唯一实底 CTA 沿用「新建知识库 / 新建主题域族」规则）；点击库进入资产·库详情。
- **Schema 模板**（v1 只读）：按 `config/knowledge-kinds.yaml` 展示全部 kind（邮件模板/提示词/术语表/问答模板/制度与政策/方法与套路）＋字段（key、名称、类型、必填）＋适用库 kind＋摘要＋条款引用；顶部说明真相源与「UI 编辑后续批次」。现有前端同步表（`frontend/src/admin/knowledge/StructuredFields.tsx`）待后端 kinds 接口后替换。原型中的「提取规则」列在规则来源落地前不展示，不造假列。
- **写作规范**：说明 + 列出 `pattern` 类知识条目（员工面文案「写法样例」）+ 新建入口（走正常草稿/审批）；不另造配置面。

### 4.4 资产（`/entries`、`/bases`）——「库里都有什么？」

- **条目**（新全量表）：列＝标题｜内容模型｜载体｜族/域/库｜状态｜版本｜责任人｜更新时间；筛选＝关键词（v1 前端过滤）、内容模型、载体、状态、族/域；行→条目详情。范围＝`knowledge` 条目全量（含 policy/pattern 等无专有字段的类型）；非结构化资料（documents）暂在库/入库视图呈现（空白④）。
- **库**：库列表（名称｜kind｜族/域｜条目数｜状态｜责任人）→ 库详情（既有 BaseView：条目表、新建条目、非结构化 P1 标注）。
- 边界：结构编辑（族/域/库定义）唯一在「设计」；资产侧只读 + 进入详情。

### 4.5 效果（`/effects`）——「知识产生了什么价值？」

- v1 指标（全部真实可算）：近 30 天引用次数（默认窗口，口径待业务确认）｜被引用条目数｜零引用条目数｜待处理反馈数。
- 分块：引用最多（Top N）｜零引用清单（可转「复审」或转缺口）｜需要复审（到期 + 反馈命中）｜反馈汇总（三原因分布）。
- 数据源：`knowledge.resolve` 审计 + 反馈 + `expires_at`。
- **明确不展示**（未埋点，登记为后续）：搜索命中率、有用反馈率、环比百分比、图表趋势。
- 操作：零引用/复审可「转缺口」（接生产·规划）或进入条目详情编辑新版本；不在本页直接改状态。

### 4.6 配置（`/bindings`、`/policies`、`/audit`）——「系统怎么运转？」

- **引用绑定**：沿用现有 BindingsView（技能 × 选择器、试算台、启停 L2、「保存≠生效」提示）。
- **审批与权限**（v1 只读说明）：现行审批链与范围/授权语义（分类不承载权限；文档级 grants 后续批次；「发布即可见 + 品牌/范围」v1 标注）；编辑能力未开放——显式标注，不造假控件。
- **审计与通知**：`knowledge.*` 审计切片真实列表（只读）；通知策略未实现处标注；呈现优先复用既有审计样式。

## 5. 关键交互

### 5.1 新建知识三步弹窗（治理唯一创建入口）

1. 内容模型：结构化 / 非结构化；
2. 载体：在线编辑 / 文件上传；
3. 详情：标题规则矩阵（§3.3）；领域/主题/库选择；结构化绑 Schema（kinds）；文件载体上传文件（结构化可解析占位符字段，人工校对后入库）；在线编辑录正文/字段。
- 提交＝创建草稿（L2），进入正常审批链；正式动作（发布）不在此发生。
- 能力可用性：v1 只开放后端已支持组合；未支持组合置灰并写明原因（CONST-10）；组合支持表在实施计划逐项核对落表。

### 5.2 确认与回执（L3 清单沿用）

发布 / 停用归档 / 删除（仅草稿）/ 跨品牌转移：事实清单 + 必填理由 + 持久回执 + `expected_version` 冲突 409（沿用 `frontend/src/adminConfirm.ts` 与 `frontend/src/components/ConfirmDialog.tsx`）。

### 5.3 0–1 实底 CTA

顶栏「新建知识」默认实底；当前视图自身有主 CTA（如「新建知识库」「新增绑定」）时降级为次强调。
