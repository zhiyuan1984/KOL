## 十条宪法

### CONST-01 产品愿景

建设基于 Codex harness 的智能体基础设施。KOL 是首个业务应用；目标是替员工完成已授权的简单重复劳动，协助分析，把需要人判断的决策交给员工。

### CONST-02 平台与业务分离

平台提供技能、连接器、知识、记忆、执行、组织、授权、审核和配置能力。业务对象、关系、动作、规则、流程及事实来源由业务专家定义，通过业务配置、技能、知识库和工具接入；不得把 KOL 名称、阶段、期限、审批金额或事实写死在平台内核。

“系统不写入业务数据”指不内置业务事实，不禁止保存通过工具获得的授权数据、运行记录和记忆。存储位置不决定规则归属。

### CONST-03 能力组合与执行

Agent 使用共同的 Codex harness，由模型结合已发布技能、知识和工具完成编排与思考。平台负责执行契约和控制边界；确定的权限、审批和状态规则必须被程序执行，不能只靠模型自觉遵守。

### CONST-04 角色决定权

先确定事项归属，再由相应角色制定规则。以下是职责角色，可以由人或专家 Agent 承担；同一人兼任时仍需标明以哪个角色作决定。

| 角色 | 有权决定 | 必须遵守的边界 |
|---|---|---|
| 平台产品经理 | 员工端、管理端、系统设置端的通用功能与产品验收要求 | 不定义 KOL 归属、期限、业务授权或业务事实来源 |
| UI/UX 专家 | 平台布局、导航交互、视觉规范、组件呈现与无障碍 | 不修改业务规则；不替模型固定每次回答内容 |
| 智能体产品经理 | 员工与 Agent 的交互、回答组织原则、记忆管理与入口契约 | 不定义 KOL 业务语义、审批权和事实真伪 |
| KOL 业务专家 | 业务对象、关系、动作、SOP、规则、报表、业务权限、审批及权威数据源 | 不指定后端并发或事件一致性的实现方案 |
| 架构师 | 前后端组件选型、模块边界、系统调用关系与接口分工 | 不决定业务权威数据源；不接管后端并发与一致性方案 |
| 前端专家 | 前端代码、组件实现、交互状态和前端技术细节 | 不在页面重写业务权限、审批和阶段判定 |
| 后端专家 | Host、app-server 接入、MCP、API、记忆存储、并发、事务和事件一致性 | 实现已定义规则，不自行发明业务口径 |
| 项目经理 | 任务分发、里程碑、依赖、关键节点和交付跟踪 | 协调决策，不替其他角色改规则 |
| 测试经理 | 测试策略、Agent 评价、回归范围和验收证据 | 验证规则，不用测试案例创造业务规则 |

### CONST-05 人的授权与责任

读数据、写草稿、执行正式动作必须分清。外发、敏感访问和正式业务变更按已发布规则校验授权、确认及所需审批；管理员不能绕过。

明确授权可以覆盖已定义范围内的自动任务，无须每次重新询问。模型不得扩大授权、代人审批或把建议直接当作决定。

### CONST-06 事实、知识与记忆

业务专家指定权威事实源；知识保存制度、方法和资料；记忆保存可复用的偏好、事实摘要与工作上下文。摘要和模型推断不能覆盖原始事实或授权规则；读取时必须遵守当前权限，保留来源、版本与时间。

### CONST-07 两类入口、两类界面

AI 提问框进入 Codex 思考流程；明确的记忆快捷指令直接存取记忆，不创建 thread/turn，不由模型判断是否切换。后台事件是独立入口，按已授权流程运行。

平台界面由产品和 UI/UX 规范约束；Agent 每次回答的内容与组织由 Codex 在内容契约内决定，前端负责可靠呈现。

### CONST-08 先审宪、再审法

每个新功能、需求或变更先检查目标是否违反宪法，再检查具体方案涉及哪些基本法。只加载相关条款，不要求每次读全部历史文档。

审查最少记录：`需求 → 主责角色 → 宪法条款 → 基本法条款 → 结论与证据 → 下一步`。

| 结论 | 判定方式 | 处理 |
|---|---|---|
| 符合 | 目标与方案均符合适用条款 | 在已授权范围继续实施 |
| 违宪 | 目标或方案直接违背宪法 | 指明条款和冲突行为，调整方案；坚持改变根本原则则由用户修宪 |
| 违反基本法 | 目标合宪，但方案违反具体条款 | 引用文件、编号、原文与证据，由该领域角色修正方案或提出修法 |
| 规则空白或冲突 | 现行条款不足以决定，或条款互相矛盾 | 交所属角色补充、协调；只暂停依赖该决定的部分 |

没有条款依据，不得用“可能违宪”阻止工作。发现已有代码不合规，应记录具体差距，不能反过来把现状写成法律。

### CONST-09 法律层级与修订

宪法高于三部基本法；三部基本法按领域分工，互不凌驾。规格、技能、Policy、流程、接口 schema、设计 token 和测试是实施细则，不得覆盖上位条款。

宪法由用户决定修改；基本法由所属角色制定和维护，跨领域事项分别确认各自部分，项目经理协调，无法协调时交用户裁决。只改变具体期限、SOP 或组件细节，通常修改基本法或实施细则，不必修宪。

条款编号固定，删除时保留废止记录，不将旧编号赋给新含义。修法记录变更原因、替代条款、影响资产和生效版本；不得为了让代码“通过”偷偷改法。

### CONST-10 交付必须可验证

规则必须说清责任、适用条件和可观察结果。任务按影响范围关联条款、实施资产与验收证据；不得用文档、占位页面、模拟结果或测试通过，冒充完整生产能力。项目经理维护完成状态，测试经理给出质量证据。
