# 智能体中台产品与 UI 宪法

> 所有产品与 UI 工作必须读取。本产品是**智能体中台 / Agent middle platform** 工作台，不是 KOL 专用壳。本文件只保存跨页面、长期稳定且违反后会造成产品错误的规则；细节由 `CONTEXT-MANIFEST.md` 按任务加载。
>
> `design-system/kol-workbench/` 是现行视觉皮肤的路径名（KOL 试点皮肤），不是产品身份；不要把该目录名读成「本平台只做 KOL」。一等能力清单与试点元条款见 §4.1–4.2（ADR-023，用户锁定 2026-09-14）。

## 1. 按领域裁决

不存在一份文档覆盖所有领域。发生冲突时先判断问题属于哪个领域：

| 冲突领域 | 最终权威 |
|---|---|
| 安全、权限、租户边界、数据事实 | FS、Policy、数据契约 |
| 产品闭环、页面职责、跨页面边界 | 本宪法 |
| 可执行交互与发布验收 | `specs/UX-KOL.md`、`specs/ux-traceability.json` |
| 全局视觉、组件、响应式、无障碍参数 | `design-system/kol-workbench/MASTER.md` |
| 单页布局与状态差异 | `design-system/kol-workbench/pages/<page>.md` |

低层文档不能改写高层领域的规则；上层也不能越权覆盖安全、权限或真实数据。重大冲突记录到 `docs/DECISIONS.md`，文字澄清和路径修正直接同步相关文档。

## 2. 核心闭环

产品闭环语义为：**表达目标 → 系统理解 → 形成计划 → 调用能力 → 产生可确认结果**。界面按风险压缩展示，不要求每次把五步全部展开：

| 风险 | 最小可见闭环 |
|---|---|
| L1 只读 | 目标 → 结果；理解与执行过程可折叠 |
| L2 草稿 | 目标 → 关键理解 → 草稿结果 |
| L3 高影响 | 目标 → 关键理解/计划 → 确认 → 执行 → 持久回执 |

每个方案必须回答：

1. 用户当前想完成什么？
2. 系统理解了哪些输入、覆盖与限制？
3. 计划、进度或等待状态是否真实可见？
4. 哪项能力正在被调用，失败后能否恢复？
5. 结果是否可验证，副作用是否经过相应确认？

## 3. 跨页面硬规则

- 这是 Agent 工作台。主界面围绕任务、对话、结果和正式资产组织，不以后台配置表单替代工作流。
- 同一任务必须维持连续上下文和可追溯关系；允许子任务、分支执行和独立审批，但必须能返回原任务。不得用“下一步教学卡”迫使用户重新描述上下文。
- `发送`、`暂存`、`导入`、`解密`、`删除`是不同副作用，必须使用独立动作和状态，不得相互暗示已经完成。
- 真实等待必须显示原因、阶段与恢复入口；不得伪造完成、联系人、邮箱、结果或进度。
- 页面只保留一个主滚动容器；区域内不得形成难以发现的嵌套滚动。
- 优先展示结果与下一项可执行动作；不得以卡片墙、说明墙或大量装饰挤压工作区。
- P0 权限、审计、确认和状态约束不得为视觉简化而省略。
- 页面和组件不得自行定义与设计系统冲突的颜色、字号、圆角或间距。

## 4. 表面职责

### 4.1 一等能力清单（锁定，2026-09-14）

下列 **16** 项全部是一等公民（独立能力面），互不隶属，也不隶属 KOL Agent。未实现或占位**不降等**。

| # | 能力面 | 法律地位 | 只回答 / 备注 |
|---|---|---|---|
| 1 | 任务/会话 | 一等 | Home「今日任务 / 我的待办」+ Chat 是平台任务脊柱 |
| 2 | 数字员工 | 一等 | `/agents`：找谁协作 / 召唤岗位专家 |
| 3 | 数字团队 | 一等；**尚未实现** | 预留法律地位。禁止用「专家团」假导航冒充。**不得**永久禁止产品名词「数字团队」 |
| 4 | 技能 | 一等 | 侧栏是否露出是 **UX 密度决定**，不是「员工永远不许看见技能」。仍禁止能力图鉴压过任务脊柱 |
| 5 | 知识库 | 一等 | 员工 `/kb`；发布/停用/版本/范围在管理端 |
| 6 | 连接器 | 一等 | 员工使用面 ≠ 管理治理面（ADR-013 / `21`） |
| 7 | 审批 | 一等 | 确认与审批队列，不是第二套 Home |
| 8 | 人员与权限 | 一等 | 治理域：谁能用、用到哪 |
| 9 | 审计/Trace | 一等 | 治理域：变更与调用能否回放 |
| 10 | 考试 | 一等 | 员工应试；闸门治理在管理端 |
| 11 | 项目 | 一等；占位可 | 未实现不降等 |
| 12 | 云盘 | 一等；占位可 | 未实现不降等 |
| 13 | 手机遥控电脑 | 一等；占位可 | 未实现不降等 |
| 14 | 定时/自动化 | 一等 | `/cron`：今天或按点要跑什么 |
| 15 | 通知/收件箱 | 一等 | 要我看的通知；未要求本轮实现 |
| 16 | 个人设置 | 一等 | Settings：个人绑定与偏好 |

「支撑能力面」只表示这些面**不得复制** Home / Chat / Pipeline / Admin 的信息架构，也不得做成第二套 Home（ADR-015）。**不是**二等公民，不是 KOL Agent 的附属 Tab，也不因「有没有进行中任务」才存在。

### 4.2 KOL 是首个业务试点，不是平台壳

KOL Agent 只是本中台上的**第一个业务实现 / 试点**。下列是 KOL 试点域对象，不是中台壳本身：

- Home 内「AI发现」「我跟进的红人」
- Pipeline（正式合作生命周期资产板）
- KOL / Collaboration / CreatorCandidate 等试点对象

后续业务试点不得把上述 IA 写成平台唯一脊柱。Home「今日任务 / 我的待办」与 Chat 是平台任务/会话面；Pipeline 与红人发现/跟进是试点特化。Pipeline **页**仍存在（`FS-KOL-010`）；是否进入员工**默认侧栏**是 KOL 试点 UX 密度，**不是**平台法律义务。缺 Pipeline 导航不是 P0 / 违约。能力主权、会话单向调用、使用≠治理、支撑面不做第二套 Home，仍服从 ADR-015。发送 ≠ 推进阶段与 L1–L3 不变。

### 4.3 页面只答一问

| 类型 | 表面 | 唯一职责 | 禁止混入 |
|---|---|---|---|
| 员工核心工作表面 | Home | “现在做什么”。平台模式：今日任务、我的待办。KOL 试点另挂 AI 发现、我跟进的红人 | 正式 Pipeline 资产管理、Admin 治理 |
| 员工核心工作表面 | Chat | 完成一个具体任务并产出可确认结果 | 全局运营看板、后台配置中心 |
| KOL 试点工作表面 | Pipeline | 管理进入正式生命周期的合作资产、阶段与推进动作 | Home 模式、待办入口、探索式搜索 |
| 治理域 | Admin | 人员与权限、连接器治理、审计/Trace | 员工日常任务、业务流水线操作 |
| 一等能力面 | §4.1 清单（含数字员工、技能、知识库、连接器使用、审批、考试、定时、设置等） | 各答本面的问题；与任务/数字员工解耦 | 复制 Home、Chat、Pipeline 或 Admin 的信息架构；降为 Agent 设置或任务 Tab；把「支撑」读成二等 |

## 5. 风险与确认

- L1：只读查询，可直接执行并展示来源或证据。
- L2：生成草稿或可撤销变更，必须明确标注“草稿/暂存”。
- L3：外发、导入正式资产、删除、解密等高影响动作，执行前必须展示对象、范围与后果并确认。
- “关注”只有在取得真实主体 ID 后才能创建 Collaboration；它不代表已发送、已入库或已进入 Pipeline。
- 外部系统写入、正式业务资产变更、权限或敏感信息变更，以及不可逆或需审计的动作，必须完成“触发 → 确认 → 执行中 → 持久回执/部分成功/失败 → 恢复动作”闭环。Toast 只能辅助提示，不能替代业务回执。本地 UI 状态与普通偏好不要求持久业务回执。

## 6. 可用性底线

- 所有操作必须能在无鼠标条件下完成；键盘焦点顺序与视觉顺序一致，焦点清晰且不能被固定栏、Composer 或浮层完全遮挡。
- Dialog/抽屉打开后将焦点移入，关闭后返回触发控件；交互式 Chip 使用原生按钮并暴露选中状态，展开控件暴露展开状态。
- 表单具有程序化标签；提交失败后聚焦错误摘要或首个错误字段。加载区暴露忙碌状态，重要结果和错误以适当方式通知辅助技术。
- 状态不能只靠颜色表达；图标、控件边界与焦点等非文本信息必须具有足够对比度。
- 满足 WCAG 2.2 AA；字号、触控目标、对比度和动效数值由 MASTER 定义。
- 加载、空、错误、无权限、部分成功均需有明确状态与可恢复动作。
- 动效只用于解释状态变化，并尊重 `prefers-reduced-motion`。

## 7. 变更门槛

只有同时影响多个页面、权限/副作用边界或产品核心闭环的规则才能加入本文件。页面布局、局部组件和一次性实现细节应进入页面规范、FS/UX 或决策记录。
