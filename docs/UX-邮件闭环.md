# UX：红人邮件沟通（按正式阶段写这一封）

**角色**：产品 / UX  
**依据**（冲突时从上到下）：`docs/灵工-Agent中台开发规范.md` → `docs/codex-KOL-编码规范.md` → `docs/remote-mcp-sop-agents-plan.md`。  
**对齐**：左栏往来、中栏过程、右侧出这一封信。发送 ≠ 改阶段。推荐仍只预填，见 `docs/UX-推荐任务.md`。  
**不是**：把「报价邮件」做成一套可复用样板，再问别的信能不能套。报价只是 **报价待确认** 这一阶段要写的那封信。阶段信短名、缺口提示、建议下一步是 **写合作邮件 Skill 的契约**；Codex app-server 按 Skill 出结果与续改；远程预览/发送走授权 Starry MCP。Host 只做会话 HTTP、闸门和阶段机，不要把目录或口令正则写进后端 TS。

---

## 0. 运营在红人会话里写信时发生什么（一句话）

每个已建联红人一条往来线。打开会话时左侧向远端 **拉一次**。当前正式阶段决定 **这一封写什么**（建联、跟进、报价、核地址、发货、催大纲…）。写信时带上往来摘要；右侧是这封阶段信的要点 + 预览 + 可改草稿。人确认后发送。去信进左侧，摘要更新。阶段仍停在当前正式阶段。

```
打开会话（拉一次往来）
    → 当前阶段决定这一封
    → 摘要作上下文
    → 结果页：本封要点 + 英文预览 + 草稿
    → 人确认发送
    → 去信进左侧 + 摘要更新
```

点芯片 / 今天推荐 / 建议下一步仍然 **只预填**，不跑箱、不发信。  
红人会话里用 `/` 点「写合作邮件」技能：先把这一封英文草稿填进输入框（报价写成 USD n per hour，不要套餐总价），人改完再提交。

打开会话 **立刻回页面**：左栏先骨架或已有往来，标题「正在同步往来」，邮件一封一封出现。摘要仍只在 SOP。中栏不要 MCP 时序。生成中可改输入；**停止**只停本轮并保留已产生内容；再发送进入本会话队列。确认发送 / 记状态不入队，生成中点记状态会提示先停止。

## 1.1 哪些操作自动拉往来，哪些只更新摘要

两条线分开：**往来收取** = 向 Starry 拉这个红人的会话（`syncKolSessionMail`）；**摘要更新** = 按当前 `mail_history` 指纹重算 digest。首页关注箱未读是另一条线（`followedMailSync`），不是会话左栏。

### 自动拉往来（Starry list + 会话详情）

| 操作 | 拉？ | 逆向（不要拉） |
| --- | --- | --- |
| 打开该红人会话 | 是，一次；20s 内合并 | 离开会话、切到别的红人、仅停留 |
| 本标签页首次 `GET session?sync=1` | 是（前端 `mail-sync:${id}` 只记一次） | 同标签再次 load / SSE ping / snapshot |
| 左栏下拉刷新 | 是，且 `force=1` 绕过 20s | 普通 reload、切页回来 |
| 登录 / boot / 首页刷新 | 只拉 **关注箱未读**，不拉会话线程 | 取消关注后停止该红人首页同步 |
| 确认发送 | **否**（本地记下这封去信） | — |
| 来信入账（ingest / 拉取到的新信） | 拉取本身已经是收取；ingest-mail **不再** list | 重复信 / 已见过的信 |
| 点芯片 / 打字 / 提交 composer / 建议下一步 | **否** | 清空输入、取消草稿 |
| 记状态 / 确认阶段 / 阶段回退 | **否**（阶段 ≠ 邮件） | 恢复官方阶段 |
| SOP、回复分析、风险扫描、画像 | **否** | — |
| Demo 重置 | 清空会话线程后，再同步关注箱 | — |

### 自动更新摘要（digest）

指纹变了才重算；指纹没变且已有可信摘要则跳过。`analysis_failed` 冻结，只在下面标了「可重试失败」的动作里带 `retryFailed` 再打模型。

| 操作 | 更新摘要？ | 逆向（不要更新） |
| --- | --- | --- |
| 打开会话 / `sync=1` | 是；可重试失败 | 无 sync 的 GET / SSE ping（指纹没变则跳过） |
| 拉取到 **新** 往来 | 是（指纹变） | 20s 合并跳过、force 但没有新信 |
| **确认发送** 成功 | 是（本地出站入账 + 可重试失败） | 取消发送、改草稿、预览、校验失败 |
| **来信入账**（ingest，发送的逆向） | 是（与发送同一条刷新） | 重复入账、空正文 |
| 点芯片 / 打字 / 推荐预填 | **否** | — |
| 记状态 / 确认阶段 / 回退官方阶段 | **否** | — |
| 往来没变 | **否**（指纹短路） | — |

发送 ≠ 改阶段。来信可能提出 `confirm_stage` 卡片或事实推进，那是阶段判断，不是摘要。

## 1. 沟通骨架（所有阶段共用，不变的是往来，不是报价）

| 阶段 | 人看见 | 系统做什么 | 不做什么 |
| --- | --- | --- | --- |
| **打开** | 左侧先「正在同步往来」+骨架，邮件一封一封出现；SOP 里一段往来摘要（摘要仍可「正在读历史邮件」） | `syncKolSessionMail` 后台拉一次，HTTP 不堵 | 每次打字、每次刷新都不重新打 Starry；不要把 MCP 时序画进左栏 |
| **输入** | 芯片是 **这一阶段的信**（写跟进 / 写报价邮件 / 核对地址…），仍锁「写合作邮件」技能 | 把 `mail_digest` 和本阶段要点写进预览 | 不默认第一只发件箱，不编造邮箱 |
| **结果** | 右侧「本轮结果 · 邮件」：**本阶段要点**、预览、底下草稿。往来摘要只留在 SOP「历史邮件往来摘要」 | L2 草稿 | 不把 SOP / 生命周期塞进这张结果；不重复贴往来依据 |
| **确认发送** | 「校验并发送原文」，或回复「确认发送」 | Gateway 真发。管理员也不能跳过 | 不改正式阶段 |
| **发送后** | 左侧多一封去信；摘要含这封新信 | 本地 ingest + 重算 digest | 不整表重拉、不自动进下一阶段 |

下拉刷新左侧仍可用，那是 **人要再拉一次**。

## 2. 和现有三栏怎么合

| 面 | 沿用 | 本沟通 UX 补上的 |
| --- | --- | --- |
| 左栏往来 | `mail_history`，点开看正文 | 打开只拉一次；发送后本地追加去信 |
| SOP「历史邮件」 | 一段往来摘要 | 写信时用同一段当上下文；发送后更新 |
| composer 芯片 | 最多 3 颗，只预填 | **第一颗是本阶段这封信的短名**，不是永远「写合作邮件」 |
| 右侧结果 | `task_result_card` + `email_card` | 合成一页：本阶段要点 + 草稿 |
| 确认 | L2 发送 | 发送后刷新摘要，阶段不变 |

不做：独立「报价工作台」、为每个阶段再造确认页、点推荐即发信。

## 3. 不同阶段写不同的信

同一条往来线，变的是 **这一封的口令、要点和模板**。

| 正式阶段 | 芯片 / 口令 | 结果页要点 | 这一封在说什么 |
| --- | --- | --- | --- |
| 初步接触 | 写合作邮件 / 首封建联 | 建联要点 | 只筛选兴趣，不是已同意合作 |
| 已回复-有兴趣 | 写跟进 | 跟进要点 | Thank you 不能当兴趣；下一步收材料 |
| 合作评估 | 要媒体包 | 评估要点 | 要数据/媒体包，不是报价确认 |
| 报价待确认 | 写报价邮件 | 报价要点（金额/交付） | 正文必须有价格；发信 ≠ 成交 |
| 商务谈判 | 写谈判邮件 | 谈判要点 | 费用/数量/授权/档期 |
| 方案待确认 | 请确认方案 | 方案要点 | please confirm ≠ 已确认 |
| 合同签署 | 合同沟通 | 合同要点 | 已发送 vs 已签署分开写 |
| 待寄样 | 核对地址 | 寄样资料 | 姓名电话地址国家邮编 SKU 数量 |
| 已发货 | 发货通知 | 发货要点 | 运单号、承运商；物流事实才改阶段 |
| 已签收-测试中 | 催大纲 | 测试要点 | 收货/测试/大纲 |
| 内容策划 | 发brief | 内容要点 | 方向、必提点 |
| 内容审核 | 初稿反馈 | 审核要点 | 修改未完仍是审核 |
| 待发布 | 确认排期 | 排期要点 | scheduled ≠ live |
| 已发布 | 核对链接 | 发布要点 | 要公开 URL |
| 结算中 | 请开发票 | 结算要点 | invoice ≠ 已付款 |

缺关键事实时要点里写明（没价格、没运单、地址不齐），草稿仍可出，但不能假装已经齐。结果页「建议下一步」、会话芯片第一颗和输入框默认提示共用 **写合作邮件 Skill** 的同一份缺口：报价缺金额 → 提示「写报价邮件 @红人 金额 [USD]」，建议「补上金额后再确认发送」；点了只预填「把金额改成 [USD]」，不锁新技能、不当成确认发送。

### 结果页（以当前阶段那封为准）

```
本轮结果 · 邮件

{本阶段要点标题}
  …本封该核对的字段…

收发说明
  …本封该核对的字段…

收发说明
  发件 / 收件 / 主题

预览正文
  英文原文（报价则必须出现金额）

────────
邮件草稿
[校验并发送原文]
建议下一步：缺金额则「补上金额后再确认发送」，齐了才是核对预览后回复「确认发送」
```

输入框默认提示与缺口一致：报价待确认未写信时是「写报价邮件 @红人 金额 [USD]」；未发送结果缺字段时第一颗芯片改成补缺口（报价「补上金额」），不锁 `email_compose`。阶段芯片标签仍是「写报价邮件」。

未发送时，底部提示框默认是 **续改这一份**（字段合并，没点名的段落原样保留）。点芯片、说「再写一封 / 重写一封」、换 Skill 或换红人才是新任务。「确认发送」仍是 L2 真发。`/` 点技能先出草稿；提交时若输入框已是英文信，Host 把正文交给 Starry，不再为这一封重打 `previewEmailDraft`。追问进 Codex app-server `thread/resume`，只吐变更字段，Host 合并进上一份草稿。

## 5. 不走这条往来线的工作

| 工作 | 为什么 |
| --- | --- |
| 阶段 SOP / 生命周期看板 | 只读展示，不是信 |
| 回复分析 | 只出指针，这一步禁止 send |
| 记状态 / `confirm_stage` | L3，必须选定正式阶段 |
| 费用审批 | 组织审批，不是往来信 |
| 达人画像 / 发现 / 解密联系方式 | 读或高危写 |
| 异常旁路（风险扫描） | 先处理异常 |

首封还没有往来时：摘要为空，建联要点退回发件/收件/主题。往来线仍成立。

## 6. 反模式

1. 打开会话后每次 reload / SSE 都再打 `pageEmailConversations`。
2. 写信不带历史摘要，只拿模板空壳。
3. 把报价 UX 当成总设计，其它阶段只「套用报价闭环」。
4. 芯片永远写「写合作邮件」，人看不出这一阶段该写哪封。
5. 点芯片 / 推荐直接发信或改阶段。
6. 发送成功后不更新摘要；来信入账后也不更新摘要（发送的逆向）。
7. 为报价、催大纲、发货各做一套确认页。
8. 把发送当成进入下一阶段。

## 7. 验收

1. 打开已建联红人会话，HTTP 立刻返回；左侧「正在同步往来」，邮件陆续出现。短时间再进不会重复拉。下拉刷新才会再请求。
1b. 生成中输入框可改；停止保留中间结果；再发送排队。确认发送 / 记状态不进队列。
2. **初步接触** 芯片是「写合作邮件」；**报价待确认** 芯片是「写报价邮件」；**待寄样** 芯片是「核对地址」；点了只预填。
3. 报价待确认打开会话，输入框默认提示是「写报价邮件 @{handle} 金额 [USD]」；点芯片仍预填「写报价邮件 @{handle}」。不写金额就出结果时，要点写「金额未写明」，建议下一步和第一颗芯片都是补上金额，不是「确认发送」。
4. 输入「写一份报价邮件 金额 680」后，右侧同时看到报价要点（USD 680）、预览和草稿。
5. 在待寄样写核对地址，要点是寄样资料，不是报价金额。
6. 预览 prompt 含往来摘要（有历史邮件时）和 **当前阶段这封信的约束**。
7. 确认发送后左侧出现去信，摘要更新。正式阶段不变。
8. 来信入账（发送的逆向）后摘要同样更新；点芯片 / 打字 / 记状态不拉 Starry、不重算摘要。
9. 报价结果出来后输入「把金额改成 720」（不带芯片），草稿金额变为 720，From/To/其余正文保留，且不再预览整封。说「再写一封」或点「写跟进」才开新任务。

**怎么验**：与生产同一条链路——已发布 Skill、真实 Codex app-server、授权远程 MCP。禁用 mock/stub 与本地假回执。`CODEX_MODE=stub`、import 后端 Host 函数、本地假预览 **不算** 本需求验收。单元测试隔离 fixture 只锁阶段机等硬规则，不代替本 UX。
目录与口令在 `backend/skills/email_compose/SKILL.md`。打开会话拉往来、确认发送、阶段写入是内核，不是信件目录。
