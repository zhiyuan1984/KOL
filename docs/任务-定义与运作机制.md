# 任务：定义与运作机制

> 整理时间：2026-10-01
> 本篇是《企业智能体与本体论研究笔记》的拆分文件之一，聚焦"任务"。相关文件：本体六构件、Skill、智能体、知识库。

## 1. 定义：事件 vs 任务

**一句话区分**：事件是已经发生的**事实**（向后看，不可改）；任务是待办的**工作**（向前看，有生命周期）。一个记录世界，一个驱动世界。

- **事件**：已经发生的事实，例如"回款已到账"。
- **任务**：接下来要完成的工作，例如"催回这笔款"。

## 2. 四种关系

### 2.1 事件 → 任务（触发）

"库存跌破安全线"事件 → 生成"补货任务"；"客户逾期 30 天"事件 → 生成"催收任务"。没有事件，任务就是拍脑袋派活。

### 2.2 任务 → 事件（生命周期本身就是事件流）

"任务已创建"、"任务已分配给张三"、"任务已完成"、"任务已逾期"——任务流转的每一步都是事件。

### 2.3 任务执行 → 业务事件

张三执行催收任务 → "催款函已发送"事件；客户打钱 → "回款已到账"事件。

### 2.4 闭环

事件 → 任务 → 事件 → 任务……这是企业运转的脉搏。

## 3. 完整场景走一遍（逾期催收）

> 10-01 09:00 "回款到期未到"**事件** → 规则判定超标 → 自动创建"催收任务"（负责人张三、截止 10-03、关联客户A）→ "任务已创建"**事件** → 推送通知 → 张三调用"发送催款函"动作 → "催款函已发送"**事件** → 客户回款 → "回款已到账"**事件** → 规则判定 → 任务"已完成" → "任务已完成"**事件**。
>
> 若 10-03 未完成 → "任务已逾期"**事件** → 自动升级，生成新任务派给主管。

## 4. 为什么"任务"被高频提及

1. **Agent 的定义就是任务驱动的**（感知→规划→执行→复盘）。
2. **任务是目标分解的载体**：目标 → 任务 → 子任务 → 动作。调度系统管的本质就是任务的分配、排序和依赖。
3. **任务是人机协作的接口**：人类组织几百年来就是任务驱动的（待办、工单、OKR）。李开复的老板AI里"承诺账本"记录的"承诺"，就是任务。

## 5. 任务在本体里的位置

任务本身可建模为本体中的一种对象：有属性（标题、负责人、截止时间、状态、优先级），有关系（催收任务→针对→客户A），状态流转全部由事件驱动。**工作管理层与业务语义层就此统一。**
