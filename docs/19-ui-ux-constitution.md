# UI/UX 宪法

员工端与 KOL 会话工作台的产品级体验法律。日期：2026-09-13；2026-09-14 修订：`/agents` 专家中心（数字员工入口）只回答「找谁协作 / 召唤岗位专家」。同日再修订：Home **内**四模式（今日任务 / 我的待办 / AI发现 / 我跟进的红人），见 ADR-018。来源：产品负责人反馈，固化为后续界面取舍的默认立场。

本文件管**注意力、信息架构和主路径感觉**。闸门、风险分级和无障碍仍以 `00-platform-charter.md`、`04-ux-ui-system.md` 与 `specs/UX-KOL.md` 为准。视觉密度与 token 默认见 `20-visual-design-system.md`。本文件**不**改 `frontend/src/pages/Chat.tsx`；会话页重构是后续实现，必须先符合本宪法。

## 核心闭环（必须是法律）

```text
Express goal → Agent understands task → Make execution plan → Call system capabilities → Return results.
```

表达目标 → Agent 理解任务 → 做出执行计划 → 调用系统能力 → 返回结果。

会话 / KOL 工作台的每一次主交互都必须能落在这条链上。界面的工作是让人表达目标、看懂 Agent 在做什么、确认有副作用的结果；不是教人点哪个菜单，也不是把 SOP、状态板和模式页签堆成第二套操作系统。

评审问题时只问：

1. 人是在表达目标，还是在填写后台表单？
2. Agent 是否理解了任务，还是把选择推回给人？
3. 执行计划是否由系统推进，还是要人在卡片之间点「下一步」？
4. 能力调用是否发生在后台，还是被展开成引擎说明书？
5. 回到线程里的是不是可确认的结果 / 草稿，而不是教材？

任一问失败，该改动违约。

## 产品规则

以下规则由 2026-09-13 产品负责人反馈导出，与核心闭环同级。

### 1. Agent 表面，不是管理后台

Session / KOL 工作台必须像在跟一个会干活的 Agent 说话，而不是 SOP 卡片、状态面板、手工模式页签互相抢注意力。

目录、连接器、Trace、调试开关属于管理端或显式调试视图。员工端可以开始一项工作，但不能变成能力图鉴。

### 2. 一条主线程

对话 / 结果是脊柱。阶段漏斗、KOL 身份等上下文是次要辅助条（chrome）：紧凑、可扫视，不是第二本小说。

主窗格里只保留一条阅读路径。身份、阶段、邮箱、等待原因可以常驻，但必须短到不打断结果。

### 3. 禁止教练式「下一步」卡片

删除「下一步：写合作邮件 →」这类教人去点哪个菜单的卡片。Agent 应直接做，或给出可改的草稿 / 结果。

Journey 条可以留作**紧凑定向**，不能再当教练剧本。`04` / `UX-STATE-VISIBLE` 里的「下一步」是等待态操作（停止 / 重试 / 接管）和缺口补全，不是「建议你去打开某某技能」。

### 4. 发送 ≠ 推进阶段

硬产品不变量。只保留一句安静的说明即可，禁止在每张卡上重复横幅。

发送卡不得带阶段选择；阶段写入必须是独立确认，且选择具体 `stage_code`。见 `UX-SEND-NE-STAGE` 与平台不变量。

召唤岗位专家比发送更早：只建立绑定会话 / 协作绑定，**不**发信、**不**写阶段。见「`/agents` 专家中心」下的召唤副作用法律。

### 5. 禁止嵌套滚动地狱

主窗格优先一条纵向滚动。任务卡 / KOL 卡禁止横向滚动。次要面板默认折叠。

横向滚动只允许真正的宽表或显式调试条，不能出现在员工主路径的卡片上。

### 6. 结果优于说明书

优先 `task_result`、草稿和确认动作，而不是 SOP 教科书和「建议下一步」墙。

资料型 Skill 可以回答「这阶段要什么证据」，但默认交付仍是结果卡，不是把课本铺进线程。

### 7. 与已在航运的 P0 对齐

后续改动不得回退这些已经落地的方向：

| P0 | 含义 |
|---|---|
| Home 无横向滚动 | 首页任务 / KOL 卡沿纵向阅读，卡片内禁止 H-scroll |
| 邮件摘要 | 往来用短摘要，不把历史信全文当作主阅读物 |
| 等待态诚实 | 排队、执行中、待确认、失败用词必须与真实状态一致，禁止无状态 spinner |
| Agents 是工作入口（专家中心 / 数字员工） | `/agents` 只回答「找谁协作 / 召唤岗位专家」。不是技能图鉴、不是第二套 Home 待办页、不是连接器目录。Home 仍独占四模式：今日任务 + 我的待办 + AI发现（线索）+ 我跟进的红人；专家中心 ≠ Home |

## 四页分工（页面角色法律）

员工端只有四页主表面。每页只回答自己的问题；跨页复制信息架构视为违约。后续 PR 不得把 Home 的四模式、待办语义、任务计数或技能入口再贴进 Pipeline，也不得贴进 `/agents` 专家中心。

| 页面 | 角色 | 只回答 | 禁止 |
|---|---|---|---|
| **Home** | 现在做什么 / 等待诚实 | **四个模式**（仍在 Home 内，不是第五页）：**今日任务** \| **我的待办** \| **AI发现** \| **我跟进的红人**。对象与改名见下节 | 正式 15 阶段资产板、管理端权限树、第五套主脊柱 |
| **Pipeline** | 合作资产页：正式生命周期坐落 | 正式阶段、品牌/负责人、停留、近期事件、同步来源/时间、阶段风险、允许提出的阶段变更 | 首页四模式（今日任务 / 我的待办 / AI发现·线索 / 我跟进的红人）、首页待办桶（需要我处理/等待中）、审批任务、首页任务计数、「帮我处理今天工作」、邮件任务入口、与 Home 相同的等待语义 |
| **Chat** | 如何完成一件具体任务 | 表达目标 → 计划 → 能力调用 → 可确认结果；邮件草稿、回复分析、阶段确认卡 | 把 Pipeline 当成第二会话启动器；在资产页批量开新会话 |
| **Admin** | 谁 / 权限 / 审计 | 组织、授权、连接器、Trace、审计 | 员工主路径的待办或生命周期扫视 |

### Home 内四模式

Home 仍是**一页**，四个入口模式，不是四个主表面，也不是第五套脊柱。员工文案顺序：

```text
今日任务 | 我的待办 | AI发现 | 我跟进的红人
```

未指定 `tab` 时默认落在 **今日任务**。员工 Home 禁止 MCP / Codex / Thread / Skill 等引擎行话（`UX-COPY-ENGINE`）。

| 模式 | 只回答 | 主对象 |
|---|---|---|
| **今日任务** | 今天的优先事项（邮件 / 阶段建议、今天推荐预填——即**旧「AI发现」**的任务推荐语义）。只推荐 / 预填，**不**自动执行；待确认需人确认才进「我的待办」 | 今日优先工作项——**不是**红人发现 |
| **我的待办** | 已入队的 Task / WorkItem 队列 | Task·WorkItem（逾期 / 今天到期 / 结果待确认 / 等审批 / 已入队 / 执行中；**仍不含**「后续」历史桶） |
| **AI发现** | 端到端**红人线索发现** | CreatorCandidate（红人线索）——**不是**任务推荐 |
| **我跟进的红人** | 我跟进的合作 | Collaboration。**加入跟进才建 Collaboration**；未跟进的发现线索不是合作 |

**改名（硬约束）：** 旧「AI发现」不得再表示任务推荐 / 今天推荐预填。新「AI发现」不得再表示邮件或阶段建议。Pipeline 与 `/agents` 专家中心不得复制这四模式的语义或对象。Home 拥有任务（今日任务 + 我的待办）；专家中心 ≠ Home（ADR-016）；并列能力面仍解耦（ADR-015）。

Admin 行的配套套件（`/admin/connectors` 枢纽与详情、`/admin/agents` 治理、连接器/授权/绑定审计切片）与员工表面的硬边界见 `21-admin-employee-page-roles.md`。可选的员工连接器**使用面**（只读消费已授权能力、个人绑定入口指向 Settings）与知识库、审批、考试同属**并列能力面**：不是 Admin，也不是本表第五页；与 `/agents` 专家中心、今日任务队列解耦，见下节与 ADR-015。`/agents` 仍是本文件 P0 工作入口 chrome（专家中心 / 数字员工），**不是**第五套主脊柱，也不是管理端；它只回答「找谁协作」，不得复制 Home 四模式、待办桶或任务计数。管理端不得复制 Home / Pipeline / Chat / Agents 的开工 IA；`/admin/agents` 只治理（发布 / 授权 / 考试闸门），不得与员工专家中心混为一页。

Pipeline 的筛选只允许 `brand|owner|stage|region|kol|sync` 与生命周期旁路/异常侧状态。阶段动作只允许「提出阶段变更」→ 人确认 → 既有 `confirm_stage` 审批/写入；不得在本页发明 LIVE 发送或新权限模型。缺字段用诚实空态，不得伪造近期事件、同步时间或审计。

可执行细则见 `specs/FS-KOL-010-pipeline.md`。与本表冲突时，以本表为准。

## 员工侧栏信息架构

员工工作台左侧栏是到达四页主表面的紧凑 chrome，不是目录说明书，也不是第二套操作系统。侧栏改动不得改写上表的四页角色，也不得削弱「发送 ≠ 推进阶段」或其他硬产品不变量。

### 逻辑簇，不是可见组标题

侧栏主栈逻辑上仍分簇（今日工作 / 数字员工 / 资产），但**禁止**画出可见的组标题（`.nav-label` 文案，含「今日 / 智能体 / 资产 / 数字员工」）。簇与簇之间只用水平分割线。`<nav>` 保留 `aria-label` 供读屏（中簇读屏名与 `/agents` 的「数字员工」入口对齐，指岗位专家，不是专家团）；不要发明新的可见组标题词。项目 / 最近若仍存在，同样走分割线、不写可见组标题。

### 定时任务属于今日工作簇

`/cron`（定时任务）与「新工作任务 / 进行中」同属今日工作簇，**不是**资产。它回答「今天或按点要跑什么」，不回答「这是哪份可回看对象」。

| 簇 | 员工入口（现行） | 禁止 |
|---|---|---|
| 今日工作 | 新工作任务、进行中、定时任务；确认入口若仍挂在本簇，必须与「审批」同路由，不得再发明第三套确认表面 | 把定时任务画进资产清单；用侧栏复制 Home 待办桶 |
| 数字员工 | `/agents` 专家中心。侧栏入口文案只写「数字员工」（岗位专家）。**不**要求「数字团队」行——该词易被读成专家团，禁止。技能目录不是员工默认入口 | **专家团**（任何入口、占位或假导航）；技能目录 / Skill picker（员工默认；仅显式调试或管理端例外）；Profile / Harness / MCP / Codex chrome；连接器**治理**或使用面挤进本簇（见 `21`） |
| 资产 | 生命周期（Pipeline 主表面）；**并列能力面**：知识库、审批、考试、可选连接器使用面（`/connectors`，Settings 邻接亦可）；明示非本期占位（云盘、遥控、项目等） | 把能力面隶属 KOL Agent 或「有进行中任务才出现」；把 Pipeline 变成今日待办；把定时任务当资产；把使用面做成治理目录或深链 `/admin/connectors` |

「等我确认」若从今日簇移除，定时任务仍留在剩余的今日块里；确认表面以资产簇的「审批」页为准。本条不授权重做 Admin 导航，也不授权改 Chat 主线程。

### 并列能力面（与 Agent / 任务解耦）

员工工作台除四页主脊柱外，可有并列能力面：知识库、审批、考试、连接器使用面，以及明示非本期的云盘、遥控、项目等。它们与数字员工开工入口、与今日任务队列相互独立：不隶属 KOL Agent，也不因「有没有进行中任务」才存在。专家中心（`/agents`）同样**不拥有**这些面：不在专家中心内嵌知识库 / 审批 / 考试 / 连接器使用面，也不用岗位专家列表当这些面的上级目录。KOL / 合作对象仅可作为各能力面中的数据或示例，不得定义该面的信息架构。Agent 会话可调用这些能力；各能力面不得复制 Chat 主线程或 Home 待办桶。连接器仍遵守使用面 vs 治理面（见 `21-admin-employee-page-roles.md`）。

这些面是可选 chrome / 并列表面，**不是**第五套主脊柱。四页法律不变。

| 硬规则 | 含义 |
|---|---|
| **能力面主权** | 知识库、审批、考试、连接器使用面（及日后云盘 / 遥控 / 项目）是独立产品面；禁止降级为 Agent 设置或任务详情 Tab。 |
| **数据可进、壳子不出** | KOL / 合作 / 邮件可作为记录类型或示例数据；页面 IA、导航、空态不得改成「先选 Agent / 先开任务」。 |
| **调用单向** | Chat / Agent 可调用已授权连接器、检索知识、提交审批；反向禁止能力面变成第二会话台或第二套今日待办。 |
| **禁止能力图鉴** | 技能目录不得做成连接器 / 知识的上级目录。`/agents` 是岗位专家召唤入口，不是能力图鉴，也不拥有并列能力面（见 P0、ADR-015）。 |
| **不是第五套 Home** | 不发明第五套主脊柱。并列能力面停留在可选 chrome，不得升格为与 Home / Pipeline / Chat / Admin 并列的第五页。 |

## `/agents` 专家中心（数字员工入口）

`/agents` 是 P0 工作入口 chrome，员工称呼为「数字员工」/ 专家中心。它**只**回答：「找谁协作 / 召唤哪位岗位专家」。它不是技能目录、不是第二套 Home 任务页、不是连接器目录，也不是第五套主脊柱。

内部对象可以叫 Expert 或 Agent；员工可见文案只用「数字员工」或「岗位专家」。本条只立法，不实施 ExpertManifest API，也不改数字员工对象模型 schema。

### 与 Home、并列能力面的边界

| 表面 | 只回答 | 专家中心禁止复制 |
|---|---|---|
| **Home** | 现在做什么 / 等待诚实。独占四模式：今日任务 + 我的待办 + AI发现（CreatorCandidate 线索）+ 我跟进的红人 | 待办桶、任务计数、今日任务预填、「今天推荐」启动器、红人线索漏斗、跟进列表 |
| **专家中心 `/agents`** | 找谁协作 / 召唤已发布岗位专家 | 技能图鉴、连接器状态、Home 四模式（含待办与线索） |
| **并列能力面** | 知识库 / 审批 / 考试 / 连接器使用面（ADR-015） | 把这些面收进专家中心或做成专家下级目录 |
| **Chat** | 如何完成一件已绑定的具体任务 | 把专家中心做成第二会话台 |

召唤之后的具体干活仍走 Chat（核心闭环）。Home 仍独占任务（今日任务 + 我的待办）；AI发现（线索）与「我跟进的红人」也只在 Home，不在专家中心。

### 员工默认表面（硬禁止）

默认员工 `/agents`（以及侧栏等与数字员工相关的员工 chrome）：

| 必须显示 | 禁止显示 |
|---|---|
| 已发布、可供召唤 / 协作的**岗位专家** | Profile 内部、Harness、MCP、Codex |
| | 技能目录 / Skill picker |
| | 连接器状态 / connector pills 作为主 IA |
| | **专家团**（无入口、无占位、无假导航） |
| | Home 待办桶、任务计数或四模式（今日任务 / 线索 / 跟进） |

引擎行话仍按 `UX-COPY-ENGINE` 禁止（MCP / Codex / Thread / Skill / 原始堆栈）。技能目录若仍存在，只许显式调试或管理端，不得作为员工默认入口。

### 召唤副作用法律

召唤一位岗位专家**只**建立绑定会话 / 协作绑定。禁止：

- 发送邮件（无 send-mail 副作用）
- 写入或推进阶段（无 stage-change 副作用）

「发送 ≠ 推进阶段」仍然有效。召唤更早：它既不是发送，也不是阶段写入。后续若要发信或改阶段，必须走既有独立确认卡（`UX-SEND-NE-STAGE`）。

### 对象命名与页面位阶

| 层 | 用词 |
|---|---|
| 内部 / 规范 / API（后续实现） | Expert 或 Agent 均可 |
| 员工可见文案 | 「数字员工」或「岗位专家」 |
| 侧栏入口 | 「数字员工」；不要「数字团队」/「专家团」 |
| 页面位阶 | `/agents` 仍是四页脊柱上的 P0 工作入口 chrome，**不是**第五套 Home |

不要发明第五个主脊柱页。不要把「数字员工」做成与 Home / Pipeline / Chat / Admin 并列的第五页。

## 非目标

- 本宪法本身不实施 `Chat.tsx` 重设计；没有单独的「宪法合规」UI PR。
- 不废止 `04-ux-ui-system.md` 的 L1–L3、双端边界、无障碍和 UX ID。
- 不把 SOP Skill、阶段机或管理端 Trace 删掉；只禁止它们占领员工主表面。
- 不把「建议 / 预填」升级成自动执行。首页「今日任务」推荐、芯片和快捷入口仍只锁定 / 预填，不绕过权限、审批和状态机。新「AI发现」是线索发现，不是把推荐自动写成 Task。
- Home 四模式仍在 Home 内；不发明第五套主脊柱。不把旧「AI发现」任务推荐语义留在新「AI发现」上。不在发现阶段自动建 Collaboration。
- 不为体验层再写一套调度器、状态机或 Host 旁路。
- Pipeline 不得再复制 Home 四模式、待办桶、任务芯片或 Chat 技能快捷入口；会话页重构仍须先符合本宪法。
- 并列能力面不是第五套 Home；不削弱核心闭环、发送 ≠ 推进阶段、无可见侧栏组标题；不改连接器使用面 vs 治理面。
- 本修订不实施 ExpertManifest / 数字员工 API，不改前端或后端；只给后续实现立法。不削弱四页法律、并列能力面（ADR-015）、连接器使用面 vs 治理面。不发明第五套主脊柱，不引入专家团。Home 四模式（ADR-018）同样只立法：不实施 FE/BE，不 LIVE，不新增 UX ID。

## 与现行主线的关系

## 设计时的允许与禁止

| 允许 | 禁止 |
|---|---|
| 人用一句话或一条芯片表达目标 | 先选模式、再选 SOP、再选手动页签才能开始 |
| Agent 做计划并调用已授权能力 | 把 MCP / Codex / Thread / Skill 时序摊给员工 |
| 线程里出现草稿、`task_result`、确认 / 拒绝 | 「建议下一步」墙、菜单教练卡、说明书式 SOP 长文 |
| 紧凑 Journey / 身份条 | 阶段漏斗写成第二主栏小说 |
| 一句「发送不等于改阶段」 | 每张卡重复发送/阶段横幅 |
| 召唤岗位专家，只建立会话 / 协作绑定 | 召唤时发信或写阶段；专家团入口或占位；员工默认 Skill / MCP / Profile / Harness / 连接器状态主 IA |
| 主窗格一条纵滚；次要面板折叠 | 任务卡 / KOL 卡横向滚动；多层嵌套滚动 |
| 等待态写清已接收、阶段、更新时间、已有产物 | 把 `waiting` 既当排队又当待确认，或不诚实的 loading |

## 落地顺序

1. 新员工端 PR 先用「核心闭环」五问自检，再按 `20-visual-design-system.md` 谈视觉。`/agents` 先过本文件专家中心条款（只召唤岗位专家；无专家团；召唤不发信、不写阶段）。管理端导航/连接器/Agent 治理先过 `21-admin-employee-page-roles.md`，再谈视觉。
2. 可执行验收仍走 `specs/UX-KOL.md` 与 `specs/ux-traceability.json`；本文件不新增 UX ID。
3. 会话页若重设计，先压缩辅助条、去掉教练卡、让结果回到脊柱，再考虑新组件。
4. 冲突写入 `DECISIONS.md`，不要在前端分支里另立一套体验规则。
