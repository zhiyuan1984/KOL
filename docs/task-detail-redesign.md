# 任务详情优化 · 实施与验收记录

## 目标与实施顺序

修复“任务明细 → 详情 → 回到原明细”的导航闭环；让详情首屏回答“哪个对象、当前状态、业务目标、当前推进、能做什么”。以有效业务信息替代大块留白、重复空态、常驻技术解释和默认显露的证据标识。

实施顺序为：确认既有设计和路由约束 → 修复来源与列表上下文恢复 → 重排详情信息层次 → 接入项目 Token 和 Ant Design → 验证导航、权限和受控写入边界 → 在最新活动发布目录定向构建 → 原子切换前端入口 → 使用真实任务只读验收。

## 范围与审查

用户批准实施前端返回修复、信息分层及视觉收敛。主责为前端实现与界面验收；适用 `CONSTITUTION.md` 的 CONST-04、CONST-08、CONST-10，`TECHNOLOGY.md` 的 TECH-FE-03、TECH-TEST-02–04，以及 `DESIGN.md` §1、§4–8、§13、§19、§24、§29。结论：符合；未更改后端权限、业务阶段、审批闸门或正式写入的权威契约。

采用保留产品和路由的定向优化。任务、工单、建议、审批、已核验事件仍是不同对象；既有 API 与所有登记字段保留。高风险点是返回来源与正式登记，分别以白名单 UI 快照、草稿确认、当前载荷确认、幂等重试及实际回执保护。

| 方向 | 落地结果 |
|---|---|

| 信息结构 | 对象与权威状态 → 目标/有效截止/推进 → 适用动作 → 有效审批、建议、工单、事件 → 收起的追溯；零工单一句；成功读到的空模块不独立占块 |
| 视觉 | Ant Design 6.6.5 Drawer/Descriptions/Collapse/Timeline/Form/Select/Input/Modal；局部主题；13px 主信息、12px 辅助；登记的抽屉宽度；单列字段；没有全局 reset 或卡片墙 |
| 操作 | 登记与工作台为次级文字入口；展开登记后提交固定在抽屉脚区；当前确认只有一个实底主 CTA；正式写入前展示载荷与异步后果 |

| 权限与缓存 | 关联模块失权清掉该模块内容，以同一身份重读主任务；主任务本身失权才清除整个详情和业务缓存；分页刷新重新读取授权范围，不混入旧对象 |

会话快照仅存 UI 条件与对象 ID，不缓存正文或事件；30 分钟到期，显式登出清除。返回重新按当前权限取数。业务目标只压缩渠道标识；原始目标、事件类型、标识、证据、发生/核验时间保留在追溯层。
