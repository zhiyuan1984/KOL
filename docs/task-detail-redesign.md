# 任务详情优化 · 实施与验收记录

## 范围与审查

用户批准实施任务中心详情的返回修复、信息分层及视觉收敛。主责为前端实现与界面验收；适用 `CONSTITUTION.md` 的 CONST-04、CONST-08、CONST-10，`TECHNOLOGY.md` 的 TECH-FE-03、TECH-TEST-02–04，以及 `DESIGN.md` §1、§4–8、§13、§19、§24、§29。结论：符合；不修改后端权限、业务阶段、审批闸门或正式写入的权威契约。

改造模式为保留现有产品与路由的定向优化。保留任务/工单/建议/审批/已核验事件的对象边界，保留既有 API 与全部登记字段；去掉常驻技术抬头、无值截止、三个重复空态和默认显露的证据标识。高风险点是返回来源与正式登记；以白名单来源快照、草稿确认、当前载荷确认、幂等重试及实际回执保护。

## 已实施

| 方向 | 落地结果 |
|---|---|
| 返回闭环 | 抽屉明确“返回任务明细”；关闭与深链参数同步；独立 Agent 详情保留来源周期、状态、搜索、联动筛选、已加载范围、展开和滚动位置；直接访问安全回退 `/tasks` |
| 信息结构 | 对象与权威状态 → 业务目标/有效截止/推进 → 适用动作 → 有效审批、建议、工单、事件 → 追溯；零工单一句，无内容模块不占独立区 |
| 视觉 | Ant Design 6.6.5 Drawer/Descriptions/Collapse/Timeline/Form/Select/Input/Modal；局部主题映射；13px 主信息、12px 辅助；480px 登记宽度；默认单列，无全局 reset 与卡片墙 |
| 操作 | 登记与工作台为 L3 入口；登记展开后的提交固定在抽屉脚区；当前确认只保留一个 L1；写入前确认载荷与异步后果 |
| 草稿与重试 | 返回、关闭、ESC、遮罩均经过未保存确认；提交中禁止关闭；失败保留草稿；同次未知结果的人工重试复用完全相同的幂等载荷，不自动重复写入 |
| 焦点与触摸 | 抽屉锁定焦点，手动补齐首尾 Tab 循环，关闭后回到来源任务行；触摸按钮 44px 命中区、24px 可见次级外框 |
| 权限与缓存 | 关联模块失权立即清理该模块内容，并以同一身份重读主任务；主任务失权才清除整个详情及业务缓存；不把子模块失败当作根任务撤权，不绕过任何授权 |

会话快照只存 UI 条件与对象 ID，不存业务正文和事件；30 分钟到期，显式登出清除。返回时重新调用当前授权接口，不展示旧缓存正文。业务化目标只压缩渠道标识，原始目标与原始事件类型、证据、发生/核验时间保留在追溯层。

## 线上诊断

2026-10-09 使用既有登录会话，只读检查 MAX BUSHCRAFT：主详情接口为 HTTP 200，审批依赖接口为 HTTP 404（`task_not_found_or_not_authorized`），建议接口为 HTTP 404（`task_not_found`）。旧组件遇到关联接口 404 会清掉整个主详情。这是“详情突然关闭/无法返回”的另一条已实测路径。

本次只修正前端对不同权限边界的处理：受限模块显示明确错误与重读入口，主任务只有在自身权威读取失败时才收起。接口 404 的后端原因、关联范围与授权配置没有被更改；不能把模块错误伪装为空数据，也不能宣称工单/审批生产闭环已完成。
