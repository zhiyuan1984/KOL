```yaml

name: design-spec-v3
style-baseline: data-dense-dashboard + data-grid
description: 员工端工作台与中台 2B 数据面的视觉 token 与布局实施细则。LLM 实现时唯一数值来源。
  颜色只给"职责→token"映射，hex 住 frontend/src/styles.css（根 AGENTS.md §3）；
  布局/字号/间距/圆角数值直接取用。冲突时以"不变量"为准：不变量 > 分节细则。

  - 员工端工作台（对话式 Agent 场景）：Home / Pipeline / Admin / 一等能力面
  - 中台 2B 数据面（高密度场景）：数据表、统计区、高级筛选、批量操作、审计
```

> 修订说明（v2 beta → v3）：本次修订解决 v2 的三类结构性问题——
> ① **补构造性 token**：v2 是"约束型"spec（只说不许做什么），v3 补上"应该长什么样"：视觉强调四级（含文字按钮）、表格密度三档、KPI 统计区、表单、高级筛选、批量操作栏、抽屉；
> ② **收敛补丁**：删除 §5.1 的 18px 单页例外，知识工作区标题统一回 13px + 字重；
> ③ **Agent 交互补完**：流式输出排版、引用溯源、打断/回退、延迟表达、快捷 chips 上限。
> v2→v3 逐条对照见文末《变更对照表》。

## 0. 给 LLM 的阅读指引

1. 先读 **§1 不变量**（8 条），任何分节与之冲突时不变量优先。
2. 颜色：**只允许** §3 表中"职责→token"的映射，不得自创颜色职责，不得写 hex。
3. 数值 token（`--control-h-*`、`--btn-text-*`、`--table-row-h-*`、`--dialog-*`、`--drawer-*`、`--ds-font-*` 等）直接取用，不得缩放、不得"约等于"。
4. 先定**密度档**（§2）：对话式工作台走 `data-dense-dashboard`，数据表/统计/筛选面走 `data-grid`；一屏内不混用两档的行高体系。
5. 输出前跑一遍 **文末《LLM 输出自检清单》**，逐项打勾。
6. 本文件未定义的视觉决策，默认走"克制"选项：更小字号、更小间距、单列、不新增颜色；**次级动作默认用 L3 文字按钮，不用默认描边按钮**。

## 1. 不变量（8 条）

1. 同一视口最多 **一个** L1 实底主 CTA；其余动作按 §4 视觉强调四级降级。
2. 风险分级：R1 只读直接执行；R2 草稿必须标注；R3 外发、导入、删除、解密、正式写入，执行前必须确认并留回执。（v2 称"行动分级 L1/L2/L3"，v3 改名为风险分级 R1/R2/R3，避免与视觉强调四级混淆）
3. 真实等待必须有原因、状态与恢复入口；不得伪造完成、联系人、结果或进度。
4. 状态不能只靠颜色表达（WCAG 2.2 AA）：形状、字重、下划线、文案至少一条同时变化。文字/可点标签 ≥4.5:1，纯图形 ≥3:1，实底上的字 ≥4.5:1。
5. 页脚与浮层不得吃掉它服务的内容；**关键操作区无滚动**（长内容允许内部滚动区，见 §8）。
6. **同一信息不重复渲染，但允许汇总层/明细层分层呈现**（v3 修订，原"只出现一次"）：
   同一数据可在汇总条（聚合值）与明细表（逐行值）同时出现，视为两层而非重复；
   **同一粒度下**，标题区/摘要区/卡片区不得重复渲染同一值；同值字段折叠；零数据不渲染。细则见 §8。
7. **栏内布局约束**：窄容器（<480px，如右栏）内禁止二次分栏，字段一律单列上下堆叠；两栏/多栏只允许在 ≥720px 内容区使用。细则见 §6。
8. **视觉强调四级**（v3 新增）：L1 实底主 CTA / L2 默认描边按钮 / L3 文字按钮 / L4 链接按钮。
   L3 用于行内操作、工具栏次级动作、"查看更多/收起"、展开入口；L4 用于外链跳转。
   **L3/L4 不得升级为 L1/L2**；该用文字按钮的地方出现描边按钮视为 bug。映射表见 §4。

## 2. 密度档

| 档 | 用于 | 节奏 |
|---|---|---|
| `data-dense-dashboard` | 员工端工作台表面：Home 五模式、Pipeline、Admin、一等能力面 | 紧凑。一屏之内回答本面唯一的那个问题；列表行本身就是内容，不做卡片墙 |
| `dialog-compact` | 全部弹窗/对话框/向导 | **弹窗为独立密度档**：内边距可用紧凑档（§7.1 `--dialog-pad-compact`）；字阶、控件高与圆角向工作台对齐（§4/§5），颜色职责与工作台一致 |
| `data-grid` | **中台 2B 数据面**：数据表、KPI 统计区、高级筛选、批量操作、审计日志 | 高密度。行高走 §9 表格三档；汇总条＋明细表分层呈现（不变量 6）；一屏内行数优先于留白 |

- 一屏内不混用两档的行高体系：工作台内的嵌入表格跟工作台档，全屏数据面跟 `data-grid` 档。
- `data-grid` 下默认表格密度为"标准档"（§9.1），行数 >50 或用户显式切换时用"紧凑档"。

## 3. 颜色：四职责 + 业务语义映射

颜色只承担四种职责，**不得互相串用**。职责与 token 的对应由本表决定；数值只住 `frontend/src/styles.css`，本文件不写 hex。

| 职责 | token | 用在哪 |
|---|---|---|
| 主行动 | `--primary` / `--primary-hover` / `--primary-fg` | **同一视口唯一的 L1 实底主 CTA**（品牌粉）。粉色除此之外不再使用 |
| 辅助 | `--accent` / `--accent-text` / `--accent-hover` | 选中态、图标砖与图标字形、行内可点强调、信息性标记；**执行中状态**（§3.1）；L3 文字按钮 hover 底 |
| 类别 | `--cat-*` / `--cat-*-text` | 按类别分组的目录面：图标砖淡底/描边与砖内字形；**知识来源标识**（§3.2）；技能目录按来源分色 |
| 状态 | `--warning` / `--danger` / `--success` | 风险、L3「需确认」、失败、成功。只表达状态，不承担品牌或辅助 |

- 类别色不承担交互与状态；类别只是加强信号，不得成为唯一信号（名称、分组、详情列必须仍能独立判读）。
- 每个类别色分两档：图形/描边 ≥3:1、砖内字形 ≥4.5:1，浅色深色分别验证。
- 「选中」不等于「主行动」：选中态用辅助色 + 形状/字重/下划线，不得靠实底按钮。

### 3.1 业务语义 → 四职责映射表

| 业务语义 | 映射到 | 表达方式（颜色只占其一） |
|---|---|---|
| 任务-待办 | 中性文字 `--text-quiet` | 灰色文字 + "待办"文案 |
| 任务-执行中 | `--accent` | 辅助色 + 脉冲动画 + "执行中"文案（三通道） |
| 任务-待确认 | `--warning` | 黄色 + ⚠ 图形 + "待确认"文案；对应 R3 |
| 任务-已完成 | `--success` | 绿色 + ✓ 图形 + "已完成"文案 |
| 任务-超时/升级 | `--danger` | 红色 + ⚠ 图形 + "已超时"文案 |
| 风险-低/中/高 | `--success` / `--warning` / `--danger` | 对应 R1/R2/R3；高风险卡红色描边 `--shadow-risk-high` |
| trace-成功/失败/等待 | `--success` / `--danger` / 中性 | 失败节点可展开详情 + 重试入口 |
| 身份：人 / agent | **文案徽章为主**（"人"/"Agent"）+ 形状区分 | 不新增色相；颜色仅作加强，复用 `--accent`（agent 侧） |
| SLA-充足/紧张/超时 | `--text-quiet` / `--warning` / `--danger` | 倒计时文字 + 进度条形状 |

- **动效**：trace 执行中的脉冲、agent 流式输出与「有新内容」提示按「颜色 + 动效 + 文案」多通道表达；**`prefers-reduced-motion` 下必须降级**（停用脉冲与平滑滚动，保留文案与静态标记）；时长、缓动与脉冲参数住 `frontend/src/styles.css`。

### 3.2 知识来源标识（并入 `--cat-*`）

| 来源 | 类别 token | 标注形式 |
|---|---|---|
| 记忆（事件/工单摘要） | `--cat-memory` | 色标 + "记忆·工单摘要" |
| 文档知识 | `--cat-doc` | 色标 + "文档·《退货政策 v4》" |
| 经验 pattern（WikiSkill） | `--cat-pattern` | 色标 + "经验·pattern 名" |
| 本体对象快照 | `--cat-ontology` | 色标 + "对象·客户" |

### 3.3 验收项

- `--primary`（品牌粉）与 `--danger`（红）的色相距离：紧凑界面中不混淆（必查项，见 §13）。

## 4. 控件尺寸与行动四级

### 4.1 尺寸 token

- 控件高度、圆角、命中区走命名 token：`--control-h*`、`--btn-text-*`、`--radius-control`、`--radius-card`、`--chip-h`、`--badge-h`。**不在页面里写具体数值**。
- 工作台按钮、搜索框、筛选项采用紧凑高度、小圆角；**胶囊形只用于身份/状态语义，不得作为通用按钮或选项造型**。
- **选项组 >8 项时禁用 chips**：改用分组下拉（optgroup）或紧凑列表。chips 只保留"已选状态"的展示（§20）。
- 同组控件等高、等宽、统一对齐；触摸模态只扩大命中区（≥44px），不同步放大视觉控件。
- 焦点态统一 `--focus-ring`，`focus-visible` 才出现。
- 间距走 `--space-*` 阶梯（`frontend/src/styles.css`）；不新增自造间距档。

| token | 值 | 用途 |
|---|---:|---|
| `--control-h-lg` | `32px` | 搜索框与同排按钮（工作台）；L1/L2 按钮默认高 |
| `--control-h-form` | `32px` | 弹窗输入框/下拉/按钮统一高度 |
| `--control-h-sm` | `24px` | 紧凑场景：表格内小控件、 dense 工具栏 |
| `--chip-h` | `28px` | 筛选 chips；触摸模态命中区扩至 44px |
| `--workspace-task-action-h` | `20px` | 任务行操作按钮与状态标签同高 |
| `--radius-control` / `--radius-card` | `6px` / `8px` | 控件 / 内容容器 |
| `--radius-dialog` | `8px` | 弹窗卡片圆角 |
| `--cost-meter-h` | `6px` | 预算进度条；比例只由形状表达，状态词与数值同时文字给出 |

### 4.2 视觉强调四级（v3 新增，不变量 8 的细则）

| 级 | 形态 | token | 用在哪 |
|---|---|---|---|
| L1 | 实底主 CTA | `--primary` 实底，`--primary-fg` 文字，高 `--control-h-lg`，圆角 `--radius-control` | 每视口 ≤1 个：提交、确认执行、发布 |
| L2 | 默认描边按钮 | 1px `--border` 描边，`--bg` 底，文字 `--text`，高 `--control-h-lg` | 次要但独立的动作：取消、返回、次级提交 |
| L3 | **文字按钮** | 无边框、无底色，文字 `--accent-text`（或 `--text`），高 `--btn-text-h: 28px`，左右 padding `--btn-text-pad-x: 8px`，hover 底 `--btn-text-hover-bg`（辅助色 8% 淡底），圆角 `--radius-control` | 行内操作（表格行"编辑/删除/查看"）、工具栏次级动作、"查看更多/收起"、展开入口、批量栏动作 |
| L4 | 链接按钮 | 文字 `--accent-text` + 下划线（hover 才出现），无高约束，随行高 | 外链跳转、跳详情页 |

- **判定规则**：动作是否值得一个描边框？行内重复出现（每行都有）的动作一律 L3；同一工具栏内 L2 ≤2 个，其余 L3。
- L3 在紧凑行内（表格行、feed 行）可用 `--control-h-sm`（24px）档，padding-x 收至 4px。
- 危险动作（删除、撤销）用 L3 + `--danger` 文字，不得做成 L1 实底红（除非该视口无其他 L1 且为最终确认）。
- **禁止**：把 L3/L4 升级为 L1/L2 "为了显眼"；一排三个描边按钮（该用 L2+L3+L3）。

## 5. 统一小字号

工作台文字统一使用 `--ds-font-sm`（13px）。标题、正文、标签、元信息、控件与弹窗不另起字阶；层次通过字重、间距与分隔表达，不扩大字号。

| 角色 | 用哪一档 | 禁止 |
|---|---|---|
| 页面、块、弹窗标题 | `--ds-font-sm`，字重 ≤600 | 独立放大字号 |
| 正文、结果、控件、元信息 | `--ds-font-sm` | 硬编码字号或另起字阶 |

- **等宽字体**：trace 节点、日志与 SKILL.md 预览统一用 `--mono`（`frontend/src/styles.css` 既有定义）；不新增字体族。
- **数据面例外**：`data-grid` 下 KPI 数值可用 `--stat-value-font: 20px`（字重 600），见 §9.2；表格内数字可用 `--mono` 对齐。这是唯一允许的字号例外。

### 5.1 知识工作区收敛说明（v3 已收敛）

v2 的单页例外（18px 标题）已删除。知识工作区标题统一回 `--ds-font-sm` + 字重 600，用字重/间距/分隔表达层次，不再独立放大字号。
非字号 token 保留：`--knowledge-filter-width: 260px`（筛选列宽）、`--knowledge-action`（本页唯一 L1；**取值必须与 §3 的"主行动"一致**，即品牌主色档，数值住 styles.css）。

## 6. 布局：三栏 + 抽屉

### 6.1 外层三栏

| token / 断点 | 数值 | 用途 |
|---|---:|---|
| 桌面导航轨道 | `260px` | 锁死 |
| `--workspace-result-rail-min` | `360px` | 双栏成立时右栏最小宽度，**flex 不得压缩突破** |
| `--workspace-result-rail-ideal` | `54%` | 结果优先视口右栏目标宽度 |
| `--workspace-result-rail-max` | `820px` | 防宽视口无限扩张 |
| `--workspace-result-rail-collapsed` | `56px` | 折叠轨道 |
| 堆叠断点 | `1100px` | 及以下：中栏在上、结果栏在下 |

- 右栏 `flex-shrink: 0`；中栏 `min-width: 0`（允许收缩）；英文长标题强制 `overflow-wrap: break-word`。
- 滚动轴总数 ≤3（左栏 / 中栏 feed / 右栏）；页面外层不滚动（细则见 §10.1）。

### 6.2 栏内布局约束（不变量 7 的细则）

- **<480px 的容器内禁止二次分栏**：字段一律单列上下堆叠（label 上、value 下）。
- **两栏/多栏只允许在 ≥720px 内容区**：如连接器表单两列，窄屏自动收为单列。
- **目录/浏览类弹窗用列表行**，不做卡片墙（密度档信条）；**指标总览类可用紧凑 KPI 卡**（§9.2），不视为"卡片墙"；**同一对象的生命周期状态不适用 KPI 卡，用分布条**（§9.2）。
- 表格固定列宽总和不得超过容器 40%（如任务表优先级 64px + 操作 124px，在窄容器中操作列收进"更多"）。

### 6.3 抽屉（v3 新增）

宽表、审计明细、复杂表单（字段 >8）不用弹窗，用右侧抽屉：

| token | 值 | 用途 |
|---|---:|---|
| `--drawer-w-sm` / `--drawer-w-md` / `--drawer-w-lg` | `480px` / `720px` / `960px` | 按内容选档；宽表用 lg |
| `--drawer-pad` | `20px` / `16px`（左右/上下） | 默认档 |

- 抽屉从右侧滑入，带遮罩；ESC / 点击遮罩关闭（有未保存变更时先确认）。
- 抽屉头 sticky：标题 + 关闭；抽屉脚 sticky：L1 + L2（左对齐 L3 文字按钮"取消"亦可）。
- 抽屉内表格直接走 `data-grid` 密度档。

## 7. 弹窗规范（通用 + 差异）

### 7.1 通用

| token | 值 | 用途 |
|---|---:|---|
| `--dialog-w-sm/md/lg` | `440px` / `560px` / `720px` | 按内容量选档，**禁止一刀切 560px** |
| `--dialog-pad` | `20px` / `20px` / `26px`（左右/上/下） | 默认档 |
| `--dialog-pad-compact` | `12px` / `16px` | 紧凑档：字段 ≤5 个的弹窗用此档 |
| `--dialog-h-max` | `88dvh` | 向导类 `94dvh`（需登记理由） |

- 输入与下拉**不使用描边**，填充 + 圆角；焦点态回描边。
- **参考图只定信息结构**（有哪些字段、什么顺序），**不定视觉比例**：字号、间距、圆角一律走本文件 token。参考图实测 px 不得直接写入 token。
- 每步/每窗一个 L1；回执只保留最新一条，固定顶部，可收起。
- 字段 >8 或含宽表 → 不用弹窗，用抽屉（§6.3）。

### 7.2 连接器设置向导（差异）

四步：保存 / 测试 / 工具清单 / 启用。步骤条是**唯一**状态载体；测试免责声明「仅验证工具目录，不代表业务动作」保留；改配置后连接器回到「待验证」，启用键置灰并写明原因。

### 7.3 浏览弹窗（差异）

- 目录浏览类 → **列表行**：图标砖 28px + 标题 + 描述单行截断 + 右侧动作位（L3 文字按钮）。
- 不显示治理状态行（治理入口留在枢纽卡片）。

## 8. 信息去重规则（不变量 6 的细则）

1. **分层呈现**（v3 修订）：汇总条（聚合值）与明细表（逐行值）可同屏，视为两层；**同一粒度下**标题区/摘要区/卡片区不得重复渲染同一值。
2. **同值折叠**：「当前」与「变更前」值相同时，只渲染一行（标"未变更"）；阶段确认卡的"当前/变更前/变更后"同理。
3. **零数据不渲染**：数量为 0 的筛选项默认收起；零值字段（如"粉丝 0万"）隐藏，hover 显示。**统计区 KPI 为 0 时保留占位**（"0"本身是信息），不隐藏。
4. **标题去重**：禁止"本轮结果·结果"类重复标题；LLM 生成文案时做字符串级去重（相邻相同语义标题合并）。
5. **数字同源**：同一视口的所有统计数字必须来自同一数据源；"77 项任务 vs 全部 22"类口径打架视为 bug。
6. **状态单点表达**：同一状态只在一处表达（步骤条/状态行二选一）；"待确认"卡内不得再写"已按确认写入"。
7. **过程流三处收敛**：推理摘要只展开最新一段；摘要被裁切时必须给"展开全文"入口，**禁止 `overflow: hidden` 静默裁切**（不变量 5）。
8. **空态诚实**：「尚无结果 / 服务不可用 / 筛选无结果」三分，保留双入口（填参数跑一次 / 交给 Agent）。

## 9. 内容密度

### 9.1 数据表三档（v3 新增，`data-grid` 核心）

| token | 行高 | 单元格上下 padding | 用于 |
|---|---:|---:|---|
| `--table-row-h-relaxed` | `52px` | `16px` | 含双行内容/对象卡的行 |
| `--table-row-h`（默认） | `44px` | `12px` | 中台数据面默认 |
| `--table-row-h-compact` | `32px` | `8px` | 行数 >50、大屏监控、用户显式切换 |

- 展开行：点击行首 ">" 展开，展开区 padding `12px 16px`，底 `--bg-subtle`。
- 空单元格：渲染 `—`（`--text-quiet`），不留白格造成"缺数据"误读。

- 排序：表头可排序列显示 ↕，升序 ↑ / 降序 ↓；筛选：表头漏斗图标 + 下拉面板（§20）。
- 分页：右下 `共 N 条 · 每页 [20/50/100] · < 1/2/3 >`，紧凑单行；N >1000 必须服务端分页并注明。

### 9.2 KPI 统计区（v3 新增）

| token | 值 | 用途 |
|---|---:|---|
| `--stat-value-font` | `20px` / 字重 600 | KPI 数值（数据面唯一允许的字号例外） |
| `--stat-label-font` | `12px` / `--text-quiet` | 指标名 |
| `--stat-delta-font` | `12px` | 环比：▲/▼ + 百分比，涨 `--success` / 跌 `--danger`（涨跌语义按指标正负向配置，不得写死红涨绿跌） |

- 文本 `pre-wrap` + `overflow-wrap` 防越界。

## 10. 中栏滚动行为

核心矛盾：Agent 持续写入（流式输出、Trace 展开、新事件），人同时在阅读历史、做确认。滚动条要在"跟随新内容"与"不打断人阅读"之间裁决。

### 10.1 结构：三段式

- 中栏 `display: flex; flex-direction: column`：header（sticky 顶）+ feed（`flex: 1; overflow-y: auto`，**唯一滚动容器**）+ composer（sticky 底：输入框/快捷操作）
  - 快捷操作 chips：最多 `--composer-chips-max: 4` 个，单行横滑或换行 ≤2 行；超出收进"更多"（L3）
- header、composer `flex-shrink: 0`，始终可见
- 滚动轴总数 ≤3（左栏、中栏 feed、右栏）；页面外层不滚动

### 10.2 自动跟随规则

| 用户位置 | 新内容到达时 |
|---|---|
| 距底部 < `--feed-follow-threshold`（视为"在底部"） | 自动跟随滚到底 |
| 距底部 ≥ 阈值（在看历史） | **不打断**；右下角出现"有 N 条新内容 ↓" pill，点击后滚到底 |
| 流式输出中用户上滚 | 立即停止跟随（一次上滚 = 明确意图） |

- pill 与"回到底部"按钮二选一（不变量 6：同一个"有新内容"只表达一次）
- `overflow-anchor: auto`：流式追加内容时视口不跳动

### 10.3 R3 确认卡必达视口

- 确认卡出现时若不在视口内：`scrollIntoView({ block: 'center', behavior: 'smooth' })`
- 决策前卡片 sticky 在 feed 顶部（或固定于 composer 上方）；决策后收起为一行"已确认/已驳回"状态（不变量 6）

### 10.4 滚动条样式

| token | 值 | 用途 |
|---|---:|---|
| `--scrollbar-size` | `8px` | overlay 式，不占布局宽度 |
| `--scrollbar-thumb` | （住 styles.css） | hover 加深；指针设备空闲 1.5s 淡出 |
| `--feed-follow-threshold` | `48px` | "在底部"判定阈值 |
| `--feed-min-h` | 按高度档（住 styles.css） | 小高度视口下 feed 保底高度 |

- 触摸设备不显示滚动条，靠手势

### 10.5 Trace 展开

- 节点展开/收起保持视口锚定，不跳动
- "查看详情"内容超出一屏时，平滑滚动到该节点顶部

### 10.6 高度档

- 小高度视口（630/589）：composer 收起为单行，feed 优先保高度
- feed 高度由 flex 分配，不写固定 px

## 14. 通用任务工作台

任务不是一次回答或一次工具调用，而是可跨会话恢复的目标。所有任务表面统一为：左栏导航与入口；中栏有序事件流、输入和当前阶段动作；右栏成果、证据和结果状态。技能可省略不需要的阶段，但不得改变这三个区域的职责。

中栏事件应依次表达目标与技能上下文、输入引导、条件或草稿、解析缺口、实际参数或预览、确认、执行回执、成果摘要和下一步。模型解释与服务端事实事件可以合并展示，但状态、进度、回执只能来自权威事件。没有真实结果时不得渲染候选、完成或进度。

**任务状态单点在右栏**（2026-10-06 用户裁决）：任务的当前状态（运行中阶段、结果已生成、待你标记完成、失败、已取消等）只在右栏结果区上方呈现一次。中栏页头只放任务标题与当前阶段动作，不放状态徽章或状态卡；中栏事件流顶部不放结论性摘要。「待确认」只用于需要人确认的 R3 动作，不得用来表示「等你标记完成」。中栏页头固定在滚动区之外（§10.1），不随事件流滚走。

同一视口当前阶段只保留一个 L1。R3 确认卡必须包含范围、参数版本、风险、确认和取消；参数变化使旧确认失效。停止、重试、导入、发送和正式状态变更使用独立动作及回执。

### 14.1 打断与回退（v3 新增）

- 流式输出/执行中，composer 区的 L1 变为"停止"（`--danger` 描边 L2 形态，非实底红）；点击后状态行变为"已停止 · 第 N 步"，**保留"回退到第 M 步重跑"**（L3 文字按钮组：列出可回退的阶段节点）。
- 回退重跑使该节点之后的所有确认失效，需重新确认（沿用"参数变化使旧确认失效"）。
- 回退后旧分支折叠为"已回退分支（N 步）"，L3 文字按钮可展开查看，不删除历史。

### 14.2 延迟表达（v3 新增）

- agent"思考中/执行中"超过 `--agent-wait-hint: 3s`：状态行显示已用时（如"思考中 · 12s"）+ "取消"（L3）。
- 超过 `--agent-wait-long: 30s`：给出预估（"预计还需约 1 分钟"）或"转人工跟进"入口（L3），不得无限转圈（不变量 3）。
- 超时（>120s 无进展）：自动降级为"稍后通知我"，任务进任务中心，结果到达时按 §10.2 规则提示。

## 15. 技能的员工体验契约

已发布技能除机器契约外，必须提供员工体验契约：标题和用途、输入与默认值、可执行/事后核验/不支持条件、过程事件、产物与来源要求、不确定性、风险与确认、失败恢复和后续动作。员工表面使用业务名称，不显示 MCP、工具 ID、内部 schema 或未经整理的日志；这些信息只在可追溯详情中出现。

技能可以声明需要哪些任务节点，但不能自定义像素、颜色职责、布局、权限、业务阶段判定或确认闸门。平台根据风险和任务状态渲染统一事件、确认和回执组件。技能输出必须区分事实、推断、建议、缺失信息和已执行结果。

## 16. 任务与技能视觉验收

- 事件流在底部时自动跟随；用户上滚后不被新内容打断，并提供单一"有新内容"入口。
- 待确认事项在提问框上方有明确提示并可定位到完整确认卡；确认完成后折叠为单行回执。
- 成果只在右栏呈现一次，保留来源、版本、时间和核验状态；中栏只保留过程摘要。
- 任务状态只在右栏出现一次；同一视口内页头、事件流与右栏不得重复或矛盾地表达同一状态。
- 右栏只呈现本轮结果；本轮没有结果而展示较早结果时，标题必须写「最近一次结果」并带时间，不得写「本轮结果」，也不得从会话历史任意消息中拼取结果。
- 能力不可用（数据连接未接通、工具未授权）与缺少输入是两种状态，分别给出原因与恢复入口；员工面不出现 MCP、连接器 id、工具别名或技能 id（§15）。
- 空态区分"尚无结果""服务不可用""筛选无结果"；不以占位结果代替真实数据。
- 新增任务类型沿用本文件 §1–§13 的 token、三轴适配、无障碍、颜色职责和滚动规则，不新增任务专用视觉体系。

## 17. Agent 流式输出排版（v3 新增）

- **Markdown 渲染**：feed 内的 markdown 表格直接渲染为紧凑表格（走 `--table-row-h-compact`）；代码块最大高度 `--feed-code-max-h: 320px`，超出内部滚动 + 右上"展开"（L3）；标题降级渲染（`#`→加粗 13px，不放大字号）。
- **工具调用卡片**：每次工具调用渲染为一行：图标 + 工具业务名 + 状态（执行中/成功/失败，§3.1 三通道）；参数默认折叠，"查看参数"（L3）展开；结果只渲染摘要，详情进"查看结果"。
- **多步骤进度**：步骤 ≥3 时在 feed 顶部渲染轻量步骤条（当前步骤高亮 + 已完成打勾）；步骤条只表达进度，不替代 §7.2 向导的状态载体职责。
- **长输出折叠**：单条 agent 回复超过 800px 高时，自动折叠超出部分，"展开全文"（L3）；折叠处保留来源区可见（§18）。

## 21. 批量操作（v3 新增）

- 表格行选择后，顶部出现批量栏：sticky，`--batch-bar-h: 48px`，底 `--surface` + 底边框；内容：`已选 N 项` + 批量动作组（L3 文字按钮，如"批量通过/批量驳回/导出"）+ 右侧"清空选择"（L3）。
- 批量栏出现时**不得遮挡首行**（验收项 §13）；表格上移或批量栏悬浮时首行下留 48px。
- 批量 R3 动作（通过/驳回/删除）走确认流程（不变量 2），确认卡列明影响条数。
- 跨页选择：保留已选，批量栏显示"已选 N 项（含其他页 M 项）"。

---

## 22. 权限与脱敏（v3 新增）

- 无权限的功能入口：渲染为禁用态 + tooltip "无权限，可申请"；整页无权限 → 紧凑空态 + "申请权限"（L2）。
- 无权限的数据字段：渲染 `****`（`--text-quiet`），hover 显示"无权查看，点击申请"（L3）。
- 脱敏展示：手机号 `138****1234`、金额 `¥**.**`（明细页可申请查看完整）；脱敏规则由权限 token 决定，LLM 不得自创打码格式。
- 不同角色看到不同密度时，表格列按角色配置显隐，**列顺序不得因权限打乱**（避免"同一张表两种样子"造成协作误解）。

---

## 23. 导出与审计（v3 新增）

- 导出入口：数据面工具栏右侧，L2 描边按钮"导出"；大数据量（>1000 行）导出为异步任务：点击后转"导出中"状态，进任务中心可查（不变量 3：真实等待给状态与恢复入口）。
- 审计日志：走 `data-grid` 表格，固定列：时间 / 操作人 / 动作 / 对象 / 结果；支持按时间/操作人筛选（§20）。
- 导出文件命名：`{业务名}_{YYYYMMDD}_{HHmm}.xlsx`，由服务端生成，LLM 不拼文件名。
