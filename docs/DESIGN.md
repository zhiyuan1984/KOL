## 0. 给 LLM 的阅读指引
1. 先读 **§1 不变量**（8 条），任何分节与之冲突时不变量优先。
2. 颜色：**只允许** §3 表中"职责→token"的映射，不得自创颜色职责，不得写 hex。
3. 数值 token（`--control-h-*`、`--btn-text-*`、`--table-row-h-*`、`--dialog-*`、`--drawer-*`、`--ds-font-*` 等）直接取用，不得缩放、不得"约等于"。
4. 先定**密度档**（§2）：对话式工作台走 `data-dense-dashboard`，数据表/统计/筛选面走 `data-grid`；一屏内不混用两档的行高体系。
5. 输出前跑一遍 **文末《LLM 输出自检清单》**，逐项打勾。
6. 本文件未定义的视觉决策，默认走"克制"选项：更小字号、更小间距、不新增颜色；浏览工作区按已登记的列表＋详情骨架，未登记的表单内容采用单列；**次级动作默认用 L3 文字按钮，不用默认描边按钮**。

## 1. 不变量（8 条）
1. 同一视口最多 **一个** L1 实底主 CTA；其余动作按 §4 视觉强调四级降级。
2. 风险分级：R1 只读直接执行；R2 草稿必须标注；R3 外发、导入、删除、解密、正式写入，执行前必须确认并留回执。（v2 称"行动分级 L1/L2/L3"，v3 改名为风险分级 R1/R2/R3，避免与视觉强调四级混淆）
3. 真实等待必须有原因、状态与恢复入口；不得伪造完成、联系人、结果或进度。
4. 状态不能只靠颜色表达（WCAG 2.2 AA）：形状、字重、下划线、文案至少一条同时变化。文字/可点标签 ≥4.5:1，纯图形 ≥3:1，实底上的字 ≥4.5:1。
5. 页脚与浮层不得吃掉它服务的内容；**关键操作区无滚动**（长内容允许内部滚动区，见 §8）。
6. **同一信息不重复渲染，但允许汇总层/明细层分层呈现**（v3 修订，原"只出现一次"）：
   同一数据可在汇总条（聚合值）与明细表（逐行值）同时出现，视为两层而非重复；
   **同一粒度下**，标题区/摘要区/卡片区不得重复渲染同一值；同值字段折叠；零数据不渲染。细则见 §8。
7. **栏内布局约束**：窄容器（<480px，如右栏）内禁止二次分栏，独立字段组采用单列；简短元数据允许标签和值同行并自然换行；两栏/多栏只允许在 ≥720px 内容区使用。细则见 §6。
8. **视觉强调四级**（v3 新增）：L1 实底主 CTA / L2 默认描边按钮 / L3 文字按钮 / L4 链接按钮。
   L3 用于行内操作、工具栏次级动作、"查看更多/收起"、展开入口；L4 用于外链跳转。
   **L3/L4 不得升级为 L1/L2**；该用文字按钮的地方出现描边按钮视为 bug。映射表见 §4。

## 2. 密度档
| 档 | 用于 | 节奏 |
|---|---|---|
| `data-dense-dashboard` | 员工端工作台表面：Home 五模式、Pipeline、Admin、一等能力面 | 紧凑。一屏之内回答本面唯一的那个问题；列表行本身就是内容，不做卡片墙 |
| `dialog-compact` | 全部弹窗/对话框/向导 | **弹窗为独立密度档**：内边距可用紧凑档（§7.1 `--dialog-pad-compact`）；字阶、控件高与圆角向工作台对齐（§4/§5），颜色职责与工作台一致 |
| `data-grid` | **中台 2B 数据面**：数据表、KPI 统计区、高级筛选、批量操作、审计日志 | 高密度。行高走 §9 表格三档；汇总条＋明细表分层呈现（不变量 6）；一屏内行数优先于留白 |
- 一屏内不混用两档的行高体系：工作台内的嵌入表格跟工作台档，全屏数据面跟 `data-grid` 档。
- `data-grid` 下默认表格密度为"标准档"（§9.1），行数 >50 或用户显式切换时用"紧凑档"。

### 2.1 全局密度模式（⚠️ 预留/未决策，v3.1）
> **状态：未决策，不作为实现依据，不进自检清单。** 全局一键切换需要产品侧先明确：偏好存储位置（本地/服务端）、切换入口、同步范围（是否含弹窗/抽屉/深色主题）、异常降级策略。在此之前，以下条文为预留草案；有效规范仅为 §2.2 组件三档。
- 全局提供两档视觉密度：`default`（标准）、`compact`（紧凑）；用户可全局切换，所有组件同步生效。
- `data-dense-dashboard` 默认 `default`，重度用户可切换 `compact`；`data-grid` 默认 `default`，行数>50 自动建议切换 `compact`。
- 密度切换仅调整行高、内边距、间距、次要字号，不改变颜色职责、控件等级与交互逻辑。

### 2.2 组件密度三档统一规则
所有数据承载组件（表格、列表、表单、卡片、导航菜单）统一使用三档密度命名，与全局模式对应：
| 密度档 | 对应全局模式 | 适用场景 |
|---|---|---|
| `relaxed`（宽松） | default 可选 | 内容少、需强调可读性；单页条目<10 |
| `default`（标准） | 默认 | 通用场景，平衡密度与可读性 |
| `compact`（紧凑） | compact 全局 / 自动触发 | 数据密集、大屏监控、条目>50 |
- 表格密度执行 §9.1；列表密度执行 §9.3.1；表单密度执行 §19.1；KPI 卡片密度执行 §9.2.1；导航菜单密度执行 §6.1.1。
- 同一页面内同类型组件密度一致；禁止同一列表/表格/导航内混用多档行高。
> 注：「对应全局模式」列为预留映射，待 §2.1 决策后启用；当前仅「密度档/适用场景」列有效。

## 3. 颜色：四职责 + 业务语义映射
颜色只承担四种职责，**不得互相串用**。职责与 token 的对应由本表决定；数值只住 `frontend/src/styles.css`，本文件不写 hex。
| 职责 | token | 用在哪 |
|---|---|---|
| 主行动 | `--primary` / `--primary-hover` / `--primary-fg` | **同一视口唯一的 L1 实底主 CTA**（品牌粉）。**实底粉只用于 L1，不再有任何例外**；等级标记 chip 仅允许描边形态占用主行动色（见 §3.1 例外声明） |
| 辅助 | `--accent` / `--accent-text` / `--accent-hover` | 选中态、图标砖与图标字形、行内可点强调、信息性标记；**执行中状态**（§3.1）；L3 文字按钮 hover 底 |
| 类别 | `--cat-*` / `--cat-*-text` | 按类别分组的目录面：图标砖淡底/描边与砖内字形；**知识来源标识**（§3.2）；技能目录按来源分色 |
| 状态 | `--warning` / `--danger` / `--success` | 风险、R3「需确认」（工具副作用风险档）、失败、成功。只表达状态，不承担品牌或辅助 |
- 类别色不承担交互与状态；类别只是加强信号，不得成为唯一信号（名称、分组、详情列必须仍能独立判读）。
- 每个类别色分两档：图形/描边 ≥3:1、砖内字形 ≥4.5:1，浅色深色分别验证。
- 「选中」不等于「主行动」：选中态用辅助色 + 形状/字重/下划线，不得靠实底按钮。

### 3.1 业务语义 → 四职责映射表
| 业务语义 | 映射到 | 表达方式（颜色只占其一） |
|---|---|---|
| 任务-待办 | 中性文字 `--text-quiet` | 灰色文字 + "待办"文案 |
| 任务-执行中 | `--accent` | 辅助色 + 脉冲动画 + "执行中"文案（三通道） |
| 任务-待确认 | `--warning` | 黄色 + ⚠ 图形 + "待确认"文案；对应 R3（工具副作用风险档） |
| 任务-已完成 | `--success` | 绿色 + ✓ 图形 + "已完成"文案 |
| 任务-超时/升级 | `--danger` | 红色 + ⚠ 图形 + "已超时"文案 |
| 风险-低/中/高（卡片/横幅/高风险卡） | `--success` / `--warning` / `--danger` | 高风险卡红色描边 `--shadow-risk-high` |
| 风险等级 chip（今日计划/我的待办任务行 R1/R2/R3） | R1/R2：`--primary` 描边 + `--primary-text` 文字；R3：`--ds-border` 描边 + `--ds-text-dim` 文字 | 方角（`--radius-chip-square`，非胶囊）；chip 内必须同时给出 R 编码文字（R1 与 R2 形态相同，仅靠编码文字区分）；R1/R2/R3 对应任务风险等级低/中/高，与工具副作用风险档同字面、不同语义，不得互相推导 |
| 任务行状态点（今日计划/我的待办表格状态列） | `--task-status-pending` / `--task-status-running` / `--task-status-done` | 6px 圆点仅作辅助（`aria-hidden`），同格必须以文字给出展示状态（失败/取消等落到 pending 档时仍以文字区分） |
| trace-成功/失败/等待 | `--success` / `--danger` / 中性 | 失败节点可展开详情 + 重试入口 |
| 身份：人 / agent | **文案徽章为主**（"人"/"Agent"）+ 形状区分 | 不新增色相；颜色仅作加强，复用 `--accent`（agent 侧） |
| SLA-充足/紧张/超时 | `--text-quiet` / `--warning` / `--danger` | 倒计时文字 + 进度条形状 |
- **例外声明：紧凑等级标记（2026-10-06 D3 决策，2026-10-07 v3.1 收紧）** —— 今日计划/我的待办任务行的风险等级 chip 属**等级标记**，不是状态色、也不是行动：它允许以描边形态占用主行动色（R1/R2 `--primary` 描边 + `--primary-text` 文字；R3 `--ds-border` 描边 + `--ds-text-dim` 文字），是本节「四职责不得互相串用」的**唯一例外**；**实底粉仍只用于 L1，恢复为无例外**（v3.1 收紧：R1 取消实底形态，视觉权重不再与风险强度反向）；该 chip 不是按钮，不得升级为视觉强调 L1（§4.2）、不得触发动作，同一视口仍 ≤1 个 L1 实底 CTA（不变量 1）。
- **动效**：trace 执行中的脉冲、agent 流式输出与「有新内容」提示按「颜色 + 动效 + 文案」多通道表达；**`prefers-reduced-motion` 下必须降级**（停用脉冲与平滑滚动，保留文案与静态标记）；时长、缓动与脉冲参数住 `frontend/src/styles.css`。

## 4. 控件尺寸与行动四级
### 4.1 尺寸 token
- 控件高度、圆角、命中区走命名 token：`--control-h*`、`--btn-text-*`、`--radius-control`、`--radius-card`、`--chip-h`、`--badge-h`。**不在页面里写具体数值**。
- 工作台按钮、搜索框、筛选项采用紧凑高度、小圆角；**胶囊形只用于身份/状态语义，不得作为通用按钮或选项造型**。
- **选项组 >8 项时禁用 chips**：改用分组下拉（optgroup）或紧凑列表。chips 只保留"已选状态"的展示（§20）。
- 同组控件等高、等宽、统一对齐；触摸模态只扩大命中区（≥44px），不同步放大视觉控件。
- 焦点态统一 `--focus-ring`，`focus-visible` 才出现。
- 间距走 `--space-*` 阶梯（`frontend/src/styles.css`）；不新增自造间距档。

| token | 值 | 用途 |
|---|---:|---|
| `--control-h-lg` | `32px` | 搜索框与同排按钮（工作台）；显式 lg 控件高；不作为高密度业务组件缺省 |
| `--control-h-form` | `32px` | 弹窗输入框/下拉/按钮统一高度 |
| `--control-h` | `28px` | 知识搜索、详情主操作的显式 md 外框 |
| `--control-h-sm` | `24px` | 桌面高密度业务组件缺省：行内动作、筛选、图标按钮 |
| `--chip-h` | `28px` | 筛选 chips；触摸模态命中区扩至 44px |
| `--workspace-task-action-h` | `20px` | 任务行操作按钮与状态标签同高 |
| `--radius-control` / `--radius-card` | `6px` / `8px` | 控件 / 内容容器 |
| `--radius-chip-square` | `4px` | 紧凑等级/风险 chip 的方角（非胶囊）；行内标记专用，不用于控件与容器 |
| `--radius-dialog` | `8px` | 弹窗卡片圆角 |
| `--cost-meter-h` | `6px` | 预算进度条；比例只由形状表达，状态词与数值同时文字给出 |

### 4.2 视觉强调四级（v3 新增，不变量 8 的细则）
| 级 | 形态 | token | 用在哪 |
|---|---|---|---|
| L1 | 实底主 CTA | `--primary` 实底，`--primary-fg` 文字，高按 size token，缺省 `--control-h-sm`，圆角 `--radius-control` | 每视口 ≤1 个：提交、确认执行、发布 |
| L2 | 默认描边按钮 | 1px `--border` 描边，`--bg` 底，文字 `--text`，高按 size token，缺省 `--control-h-sm` | 次要但独立的动作：取消、返回、次级提交 |
| L3 | **文字按钮** | 无边框、无底色，文字 `--accent-text`（或 `--text`），缺省高 `--control-h-sm: 24px`，显式 md 用 `--control-h: 28px`，左右 padding `--btn-text-pad-x: 8px`，hover 底 `--btn-text-hover-bg`（辅助色 8% 淡底），圆角 `--radius-control` | 行内操作（表格行"编辑/删除/查看"）、工具栏次级动作、"查看更多/收起"、展开入口、批量栏动作 |
| L4 | 链接按钮 | 文字 `--accent-text` + 下划线（hover 才出现），无高约束，随行高 | 外链跳转、跳详情页 |
- **判定规则**：动作是否值得一个描边框？行内重复出现（每行都有）的动作一律 L3；同一工具栏内 L2 ≤2 个，其余 L3。
- 桌面高密度业务组件缺省 size=sm、density=compact；大小与视觉强调独立。L3 默认使用 --control-h-sm，padding-x 使用 --space-1；搜索和详情主操作显式 md。
- 危险动作（删除、撤销）用 L3 + `--danger` 文字，不得做成 L1 实底红（除非该视口无其他 L1 且为最终确认）。
- **禁止**：把 L3/L4 升级为 L1/L2 "为了显眼"；一排三个描边按钮（该用 L2+L3+L3）。

### 4.3 工作台搜索、Tab 与分类筛选

工作台工具行采用紧凑搜索框与动作水平对齐；搜索框不因剩余空间无限扩张。尺寸、边框、圆角和焦点使用以下 token：

| token | 值 | 用途 |
|---|---:|---|
| `--workspace-search-max-w` | `18rem` | 工作台搜索框最大宽度；可在工具行收缩，窄屏占满可用宽度 |
| `--workspace-search-pad-x` | `10px` | 搜索文本与图标的水平内边距 |
| `--workspace-tab-h` | `36px` | 指针/键盘下一级业务 Tab 的视觉高度；触摸命中区至少 `44px` |
| `--workspace-tab-indicator-h` | `2px` | Tab 选中下划线 |
| `--workspace-tab-gap` | `16px` | 同级业务 Tab 间距 |
| `--filter-tab-h` | `28px` | 工作台分类筛选项的视觉高度；触摸命中区至少 `44px` |

- **搜索框**：高 `--control-h-lg`，圆角 `--radius-control`，底色 `--bg`，边框 `--border`；如带搜索图标，图标与输入文字共用一条基线。占位文字用 `--text-quiet`。聚焦时边框与 `focus-visible` 外环使用 `--focus-ring`；清空只清除查询，不触发刷新或计划生成。窄屏可以满宽，宽屏不超过 `--workspace-search-max-w`。
- **一级业务 Tab**（如“今日任务 / 我的待办 / AI 发现 / 公海 / 我的红人”）：共享细基线；未选中项透明无边框，选中项以文字字重和下划线表达，使用辅助色，不使用独立圆角底块或主行动色。计数是弱化附属信息，不单独形成控件。
- **分类筛选**（如“全部 / 重要紧急 / 重要 / 紧急 / 一般”）：是筛选按钮组，不冒充页面导航 Tab；视觉沿用紧凑的文字项与选中下划线，数量附属于标签。点击筛选只改变当前列表结果，不生成计划、不重置搜索词或列表滚动位置；显示全量计数时应明确计数范围。
- Tab 语义按控件职责实现：页面切换使用 `tablist` / `tab` / `tabpanel`、`aria-selected`、方向键切换及 Home/End 首末项定位；筛选使用原生按钮和 `aria-pressed`，支持 Tab 聚焦及 Enter/Space 激活，不为筛选组虚构 Tab 语义。两者都必须有可见 `:focus-visible` 和禁用态。
- 搜索输入、Tab 切换、筛选和按钮 hover/focus 状态使用 `--duration-control`；`prefers-reduced-motion` 下取消过渡。触摸输入只扩展命中区，不扩大可见控件。

### 4.4 CTA 按钮状态

CTA 仍按 §4.2 L1–L4 分级。一个视口最多一个 L1；“生成/整理计划”只有在它是该视口唯一主要提交动作时才用 L1。重复出现在列表每行的“打开/编辑/重试”使用 L3；分类筛选不是 CTA。

- 默认、hover、`focus-visible`、pressed、disabled、busy 状态要有可辨识反馈；焦点统一走 `--focus-ring`，禁用态不响应 hover，busy 态保留原位尺寸并显示真实等待文案/状态。
- L1 hover 使用 `--primary-hover`；L2 hover 使用 `--surface-hover`；L3 hover 使用 `--btn-text-hover-bg`。状态色仅用于状态或危险动作，不把失败/删除做成品牌主 CTA。
- 按钮使用原生 `button`，由 `disabled` / `aria-busy` 表达不可用和进行中；图标按钮必须有可访问名称。R3 动作继续执行确认与回执，不因视觉样式变化而简化。

## 5. 文字层级与字号
工作台与数据面以 `--ds-font-sm`（13px）为基准字号；通过字重、字色、间距构建层级，原则上不放大字号；数据密集场景启用紧凑字号档。

### 5.1 字号体系
| token | 字号 | 用途 | 密度限制 |
|---|---:|---|---|
| `--ds-font-sm` | 13px | 正文、标题、标签、控件、元信息（全局基准） | 全密度通用 |
| `--ds-font-xs` | 12px | 次要标签、元信息、备注、紧凑表格、辅助说明 | compact 密度默认启用；default 密度仅用于次要信息 |
| `--stat-value-font` | 20px / 字重 600 | KPI 数值 | 数据面唯一字号例外，全密度通用 |
| `--stat-label-font` | 12px | KPI 指标名、delta 值 | 全密度通用 |
- **禁止**：正文、标题独立放大至 14px 及以上；标题层级通过字重+间距表达，不通过字号。
- **等宽字体**：trace 节点、日志、代码、表格数字统一用 `--mono`；不新增字体族。

### 5.2 文字层级（五级）
所有页面统一使用五级文字语义，通过「字号 + 字重 + 字色」组合区分：
| 层级 | 字号 | 字重 | 字色 | 用途 |
|---|---|---|---|---|
| L1 页面/块标题 | 13px | 600 | `--text` | 页面标题、弹窗标题、板块标题 |
| L2 次级标题/行标题 | 13px | 500 | `--text` | 列表项标题、表单项组标题、卡片标题、一级菜单 |
| L3 正文/主信息 | 13px | 400 | `--text` | 正文内容、表格主列、控件文字、二级菜单 |
| L4 辅助信息 | 12px | 400 | `--text-quiet` | 次要标签、元信息、时间、备注、描述、分组标题 |
| L5 占位/弱化信息 | 12px | 400 | `--text-faint` | 空值提示、占位符、非重点备注、禁用菜单项 |
- 字重仅使用 400 / 500 / 600 三档；禁止 700 及以上粗体，避免视觉过载。
- 状态色（success/warning/danger）仅用于状态语义，不用于普通层级区分。

### 5.3 数据面字号压缩规则
- `data-grid` + `compact` 密度下：表格正文可使用 `--ds-font-xs`（12px），表头保持 13px。
- `data-dense-dashboard` + `compact` 密度下：列表次要信息、导航子菜单统一使用 12px。
- 压缩仅针对次要信息；主信息、操作按钮保持 13px，保证可点击性与可读性。

### 5.4 知识工作区收敛说明（v3 已收敛）
v2 的单页例外（18px 标题）已删除。知识工作区标题统一回 `--ds-font-sm` + 字重 600，用字重/间距/分隔表达层次，不再独立放大字号。
非字号 token 保留：`--knowledge-filter-width: 260px`（筛选列宽）、`--knowledge-action`（本页唯一 L1，复用辅助蓝既有色值，数值住 styles.css）。

## 6. 布局：三栏 + 抽屉
### 6.0 基础栅格与对齐规则
间距采用 4px 阶梯；控件和行高直接采用登记 token，不以栅格倍数改写尺寸。

#### 6.0.1 间距阶梯与高度 token
- 全局间距以 4px 为最小阶梯；高度采用已登记 token（包括 20、24、28、32、36、44px），最终外框使用 border-box。
- 水平间距与内边距直接复用 --space-*；列宽按可用容器与已登记骨架分配。
- 间距 token `--space-1` ~ `--space-5` 为 4 / 8 / 12 / 16 / 24px，禁止自定义间距档。

#### 6.0.2 内容列栅格
- ≥720px 内容区使用 **12 列栅格**，列宽均分，列间距 `--space-3`。
- 表单、卡片网格、统计区必须对齐列栅格；禁止跨列错位、随意定宽。
- <480px 窄容器禁用列栅格，内容单列排布（不变量 7）。

#### 6.0.3 基线对齐规则
- 行容器内图标、按钮、标签垂直居中；文本之间按基线对齐。
- 控件内图标采用登记的图标尺寸，不以文字基线拉高外框。
- 表格单元格内容统一垂直居中；多行内容顶对齐。

#### 6.0.4 全局对齐原则
| 内容类型 | 对齐方式 | 说明 |
|---|---|---|
| 文本、标签、标题 | 左对齐 | 所有阅读类内容左对齐，保证阅读流 |
| 数字、金额、统计值 | 右对齐 | 表格数字列、KPI 数值右对齐，便于对比 |
| 操作按钮、状态标签 | 右对齐 / 居中 | 表格操作列右对齐；状态列可居中 |
| 表单标签 | 顶对齐 / 左对齐 | label 上置左对齐，输入框左对齐 |
- 禁止同一列内混合对齐方式；禁止正文居中排布。

### 6.1 外层三栏
| token / 断点 | 数值 | 用途 |
|---|---:|---|
| 桌面导航轨道 | `260px` | 锁死 |
| `--workspace-result-rail-min` | `360px` | 双栏成立时右栏最小宽度，**flex 不得压缩突破** |
| `--workspace-result-rail-ideal` | `54%` | 结果优先视口右栏目标宽度 |
| `--workspace-result-rail-max` | `820px` | 防宽视口无限扩张 |
| `--workspace-result-rail-collapsed` | `56px` | 折叠轨道 |
| 堆叠断点 | `1100px` | 及以下：中栏在上、结果栏在下 |
- Chat 与 AI发现采用 §27.2 的固定中栏、剩余宽度结果栏；上表右栏 ideal/max 仅用于其他工作台模式。
- 右栏 `flex-shrink: 0`；中栏 `min-width: 0`（允许收缩）；英文长标题强制 `overflow-wrap: break-word`。
- 滚动轴总数 ≤3（左栏 / 中栏 feed / 右栏）；页面外层不滚动（细则见 §10.1）。

### 6.1.1 多级级联导航菜单
> 适用范围：左侧桌面导航轨道（260px 锁宽）；业务域-业务主题-知识点、模块-子模块-功能点等 2~3 级级联导航场景。
> 最大层级：3 级（一级主菜单 / 二级子菜单 / 三级细分）；超过 3 级改用抽屉或面包屑跳转，避免导航过深。
> 密度同步：行高执行 §2.2 组件密度三档规则（§2.1 全局切换未决策前，不做跨组件联动）。

#### 6.1.1.1 尺寸与行高
| 密度档 | 行高 token | 上下内边距 | 适用场景 |
|---|---|---|---|
| default（默认） | `--list-row-h: 40px` | 10px | 通用导航，默认配置 |
| compact（紧凑） | `--list-row-h-compact: 32px` | 6px | 菜单项＞30、大屏监控、全局紧凑模式 |
| relaxed（宽松） | `--list-row-h-relaxed: 48px` | 14px | 少菜单、触控场景 |
- 所有行高采用本节登记 token，不按栅格倍数改写。
- 分组标题行高 28px，上下 padding 8px，视觉权重低于菜单项。

#### 6.1.1.2 层级缩进规则
每向下一级，左侧统一缩进一个单位，层级关系仅通过缩进+字重区分：
| 层级 | 左侧缩进 | 视觉元素 |
|---|---|---|
| 一级菜单 | 12px | 16px 图标 + 文字 + 右侧展开箭头 |
| 二级菜单 | 36px（12 + 24） | 纯文字 + 右侧展开箭头（存在三级时显示） |
| 三级菜单 | 60px（12 + 24×2） | 纯文字 |
- 层级缩进单位：`--nav-indent-level: 24px`（8px × 3，对齐栅格）；每深一级递增 24px。
- 一级菜单图标 16px，与文字基线对齐，间距 8px。
- 展开箭头 12px，固定在行最右侧，距右边 12px；展开时向下，收起时向右，旋转 90° 切换状态。

#### 6.1.1.3 文字与状态规范
文字层级复用 §5.2 五级规范，状态严格遵循颜色职责，多通道表达：

| 状态 | 背景 token | 左侧竖条 | 字重 | 字色 | 说明 |
|---|---|---|---|---|---|
| 默认 | 透明 | 无 | 一级 500 / 二三级 400 | `--text` | 常规态 |
| Hover | `--bg-subtle` | 无 | 不变 | `--text` | 整行背景变化，无描边 |
| 选中（当前页） | `--accent` 8% 淡底 | 2px `--accent` 实色竖条 | 600 | `--text` | 三通道表达：竖条+字重+淡底；辅助色承担选中态 |
| 禁用 | 透明 | 无 | 400 | `--text-faint` | 置灰，无 hover 反馈 |
| 展开父项 | 透明 | 无 | 500 | `--text` | 展开时字重微提，不换背景 |
| 分组标题 | 透明 | 无 | 500 | `--text-quiet` | 12px，模块分组弱化处理 |

> 合规性说明：
> - 选中态为形状+字重+颜色三通道，满足 WCAG 2.2 AA 与不变量 4；
> - 选中态使用辅助色 `--accent`，不占用主行动色，符合「选中≠主行动」规则；
> - 层级仅通过缩进与字重区分，不使用卡片、按钮、背景色强化，视觉噪音最低。

#### 6.1.1.4 分隔与分组
- 模块分组之间使用 1px `--border` 分隔线，上下间距 `--space-2`。
- 分组标题距上方分隔线 8px，距下方第一个菜单项 4px。
- 禁止每个菜单项都加下边框，仅在分组处分隔。

#### 6.1.1.5 交互与折叠态
1. **点击区域**：整行可点击，命中区铺满全行宽；不只是文字或图标可点。
2. **展开收起**：点击父菜单整行切换展开/收起，箭头同步旋转；默认收起，仅展开当前激活路径。
3. **激活路径**：当前页面所在的所有父级菜单默认全部展开；选中项始终在可视区内。
4. **键盘导航**：Tab 依次聚焦，Enter 展开/跳转，方向键上下切换；符合无障碍要求。
5. **折叠态（56px 轨道）**：仅显示一级菜单图标，居中对齐；hover 弹出侧边抽屉展示完整子菜单；选中项图标背景用 `--accent` 8% 淡底，左侧保留 2px 竖条。
6. **文字截断**：菜单项文字超长时单行截断，hover 显示 tooltip 完整名称。

#### 6.1.1.6 禁止项
1. ❌ 禁止把菜单项做成 L2/L3 按钮样式；菜单是导航行，不是操作按钮。
2. ❌ 禁止每级菜单用不同背景色、卡片容器区分层级；层级只用缩进+字重表达。
3. ❌ 禁止选中态用 `--primary` 主色实底；选中态属于辅助语义。
4. ❌ 禁止超过 3 级嵌套；更深层级改用面包屑+详情页，不堆叠在导航栏内。
5. ❌ 禁止自定义缩进单位；必须统一 24px/级，对齐 8px 栅格。

### 6.2 栏内布局约束（不变量 7 的细则）
- **<480px 的容器内禁止二次分栏**：独立字段组采用单列；简短元数据允许标签和值同行并自然换行；长表单 label 上、value 下。
- **两栏/多栏只允许在 ≥720px 内容区**：如连接器表单两列，窄屏自动收为单列。
- **目录/浏览类弹窗用列表行**，不做卡片墙（密度档信条）；**指标总览类可用紧凑 KPI 卡**（§9.2），不视为"卡片墙"；**同一对象的生命周期状态不适用 KPI 卡，用分布条**（§9.2）。
- 表格固定列宽总和不得超过容器 40%（如任务表优先级 64px + 操作 124px，在窄容器中操作列收进"更多"）。

### 6.3 抽屉（v3 新增）
宽表、审计明细、复杂表单（字段 >8）不用弹窗，用右侧抽屉：

| token | 值 | 用途 |
|---|---|---|
| `--drawer-w-sm` / `--drawer-w-md` / `--drawer-w-lg` | `480px` / `720px` / `960px` | 按内容选档；宽表用 lg |
| `--drawer-pad` | `20px` / `16px`（左右/上下） | 默认档 |
- 抽屉从右侧滑入，带遮罩；ESC / 点击遮罩关闭（有未保存变更时先确认）。
- 抽屉头 sticky：标题 + 关闭；抽屉脚 sticky：L1 + L2（左对齐 L3 文字按钮"取消"亦可）。
- 抽屉内表格直接走 `data-grid` 密度档。

## 7. 弹窗规范（通用 + 差异）
### 7.1 通用
| token | 值 | 用途 |
|---|---:|---|
| `--dialog-w-sm/md/lg` | `440px` / `560px` / `720px` | 按内容量选档，**禁止一刀切 560px** |
| `--dialog-pad` | `20px` / `20px` / `26px`（左右/上/下） | 默认档 |
| `--dialog-pad-compact` | `12px` / `16px` | 紧凑档：字段 ≤5 个的弹窗用此档 |
| `--dialog-h-max` | `88dvh` | 向导类 `94dvh`（需登记理由） |
- 输入与下拉**不使用描边**，填充 + 圆角；焦点态回描边。
- **参考图只定信息结构**（有哪些字段、什么顺序），**不定视觉比例**：字号、间距、圆角一律走本文件 token。参考图实测 px 不得直接写入 token。
- 每步/每窗一个 L1；回执只保留最新一条，固定顶部，可收起。
- 字段 >8 或含宽表 → 不用弹窗，用抽屉（§6.3）。

### 7.2 连接器设置向导（差异）
四步：保存 / 测试 / 工具清单 / 启用。步骤条是**唯一**状态载体；测试免责声明「仅验证工具目录，不代表业务动作」保留；改配置后连接器回到「待验证」，启用键置灰并写明原因。

### 7.3 浏览弹窗（差异）
- 目录浏览类 → **列表行**：图标砖 28px + 标题 + 描述单行截断 + 右侧动作位（L3 文字按钮）。
- 不显示治理状态行（治理入口留在枢纽卡片）。

## 8. 信息去重规则（不变量 6 的细则）
1. **分层呈现**（v3 修订）：汇总条（聚合值）与明细表（逐行值）可同屏，视为两层；**同一粒度下**标题区/摘要区/卡片区不得重复渲染同一值。
2. **同值折叠**：「当前」与「变更前」值相同时，只渲染一行（标"未变更"）；阶段确认卡的"当前/变更前/变更后"同理。
3. **零数据不渲染**：数量为 0 的筛选项默认收起；零值字段（如"粉丝 0万"）隐藏，hover 显示。**统计区 KPI 为 0 时保留占位**（"0"本身是信息），不隐藏。
4. **标题去重**：禁止"本轮结果·结果"类重复标题；LLM 生成文案时做字符串级去重（相邻相同语义标题合并）。
5. **数字同源**：同一视口的所有统计数字必须来自同一数据源；"77 项任务 vs 全部 22"类口径打架视为 bug。
6. **状态单点表达**：同一状态只在一处表达（步骤条/状态行二选一）；"待确认"卡内不得再写"已按确认写入"。
7. **过程流三处收敛**：推理摘要只展开最新一段；摘要被裁切时必须给"展开全文"入口，**禁止 `overflow: hidden` 静默裁切**（不变量 5）。
8. **空态诚实**：「尚无结果 / 服务不可用 / 筛选无结果」三分，保留双入口（填参数跑一次 / 交给 Agent）。

## 9. 内容密度
### 9.1 数据表三档（v3 新增，`data-grid` 核心）
| token | 行高 | 单元格上下 padding | 用于 |
|---|---:|---:|---|
| `--table-row-h-relaxed` | `52px` | `16px` | 含双行内容/对象卡的行 |
| `--table-row-h`（默认） | `44px` | `12px` | 中台数据面默认 |
| `--table-row-h-compact` | `32px` | `8px` | 行数 >50、大屏监控、用户显式切换 |

- 展开行：点击行首 ">" 展开，展开区 padding `12px 16px`，底 `--bg-subtle`。
- 空单元格：渲染 `—`（`--text-quiet`），不留白格造成"缺数据"误读。
- 固定列：左固定列 ≤2 列，右操作列固定；固定列加 `--shadow-scroll` 边缘阴影提示可横滑。
- 排序：表头可排序列显示 ↕，升序 ↑ / 降序 ↓；筛选：表头漏斗图标 + 下拉面板（§20）。
- 分页：右下 `共 N 条 · 每页 [20/50/100] · < 1/2/3 >`，紧凑单行；N >1000 必须服务端分页并注明。

### 9.2 KPI 统计区（v3 新增）
| token | 值 | 用途 |
|---|---:|---|

| `--stat-label-font` | `12px` / `--text-quiet` | 指标名 |
| `--stat-delta-font` | `12px` | 环比：▲/▼ + 百分比，涨 `--success` / 跌 `--danger`（涨跌语义按指标正负向配置，不得写死红涨绿跌） |

- **下钻优先落到带筛选条件的明细表**；确无筛选轴时，定位到页内对应该状态的队列列表，并登记该缺口（仅滚动到页内某块内容不计为下钻）。下钻落点必须与契约中的筛选参数一致，不得用新的展示口径覆盖原始计数。

- 空单元格渲染 `—`（`--text-quiet`），规则同 §9.1 数据表。

#### 9.3.2 工作台任务列表行

| token | 值 | 用途 |
|---|---:|---|
| `--workspace-list-row-h` | `44px` | 单行任务的最小高度 |
| `--workspace-list-row-h-relaxed` | `52px` | 任务标题与一条辅助信息并列/换行时的最小高度 |
| `--workspace-list-cell-pad-x` | `8px` | 行内单元格水平留白 |

### 9.4 无限加载（Infinite‑Load）
> 适用边界：
> ✅允许：`data‑dense‑dashboard` 下**查找+浏览混合场景**：知识库列表、对象浏览列表、feed 结果列表；用户既会滚动浏览，也会跳去查找特定条目。
> ❌禁止：`data‑grid` 高密度中台数据表、审计日志、大批量业务表格，这类场景只能使用 §9.1 页码分页器，不得启用无限加载。
> 滚动约束：复用全局滚动规则，使用组件内部 `overflow‑y:auto` 滚动容器；**禁止页面外层滚动**（不变量5、§10.1）。

#### 9.4.1 两种模式（查找+浏览混合场景二选一，LLM 决策规则）
|模式|使用条件|说明|
|---|---|---|
|A 自动触底无限加载（优先）|条目预估 20–100 条；浏览行为占比高|滚动距离底部阈值自动拉取下一页；无常驻点击按钮|
|B 手动「加载更多」L3按钮（备选降级）|条目<20 或预估>100；查找定位占比更高；后端不支持滚动触发|列表底部放置 L3 文字按钮，由用户主动点击加载下一批；**禁止插入列表行中间**|

> LLM决策逻辑（混合场景）：
> 1. 如果业务预估条目 20‑100，优先选用 **模式A：自动触底无限加载**；
> 2. 如果条目少（<20）或数据量巨大（>100），或者明确后端能力受限，降级 **模式B：手动加载更多（L3文字按钮，置于列表底部）**；
> 3. 只要密度档是 `data‑grid`，直接忽略本小节，使用 §9.1 标准页码分页。

#### 9.4.2 模式A：自动触底无限加载（行为 + UX）
1. **触发阈值**：`--infinite-load-threshold: 48px`（v3.1 独立 token；**不再复用 `--feed-follow-threshold`**——跟随阈值管"阅读不打断"，加载阈值管"数据拉取"，语义不同不得耦合）；滚动容器视口距离内容底部 ≤48px 触发加载。
2. **防抖动/防重复请求**：加载中状态下，忽略滚动触发事件；请求结束（成功/失败）才恢复监听。
3. **终止条件**：当 `hasMore=false`（没有更多数据），移除滚动监听，不再触发加载。
4. **无障碍要求**
    - 底部状态容器设置 `role="status" aria‑live="polite"`，状态变更屏幕阅读器可播报；
    - `prefers‑reduced‑motion`：关闭任何滚动动效，仅保留静态文案与控件（§3.1动效不变量）；
    - 键盘 Tab 可聚焦到底部重试按钮；滚动本身不依赖键盘。
5. **大数据提示**：当累计渲染条目 >80 条，UI 不做自动卸载；**业务层按需自行增加虚拟滚动，本spec不定义虚拟滚动实现**。

##### 模式A：状态 UI（全部渲染在列表 DOM**之后**，列表容器 footer，不插入列表行之间）
> 全部复用现有 token，不新增变量
|状态|表现|token、文案、图标|
|---|---|---|
|待触发（还有更多数据）|不渲染任何 DOM，无提示文字、无图标|无输出|
|加载中|容器水平居中：spinner + 文字「正在加载更多」|字号 `--ds-font-sm`；文字色 `--text-quiet`；spinner 颜色 `--accent`；无额外装饰图标|
|已全部加载完成|容器水平居中：静态文字「已加载全部」|字号 `--ds-font-sm`；文字色 `--text-quiet`；无按钮、无图标|
|加载失败|容器水平居中：警告语义图标 + 文案「加载失败，点击重试」 + **L3文字按钮「重试」**|警告图标语义 `--danger`；按钮严格遵守L3全套token：`--btn-text-h`、`--btn-text-pad-x`、`--btn-text-hover-bg`、`--radius-control`；按钮文字色 `--danger`|

> ❌禁止：常驻"上拉加载更多 / 滚动加载更多"提示文案；禁止状态节点穿插列表行中间。

#### 9.4.3 模式B：手动「加载更多」L3按钮（降级备选，查找‑浏览混合）
> 适合：用户希望掌控加载时机，方便感知剩余数量；条目偏少/偏多场景。
1. DOM位置：列表**最末尾**，列表结束之后，严禁嵌入列表行中间。
2. 控件等级：**必须 L3 文字按钮，禁止升级 L2描边按钮**（不变量8）。
3. 状态流转
    - 可点击态：文案示例 `加载更多（剩余{{n}}条）`；L3文字按钮；
    - 加载中：按钮置灰，内嵌 spinner，文案改为「正在加载…」，不可点击；
    - 加载成功且无剩余：直接隐藏按钮，渲染静态文本「已加载全部」；
    - 加载失败：切换为 L3「加载失败，点击重试」，文字色 `--danger`。
4. token：完整复用L3文字按钮整套token，不新增变量。

#### 9.4.4 混合场景配套UX约束（查找+浏览）
1. 无限加载**不能替代筛选、搜索**；页面顶部依然保留搜索与高级筛选（§20），满足用户主动查找需求；无限加载只负责浏览翻页。
2. 筛选、搜索变更时：重置无限加载状态（页码重置、清空列表、重置 `hasMore` 标记，重置滚动监听）。
3. 当用户执行筛选后结果总数明确可获取：可在列表顶部展示「共 N 条结果」KPI式计数，给查找用户总量感知（复用§9.2统计展示规则）。
4. 不要混用：同一列表**不能同时出现无限加载+页码分页器**；二选一。

#### 9.4.5 禁止清单
1. ❌`data‑grid` 数据表使用无限加载 / 手动加载更多；数据表强制 §9.1页码分页；
2. ❌把加载更多按钮/状态插入列表行中间；
3. ❌将L3加载更多升级为L2描边按钮；
4. ❌常驻显示"滚动加载更多"提示文字；
5. ❌同一列表同时开启自动无限加载又保留手动按钮；模式A/B互斥。

## 10. 中栏滚动行为
核心矛盾：Agent 持续写入（流式输出、Trace 展开、新事件），人同时在阅读历史、做确认。滚动条要在"跟随新内容"与"不打断人阅读"之间裁决。
### 10.1 结构：三段式
- 中栏 `display: flex; flex-direction: column`：header（sticky 顶）+ feed（`flex: 1; overflow-y: auto`，**唯一滚动容器**）+ composer（sticky 底：输入框/快捷操作）
  - 快捷操作 chips：最多 `--composer-chips-max: 4` 个，单行横滑或换行 ≤2 行；超出收进"更多"（L3）
- header、composer `flex-shrink: 0`，始终可见
- 滚动轴总数 ≤3（左栏、中栏 feed、右栏）；页面外层不滚动
### 10.2 自动跟随规则
| 用户位置 | 新内容到达时 |
|---|---|
| 距底部 < `--feed-follow-threshold`（视为"在底部"） | 自动跟随滚到底 |
| 距底部 ≥ 阈值（在看历史） | **不打断**；右下角出现"有 N 条新内容 ↓" pill，点击后滚到底 |
| 流式输出中用户上滚 | 立即停止跟随（一次上滚 = 明确意图） |
- pill 与"回到底部"按钮二选一（不变量 6：同一个"有新内容"只表达一次）
- `overflow-anchor: auto`：流式追加内容时视口不跳动
### 10.3 R3 确认卡必达视口
- 确认卡出现时若不在视口内：`scrollIntoView({ block: 'center', behavior: 'smooth' })`
- 决策前卡片 sticky 在 feed 顶部（或固定于 composer 上方）；决策后收起为一行"已确认/已驳回"状态（不变量 6）
### 10.4 滚动条样式
| token | 值 | 用途 |
|---|---:|---|
| `--scrollbar-size` | `8px` | overlay 式，不占布局宽度 |

## 14. 通用任务工作台
任务不是一次回答或一次工具调用，而是可跨会话恢复的目标。所有任务表面统一为：左栏导航与入口；中栏有序事件流、输入和当前阶段动作；右栏成果、证据和结果状态。技能可省略不需要的阶段，但不得改变这三个区域的职责。
中栏事件应依次表达目标与技能上下文、输入引导、条件或草稿、解析缺口、实际参数或预览、确认、执行回执、成果摘要和下一步。模型解释与服务端事实事件可以合并展示，但状态、进度、回执只能来自权威事件。没有真实结果时不得渲染候选、完成或进度。
同一视口当前阶段只保留一个 L1。R3 确认卡必须包含范围、参数版本、风险、确认和取消；参数变化使旧确认失效。停止、重试、导入、发送和正式状态变更使用独立动作及回执。

### 14.1 打断与回退（v3 新增）
- 流式输出/执行中，composer 区的 L1 变为"停止"（`--danger` 描边 L2 形态，非实底红）；点击后状态行变为"已停止 · 第 N 步"，**保留"回退到第 M 步重跑"**（L3 文字按钮组：列出可回退的阶段节点）。
- 回退重跑使该节点之后的所有确认失效，需重新确认（沿用"参数变化使旧确认失效"）。
- 回退后旧分支折叠为"已回退分支（N 步）"，L3 文字按钮可展开查看，不删除历史。

### 14.2 延迟表达（v3 新增）
- agent"思考中/执行中"超过 `--agent-wait-hint: 3s`：状态行显示已用时（如"思考中 · 12s"）+ "取消"（L3）。
- 超过 `--agent-wait-long: 30s`：给出预估（"预计还需约 1 分钟"）或"转人工跟进"入口（L3），不得无限转圈（不变量 3）。
- 超时（>120s 无进展）：自动降级为"稍后通知我"，任务进任务中心，结果到达时按 §10.2 规则提示。

## 15. 技能的员工体验契约
已发布技能除机器契约外，必须提供员工体验契约：标题和用途、输入与默认值、可执行/事后核验/不支持条件、过程事件、产物与来源要求、不确定性、风险与确认、失败恢复和后续动作。员工表面使用业务名称，不显示 MCP、工具 ID、内部 schema 或未经整理的日志；这些信息只在可追溯详情中出现。
技能可以声明需要哪些任务节点，但不能自定义像素、颜色职责、布局、权限、业务阶段判定或确认闸门。平台根据风险和任务状态渲染统一事件、确认和回执组件。技能输出必须区分事实、推断、建议、缺失信息和已执行结果。

## 16. 任务与技能视觉验收
- 事件流在底部时自动跟随；用户上滚后不被新内容打断，并提供单一"有新内容"入口。
- 待确认事项在提问框上方有明确提示并可定位到完整确认卡；确认完成后折叠为单行回执。
- 成果只在右栏呈现一次，保留来源、版本、时间和核验状态；中栏只保留过程摘要。
- 空态区分"尚无结果""服务不可用""筛选无结果"；不以占位结果代替真实数据。
- 新增任务类型沿用本文件 §1–§13 的 token、三轴适配、无障碍、颜色职责和滚动规则，不新增任务专用视觉体系。

## 17. Agent 流式输出排版（v3 新增）
- **Markdown 渲染**：feed 内的 markdown 表格直接渲染为紧凑表格（走 `--table-row-h-compact`）；代码块最大高度 `--feed-code-max-h: 320px`，超出内部滚动 + 右上"展开"（L3）；标题降级渲染（`#`→加粗 13px，不放大字号）。
- **工具调用卡片**：每次工具调用渲染为一行：图标 + 工具业务名 + 状态（执行中/成功/失败，§3.1 三通道）；参数默认折叠，"查看参数"（L3）展开；结果只渲染摘要，详情进"查看结果"。
- **多步骤进度**：步骤 ≥3 时在 feed 顶部渲染轻量步骤条（当前步骤高亮 + 已完成打勾）；步骤条只表达进度，不替代 §7.2 向导的状态载体职责。
- **长输出折叠**：单条 agent 回复超过 800px 高时，自动折叠超出部分，"展开全文"（L3）；折叠处保留来源区可见（§18）。

## 24. 业务页面组合模式（Pattern）
> 建设性 token：中台高频页面的标准结构与组件组合规则。LLM 生成对应页面时优先套用本章节模式，不得自由堆砌组件。
> 所有模式严格遵循密度档、栅格、对齐、视觉四级规则，复用全部已有 token。

### 24.1 数据列表页（知识/任务/日志通用）
**适用**：知识库列表、任务列表、审计日志、技能目录等查找+浏览混合场景。
**标准结构（从上到下）**：
1. 页面标题栏：标题 + 右侧主操作区（1 个 L1 + ≤2 个 L2）
2. 筛选栏：搜索框 + ≤4 个常用筛选 + 更多筛选 + 已保存筛选（执行 §20）
3. 已选条件行：chips 展示已选项 + 清空全部（L3）
4. 结果计数：`共 N 条`（L4 辅助文字，左对齐）
5. 列表/表格区：执行 §9.1 表格 或 §9.3.1 列表密度规则
6. 底部分页/无限加载：
   - `data-grid` 数据表：右下页码分页器（§9.1）
   - `data-dense-dashboard` 列表：无限加载（§9.4），优先模式 A
7. 空态：无结果时渲染紧凑空态（§9.3）

**约束**：
- 操作按钮层级：主操作 L1 居右，次级操作 L3 放在行内；工具栏 L2 ≤2 个。
- 筛选栏与列表左对齐，同宽；禁止筛选栏比列表宽或窄。
- 列表操作列固定右对齐，单操作 72px、双操作 124px。

### 24.2 三栏浏览页（左筛选+中列表+右详情）
**适用**：知识库浏览、客户/对象详情、技能目录、工单列表等边看边查场景。
**标准结构**：
1. 左筛选栏（260px，锁宽）：分类树 + 基础筛选项，内部滚动
2. 中列表栏（自适应）：列表标题 + 搜索 + 列表 + 无限加载/分页
3. 右详情栏（最小 360px，理想 54%，最大 820px）：详情标题 + 元信息 + 详情内容 + 操作区
**约束**：
- 三栏遵循 §6.1 外层三栏断点规则；≤1100px 堆叠为上下布局。
- 右栏 <480px 时禁止独立字段二次分栏；简短元数据允许同行换行（不变量 7）。
- 列表选中态用辅助色 + 左侧描边，不得用实底背景。

### 24.3 统计下钻页（KPI + 明细表）
**适用**：运营大盘、任务总览、调用统计等汇总+明细场景。
**标准结构**：
1. 页面标题 + 时间/维度筛选
2. KPI 统计区（2~6 个指标）：执行 §9.2，全部可点击下钻
3. 明细表区：带筛选的数据表，默认展示对应汇总维度的数据
**约束**：
- 汇总值与明细值必须同源，数值一致（不变量 6）。
- KPI 卡片与表格列一一对应；禁止汇总与明细口径不一致。
- 表格默认标准密度，超过 50 行可切换紧凑。

### 24.4 配置表单页（技能/连接器/系统设置）
**适用**：技能配置、连接器设置、系统参数等多字段表单场景。
**标准结构**：
1. 页面标题 + 右侧保存/取消（L1 + L2）
2. 表单内容区：
   - 字段分组，每组有组标题 + 分隔线
   - 基础配置展开，高级配置默认折叠
   - label 上置左对齐，必填项标红 `*`
3. 底部操作区 sticky：左对齐 L3「重置」，右对齐 L2「取消」+ L1「保存」
**约束**：
- 字段 >8 个时分 section 折叠；>15 个字段启用紧凑密度。
- 错误摘要置顶，点击定位对应字段（§19）。
- 提交后给出明确成功/失败状态回执，保留返回入口。

### 24.5 Agent 会话工作台
**适用**：对话式 Agent、任务执行、调试工作台等中栏 feed 场景。
**标准结构**：
1. 左导航：技能/会话列表（260px）
2. 中栏 feed 区：三段式结构（header + feed 滚动区 + composer 底栏），执行 §10
3. 右栏结果区：执行结果、引用来源、参数详情，执行 §6.1
**约束**：
- 中栏流式输出执行 §17；引用溯源执行 §18。
- 工具调用、状态、回执统一靠左；用户输入靠右。
- 右栏信息分层展示，次要信息默认折叠，避免信息过载。

### 24.6 密度组合规则（列表行 / 卡片）
**适用**：所有业务列表行与信息卡片。原子 token 齐全不等于密度合格：LLM 在缺少组合约束时默认输出最大号控件、最宽松间距、最高视觉权重，导致密度塌陷。本节是组合层面的强制约束，只复用已有 token，不新增变量。

**宽容器列表行标准结构（三段式，≥720px）**：
1. 左选择区：复选框 + 头像/图标，8px 间距，垂直居中；无选择场景可省略。
2. 中信息区：标题行（13px/500 `--text`）+ 元信息行（12px `--text-quiet`，横向排列、单行截断）+ 辅助行（12px `--text-faint`，单行截断），左对齐；禁止自由堆叠。
3. 右操作区：状态标签 + 操作按钮，右对齐；行内重复出现的操作统一 L3 文字按钮（紧凑行内 24px 高、4px 间距）。

**窄容器收敛**：480–719px 优先把动作移至信息下方；<480px 时身份、指标、理由、文字操作纵向排列，头像与选择框仅作左侧锚点，不再分配独立右操作列。头像顶对齐；元信息允许换行，理由可两行摘要，但必须有展开全文入口，不得因截断丢失证据。会话工作台的具体组合见 §26。

**状态与按钮边界**：
- 状态（待跟进、已入库、执行中…）一律用 chip / 文字 + 图形表达，禁止使用实底或描边按钮样式；状态 chip 高 20px、描边、12px/500 + 语义色，不得触发动作。
- 只有触发动作的交互才允许使用按钮；禁止把状态做成可点击的按钮形态。

**卡片操作分级**：
- 单张卡片内 L2 描边按钮 ≤1 个（主操作），其余一律 L3 文字按钮；§4.2 的"工具栏 L2 ≤2"是上限，卡片内收紧为 ≤1。
- 发现候选卡片（`DiscoveryLeadRow`）**不设 L2**：加入公海/跟进/忽略/看来源/查看详情全部为 L3 文字按钮。LLM 默认会给"主要动作"最高强调，本条把该场景的裁量空间清零（2026-10-08）。
- 次级卡片弱化处理：边框分隔、无厚重阴影，容器视觉权重不得超过内容。
- 同一信息不得重复渲染：操作语义由按钮本身承载，不另加解释文字。

**信息分层强制**：
- 列表、卡片内必须呈现标题/正文/辅助三级（执行 §5.2 五级文字层级）；辅助信息必须 12px + 弱化字色，禁止整行同一字号字重。
- 窄栏（<480px）内禁止二次分栏，独立字段单列，简短元数据同行换行（不变量 7）。

## 25. 生命周期业务组件契约（v3.3）

基础 Token 只定义颜色、字号和尺寸，不能代替业务组件。具有生命周期的对象管理页，优先使用以下两个组件；不得将状态、表单和操作自由拼成卡片墙。

### 25.1 LifecycleNavigation：状态导航

实施资产：`frontend/src/components/LifecycleNavigation.tsx`。

- 输入：稳定状态 ID、可读名称、数量、当前选中项、禁用态和选择回调。状态与数量由所属业务读模型提供，不内置通用状态机，不推断权限。
- `views` 模式切换业务视图，使用 tablist/tab/tabpanel、aria-selected、方向键与 Home/End；`filter` 模式只筛选当前数据，使用原生按钮与 aria-pressed，不虚构页面 Tab 语义。
- 共享基线与选中下划线，选中态同时改变字重和辅助色。视图使用 `--workspace-tab-h`；状态筛选使用 `--filter-tab-h`；间距与指示线使用 `--workspace-tab-gap` 和 `--workspace-tab-indicator-h`。
- 状态计数必须声明范围：当前授权全量、服务端筛选结果或本次返回集合。限制数量的接口不得将本次返回数标为全量。
- 加载和失败时不显示 0；读取成功的真实零计数保留。未知状态原样保留，不合并为已完成或其他已知状态。
- 筛选和视图切换保留搜索、选择与未提交内容，不执行发布、启用或状态推进。触摸命中区使用 `--touch-hit-min`，不把导航画成实底 CTA。

### 25.2 LifecycleWorkspace：生命周期管理工作区

实施资产：`frontend/src/components/LifecycleWorkspace.tsx` 与 `lifecycle-workspace.css`。

- 固定结构：紧凑标题/来源与时间/次级入口 → 操作回执 → 业务视图导航 → 内容滚动区。页面壳与导航不随长表单滚出视口。
- 视图内使用同源指标、状态导航、紧凑表格与按需展开编辑区；默认以已存在对象列表为中心，不常驻展示空白创建表单。
- 生命周期状态、发布状态和执行开关是不同维度，分别标记。发布不等于自动执行；工单生命周期不等于模板生命周期。
- 分组表格筛选只应用所属报告的 by_status 数据，不能把 Task 根状态、Work Order 状态或业务阶段混为一套状态机。
- 每个独立数据模块至少有 loading/ready/error 状态；失败只影响该模块。空态只在读取成功后呈现；失败给重试，技术错误进入诊断展开层。
- 长表单按 §19 分组，条件字段仅在对应配置等级下展示；隐藏字段禁用以避免残留配置误提交。切换视图不清空未提交编辑。
- 文本输入、复选框与开关有独立样式边界，宽度/内边距/最小高度不得用无类型 input 选择器污染复选框。复选框视觉尺寸复用 `--icon-sm`，焦点使用 `--focus-ring`。
- 列表内重复操作用 L3，当前编辑提交才用 L1。正式发布、停用、绑定和执行开关复用确认组件；对象、版本、后果、原因和操作回执可核查。最终授权与合法动作仍由后端校验。

### 25.3 工单治理页组合与验收

`AdminWorkOrders.tsx` 使用三个管理视图：治理概览 / 人员绑定 / AI 工单模板。

- 概览中的工单状态来自组织授权工单计数；按状态筛选受理组织存量，不增加管理员代员工接单、完成或推进阶段的操作。
- 模板状态由模板契约提供；列表数量仅统计本次返回集合（现接口最多 100 个模板），任务战报同样注明本次返回（默认最多 50 个 Task 根）。全量分页读模型是已有接口能力缺口，不用前端推断补齐。
- 有效组织/人员目前只有计数读模型，暂不伪造明细下钻；阻断项可进入人员绑定与质量明细。补充组织/人员明细接口后再关联下钻。
- 验收至少覆盖：单个接口失败而其他模块仍可用；失败不显示零业务数据；键盘视图导航；筛选与搜索保留；A3 条件字段；复选框尺寸；发布与执行独立确认；取消不写入；1440/1024/390 宽度无页面横向溢出。
- 测试资产：`frontend/e2e/admin-work-orders.spec.ts`；契约形状 API 桩只证明呈现与交互，不证明生产 PostgreSQL 集成。

## 26. 会话工作台组件契约（v3.4）

适用入口：Home 的 `/?tab=discovery`、已有 `/?tab=discovery&session_id=…` 深链，以及服务端声明为发现任务的独立 `/s/:id` 会话。带会话 ID 时恢复同一任务的条件、实际参数、受控动作和结果；独立会话在原地址呈现，共享骨架不要求跳回 Home。入口与兼容边界服从 [ia-information-architecture.md](ia-information-architecture.md) §1.1。实施资产是当前页面组件，不生成独立演示页面。密度采用 `data-dense-dashboard`；本文作为实施细则，不改变三部基本法。

### 26.1 固定骨架与信息层级

- `WorkspaceShell` 是 Home 工作台几何的唯一来源：中栏有序事件流和底部输入区，右栏结果面。业务模块提供插槽，不能再嵌入第二套滚动外壳。
- 新增可选 `railHeader` 插槽：结果头、范围、状态筛选和批量操作不随结果列表滚动；`rail` 承载回执、候选、空态与入库确认。未提供该插槽的模式保留既有结构。
- 当前任务状态取真实动作相位，文字和图形同时表达。等待确认不称为正在采集；完成不称为已经入库。
- 右栏自动跟随只在用户位于底部时生效；回看时保留位置，使用同一滚动节点提供“回到最新”。中栏与右栏各有独立阅读位置。
- 低高度或窄视口仍按 §11 三轴规则换档；只在具有独立结果视口时固定结果头。移动堆叠布局不强行制造固定高度或额外滚动轴。

### 26.2 条件、说明与确认

- 填写时展开技能说明；本轮已有实际采集提案或已提交后默认折叠，展开仍可核对完整边界、步骤与恢复方式。已提交条件收为平台、地区、关键词数量摘要，完整只读条件按需展开；修改仍进入既有编辑路径。
- 有限选项为文字选项 + 勾选，选中同时改变字重，不使用常驻底色。关键词是可编辑 token，保留删除、清空和未回车草稿提交的既有行为。
- 粉丝上下限保留同一范围组和各自 label；不改变字段名、默认值、校验或提交语义。标签顶部对齐。<480px 的实际中栏容器，标签在值上方，禁止用视口宽度推断栏宽。
- 条件、实际执行参数和采集后核对项保持清楚的来源边界。实际参数仍来自受控动作 arguments；地区、粉丝、均播、期望人数不得暗示为远端采集数量限制。
- 标题与正文复用 `--ds-font-sm`（13px），辅助文案复用 `--ds-font-helper`（12px），间距复用 `--space-1` / `--space-2` / `--space-3`，不扩大字号制造层级。
- 待确认时确认卡承担下一步，不同时输出“正在处理已确认条件”的计划。确认或入库确认出现时，输入框发送降为 L2；当前确认是唯一 L1。发送、启动采集、正式入库仍是独立动作。
- 活跃采集回执默认展开；结束后的远程任务、结果状态、更新时间、候选数量放入可展开回执。缺失值明确标记，不补造时间或进度。

### 26.3 结果筛选与线索行

- 本次候选筛选复用 `LifecycleNavigation mode="filter"`，使用 aria-pressed；数量注明“本次结果”，来源为当前任务已返回候选，不声称全量。空集合未成功读取时不输出零计数。
- 同基线、下划线、字重和辅助色表达选中。高度、间距和指示线复用 `--filter-tab-h`、`--workspace-tab-gap`、`--workspace-tab-indicator-h`；粗指针命中区升为 `--touch-hit-min`。Home 工作模式也以共享基线和下划线呈现。
- 右栏线索结构为：选择框与顶对齐头像 → 身份与真实状态 → 指标、推荐分与置信度 → 匹配理由 → L3 文字操作 → 按需展开的证据。动作不占窄栏右侧独立列。
- 平台、推荐分、置信度是事实属性，使用文字；“待跟进”“可入库”等真实状态可使用 `--badge-h`。不将同一个在库状态展示两次。
- 头像复用 `--control-h-sm`，复选框视觉复用 `--icon-sm`；重复文字动作复用紧凑控件档，触摸仍达到 `--touch-hit-min`。无来源 URL 明确显示不可用，不伪造链接。
- 元信息换行；理由默认两行摘要，展开行显示全文、来源、采集时间、分数构成与缺失项。选择与展开使用稳定候选 ID，更新、筛选与异步回执不得重建用户意图。

## 27. 通用任务会话契约（2026-10-08 增补）

主责：UI/UX 专家、智能体产品经理；实现：前端专家。依据 CONST-04/07、PROD-AGENT-03/09、TECH-FE-01~03，收敛 Chat 与发现任务的呈现，业务授权、确认版本与执行接口保持原契约。本节将 §26 的发现会话骨架扩展至 Chat，并细化 §10/14/16，不改变基本法。

## 29. 任务详情 · 紧凑抽屉接入契约

本节落实 §1、§4、§5、§6.3、§8、§19 与 §24，不另建视觉规范或修改业务规则。

- 详情用局部 Ant Design `Drawer` 封装：固定头部与必要提交脚区，长正文内部滚动；宽度读取 `--drawer-w-sm`，不得覆写为任意固定宽度。Portal 使用同一局部 `ConfigProvider`，不导入全局 reset。
- 返回名称为“返回任务明细”。本页抽屉保持明细列表挂载；详情深链关闭仅移除详情参数，其余周期/状态条件保留。独立详情来源只接受既有任务列表路由；查询、联动筛选、展开、加载范围及滚动以会话内 UI 快照恢复，不缓存正文和业务事件；重新按当前权限取数。
- 主信息采用 `--ds-font-sm`，辅助与追溯采用 `--ds-font-xs`；独立字段单列，简短标签和值可以同行自然换行。按钮按 §4 分级：返回 L2，登记入口/工作台/证据展开 L3；正式提交或当前确认只有一个 L1。
- 阅读顺序为对象与权威状态 → 目标/截止/当前推进 → 适用动作 → 有效工单、审批、建议、事件 → 默认收起的完整追溯。零工单一句，已成功读取的空审批/建议/工单模块不独立占块；加载、错误、撤权不得伪装为零数据。
- 业务化摘要不更改原目标含义；完整原目标、事件类型、事件标识、证据与发生/核验时间仍可查看。同时间只在摘要合并，原字段保留在展开层。
- 登记仍保留所有既有字段与事实/证据校验。正式写入前确认当前载荷与异步后果；未提交内容关闭前确认，提交中禁用关闭；失败保留草稿，同次重试保持原幂等标识，成功展示实际事件、判断与作业回执，不冒充任务完成。
- 焦点锁定在最上层浮层，关闭后回到来源任务行；ESC、遮罩、返回与关闭共用关闭入口。输入模态、窄屏、短高度、主题、减少动效按 §11–§13 验收，不使用隐藏溢出掩盖排版问题。

实施资产、分层验证与回滚记录放在 [任务详情实施记录](task-detail-redesign.md)，本文的组件规则不代表生产业务闭环已经通过验证。
