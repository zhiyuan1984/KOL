# 长正文邮件与真实终态时钟原生恢复

## 基线与审宪

本切片以已正式发布的 `71dc3efcc1bf0119c971b4f93a11560bfe5496c0` 为基线。PostgreSQL 已是唯一权威，77 项正式 schema 已应用；本切片不新增 schema、不改业务权限、账号、审批、工具装配、Starry 开关或凭据，也不改任何前端文件、原调度频率和恢复策略。本体 objects/events/tickets/rules registry 保持不变；仍使用真实发布 gate，不增加旁路。

## 有证据的两个根因

生产自然增量已真实提交 12 条中文翻译和 12 条摘要，第 13 项却失败。只读长度元数据显示其正文 37,612 字符，不读取或交付邮件正文/身份；原单次 Codex 45 秒在该项等待 turn/completed 超时。既有 240 秒为增量软预算，不能通过扩大测试阈值或截断正文来交差。

另一个真实审计错误是 Cron `finished_at` 和 Execution `terminal_at` 用了 handler 启动前的时间，而 native 邮件结束时间晚约四分钟。默认生产时钟现于 handler 返回后读取，显式固定测试时钟仍保持可复现；业务评估时点仍是调用开始时点，不改变公海/截止时间策略。

## 具体实现与不变量

| 范围 | 修复与保全 |
| --- | --- |
| Codex 长正文 | 普通正文仍单次调用。超过 12,000 Unicode code points 才分片，每片最多 4,000 code points；空白边界优先，Unicode surrogate 不截断；拼回片段严格等于完整输入。 |
| 译文接收 | 每片必须为真实可用中文，英文回显、仅内部标题、确定性占位或任一片失败均返回整体不可用，不能返回或持久化已完成前缀；只有全部片成功才合并完整译文。 |
| 模型与预算 | 不改 CLI 默认/CODEX_MODEL、不改凭据、每次 45 秒上限不改、增量软预算不改。模型 I/O 仍在 PG 事务外；最终 CAS 与检查点仍由既有原生同客户端事务提交。 |
| MCP | 实时 tools/list 仅证实唯一必填 `requestJson:string`；将原 inner `text` 封装，不擅自猜 DTO。受控 envelope 解包、明确错误和不可用内容拒绝。实际 synthetic MCP 探测仍 `mcp_tool_is_error`，不宣称 live 成功；内层 DTO/成功响应仍需上游契约。 |
| Cron 终态 | 默认实时时钟在真正完成后采样，失败与成功均修正；显式模拟时钟保留；不改持久状态 CAS、入队与实际 handler 职责。 |
| 测试 | 旧业务、权限、审批、截止时间、性能阈值断言不改；新增 Unicode 源重构、任片失败/回显拒绝与 PG 实际终态时间回归。只使用专属 PG 测试库及合成文本，生产库排除。 |

## 真实能力证据与发布边界

原生产 Codex 已提交 12 条翻译/摘要；单次新增合成大正文验证于 `2026-10-15T14:39:49.933Z` 输入 37,697 字符唯一合成英文，实际 source=`codex_memory`，生成 12,106 字符中文，非 stub、error=null；未访问真实邮件或写业务数据库。MCP schema/合成探测只证明其当前阻断，不可拿 tools/list 代替实际翻译成功。

安全发布以现有锁、私有一致性 PG 备份和环境副本、快进、本体 gate、77 项动态账本、前端构建、五个现有 systemd 服务为边界，不 `--sync`、不 reset、不推公开 GitHub。不会再次切换 Starry 或重复恢复两条系统时间，不人为入队邮件、公海或任何业务；仅重启既有自然常驻入队，Worker 执行。

最终上线验收必须关联实际 native 邮件 run 和已提交计数、真实模型结果、Cron 与 Execution 完成时间、当前自然公海 snapshot、新心跳与原批准审计。有限增量成功仍可能 `remaining_work=true`，不能宣称全部历史邮件已完成。任何实际失败保留部分事实并保护停止新增轮询，不抹除历史 needs_takeover。生产 AI 用户任务配置为 0 时不伪造任务、员工或回执。
