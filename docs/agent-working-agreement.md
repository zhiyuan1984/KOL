# Agent 工作协议（本仓库）

> 每个计划/目标开工前先读这一页。它记录的是**踩过的坑**，不是通用最佳实践。
> 与 `AGENTS.md`、`docs/CONSTITUTION.md` 冲突时以后者为准；这里只管"怎么做活"。

## 1. 模式：混合，不是二选一

| 环节 | 谁做 | 理由 |
|---|---|---|
| 探索 / 事实核查（只读） | **子代理** | 把"读 1000+ 行 + 翻迁移 + 查真实数据"的噪音挡在主上下文之外，只回报精炼事实 |
| 写代码 + 跑测试 + 提交 | **主代理自己** | 上下文连续、不付交接成本、不会撞 2 小时硬上限 |
| 代码评审 | **子代理，但每个自然阶段一次**（如"数据契约完成"、"UI 完成"），不是每任务一次 | 独立眼睛值钱，天天审会退化成纯开销 |
| 台账（progress ledger） | 主代理自己 | 唯一必需的流程开销：中断后可原地恢复 |

**什么时候才逐任务子代理**：任务大 + 彼此独立 + 能真并行，三者同时满足。否则一律 inline。
**砍掉**：每任务的 brief / report / review-package 三件套与 scoped 复审；计划文件 + 提交信息足够承载上下文。

## 2. 任务切分：按"30 分钟内可独立验证"切

- 一任务 = 一个可独立验证的交付面（一次迁移 / 一个端点 / 一个组件）。验收若需要同时验证"DDL + 数据流 + 投影 + 关联"，那就是四个任务。
- 任务含迁移时，brief 里必须点名编号——写计划前先 `ls backend/migrations/`（踩过：编号撞车）。

## 3. 计划里每条"字段/文案规则"必须带事实证据

- 写"缺失时显示 X"或"回退到 Y"之前，先确认该字段**没有数据时是什么值**，把证据（`file:line` 或只读查询结果）贴在规则旁边。
- 踩过：写了「`score` 回退列值」，而列是 `REAL NOT NULL DEFAULT 0` → 未打分显示成「推荐分 0 分」，正好违反"缺失不得用 0 冒充"。
- 证据只有三类：列定义 / 真实数据形态 / 缺失语义（null 还是 0 / ""）。

## 4. 验证成本要写进计划并批量化（本仓库实测基线）

| 动作 | 量级 |
|---|---|
| 单文件 vitest | 20–50 s |
| `tsc --noEmit`（整程序，含既有错误） | 数十秒起 |
| playwright 一轮（含前端构建） | 2–4 min |
| 完整后端套件 | ~27 min |
| 真实 Codex 轮次 | 2–3 min（本机还要先空转约 2 min WebSocket 重试） |
| 服务器部署（ff-merge + restart + 健康等待） | ~1 min |

规则：**只在提交前**跑一次聚焦集 + 一次 tsc；同一批 e2e 一次跑完再分析；真实爬取/Codex 类验证合并成"一次跑够"。禁止每改一处跑一遍。

## 5. 并发写入协议

- 开工前 `git status` + 确认 HEAD 是否在动；**发现同一批文件有人改，先停下确认分工**（或改用 worktree），不要靠"改完立刻提交"打补丁。
- 计划里显式声明**文件所有权**与冲突文件清单。
- 评审包以记录的 BASE 为准；发现 HEAD 被并发推进就重建包，别用旧 BASE 硬比。

## 6. 设计类需求：第一个任务必须是"能点的最小版本"

界面上线前先给用户可运行版本，拿到反馈**再**写后续计划。踩过：按线框实现 5 个任务 + 评审 + 修复波 + 上线，用户看完实机否掉一半。

## 7. 上下文纪律

- 只读需要的行区间，不整文件读；模板写一次，后续引用路径而不重印；事实进台账后不再重新推导。
- 判断类活儿留在主代理；计划里已给全代码的纯转录交给最便宜模型档。
- 子代理 dispatch 必须写"不做的事"清单，并禁止自选增量（踩过：实现者自作主张加测试拉长会话）；报告只回状态 + 提交 + 一行测试结论 + 文件清单，便于被中断时接手。
