## 安全发布方式

现有 `.github/workflows/release-gate.yml` 的自动部署对共享 `~/kol` 执行 `git reset --hard`，并重启执行Worker。该共享工作区存在其他任务的未提交修改，因此不能将此次push交给该破坏性路径。

本次提交使用仓库现有的 `[skip ci]` 约定，避免触发上述自动部署；不修改、禁用或删除CI工作流。改为手动执行受影响验证，并从已推送的main提交创建独立发布工作树，构建后仅切换Web/API服务。明确：本次不宣称GitHub全量CI已经通过。

原线上非本轮模块的未提交修改若必须保持当前生产行为，按独立白名单和SHA-256清单保留在发布覆盖层，**不提交进本轮main代码**；发布回执必须明确区分main提交与保留覆盖层，不能声称整个生产工作树无差异。主工作区不得执行hard reset、clean、stash或覆盖式checkout。

切换前保存服务覆盖配置及Worker PID；失败恢复上一Web/API目录，不改业务数据，不执行数据库迁移，也不自动重启Worker。
