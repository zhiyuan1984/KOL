# 企业智能体前端设计：员工端 + 管理端

> 整理时间：2026-10-01
> 本篇是《企业智能体与本体论研究笔记》的拆分文件之一。
> 设计输入：概念落地总表（codex harness + WikiSkill + Markdown/Git 知识库 + 事件表/工单表/摘要记忆）。
> 权威参考：Salesforce Agentforce（Builder / 互动总管）、Microsoft Copilot Studio（活动图 / 合规中心）、Microsoft Copilot Home（派工单模型）。

---

## 一、设计原则

1. **两端分工**：员工端是执行面（干活），管理端是治理面（定规则、管风险）。对应调度/执行/控制三系统的分工。
2. **人机协作，人担责**：AI 执行、思考、交付、建议，但不能担责（李开复）。关键动作必须人确认——两端都要把"确认点"做成一等交互。
3. **所见即架构**：每个界面元素都能映射回概念总表的载体，不造"悬空功能"。
4. **先骨架后血肉**：先三栏骨架 + 治理最小集，再迭代 trace 可视化、高级分析。

## 二、员工端：三栏工作台

### 2.1 整体布局

```
┌──────────┬────────────────────────────┬──────────────┐
│ 左栏     │ 中栏                       │ 右栏         │
│ 导航     │ 实时上下文 + 执行过程       │ 结果 + 确认   │
│ ~240px   │ 自适应                     │ ~320px       │
└──────────┴────────────────────────────┴──────────────┘
```

设计逻辑：一句话概括——**左栏选"干什么"，中栏看"凭什么这么干"，右栏定"干得对不对"**。

### 2.2 左栏：导航

| 菜单 | 内容 | 数据来源 |
|---|---|---|
| 任务 | 工单列表，按状态分组：待办 / 执行中 / 待我确认 / 已完成；每项显示优先级、SLA 倒计时、未读数；筛选：我的 / 我派发的 / 超时风险 | 工单表 |
| 技能 | 可用 skills 目录：名称、一句话描述、适用场景、上次使用效果；点击查看 SKILL 说明 + "用这个 skill 新建任务" | WikiSkill skills/ 层 |
| 知识 | 文档检索框 + 常用文档快捷入口 | 文档库向量检索 |
| （底部）我的 | 个人设置、我的记忆摘要、通知中心 | 摘要表 |

参考：Microsoft Copilot Home 的"派工单"模型——入口问题从"我想问什么"变成"我今天要让 Agent 干什么"。

### 2.3 中栏：实时上下文

**上半：任务卡**
- 任务标题、目标描述、状态、负责人（人 / 具体 agent）、SLA 倒计时、优先级标签
- 关联对象快照：本体对象的关键属性（如客户：名称、逾期金额、信用等级），点击展开对象全貌
- 数据来源：对象注册表 + 数据库表

**中段：上下文面板**（harness 上下文组装的可视化——让"实时上下文"被看见）
- **记忆**：相关事件摘要、历史工单摘要（如"上次催收 09-20，客户承诺 10-05 回款"）
- **知识**：相关文档片段（带出处：《退货政策 v4》第 5 条）、相关经验 pattern（WikiSkill："催收先查全貌再定话术"）
- 每个片段标注来源，可点击追溯原文

**下半：执行过程**（trace 时间线）
- 参考 Copilot Studio 活动图 / Agentforce 完整追踪：推理 → 调工具 → 收反馈的节点流
- 每个节点：动作名称、输入输出摘要、耗时、状态（成功 / 失败 / 待确认）
- 失败节点红色高亮，可展开看错误详情和重试入口

### 2.4 右栏：结果

| 状态 | 内容 |
|---|---|
| 执行中 | agent 实时输出流、当前步骤、预估剩余 |
| 待确认（HITL） | 动作确认卡：要做什么、影响范围、依据（规则/政策原文链接）、**[批准] [修改] [拒绝]**；按风险分级着色（绿/黄/红），高风险强制人工确认 |
| 已完成 | 交付物（文本/文件/链接）、执行摘要、"已写入事件表 / 工单已更新" |
| 审计入口 | 查看本次任务的完整审计链（谁、何时、做了什么、依据什么） |

参考：Windows Agent Workspace 的"用户始终在环"（consent 三档、执行隔离）——确认卡就是 consent 的落地。

### 2.5 核心交互流程

```
选任务（左栏）→ 中栏加载上下文（harness 按任务组装）→ agent 开始执行
    → 执行过程在中栏 trace 实时展开
    → 遇到需确认动作 → 右栏弹出确认卡 → 人批准/修改/拒绝
    → 完成 → 右栏交付物 + 事件落表
    → 可能生成后续任务 → 出现在左栏任务列表
```

### 2.6 任务状态机

```
新建 → 待分配 → 执行中 → 待确认 → 已完成
                  ↓超时        ↓拒绝
                已升级      退回执行中 / 已关闭
```

## 三、管理端：治理控制台

### 3.1 模块导航

| 模块 | 管什么 | 对应概念 |
|---|---|---|
| 概览 | 今日任务量、成功率、平均耗时、待审批数、异常告警、skill 调用 Top | 执行/调度运行状态 |
| 本体管理 | 对象类型列表（注册表）、属性定义、关系图、规则表（条件-动作配置） | 本体六构件 |
| 技能管理 | skills 列表（版本/状态/调用统计）、PURPOSE 溯源、WikiSkill 运维台 | Skill、知识库（经验） |
| 知识库管理 | 文档列表（Git 同步状态、版本历史、生效/过期标记）、向量检索测试台 | 知识库（文档） |
| 权限管理 | RBAC 矩阵（角色×动作权限）、用户-角色分配、agent 身份权限、审批流配置 | 控制系统 |
| 调度监控 | 工单队列、派单规则配置、SLA 配置、超时升级记录 | 调度系统 |
| 审计中心 | 事件日志查询、操作日志、合规案件 | 控制系统 |
| 记忆管理 | 摘要浏览、记忆检索测试、记忆清理规则 | 记忆 |

### 3.2 关键页面详述

**技能详情页**（参考 Agentforce Builder + 测试中心）
- SKILL.md 预览、版本历史、PURPOSE（为解决哪个 pattern 而存在，可回溯到 trace）
- 调用统计：调用次数、成功率、平均耗时
- 测试：模拟器（输入测试任务，看 trace 和结果，发布前验证）
- 操作：上线 / 下线 / 回滚到上一版本

**WikiSkill 运维台**
- 三层状态：raw/（轨迹量）、wiki/（patterns 数量、log）、skills/（生效 skill 数）
- patterns 列表：每个 pattern 的内容、来源 trace、支撑的 skill
- skill-impact 审计：哪些提案被接受/拒绝及原因
- 进化循环控制：启停、验证集门控结果、本轮变更 diff

**审计案件页**（参考 Copilot Studio 合规中心）
- 触发阈值（违反了哪条政策）、风险等级（高/中/低）
- SLA 倒计时、事件时间线（完整活动历史）
- 批准 / 拒绝 + 审计笔记；支持导出合规报告

**本体对象页**
- 属性表（字段、类型、来源系统）、关系图（与哪些对象关联）
- 关联规则（哪些规则引用了该对象）、数据来源连接器状态

**权限矩阵页**
- 行：角色（含 agent 身份，参考 Copilot Autopilot 的 directory identity）；列：动作/数据范围
- 单元格：允许 / 需审批 / 拒绝；变更走审批流，留审计记录

### 3.3 管理端落地顺序

1. 先上治理最小集：技能列表、审计日志、权限矩阵
2. 再上：WikiSkill 运维台、调度监控、知识库管理
3. 最后：概览仪表盘高级分析、记忆管理

## 四、人机责任边界（两端统一体现）

| | agent 可自主 | 必须人确认 | 人专属 |
|---|---|---|---|
| 范围 | 查数据、生成草稿、低风险动作 | 高风险动作（资金、对外承诺、批量操作）、策略例外 | 担责、最终决策、审计签字 |
| 员工端体现 | 自动执行，trace 可见 | 右栏确认卡（绿/黄/红分级） | 确认、修改、拒绝 |
| 管理端体现 | 执行日志 | 审批流配置、合规案件 | 审计签字、案件裁决 |

熔断：连续失败超阈值 / 风险动作无审批 → 自动暂停 agent 并告警，事件落表。

## 六、MVP 建议

- **员工端 MVP**：左栏任务 + 中栏上下文（任务卡 + 记忆/知识片段）+ 右栏确认卡；trace 先做简化版（步骤列表代替节点图）。
- **管理端 MVP**：技能列表、审计日志、权限矩阵。
- **复用优先**：工单列表可先复用现有工单系统前端，逐步替换；文档库复用 Git 托管平台界面。
