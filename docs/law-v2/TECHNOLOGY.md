# 技术与交付基本法

上位法：[CONSTITUTION.md](CONSTITUTION.md)。ARCH 由架构师制定，FE 由前端专家制定，BE 由后端专家制定，TEST 由测试经理制定。业务语义、事实来源和业务审批权由 [BUSINESS.md](BUSINESS.md) 决定。

## 组件与调用关系

### TECH-ARCH-01 组件选择

以当前 React/TypeScript 前端、Hono/TypeScript 后端、SQLite 存储和 Codex app-server 为迁移起点，不因重写法规更换技术栈。架构师决定组件选择与模块边界；新增数据库、队列、搜索或服务拆分必须说明实际需求、替代方案和迁移影响。

记忆快查可先使用结构化索引和全文检索；需要语义召回时再补充相应能力。采用何种数据库不改变业务专家对权威来源的决定权。

### TECH-ARCH-02 三种调用链

```text
AI 提问 → Host 建立任务与权限上下文 → Codex harness → 已授权知识/记忆/工具
记忆快捷指令 → Host 校验权限 → 记忆/事实索引服务 → 结构化结果
事件/定时 → 校验来源与执行身份 → 已发布流程 → 受控动作或索引更新

任何需要提交的业务副作用 → Host Gateway 校验 → 已授权连接器 → 回执
```

使用 Codex 提供的 harness，不按业务分别搭建第二套推理循环。思考型后台摘要也通过统一 harness；快捷接口和确定的后台动作不要求 thread/turn。API、MCP 和 webhook 共用权限与动作契约，不因协议不同形成旁路。

### TECH-ARCH-03 平台与业务包边界

平台模块管理身份、任务、运行、成果、配置、执行、知识、记忆和审计。业务包声明对象、规则、技能、流程、数据源、工具及界面入口；平台加载并校验，不在内核维护 KOL 分支、SOP 模板或审批金额表。

Agent 不等于独立进程，数字员工不等于 Skill。工具适配器只处理协议、字段映射、鉴权、限流和外部限制，不改写业务阶段或授权含义。

### TECH-ARCH-04 共享契约

任务、工作项、运行、成果、审批、记忆、事件和错误采用可校验、带版本的接口结构。最少明确输入、输出、对象范围、状态、风险、失败与兼容方式；各模块的设计权与实施责任不能因共用 schema 混为一体。

发布资产应声明 ID、版本、责任人、范围、依赖、输入输出、工具权限与所需审批；流程还应声明触发、分支、完成条件、超时和接管。缺失依赖或未知版本明确报错，不静默采用默认业务值。

## 前端实现

### TECH-FE-01 显式入口与展示

前端按已登记的入口类型调用思考、记忆或受控动作接口。快捷按钮不得暗中发送一条聊天消息；AI 提问框不得暗中返回本地摘要冒充新分析。思考进度来自执行事件，快速读取显示自己的加载状态。

前端使用后端返回的可见数据、允许动作和合法目标，不自行计算审批链或阶段权限。禁用按钮是体验提示，不替代服务端校验。

### TECH-FE-02 内容与安全

按版本化结构呈现 Codex 内容，支持文字、表格、卡片、草稿和回执。模型输出按不可信内容处理，不执行任意脚本；未知组件有安全降级。业务动作引用已注册动作 ID，不能执行模型拼出的任意接口。

### TECH-FE-03 状态与恢复

同一任务、对象、草稿和审批使用稳定 ID 与版本；切换页面不丢失待确认内容。断线重连从事件位置恢复，重复事件不重复展示或提交。版本变化后提示差异，不能拿旧确认提交新内容。

## 后端执行与数据

### TECH-BE-01 每次访问校验权限

查询、搜索、统计、详情、工具调用、后台任务、记忆召回、文件、导出及分享都检查当前身份与对象范围。权限过滤在取数与返回结果前完成，不能把完整数据交给浏览器或模型再过滤。

缓存、索引、后台作业和会话按实际授权范围隔离；撤权后旧缓存不能继续提供数据。`team` 标签、KOL ID、姓名或邮箱前缀都不是授权凭证。后台使用明确的服务身份与授权范围，不默认继承管理员全量权限。

### TECH-BE-02 统一提交闸门

所有正式副作用在网关核验身份、对象、动作权限、当前版本、确认、适用审批、发布规则版本和幂等键。确认只覆盖当时展示的对象、内容与范围；关键字段改变时重新确认。

审批链有引用、人员存在并不足以证明有审批权，还须符合已发布业务规则。后端执行和验证该规则，不通过另写金额表重定义业务。预授权自动动作携带有效授权及策略版本，不伪造人工点击记录。

### TECH-BE-03 并发、幂等与回执

后端专家制定并发控制、事务和一致性方案。正式写入校验预期版本；同一排他范围的归属取得、续期和释放须原子判定，竞争失败返回明确冲突，不能后写覆盖先写。

重复确认、重试和事件重放不得造成重复发送、导入或归属变更。保留请求标识和真实外部回执；超时但可能已提交时先查状态或人工核对，不能盲重试。无法确认结果时如实返回“不确定”。

### TECH-BE-04 事件与持久作业

接收 webhook 时验证来源、租户绑定及防重放信息。事件记录稳定 ID、对象、发生时间、接收时间、来源版本及关联动作；处理器能去重、重试、恢复，并正确处理迟到和乱序事件。

业务事实提交与后续索引更新不得因进程退出而永久丢失，可用事务事件记录及可恢复队列实现。异步采集、摘要和定时任务持久化状态、终态、错误与回执；只使用页面回调或进程内定时器不满足长期自动化要求。具体方案由后端专家决定。

### TECH-BE-05 到期执行

按业务配置计算期限，以权威互动事实和当前归属版本复核到期。多个执行器抢到同一任务也只能产生一次有效释放；互动或归属已变化时旧任务作废或重排。

读取事件的发生时间，不能用晚到的接收时间随意延长归属。数据缺失、同步滞后和新旧事件竞争按业务口径处理；权限变化应立即影响读取，索引异步刷新期间也不能越权返回旧摘要。

### TECH-BE-06 记忆存储与索引

结构化事实记录、原文证据和衍生摘要分别标识，按公司、可见范围、对象 ID、类型、状态、时间建立索引。先完成权限与精确对象过滤，再做关键词或语义检索；模型上下文按相关性和预算选取，不直接堆叠最近若干条。

摘要绑定完整来源版本或可靠内容指纹，不能仅凭正文长度判断未变化。支持更正、停用、到期、删除及重建；源内容删除或权限变化应使关联索引失效。快速读不调用模型，正式状态写入不藏在记忆接口里。

### TECH-BE-07 连接器与真实执行

连接器登记端点、协议、schema、读写风险、授权方式、凭据引用、范围、限流和失败语义；工具名标为只读不等于实际行为只读。凭据保存在受控服务端，不放入模型上下文、前端、知识或日志。员工使用面 DTO 不含凭据引用。

生产使用真实的已授权 API/MCP，禁用演示账号、模拟数据与绕过鉴权的调试模式。模型不可用时思考任务明确失败或等待，不能用静态模板冒充已完成思考；独立记忆查询可继续按权限工作。

### TECH-BE-08 可追溯与不可信输入

记录操作者、范围、对象、动作、前后版本、规则版本、时间、结果和回执；模型执行另记任务、thread/turn、模型与 Skill 版本，快捷操作只需请求及动作记录，不伪造 thread/turn。

邮件、网页、上传文件、知识和记忆均可能含不可信指令，不得据此修改权限、跳过审批或泄露秘密。员工看到经过脱敏的业务结果；管理员仅在审计权限范围查看技术详情。

### TECH-BE-09 保留、删除与安全运维

执行已发布的保留策略，区分个人会话、记忆、共享资料、业务事实及审计。归档、删除、导出与分享应校验权限并记录结果；保留审计不代表永久保留全部正文或敏感数据。备份与恢复需覆盖权限、配置和事件处理位置。

生产配置保护凭据与管理接口，限制文件访问范围和上传内容。事故可停用连接器、自动任务或新提交，同时保留已发生动作的回执和接管路径。

## 测试、交付与运营

### TECH-TEST-01 按规则验证

测试经理为变更选择单元、接口契约、集成、端到端、权限、恢复及 UI 验证；Agent 能力另做事实、工具使用和决策质量评价。业务专家确定业务正确口径与可接受阈值，测试经理负责证据与测试方法。

保留 `需求/FS → 新条款 → Skill/Policy/配置/代码 → 测试/EVAL → 发布版本` 的追踪。历史测试断言与新版冲突时先核对规则，不能为保住旧测试恢复废止要求。

### TECH-TEST-02 必测边界

受影响能力必须覆盖下列适用场景，任何相关越权或错误副作用失败不得发布：

| 范围 | 必测结果 |
|---|---|
| 两类交互入口 | 快捷查询零 thread/turn、零模型调用；缺失不暗中升级；AI 提问确实进入 harness |
| 权限与隔离 | 跨公司/品牌/普通员工拒绝；授权负责人范围有效但不绕过高风险闸门；详情、缓存、摘要、统计和分享同样受控 |
| 发信与正式写入 | 未确认不发送；重复确认只提交一次；编辑使旧确认失效；发送不改阶段；未知回执不误报成功 |
| 归属与 14 天规则 | 临界时间前后、有效续期、两个员工并发、重复与迟到邮件、旧计时任务、重启恢复、源不可用和回公海字段限制 |
| 记忆 | 来源可追溯；同长度正文修改也使摘要失效；纠正、删除、过期和撤权生效；快捷读取不重算 |
| 异步与交互 | 超时、取消、部分成功、恢复和接管；键盘、焦点、读屏及约定视口 |
| Agent 质量 | 正常、缺字段、空结果、冲突证据、提示注入、工具失败、长上下文、人工改稿；不捏造事实、权限或执行结果 |

### TECH-TEST-03 发布证据

区分模拟测试、真实 harness 测试和授权外部集成验证；一种通过不证明另外两种通过。只读或记忆功能不要求为证明自己可用而发送邮件；验证外部写入使用明确授权的对象和范围。

发布锁定平台、Agent、Skill、Workflow、Policy、schema、连接器、模型及配置版本，并保存相关测试、评价和回滚证据。代码检查和契约校验通过不等于完整业务闭环已验收。

### TECH-TEST-04 里程碑与回滚

项目经理按依赖安排“规则明确 → 契约实现 → 核心链路 → 真实验证 → 发布”，每个节点有负责人和可验收结果。小范围变更做适用检查，不重复无关全量流程。

后端专家负责服务、队列、同步、错误、延迟、成本和审批积压的监控及恢复；前端专家负责客户端故障，测试经理验证回滚，业务专家判断业务补偿。出现泄露、越权或重复副作用时停止受影响的新提交；已发邮件、已付款等不可逆结果只能补偿，不能宣称已回滚消失。
