# 产品基本法：平台、Agent 与记忆

上位法：[CONSTITUTION.md](CONSTITUTION.md)。PLAT 条款由平台产品经理制定；AGENT 条款由智能体产品经理制定。KOL 对象与规则引用 [BUSINESS.md](BUSINESS.md)，不得在本文件另定口径。

## 平台能力

### PROD-PLAT-01 三类产品面

员工端用于执行任务、使用能力和查看成果；管理端用于组织、资产、授权、发布、审批配置和审计；设置端用于个人资料、偏好、账号连接与隐私。同一人可有多个身份，切换界面不扩大服务端权限。个人外部账号绑定由设置端维护，其他页面只引用其状态。

### PROD-PLAT-02 基础设施范围

平台持续覆盖下表能力，但能力存在不等于必须拥有独立页面。未实现的能力明确标注，不能以空页面、跳转或现有业务表冒充完成。

| 能力组 | 必须纳入产品范围 |
|---|---|
| 工作执行 | 任务、工作项、会话、运行记录、成果、人工接管 |
| 能力资产 | 数字员工、Agent、数字团队、技能及技能市场、知识库 |
| 集成 | API、MCP、webhook、账号连接、工具目录和运行健康 |
| 治理 | 公司与组织、成员、角色、授权、审批、审计、配置及版本 |
| 运营与辅助 | 自动任务、通知、考试与资格、项目、文件资料、远程使用、个人设置与隐私 |

数字员工是岗位身份，Agent 是能力组合，技能是可复用动作，任务是工作目标；不得互相替代。KOL 项目、看板、公海属于业务包。

### PROD-PLAT-03 可配置的业务承载

提供注册业务对象、字段、关系、动作、规则、流程和界面入口的机制，支持校验、预览、发布、停用、版本与回滚。具体 KOL 归属、到期和可见范围由业务专家定义；平台按已定义契约提供承载能力，不替业务先定规则。

### PROD-PLAT-04 资产使用与治理

员工使用权限范围内的已发布 Agent、技能、知识和连接器；管理员管理发布版本、适用范围和可用状态。知识应支持查找、预览、收藏、用于当前任务；治理应支持上传、提取、修订、审核、发布、停用和版本追踪。

将知识“用于当前任务”只形成上下文或未提交草稿。知识自动提炼和优化先生成候选，未经发布不得改变现行制度或共享知识。

### PROD-PLAT-05 授权、审核与配置

平台提供角色、数据范围、工具权限和审批流程的配置、查询及记录能力。配置界面应说明变更对象、影响范围和生效版本；保存草稿不等于发布生效。业务审批链由业务专家制定，平台管理员不得通过配置操作绕过执行时的校验。

### PROD-PLAT-06 自动任务与通知

支持定时、webhook 和内部事件触发，声明执行身份、对象范围、条件、频率、暂停、重试和接管方式。关闭网页或会话不能使已发布自动任务失效。通知应针对需要行动的结果，去重并尊重个人通知设置；通知不扩大原数据可见范围。

### PROD-PLAT-07 生命周期与隐私

账号停用、权限撤销、任务转办、文件与会话分享、导出、归档、删除及保留期必须有明确结果。分享范围不得超过发布者权限，支持到期和撤销；敏感成果按业务规则限制分享。删除会话不默认删除业务回执、正式关系和应保留审计，界面须说明实际删除范围。

考试内容、合格标准及其业务授权影响由相应业务角色确定；平台负责分配、作答、结果和资格记录。前端自报“通过”不能成为授权依据。

## Agent 交互与记忆

### PROD-AGENT-01 入口决定路径

| 入口 | 执行约定 |
|---|---|
| AI 提问框；明确标为“让 Agent 分析/起草”的入口 | 发起 Codex 思考流程，允许检索记忆、知识和工具；简单问题也不暗中改走快捷路径 |
| 明确的记忆查询、记录、修改、删除快捷指令 | 直接访问已授权记忆服务，不创建或恢复 thread，不启动 turn，不调用模型补结果 |
| 确认发送、变更正式状态等业务动作按钮 | 提交已经明确的受控命令，按业务规则执行；不能伪装为“改记忆”，无需为了提交再让模型思考 |
| 后台事件或定时任务 | 执行预先发布的流程；需要提炼摘要时可单独启动后台 Codex 作业 |

路由类型必须显式登记，前后端不能仅凭按钮文案或关键词猜测。记忆未命中、过期或服务失败时，返回真实状态，提供明确的“交给 Agent”入口，由用户选择。

### PROD-AGENT-02 快捷指令契约

每条快捷指令声明名称、动作 ID、输入、结果类型、适用权限、读写范围和失败处理。查询只展示已有记忆或已建好的事实索引；记录与修改仅处理已明确的内容，不在快捷请求里做自由文本意图推断。

“我跟进的红人”“我的待办”“跟进任务”“风险任务”“任务摘要”“邮件往来摘要”应提供快捷查询。已有评分、报表和 SOP 可以快查；重新评分、生成报表解读或决定下一步属于思考任务。

### PROD-AGENT-03 回答契约

Codex 根据任务决定用文字、列表、表格、卡片或组合形式组织内容。回答应区分事实、推断、建议、缺失信息和已执行结果；需要追溯时可查看来源、时间及操作回执，不强制每次都生成同一套区块。

只有影响当前任务的必要信息缺失时才追问；已经明确的授权和选择应复用。模型可以提出行动，不能通过生成按钮、文本或卡片授予自己权限。

### PROD-AGENT-04 记忆内容与边界

可记忆员工明确表达的偏好、对象画像、互动摘要、任务摘要、已发生事件及后续约定。密码、令牌和完整秘密不得进入记忆；无关聊天不自动长期保存。员工可以查看、纠错、停用和删除自己有权管理的记忆。

自动抽取必须受发布策略约束。用户陈述保存为“用户陈述”，模型判断保存为“推断”；只有匹配业务规定的来源证据才记为事实，不能把一句“已经签约”直接改成正式签约状态。

### PROD-AGENT-05 记忆最小信息

每条记忆至少能识别：`所属公司、可见范围、对象类型与 ID、记忆类型、内容、来源及版本、发生时间、更新时间、有效状态`。涉及个人再记录所属员工；涉及推断再记录依据和不确定性；涉及到期再记录到期规则与时间。

平台、方向、画像等 KOL 元数据由业务专家定义，存储结构由后端专家实现。更正应能追溯前一版本；过期、撤权、源数据删除和纠正应影响后续检索，不靠模型自己忘记。

### PROD-AGENT-06 快速索引与新鲜度

按当前员工权限、对象 ID、状态、时间及业务元数据建立可筛选索引；关键词或语义检索是补充。不能只按“最近若干条记忆”拼接回答，也不能先召回他人数据再让模型过滤。

快捷结果显示摘要更新时间，必要时显示源数据时间及过期状态。延迟和新鲜度目标由产品经理提出、后端评估、测试经理验收；上线规格必须有具体数值，不能只写“快速”。

### PROD-AGENT-07 事件驱动记忆

有效业务事件提交后更新对应索引；同一来源版本不重复提炼摘要。新邮件、任务变更、归属变更和审批结果可触发更新；后台摘要失败应保留旧摘要并标过期或失败，不能伪造新摘要。

快捷读取本身不触发模型重算。记忆生成失败不得回滚已成功的发信等事实；后续通过可重试作业修复索引。

### PROD-AGENT-08 任务与对象分开

正式任务保存负责人、目标、关联对象、状态、截止时间、风险、摘要、产物及下一步；运行记录另行保存一次次执行结果。任务可跨会话继续，不依赖某个 thread 才存在。

AI 推荐是候选任务，只有员工采纳或已发布的自动创建规则触发后，才进入正式待办。“跟进一个红人”是对象关系，不能自动等同于一个未完成任务。

### PROD-AGENT-09 可靠协作

明确显示排队、执行、待补充、待审批、可重试、失败、完成或已取消状态，并提供适用的取消、恢复或人工接管入口。取消后仍应展示已发生的外部动作；不能通过隐藏消息抹去执行历史。

不同员工访问同一 KOL 时仍保持各自会话权限；对象关系和授权决定可取上下文，不能仅凭同一 KOL ID 复用他人的会话。
