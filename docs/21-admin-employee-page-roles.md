# 管理端 ↔ 员工端页面角色契约

管理端与员工端的**页面角色法律**，尤其连接器与 Agent 治理。日期：2026-09-13；2026-09-14 交叉引用：`/admin/agents` 治理 ≠ 员工 `/agents` 专家中心；员工专家中心禁止连接器状态 chrome。同日交叉引用：员工 `/kb`（查找 / 预览 / 收藏 / 用于当前任务）≠ 管理端知识治理（停用 / 发布 / 版本 / 范围），见 ADR-021。来源：产品发现两端导航/页面重叠（员工侧栏深链 `/admin/connectors`、管理端顶栏跳员工 `/agents`、远端 pill 克隆、Starry 绑定双挂、遗留连接器清单），固化为后续信息架构取舍的默认立场。

本文件**只**管双端谁答哪一问、管理端配套套件、**员工使用面 vs 管理治理面**、导航与遗留收敛。它**不**改 `19` 四页法律，**不**新增 UX ID，**不**实施后端。闸门、L1–L3、无障碍和员工禁词仍以 `04-ux-ui-system.md` 与 `specs/UX-KOL.md`（`UX-COPY-ENGINE`）为准。视觉密度与 token 默认见 `20-visual-design-system.md`：同一套 token，**不同信息架构**。

## 与现行法律的关系

| 文档 | 本文件不得改写的内容 | 本文件补的缺口 |
|---|---|---|
| `19-ui-ux-constitution.md` | 核心闭环五问、四页分工（Home / Pipeline / Chat / Admin）、并列能力面与 Agent / 任务解耦、员工 `/kb`（ADR-021，非邮件台）、Agent 表面、`/agents` 专家中心（召唤岗位专家，非第五页） | Admin 行展开为**配套套件**，不是第二套员工工作台 |
| `04-ux-ui-system.md` | 双端边界、状态可见、L1–L3、语义色、无障碍 | 管理端路由与员工表面的一一对应（配套，不是副本） |
| `specs/UX-KOL.md` | 可执行 UX ID、Given/When/Then、发布门禁绑定 | 不发明 Admin UX ID；员工端继续禁 MCP / Codex / Thread / Skill / 原始堆栈 |
| `20-visual-design-system.md` | 密度、token、indigo 主色、禁止第二套主题 | 管理端用同一 token；IA 是治理表/授权矩阵，不是 Home/Agents 工作台 |

评审管理端 PR 时先过 `19` 五问与本文件硬边界，再谈 `20` 的密度和色。任一法律层失败，该改动违约，不论是否「更好找」。

`19` 的 Admin 行仍然只回答「谁 / 权限 / 审计」。本文件把这一行写成可落地的配套套件：连接器枢纽、Agent 治理、授权与审计切片。`/agents` 继续是员工端 P0 专家中心（找谁协作 / 召唤岗位专家），不是管理端。`/admin/agents` 只做发布 / 授权 / 考试闸门，不得与员工专家中心混读。

## 为何需要这份契约

现状把「治理」和「干活」叠在同一套导航与 chrome 上：

| 重叠 | 现状（诊断，不是本 PR 改代码） | 违约 |
|---|---|---|
| 员工侧栏深链管理端 | `Workbench`「技能目录 · 连接器」在管理员可见时链到 `/admin/connectors` | 员工主路径变成能力图鉴入口；连接器配置不属于员工表面 |
| 管理端顶栏跳员工工作入口 | `AdminConsole`「员工 · 智能体」链到员工 `/agents` | Admin 没有自己的 Agent 治理页，只能去抄员工开工台 |
| 远端 pill 克隆 | 管理端顶栏常驻 `remote-legend` / `remote-pill`；员工 `/agents` 调试态也用同一套 | 管理端健康条做成员工 Agents 的副本；员工主路径一旦打开调试就看见引擎图例 |
| Starry 绑定双挂 | `AdminConsole`「连接 Starry」与「个人设置 → 连接 Starry」共用 `StarryBindForm` | 个人邮箱绑定是 Settings 的事；组织 Starry 策略应在连接器治理，不应再挂一份个人绑定表 |
| 遗留连接器清单 | `Admin.tsx`「本期连接器」、`SimplePages` 管理配置、SkillHub 调试连接器砖（`starrykol` / `kolclaw` → `/admin/connectors`） | 同一事实三处列表；员工/调试砖直接深链管理端 |

本文件的立场：员工端继续干活；管理端只治理。两端可以**配套**（同一对象、不同问题），禁止**复制**（同一 IA、同一 chrome、同一 CTA）。

## 硬边界（双端各答一问）

| 端 | 只回答 | 禁止 |
|---|---|---|
| **员工端** | 现在做什么、正式生命周期坐落在哪、如何完成这一件、召唤哪位已发布岗位专家；已被授权可用哪些连接能力（使用/状态，不是配置） | 连接器配置、凭据、组织授权树、发布闸门、考试门槛、引擎 Trace、MCP/Codex/Thread/Skill 行话；员工专家中心上的连接器状态主 IA |
| **管理端** | 谁能用、用到哪、连到哪、是否发布、考试是否挡住、授权与绑定如何变更、审计能否回放 | 员工待办桶、生命周期扫视、再开一单、会话开工、把 Pipeline 或 Home 再做一遍 |

超级用户可以进两端和显式调试视图，但仍不能跳过发送、阶段、解密、导入、删除和审批闸门（`04` / `08`）。进管理端不等于旁路 Host。

员工端四页法律（`19`）不变：

| 页面 | 角色 | 只回答 | 禁止 |
|---|---|---|---|
| **Home** | 现在做什么 / 等待诚实 | 四模式见 `19` / ADR-018：今日任务、我的待办（逾期/今天到期/结果待确认/等审批/已入队/执行中）、AI发现（CreatorCandidate 线索）、我跟进的红人 | 正式 15 阶段资产板、管理端权限树、连接器治理目录 |
| **Pipeline** | 合作资产页：正式生命周期坐落 | 正式阶段、品牌/负责人、停留、近期事件、同步来源/时间、阶段风险、允许提出的阶段变更 | 首页四模式 / 待办桶（见 `19` / ADR-018）、管理端授权矩阵、第二套连接器清单 |
| **Chat** | 如何完成一件具体任务 | 表达目标 → 计划 → 能力调用 → 可确认结果 | 把 Pipeline 当第二会话启动器；在线程里展开连接器配置 |
| **Admin** | 谁 / 权限 / 审计 | 组织、授权、连接器、Agent 治理、Trace、审计 | 员工主路径的待办、生命周期扫视、再开一单 |

`/agents` 不是第五套主表面，也不是 Admin。`19` P0 已锁定：员工 `/agents` 是**专家中心**——只回答「找谁协作 / 召唤岗位专家」，不是技能图鉴、不是第二套 Home、不是连接器目录；员工默认禁止 Profile / Harness / MCP / 技能目录 / 连接器状态主 IA / **专家团**。管理端不得再链回这个入口充当「智能体页」。员工专家中心禁止连接器状态 chrome；连接器治理仍只在本文件的管理端枢纽。

## 员工四表面 vs 管理端配套套件

配套 = 同一业务对象，回答治理问题。副本 = 同一信息架构、同一开工 CTA、同一远端 pill。

| 员工表面 | 员工只回答 | 管理端配套（不是副本） | 管理端只回答 | 禁止做成副本的做法 |
|---|---|---|---|---|
| **Home** | 现在做什么、等待是否诚实（四模式见 `19` / ADR-018） | 无对应工作台。组织/账号在 Admin 员工目录 | 真人账号启停、角色、站点 | 管理端首页待办、等待桶、推荐简历、红人线索漏斗 |
| **Pipeline** | 正式生命周期坐落 | 无对应资产板。阶段写入仍走既有确认/审批 | — | 管理端第二套 15 阶段扫视或「帮我处理今天」 |
| **Chat** | 如何完成这一件 | 显式调试 / 脱敏 Trace（管理员另开，不占员工脊柱） | 这次调用了什么、谁批了、回执是什么 | 管理端第二会话、再开一单、把结果卡当治理页 |
| **Agents（专家中心 / 数字员工）** | 找谁协作 / 召唤已发布岗位专家（只建绑定会话） | **`/admin/agents` 治理页** | 发布状态、可写范围、考试闸门、连接器授权矩阵 | 管理端顶栏跳 `/agents`；治理页做成员工专家中心或「我的智能体」开工台；两端互相抄连接器状态 chrome |
| **知识库 · 员工面 `/kb`** | 查找 / 理解适用场景 / 预览 / 收藏 / 用于当前任务（ADR-021）。邮件模板只是一类资料 | 管理端知识治理（发布 / 停用 / 版本 / 范围） | 谁发布、是否停用、哪个版本、适用哪些品牌/区域 | 员工面做成邮件模板管理台；主 CTA 启用/停用/发布/隐藏；从 KB 发信或写阶段；KB 首页写 Codex / harness |
| **连接器 · 员工使用面** | 我已被授权可用哪些连接能力、当前对我意味着什么、个人绑定去哪。只读消费已授权条目 | 无。治理不在员工 chrome | — | 做成治理目录、启停/凭据/授权编辑、深链 `/admin/connectors`、把个人绑定表再挂一份 |
| **连接器 · 管理治理面** | 员工不回答治理问题 | **`/admin/connectors` 枢纽 + `/admin/connectors/:id` 详情** | 启用、凭据引用（永不回显）、员工 read/write、组织 Starry 策略 | 员工侧栏深链治理枢纽；SkillHub 砖当员工主路径；个人绑定表再挂一份到 Admin |
| **Settings（个人）** | 我的发件箱绑到谁 | 组织策略在连接器详情；个人绑定只留 Settings | — | Admin「连接 Starry」再渲染一份 `StarryBindForm` |

「员工不可见配置」指**配置 / 凭据 / 组织策略 / 授权编辑**对员工不可见。它**不**禁止一条独立的使用/状态面：员工可以看见自己已被授权可用的连接能力，以及「个人绑定去哪」。那条使用面不是治理目录，也不是 Admin 枢纽的副本。

个人邮箱绑定（例如把当前账号绑到一只 Starry 发件箱，供首页「我跟进的红人」过滤）**只留**「个人设置 → 连接 Starry」。组织级 Starry 策略（是否对本组织启用、谁可绑、员工 read/write）落在连接器详情，不落在个人绑定表。员工使用面若出现绑定 CTA，只链到 Settings，不复刻 `StarryBindForm`。

## 员工使用面（`/connectors`）

独立员工表面，**不是** `/admin/connectors` 的只读镜像，也不是第五套主表面（四页法律不变；本页与知识库 / 审批 / 考试同属 `19` 的并列能力面 / 可选 chrome）。只回答三句：我已被授权可用哪些、当前对我意味着什么、个人绑定去哪。

`19` 已锁定：本面及同列能力面与数字员工开工入口、今日任务队列相互独立——不隶属 KOL Agent，也不因「有没有进行中任务」才存在。KOL / 合作只可作为数据或示例，不得定义本面 IA。**治理仍只在管理端**枢纽 / 详情（本文件下文）；使用面 vs 治理面不因本条而合并。

员工知识库 `/kb` 同属并列能力面，分家方式平行：员工只查找 / 预览 / 收藏 / 用于当前任务；停用 / 发布 / 版本 / 范围只在管理端。细则见 `19` 知识库节与 ADR-021。本文件不重写知识管理页。

| 必须 | 禁止 |
|---|---|
| 只列出当前用户经已有 `GET /api/connectors` 能看见的条目（已授权且已启用） | 伪造未返回的「未授权」清单、组织全量目录、或 LIVE 健康 |
| 业务标签 + 诚实状态（可用 / 需个人绑定 等）；空态写「目前没有已授权给你的」 | 启用/停用、凭据引用编辑、员工 read/write 授予、组织 Starry 策略 |
| 可绑定能力（如 Starry）的 CTA 只指向 `/settings?tab=starry` | 在本页或 Admin 再挂一份个人绑定表；JWT / API Key 粘贴框 |
| 侧栏若有入口，只链本页，且不进数字员工簇、不发明可见组标题 | 任何员工默认路径深链 `/admin/connectors` |

现有员工 API **不**返回未授权或已停用的连接器。因此使用面不能诚实地画出「未授权」行；缺行用空态说明，不要前端补一份治理目录。授权矩阵、组织策略字段仍属后端另开计划。

## `/admin/connectors` 枢纽

唯一的组织连接器目录。只回答：组织现在挂了哪些连接器、是否启用、凭据是否已登记（只显示引用态，不显示秘密）、最近一次治理变更指向哪条详情。

| 必须 | 禁止 |
|---|---|
| 每条连接器进 `/admin/connectors/:id` | 在枢纽页直接贴员工 `/agents` 或「再开一单」 |
| 状态用业务/治理文案（未配置 / 已登记 / 已启用 / 已停用） | 把员工 Agents 的 `remote-pill` 图例整排克隆到枢纽顶 |
| 空态写「尚未挂接」，不伪造 LIVE 健康 | 在本页回显 secret、JWT、API Key、Bearer |
| 新增连接器只收短名、显示名、`credential_ref`（位置，不是原值） | 再并列 `Admin.tsx` / SkillHub / SimplePages 三份「本期连接器」 |

进程级 URL / API Key 仍在 Host 环境变量；用户 JWT 不准填进连接器凭据位置。枢纽可以提示「进程级密钥不在本页」，但不得提供粘贴框当第二套 env 编辑器。

## `/admin/connectors/:id` 详情

单条连接器的治理页。只回答这一条的启用、凭据引用、员工授权、组织策略。

| 区块 | 只回答 | 禁止 |
|---|---|---|
| **启用** | 本组织是否启用这条连接器 | 启用后假装已经 LIVE、或绕过 Gateway |
| **凭据引用** | 是否已登记 `credential_ref` / `credential_reference`；变更只写新引用 | **永不回显**原值、JWT、Key、Bearer；编辑框提交后清空 |
| **员工 read/write** | 哪些人/角色对这条连接器有 read、哪些有 write | 把授权做成员工技能目录；write 不等于发送/阶段/解密旁路 |
| **组织 Starry 策略**（仅 Starry 条） | 组织是否允许绑定、谁可绑、跟进范围是否受本组织约束 | 再挂个人 `StarryBindForm`；把「连接 Starry 邮箱」做成管理端主 CTA |
| **本条审计** | 启用/停用、引用变更、授权变更的最近记录 | 把员工审批待办或 Pipeline 事件当成本条审计 |

个人邮箱绑定继续走 Settings。详情页可以写一句安静说明：「跟进邮箱在个人设置按人绑定；本页只定组织策略。」不要把 Settings 表单嵌进来。

`company_admin` / `department_admin` 的范围仍以 `01-organization-tenancy.md` 为准：公司组织资产与部门范围内的 Agent / 知识 / 审批。管理员改授权也不能让自己跳过运行时闸门。

## `/admin/agents` 治理页

**新页面**。替换管理端顶栏「员工 · 智能体 → `/agents`」。只回答组织里的数字能力是否可被员工召唤，不回答「今天从哪张卡再开一单」，也不回答「找谁协作」（那是员工专家中心）。

本页是治理，不是员工专家中心。发布 / 授权 / 考试闸门在此；员工 `/agents` 只列可召唤的岗位专家。不要把治理矩阵或连接器状态抄进员工专家中心。

| 区块 | 只回答 | 禁止 |
|---|---|---|
| **发布状态** | `unpublished` / `pilot-not-production` / 已发布；员工能否提交 | 在本页替员工提交任务或打开 Chat |
| **可写范围** | 品牌 / 区域 / 对象 / 动作的可写声明（只读展示 + 治理入口） | 把可写范围画成 Pipeline 资产板 |
| **考试闸门** | 哪些考试挡住哪些 Agent / 员工；分配是否完成 | 把员工 `/exam` 做成第二份答题页 |
| **连接器授权矩阵** | 每个 Agent × 连接器的 read/write 授予 | 矩阵单元格深链员工 Agents 开工；把 MCP 工具名摊成员工文案 |

`UX-AGENT-UNPUBLISHED` 仍是员工端契约：未发布可看说明、不可提交。本页是管理端改变该状态的地方，不是员工空态的副本。

管理端顶栏允许：「返回员工工作台」（回 Home）。不允许：「员工 · 智能体」跳 `/agents`。若管理员要自己干活，走员工导航，不从治理顶栏抄一条工作入口。

## 审计切片（连接器 / 授权 / 绑定）

管理端必须能单独扫到这三类变更，而不是只靠「数据 / 留存 / 审计」里最近 20 条大杂烩。

| 事件类 | 必须能看到 | 必须脱敏 |
|---|---|---|
| 连接器 | 启用/停用、`credential_ref` 变更（只记引用标识）、创建 | 秘密原值、JWT、Key |
| 授权 | 员工/角色对连接器或 Agent 的 read/write 授予与收回 | 无业务必要的账号秘密 |
| 绑定 | 个人 Starry 绑定/解绑（谁、哪只邮箱、何时）；组织策略变更 | Bearer / JWT 正文 |

切片可以是 `/admin` 审计区的过滤，或连接器/Agent 详情上的「本对象最近变更」。不要新做员工「等我确认」页，也不要把 Pipeline 近期事件当审计。审计字段义务仍以 `08-permission-approval-audit.md` 为准（申请人、前后摘要、时间、决定、幂等键；敏感字段脱敏）。

本文件不新增审计表 schema；后端缺字段时另开计划，不得在纯前端 PR 里假装已有 LIVE 回放。

## 导航规则

| 位置 | 必须 | 禁止 |
|---|---|---|
| 员工侧栏 | 工作入口停在 Home / 进行中、`/agents`（文案「数字员工」，岗位专家）、Pipeline、知识、审批、考试、Settings。可选「连接器」入口只链员工使用面（`/connectors`），放资产簇或 Settings 邻接，不进数字员工簇。确认队列在 Home（结果待确认 / 等审批），不另做「等我确认」顶栏 | 「技能目录 · **连接器**」或任何员工默认项深链 `/admin/connectors`；侧栏再挂一条克隆审批的「等我确认」；发明可见组标题；专家团入口或占位；数字员工簇挂技能目录 |
| 员工进管理端 | 仅侧栏账户芯片弹出菜单「管理控制台」→ `/admin`（需 `available_modes` 含 admin）。账户切换住在该弹出菜单；菜单不含连接器或 Starry | 主路径任何「连接器」砖、SkillHub 调试砖、Agents 卡链进 Admin 治理 |
| 管理端顶栏 | 治理标题 + 返回员工工作台；健康条用**管理端专用**文案（启用/未挂接/凭据已登记） | 克隆员工 Agents `remote-pill` / `live-dot` 图例当默认 chrome |
| 管理端信息架构 | 员工目录、连接器枢纽、`/admin/agents`、审批角色、考试分配、知识、数据/审计 | 再要一个「我的智能体」页、再要一个 Pipeline、再要一份个人 Starry 表 |
| 调试视图 | 显式打开后，管理员才可见引擎图例 / SkillHub 连接器砖 | 把调试砖留在员工默认侧栏或默认 Agents 英雄区 |

员工默认表面继续遵守 `UX-COPY-ENGINE`：不出现 MCP、Codex、Thread、Skill、原始堆栈、内部工具名。管理端 Trace 可以显示引擎信息，必须脱敏。SkillHub / `/market/skills` / `/partners` 若仍是调试或目录实验页，其连接器砖只允许在**显式调试且具备 admin** 时出现，并指向管理端枢纽；**不得**出现在员工默认侧栏或默认 Agents 英雄区。默认员工的「连接器」入口只去使用面。

## 遗留收敛

下列表面不再各自维护一份连接器真相。后续纯前端 PR 把它们收进 `/admin/connectors`（枢纽）与 `/:id`（详情）；本文件只立法，不改 JSX。

| 遗留 | 现状职责 | 收敛后 |
|---|---|---|
| `frontend/src/pages/Admin.tsx`「本期连接器 / 本期隐藏 / 品牌邮箱」 | 技能管理页旁路清单 | 删除或重定向到枢纽；品牌邮箱策略并入对应连接器详情 |
| `frontend/src/pages/SimplePages.tsx`「管理配置 → 本期连接器」 | 第二份只读清单 | 删除或重定向到枢纽 |
| `SkillHub` 连接器砖（`starrykol` / `kolclaw` → `/admin/connectors`，`enterprise_mail` / `wecom` → `/admin`） | 调试目录冒充治理入口 | 只留显式调试；默认员工导航不可见；目标统一为枢纽 |
| `AdminConsole` 连接器标签下的扁平列表 + 个人 Starry 标签 | 枢纽雏形 + 绑错位 | 列表升级为枢纽；Starry 个人绑定迁出到 Settings；组织策略留在 `/:id` |
| `AdminConsole` 顶栏「员工 · 智能体」 | 跳员工 `/agents` | 改为 `/admin/agents` 治理页 |

收敛完成的判定：组织里「有哪些连接器、开没开、谁能读写」只在管理端枢纽/详情出现一次；**员工端零处治理目录**。员工使用面可以列出「我已被授权可用哪些」，但不得复制枢纽的启停、凭据引用或授权矩阵。

## 视觉：同一 token，不同 IA

管理端与员工端共用 `20` 的画布、边框、indigo 主色、语义色和 Linear 密度。**禁止**为管理端另开一套主题，也**禁止**把管理端做成第二套 Home / Agents。

| 员工工作台 IA（`19` + `20`） | 管理端 IA（本文件 + `20` token） |
|---|---|
| 英雄区 + 开工 CTA + 结果卡 | 页头（治理标题）+ 分类导航 + 表/行 + 授权矩阵 |
| 一条主线程、紧凑 Journey chrome | 一条纵滚的治理表；宽表允许横向滚动（`19` 已允许宽表/调试条） |
| `remote-pill` 仅显式调试 | 管理端健康条：文字状态，不是员工 pill 克隆 |
| 「再开一单 / 用此智能体开始」 | 「启用 / 停用 / 授予 read / 授予 write / 查看审计」 |

阴影、字号、主色槽位不另立法。若有人要把管理端做成仪表盘卡片墙或第二套 Agents 英雄区，先过本文件硬边界，再谈好看。

## 非目标

- **不 LIVE。** 本契约不授权真实 MCP 写入、生产放行或把「已启用」写成「远端已通」。
- **不把 MCP 行话交给员工。** `UX-COPY-ENGINE` 继续有效。管理端可以说连接器短名与状态；员工端只说已授权能力与业务结果。
- **管理端不是第二套 Pipeline。** 不扫视 15 阶段，不提阶段变更，不复制 Home 待办。
- **管理端不是第二套 Agents 工作台。** `/admin/agents` 只治理（发布 / 授权 / 考试闸门），不召唤、不开工；不得与员工专家中心混读。
- **本文件不新增 UX ID**，不写 `specs/UX-ADMIN-PAGES.md`，不改 `ux-traceability.json`。没有绑定 FS 的交互描述不能进发布门禁。
- **不重做 `Chat.tsx`，不改数字员工对象模型，不实施 ExpertManifest API。** 员工专家中心立法见 `19` / ADR-016；本文件只锁定「专家中心 vs 治理页」与「员工专家中心禁止连接器状态 chrome」。
- **不把员工 `/kb` 写成治理页。** 员工知识库立法见 `19` / ADR-021（查找 / 预览 / 收藏 / 用于当前任务）。本文件只锁定「员工 KB vs 管理知识治理」；不重写管理知识页，不迁 schema。
- **不在本契约里加后端字段、新权限模型或 Host 旁路。** 管理员也不能跳过 `08` 闸门。
- **不为体验层再写调度器或状态机。**

## 落地顺序

1. **本契约先合并。** 后续 PR 用本文件硬边界自检；冲突写入 `DECISIONS.md`，不要在前端分支另立一套双端规则。
2. **纯前端：导航 + 枢纽壳 + 员工使用面。** 去掉员工侧栏管理端深链；员工若有连接器入口只链 `/connectors`；管理端顶栏改为 `/admin/agents`；Starry 个人绑定只留 Settings；遗留「本期连接器」指向或并入枢纽。只使用已有 API 能支撑的只读/启停/授权壳与员工只读消费。不夹带 LIVE、不新造 UX ID。
3. **后端字段另开计划。** 组织 Starry 策略、授权矩阵、审计切片若缺字段，单独规格 + 迁移 + 契约测试。禁止在第 2 步的前端 PR 里假装字段已齐。

可执行员工体验验收仍走 `specs/UX-KOL.md` 与 `specs/ux-traceability.json`。管理端配套套件在没有 FS / UX ID 绑定前，只当信息架构法律，不当发布门禁绿项。
