# 从 Host 硬编码到声明式 Agent 的迁移路线

目标是让新增 Agent 主要通过配置 Agent、Workflow、Skill、Policy、MCP 白名单、知识和审批完成；平台代码只随通用内核能力增长，不随 Agent 数量线性复制。

## 必须留在 Host/内核

租户与数据范围校验、状态机、`legalTargets` 人确认闸门、`autoLegalTargets` 自动事实写入、`expected_version` 冲突、发送 Gateway、占位邮箱校验、幂等、超时、熔断、异常冻结、审计、digest 存储和最终提交。

## 必须退出 Host

信件目录与模板选择、缺口文案、口令正则抽槽、首页推荐表、阶段 SOP 的 next action、业务 Skill 选择、业务结果拼装、默认金额和默认第一发件箱。它们迁入 Skill/Workflow/知识或由 Codex turn 产出，Host 只做否决和持久化。

## 分阶段执行

1. 先统一真实 app-server 路径：生产业务 turn 不得由 `runStub`、Host 直出或旁路 REST 完成。
2. 为每个 Skill 声明 `required_inputs`、`output`、`mcp`、风险和禁止事项；删除 Host 第二套目录。
3. 将 journey/chips 改为读取最近一次 Codex 产物；推荐只预填，提交后才创建 Task。
4. 将邮件预览、发送、阶段变更拆成三个独立产物和闸门；一次打开会话只做一次 Starry 摘要拉取。
5. 将爬虫改为 Job：`start_crawl → get_crawl_status → get_creators → upload_creators`，禁止同步伪装。
6. 建立真实链路、权限、UX、评价回归后再灰度删除旧分支。

组织主数据状态：安培时代公司、组织树和张慧玲/刘敏部门负责人已确认；部门负责人公司级品牌、区域和普通数据读写策略已进入 registry。后续只需将正式组织系统身份和版本同步接入，而不再把组织主数据视为待发现项。

## 完成判定

随机新增一个普通 Agent 时，不新增业务调度器、状态机、旁路 REST 或前端权限代码；只新增配置、Skill、Workflow、Policy、知识、MCP 声明和规格/评价样例即可通过发布门禁。

## 企业化路线（承载剩余审计建议）

企业化工作不再扩张宪法文件，按现有契约、UX、评价和发布门禁推进：

| 阶段 | 目标 | 必须完成的证据 | 退出条件 |
|---|---|---|---|
| E0 试点加固 | KOL 试点可重复验收 | 红线定向测试、完整测试失败清单、UX 追踪、受控发信记录 | 关键红线稳定通过；失败原因可归属 |
| E1 多组织运行 | 公司/部门/品牌/区域关系进入正式 PEP | 正式身份同步、关系版本、生效时间、跨公司/跨品牌回归 | PEP 不依赖姓名或前端字段；审计可回放 |
| E2 配置型 Agent | 普通 Agent 只改 manifest/Skill/Workflow/Policy/知识 | 评价集、UX 状态、全量测试、回滚演练 | 不新增业务调度器、旁路 REST 或前端权限代码 |
| E3 企业平台 | 多公司、多品牌、多部门和运行治理 | 租户隔离、配额、成本、监控、SLO、灾备、数据保留和管理端审计 | 生产门禁全绿；组织和副作用证据闭环 |

阶段写入生命周期记录、全量测试和 E2E 是当前 E0 的阻断项。TB 远端绑定按业务负责人指示从本轮验收阻断中豁免，但运行时仍不得回退到其他品牌或首个邮箱；它属于后续外部数据治理项。
