# 设计基本法：平台 UI/UX 与 Agent 内容呈现

制定角色：UI/UX 专家。上位法：[CONSTITUTION.md](CONSTITUTION.md)。产品功能与交互行为遵守 [PRODUCT.md](PRODUCT.md)，业务含义与确认要求遵守 [BUSINESS.md](BUSINESS.md)。本文件定义设计要求，不重写业务权限或技术实现。

## 十二条设计规则

### UX-01 两类设计对象

平台 UI/UX 包括导航、员工端、管理端、设置端、表单、权限提示和标准组件，由 UI/UX 专家设计。Agent 内容由 Codex 根据任务组织；智能体产品经理定义回答契约，UI/UX 专家设计可用呈现方式，前端实现。

可以约定结构化内容类型和必要操作字段，不规定每次必须出现几张卡、几个区块或固定排序。内容结构变化不允许改变业务动作的授权边界。

### UX-02 页面职责

每个页面有清楚的主要用途，导航名称与实际能力一致。员工使用已发布资产，管理端配置与治理资产，设置端管理个人账号和偏好；不能把三个入口做成重复的配置台。

首页支持继续任务、查看待办及业务快捷结果；对话页完成分析与协作；KOL 看板、公海和跟进页根据业务包提供。能力不必全部挤入侧栏，也不能因为未实现而永久禁止规划中的能力。

### UX-03 入口可辨认

AI 提问框明确用于“让 Agent 分析或处理”；记忆快捷入口明确用于“查看已有记录”或“记录已明确内容”。同一个外观和名称不能一次查记忆、一次启动推理。

快捷未命中、过期或失败时显示具体状态；需要进一步分析时提供明确的 Agent 入口。后台更新与前台读取消耗、状态分开，不用“正在思考”掩饰普通查询。

### UX-04 内容组织

优先让员工看清问题的答案、证据或需要采取的动作，按任务需要展开细节。表格用于比较，卡片用于对象和动作，时间线用于过程，长文支持分段阅读；不为了统一外观把所有结果塞进同一种卡片。

事实、推断、建议与执行回执在有混淆风险时明确区分。记忆摘要可查看来源、更新时间和过期状态；无数据字段不编造、不用空占位装饰成完成结果。

### UX-05 状态真实且可行动

加载、空结果、无权限、待补充、待审批、执行中、失败、部分成功、已完成及已取消有清楚区别。错误说明发生了什么、哪些已完成，以及可执行的重试、修正或接管入口。

员工日常操作界面使用业务语言，不暴露原始堆栈、内部工具名或 thread/turn 标识。技术追踪在有权限的管理视图展开；正常的“技能”“连接器”等产品名称不作为禁词。

### UX-06 确认与回执

正式动作的确认展示对象、范围、变更内容、后果以及适用审批状态。发送前展示最终发件箱、收件人、主题、正文和附件；改正式阶段另用独立入口展示目标阶段，不能放在发送确认里顺便完成。

批准、确认提交与执行成功分开显示。旧确认失效时说明变化；未知回执显示待核对。审批拒绝按业务要求收集原因，普通取消不额外设置审批障碍。

### UX-07 记忆管理与权限

员工能找到自己的记忆，查看来源与范围，纠正、停用或删除有权管理的条目。私人记忆、团队可见和业务共享记录有可理解的标识；“团队”必须指明确授权群体。

归属改变后不继续展示旧权限下的摘要、计数或缓存。受限对象不通过搜索建议、错误文案或空卡片泄露身份；可授权管理员查看原因的入口与员工结果区分开。

### UX-08 统一视觉来源

延续安静白底、克制排版、轻分隔和低强调的整体方向。产品主按钮使用统一的产品粉红语义 token；每个视口原则上只有一个主要实底动作，其余动作降低强调。

色值、字体、间距、圆角和阴影统一维护在 [MASTER](./design-system/kol-workbench/MASTER.md)，实现同步到 [styles.css](../frontend/src/styles.css)；本文件不复制色值。MASTER 内产品 token 优先于其参考样式段落，外部风格示例不能自行覆盖已发布 token。

### UX-09 组件与密度

输入框、按钮、菜单、对话框、表格和结果卡复用组件与语义 token，不在页面另造视觉体系。密度通过排版、间距和信息层次调整，不能用整体缩放或过小文字伪装精简。

可编辑草稿保留修改状态；加载和确认期间避免布局跳动、重复提交及遮挡主要动作。未知 Agent 内容类型提供可阅读的安全降级，不显示可执行的原始代码。

### UX-10 无障碍与响应式

沿用 WCAG 2.2 AA 的验收目标：键盘可完成核心操作、焦点清晰、表单有标签、错误可感知、状态不只依靠颜色；弹窗管理焦点并能返回触发位置，尊重减少动画偏好。

按支持范围验证 360、768、1024、1366 及 1440 以上视口。窄屏导航、表格和草稿有可用布局，不能把被遮挡或隐藏的控件留在不可理解的键盘顺序中。具体组件尺寸与对比度以经验证的统一 token 为准。

### UX-11 设计交付与验收

功能设计最少说明入口、主要用途、关键状态、动作反馈及响应式差异；视觉改动说明采用的组件或 token。UI/UX 专家负责设计判断，前端专家负责实现，测试经理验证关键操作、状态和可访问性。

截图、设计工具或技能输出是设计辅助材料，不能覆盖宪法、业务规则或已发布设计规范。小改动复用既有组件，不强制重新做全套设计研究。

### UX-12 旧设计规则的取舍

保留使用与治理分离、统一 token、无障碍、真实状态、发送与阶段分离及明确确认。旧页面布局可以作为实施参考，但“必须先聊天”“必须固定卡片数量”“固定分组就是法律”不再作为新版要求。

原设计入口（v1 `design.md`）已由本文件取代。[IA](./ia-information-architecture.md)、[页面规范](./design-system/kol-workbench/pages/)、[UX-EMPLOYEE](../specs/UX-EMPLOYEE.md) 中未冲突的细节可继续复用；冲突部分按本包更新，不通过恢复已废止 UX ID 强制旧布局。
