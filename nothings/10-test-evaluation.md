# 测试、评价与验收

测试驱动保证确定性内核，评价驱动保证概率性 Agent。两者都必须从功能规格生成证据，不能用“看起来能用”代替门禁。

## 测试分层

1. **单元测试**：状态机、权限判定、`legalTargets`、幂等、回执、异常冻结。
2. **契约测试**：Skill frontmatter、output schema、MCP 参数/响应和数据字典映射。
3. **Harness 集成测试**：真实 Codex app-server 的 initialize、thread/start/resume、turn/start、流式事件、审批和恢复。
4. **物理集成测试**：授权 Starry/MediaCrawler MCP，验证超时、限流、异步 Job、错误和回执。
5. **端到端测试**：员工端任务、等待/审批/失败/接管；管理端配置、追踪和审计。
6. **无障碍与 UX 测试**：键盘、焦点、读屏、对比度、状态播报和响应式布局。

## 红线门禁

- 非授权租户、部门、品牌、区域和对象必须拒绝。
- 未确认不得发送、改正式阶段、解密、导入或删除。
- 发送与阶段变更必须是独立动作。
- 员工端不得出现 MCP、Codex、Thread、原始堆栈和内部工具名。
- 生产链路必须是真实 app-server + 授权 MCP；`CODEX_MODE=stub` / `runStub` 只能用于 CI 和确定性内核测试。
- 异步 MCP 必须有 Job、轮询/事件、终态、取消、重试和上传回执。

安培时代组织范围测试还必须覆盖：张慧玲、刘敏自动获得全部品牌/区域普通数据读写；普通成员不能继承该范围；高风险动作即使由部门负责人发起仍必须经过 Gateway 和确认/审批。

## Agent 评价集

每个 Skill 至少维护：正常样例、缺字段样例、越权样例、冲突上下文、提示注入、工具失败、重复提交、长上下文和人工改稿样例。评价记录模型/Skill/MCP 版本、输入、工具选择、产物、是否触发正确闸门和人工评分。

核心指标：任务成功率、事实正确率、工具选择正确率、越权拒绝率、需人工接管率、重复副作用率、首 token/完成延迟、成本和员工采纳率。任何红线失败阻止发布；质量阈值由业务负责人和测试共同签署。

### 评价风险分级

评价集按副作用风险分级，不要求所有 Skill 使用相同数量的样例：

| 等级 | 适用能力 | 最低样例 | 发布门槛 |
|---|---|---|---|
| P0 | 发信、阶段写入、导入、解密、删除、审批提交 | 正常、缺字段、越权、注入、冲突上下文、工具失败、重复提交、人工改稿 | 红线 100%；重复副作用 0；业务负责人和测试共同签字 |
| P1 | 普通数据写入、知识发布、任务转办 | 正常、缺字段、越权、工具失败、重复提交、人工改稿 | 权限拒绝 100%；schema 错误 100% 拒绝；失败可恢复 |
| P2 | 只读查询、摘要、画像、筛选 | 正常、空结果、权限过滤、工具失败、长上下文 | 事实来源完整；越权 100% 拒绝；不得产生副作用 |

KOL 现有 `evals/kol/core.jsonl` 已覆盖 16 个 P0/P1/P2 核心样例，包含正常、空结果、缺字段、越权、提示注入、冲突上下文、工具失败、异步 Job、重复提交、人工改稿、未发布 Agent 和部门负责人高风险动作。新增能力必须登记风险等级、评价 ID、阈值和人工复核人，不能只增加 Prompt 或演示样例。

## 验收证据包

发布前必须有规格追踪矩阵、自动化测试报告、真实 MCP 记录（脱敏）、Agent 评价报告、UX/无障碍结果、权限审计样本、灰度计划、回滚演练和业务负责人签字。
