# 计划、规约、编码与 Codex 协作

## 四种方法的组合

- **氛围编程**：人和 Codex 在明确上下文、范围、检查点、停止条件和回滚点内探索；Codex 可以提出方案和实现，人负责目标、取舍、事实和高风险决定。
- **规约驱动**：[`LAW-MAP.md`](LAW-MAP.md) 的 A–K、功能规格、Skill/Workflow/Policy 和物理接口构成可执行契约；自然语言不能替代状态、权限、schema 和验收。不要按 `00`–`21` 编号当主线。
- **测试驱动**：先为硬规则写失败测试，再实现状态机、权限、幂等和适配器；修复必须保留回归测试。
- **评价驱动**：对 Agent 的工具选择、事实、表达、拒绝越权、等待确认和恢复能力建立场景集、评分量表和发布阈值。

## Codex 工作循环

```text
读宪法/功能规格 → 扫描代码与物理接口 → 列影响与不变量
→ 先写测试/评价 → 最小实现 → 真实 harness/MCP 验证
→ 检查员工端/管理端 → 记录证据 → 灰度/回滚
```

每次任务开始必须说明目标、非目标、修改范围、风险、验证命令和停止条件。Codex 不得自创第二套业务规则；发现规格冲突先提出决策记录。

## 代码归属

业务意图、缺口、推荐和模板在 Skill/知识；状态机、PEP、审批、幂等、回执、熔断和审计在 Host；外部读写在远程 MCP/Gateway；展示在通用前端。新增 Agent 通常不应新增调度器、状态机、旁路 REST 或专属权限代码。

## 代码评审门禁

检查租户/品牌范围、真实 app-server 路径、MCP 白名单、L1-L3、发送/阶段分离、8/15 阶段模型、错误恢复、员工端术语隔离、测试和评价追踪。`runStub`、Host 直出业务结果、前端写状态和重复 Skill 主键直接退回。
